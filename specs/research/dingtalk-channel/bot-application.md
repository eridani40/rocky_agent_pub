# 钉钉机器人申请流程 + 飞书/钉钉企业归属差异

## 1. 钉钉机器人怎么申请（一步步）

> 来源：[钉钉开发者百科-获得开发者权限](https://open-dingtalk.github.io/developerpedia/docs/explore/portal/grant-admin) + [钉钉开放平台-创建应用](https://open.dingtalk.com/document/dingstart/create-application) + [Stream SDK Node.js README](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs)

### 1.1 前提条件

| 条件 | 说明 |
|---|---|
| **钉钉账号** | 手机号注册（免费） |
| **一个团队/企业** | 钉钉应用的载体——**不能脱离组织独立存在** |
| **开发者权限** | 「应用开发子管理员」权限（管理员授予 or 自助申请审批） |

**关键**：钉钉应用/机器人**必须挂在一个团队/企业下**，个人无法脱离组织创建。

### 1.2 完整申请路径（6 步）

**步骤 1：创建团队（如果还没有）**

如果还没有企业/团队（大多数个人开发者的起点）：
- **手机端**：钉钉 → 左上角企业名称 → 下滑「创建/加入团队」→「创建团队」→ 填企业信息（名称/地区/行业）→ 创建
- **电脑端**：通讯录 →「创建团队」→ 输入手机号 → 按提示操作

> **不需要营业执照**——创建的「团队」是免费团队，非企业认证。钉钉官方百科原话：「**创建的团队不认证也可正常使用钉钉**」（[阿里云问答](https://developer.aliyun.com/ask/669329)）。企业认证后获得更高权益（API 配额等），但基础开发**不需要**。

**步骤 2：获取开发者权限**

登录[钉钉开发者后台](https://open.dingtalk.com/)（`open.dingtalk.com`），用钉钉扫码登录。如果没权限会报错提示。两种获取方式：

| 方式 | 操作 | 适合 |
|---|---|---|
| **管理员授予**（推荐） | 主管理员进 OA 管理后台 → 安全与权限 → 权限管理 → 选员工 → 勾选「应用开发子管理员」 | 已在企业内 |
| **自助申请** | 成员提交审批单 → 管理员审批通过 | 临时调试 |

> 如果是自己创建的团队，**你就是主管理员**，直接给自己授予权限即可。

**步骤 3：创建企业内部应用**

开发者后台 →「应用开发」→「企业内部开发」→「创建应用」

填应用名称 + 描述 + 图标 → 确定。

**步骤 4：添加机器人能力 + 选 Stream 模式**

进入应用详情 →「应用能力」→「添加应用能力」→ 选「机器人」→ 完善机器人信息（名称、头像、消息接收模式）：

- **消息接收模式选「Stream 模式」**（不是 HTTP 模式——桌面应用无公网回调地址）
- 发布机器人

**步骤 5：获取凭证（clientId / clientSecret = robotCode）**

应用详情页 →「凭证与基础信息」→ 看到：
- **Client ID**（= AppKey）→ 填到 Rocky 渠道配置的 `clientId` 字段
- **Client Secret**（= AppSecret）→ 填到 Rocky 渠道配置的 `clientSecret` 字段

> 这就是 Rocky 钉钉渠道 configSchema 需要的两个凭证字段。

**步骤 6：发布应用 + 添加可见范围**

应用需要**发布** + 设置**可见范围**（哪些成员能用）：
- 应用详情 →「版本管理与发布」→ 创建版本 → 发布
- 应用详情 →「可见范围」→ 添加成员/部门

> 测试阶段可以只加自己为可见范围。发布后，在钉钉群里 @机器人 或私聊机器人即可。

### 1.3 凭证来源总结

| 凭证 | 来源 | 对应 Rocky 字段 |
|---|---|---|
| **clientId** (AppKey) | 开发者后台 → 应用详情 → 凭证与基础信息 | `config.clientId` |
| **clientSecret** (AppSecret) | 同上 | `config.clientSecret` |
| **robotCode** | = clientId（钉钉 robotCode 与 AppKey 同值） | 内部使用 |
| **AccessToken** | 运行时用 clientId+clientSecret 调 API 自动获取（2h 刷新） | 运行时内部管理 |

## 2. 为什么飞书不需要在企业内？（核心差异）

### 2.1 先纠正一个误解

**飞书应用同样需要挂在一个「企业/租户」下**——飞书的「企业自建应用」定义就是「由企业内部人员开发，只能在同一企业内发布和使用」（[飞书开放平台-自建应用开发流程](https://open.feishu.cn/document/develop-process/self-built-application-development-process)）。

**那为什么体验上觉得飞书「不需要企业」？** 因为飞书开放平台提供了**「测试企业」一键创建**机制：

> 来源：[飞书开放平台-测试企业与人员](https://open.feishu.cn/document/develop-process/test-and-release-app/testing-enterprise-and-personnel-functions)
>
> 「每个开发者可以创建最多 3 个测试企业。」

这意味着：
1. 任何个人开发者登录飞书开放平台 → 一键创建测试企业（无需营业执照、无需审核）
2. 在测试企业下直接创建自建应用 → 拿到 appId/appSecret
3. 应用在测试企业内立即可用（添加可见范围 = 自己）

**飞书的「测试企业」= 零门槛沙箱**，让个人开发者不需要真实企业就能跑通全流程。

### 2.2 钉钉的对应机制

钉钉**也有类似的机制**，只是叫法不同 + 步骤更多：

| 钉钉 | 飞书 |
|---|---|
| 手动「创建团队」（手机端/电脑端） | 一键「创建测试企业」（开发者后台内） |
| 自己成为主管理员 → 自己授予开发者权限 | 创建测试企业后自动有管理员权限 |
| 在团队下创建应用 | 在测试企业下创建应用 |

钉钉开发者百科原话（[获得开发者权限](https://open-dingtalk.github.io/developerpedia/docs/explore/portal/grant-admin)）：

> 「**最佳实践**：如果你无法获得当前组织的主管理员权限的话，**建议创建一个测试组织**，这样可以用主管理员权限快速掌握和验证钉钉全部的能力。」

**结论**：钉钉也支持个人开发者零门槛使用（创建免费团队 = 测试组织），只是：
1. 钉钉的团队创建入口在**客户端**（不在开发者后台），飞书的测试企业在**开发者后台**内一键建
2. 钉钉需要手动授予「应用开发子管理员」权限，飞书创建测试企业后自动有权限
3. 钉钉流程多 2~3 步，但**不需要营业执照、不需要企业认证**

### 2.3 根本差异对比表

| 维度 | 飞书 | 钉钉 |
|---|---|---|
| **应用载体** | 租户/企业（测试企业 or 真实企业） | 团队/企业（免费团队 or 认证企业） |
| **个人开发者零门槛** | ✅ 测试企业一键创建（后台内，≤3 个） | ✅ 免费团队创建（客户端操作，不限数量） |
| **需要营业执照？** | ❌ 不需要 | ❌ 不需要（免费团队无需认证） |
| **需要企业管理员审批？** | 测试企业=自己就是管理员 | 自建团队=自己就是主管理员 |
| **开发者权限获取** | 创建测试企业 → 自动获得 | 创建团队 → 需手动授予「应用开发子管理员」（自建团队自授） |
| **创建入口** | 开发者后台内（一站式） | 客户端创建团队 + 开发者后台创建应用（两处） |
| **应用可见范围** | 测试企业内自由配置 | 团队内自由配置 |
| **应用发布审核** | 企业自建应用需企业管理员审核（测试企业=自审） | 企业内部应用需发布+设置可见范围 |
| **体验差异** | **一站式流畅**（开发者后台内全搞定） | **需跨平台操作**（客户端建团队 → 后台建应用 → 授权） |

### 2.4 一句话总结

> **飞书和钉钉都需要在「组织」下创建应用——这不是平台差异，而是企业 IM 的本质（应用必须归属组织）。真正的差异是**：飞书在开发者后台内一键创建测试企业（零摩擦），钉钉需要先在客户端创建团队再回开发者后台（多几步但同样零认证）。

## 3. 对 Rocky 用户的影响

### 3.1 用户配置钉钉渠道的完整前置步骤

```
1. 手机/电脑钉钉 → 创建团队（免费，无需营业执照）→ 自己成为主管理员
2. 钉钉开发者后台 → 扫码登录 → 给自己授予「应用开发子管理员」权限
3. 开发者后台 → 应用开发 → 企业内部开发 → 创建应用
4. 应用能力 → 添加「机器人」→ 消息接收模式选「Stream」→ 发布
5. 凭证与基础信息 → 复制 clientId + clientSecret
6. Rocky 渠道页 → 新建「钉钉」渠道 → 粘贴 clientId + clientSecret → 启用
7. 钉钉群 @机器人 / 私聊机器人 → 开始对话
```

### 3.2 与飞书配置步骤对比

| 步骤 | 飞书 | 钉钉 |
|---|---|---|
| 建组织 | 开发者后台一键创建测试企业 | 客户端手动创建团队 |
| 获取开发者权限 | 自动 | 手动授予（自建团队自授） |
| 建应用 | 开发者后台创建自建应用 | 开发者后台创建企业内部应用 |
| 加机器人能力 | 添加应用能力→机器人 | 添加应用能力→机器人 |
| 选消息模式 | SDK 默认 WSClient（无需选） | **显式选 Stream 模式** |
| 拿凭证 | appId + appSecret | clientId + clientSecret |
| Rocky 配置 | 粘贴 appId + appSecret | 粘贴 clientId + clientSecret |

**飞书少 2 步**（建测试企业一站式 + 无需选消息模式），但核心流程一致。

### 3.3 文档建议

Rocky 渠道配置页应提供「钉钉接入说明」（类似飞书的 `component-feishu-setup-doc.md`），引导用户完成上述 7 步。重点是步骤 1-2（建团队 + 授权），因为这是与飞书体验差异最大的地方。
