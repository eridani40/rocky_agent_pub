# iFurySt/open-codex-computer-use 调研报告

> 一句话定位：开源版 Codex Computer Use，**Swift 原生 macOS 实现**为主轴（含完整 AX + ScreenCaptureKit + CGEvent postToPid 后台输入链），Go+Python/PowerShell 做实验性 Linux/Windows runtime，对外统一暴露官方 9 个 tools 的 MCP（stdio JSON-RPC）server。

## 一句话总览

- **语言栈**：macOS 主线 = Swift 6.2（`swift-tools-version: 6.2`，`.macOS(.v14)`），`Package.swift` 产出 `OpenComputerUseKit` 库 + 多个 executable（`OpenComputerUse` 主 app / `CursorMotion` / `StandaloneCursor` 光标实验 / `OpenComputerUseFixture` 测试夹具 / `OpenComputerUseSmokeSuite`）。Linux/Windows 是 Go 二进制 + 内嵌 Python（AT-SPI）/PowerShell（UIA）bridge。
- **本地 vs 云**：100% 本地执行。LLM 推理在外部 agent（Codex / Claude Code / Gemini CLI）侧，本服务只做 MCP tool 执行（截图/AX/输入）。
- **macOS 原生程度**：高。Swift 直接调 `ApplicationServices`（AXUIElement*）/`CoreGraphics`（CGEvent）/`ScreenCaptureKit`/`AppKit`，无 AppleScript / osascript 依赖（架构文档明确"避免回退 AppleScript"）。
- **与 codex 集成方式**：MCP stdio server（newline-delimited JSON-RPC 2025-03-26）。`open-computer-use install-codex-mcp` 写 `~/.codex/config.toml`；也可作 plugin 安装（`install-codex-plugin`）。`turn-ended` 通过 `notifications/turn-ended` 或 CLI distributed notification 做会话清理。
- refs 路径：`refs/open-codex-computer-use/`。

## action 集合 + 参数

**形态：多个独立 tool**（非聚合 computer 工具），共 **9 个**，对齐官方 `computer-use` 1.0.755/770 的 tool surface。所有 tool 的 `description` 均带后缀 `"This tool is part of plugin \`Computer Use\`."`。

定义位置：`packages/OpenComputerUseKit/Sources/OpenComputerUseKit/ToolDefinitions.swift:32-151`。分发器：`ComputerUseToolDispatcher.swift:46-108`。

| tool | 必填参数 | 可选参数 | 说明 |
|---|---|---|---|
| `list_apps` | — | — | 列出运行中 + 近 14 天用过的 app（Spotlight metadata `kMDItemUseCount`/`kMDItemLastUsedDate_Ranking` + NSWorkspace 运行态合并） |
| `get_app_state` | `app` | `text_limit`(int\|`"max"`,默认500)、`max_tree_nodes`(默认1200)、`max_tree_depth`(默认64) | **核心**：启动/复用 app session，返回 key window 截图 + AX tree。架构文档要求"每 assistant turn 开头必调一次" |
| `click` | `app` | `element_index`\|(`x`,`y`) 二选一、`click_count`(默认1)、`mouse_button`(`left`/`right`/`middle`,默认left) | 元素索引优先；坐标为**截图像素坐标** |
| `perform_secondary_action` | `app`,`element_index`,`action` | — | `action` 来自 get_app_state 输出的 `Secondary Actions`（AXUIElementCopyActionNames），非固定枚举 |
| `scroll` | `app`,`element_index`,`direction` | `pages`(number,默认1,支持小数) | direction ∈ {up,down,left,right}；element-scoped（必须指向可滚动元素） |
| `drag` | `app`,`from_x`,`from_y`,`to_x`,`to_y` | — | **仅坐标模式**，无 element_index；坐标为截图像素坐标 |
| `type_text` | `app`,`text` | — | 字面文本输入（不支持快捷键语义） |
| `press_key` | `app`,`key` | — | xdotool `key` 语法：`a`/`Return`/`super+c`/`Up`/`KP_0` 等 |
| `set_value` | `app`,`element_index`,`value` | — | 直接赋值给 settable AX element（比 type_text 语义化） |

**关键约束**：
- `additionalProperties: false`（`ToolDefinitions.swift:158`）
- `list_apps` / `get_app_state` 标 `readOnlyHint: true, idempotentHint: true`；其余 `destructiveHint: false, openWorldHint: false`
- 没有独立 `launch_app` / `screenshot` / `get_ax_tree` / `wait` / `hover`——都被合并进 `get_app_state`（聚合型读状态）
- element_index 是 get_app_state 输出的**顺序整数**（treeLines 行首数字），不是稳定 ID

## OS 抽象层

**没有统一 OS interface 抽象**——而是**协议面统一 + 实现完全独立**。三个 OS 各有一套实现，共享相同的 9-tool schema 和 MCP 协议，但代码无共享抽象层。

| 平台 | 实现位置 | 语言 | 底层 API |
|---|---|---|---|
| macOS（主线） | `packages/OpenComputerUseKit/` + `apps/OpenComputerUse/` | Swift | AXUIElement / CGEvent / ScreenCaptureKit / AppKit |
| Linux（实验） | `apps/OpenComputerUseLinux/main.go` + `runtime.py` | Go（CLI/MCP/socket cache）+ Python（AT-SPI bridge） | GNOME AT-SPI2 via `gi.require_version("Atspi","2.0")` + GDK 截图 |
| Windows（实验） | `apps/OpenComputerUseWindows/main.go` + `runtime.ps1` | Go + PowerShell | `System.Windows.Automation`（UIA）+ Win32 `PostMessage`/`SendMessage` fallback |

**抽象边界 = tool schema + JSON-RPC 协议 + runtimeId/element_index 语义**：
- Linux `runtime.py:265-280` 的 `record_for_node` 输出字段（`index`/`runtimeId`/`automationId`/`controlType`/`frame`/`actions`）刻意对齐 macOS AX tree 结构
- 三平台都用 **window-relative frame**（元素 frame 相对窗口左上角），见 `runtime.py:126-137` 的 `relative_frame`
- 三平台 tree budget 一致：1200 节点 / 64 层 / 500 字符 text_limit（`AccessibilitySnapshot.swift:41-49`；`runtime.py:27-29`）
- 跨平台切 = 按 `process.platform/process.arch` 选 npm 包内置的 Go 二进制（Node launcher 自动选 `dist/windows/<arch>/` 或 `dist/linux/<arch>/`）

**Go runtime 的角色**（Linux/Windows）：通过 `go:embed` 把 `runtime.py`/`runtime.ps1` 打包，执行 tool call 时临时落盘并 spawn 子进程，传 operation JSON 路径，读 stdout JSON 返回。Go 负责 CLI/MCP JSON-RPC/进程内 snapshot cache，Python/PowerShell 只做一次性的 AX/AT-SPI/UIA 操作（`runtime.py:829-840` main 入口）。

## macOS 实现（重点）

Swift 源码位置：`packages/OpenComputerUseKit/Sources/OpenComputerUseKit/`，核心 4 个文件：
- `AccessibilitySnapshot.swift`（1500+ 行，AX tree 采集 + ScreenCaptureKit 截图 + 坐标转换）
- `ComputerUseService.swift`（1900+ 行，9 个 tool 的业务逻辑）
- `InputSimulation.swift`（350 行，CGEvent 鼠标键盘）
- `KeyMapping.swift`（166 行，xdotool key parser）
- `Permissions.swift`（548 行，TCC.db 读取 + AXIsProcessTrusted）
- `SoftwareCursorOverlay.swift`（900+ 行，可视化光标 overlay，非必需）

### 鼠标控制（CGEvent + postToPid）

`InputSimulation.swift:45-140`：

- **默认走 `CGEvent.postToPid(pid)` 定向投递**，不抢前台、不移动用户真实硬件光标。`click`/`scroll`/`drag` 默认 targeted（`ComputerUseService.swift:413-427` 的 `performNonAXClickFallback` → `clickTargeted`）。
- 全局 `.cghidEventTap` fallback **默认关闭**，仅在 `OPEN_COMPUTER_USE_ALLOW_GLOBAL_POINTER_FALLBACKS=1` 时启用（`ComputerUseService.swift:112-121`）。
- `clickGlobally`（`InputSimulation.swift:58-68`）：`CGEventSource(stateID: .hidSystemState)` → 循环 `mouseMoved`/`leftMouseDown`/`leftMouseUp`，每次 `event.post(tap: .cghidEventTap)` + `Thread.sleep(0.03)`。
- `clickTargeted`（`InputSimulation.swift:70-80`）：`CGEventSource(stateID: .combinedSessionState)` → 同序列但 `event.postToPid(pid)`。
- `dragTargeted`（`InputSimulation.swift:102-120`）：10 步线性插值 `leftMouseDragged`，每步 `postToPid`。
- `scrollTargeted`（`InputSimulation.swift:82-90`）：`CGEvent(scrollWheelEvent2Source: nil, units: .line, wheelCount: 2, wheel1:wheel2:)` + `event.postToPid`。delta = `12.0 * pages`（`scrollWheelDelta`，line 344）。

### 键盘控制（CGEvent + keyboardSetUnicodeString）

`InputSimulation.swift:142-222`：

- **`typeText`**（line 142-162）：按 **Unicode extended grapheme cluster** 聚合，每 chunk ≤ 64 UTF-16 units（`maxKeyboardUnicodeChunkLength`）。`CGEvent(keyboardEventSource: nil, virtualKey: 0, keyDown: true/false)` + `keyboardSetUnicodeString(stringLength:buffer.count, unicodeString: baseAddress)`，`down.postToPid(pid)`/`up.postToPid(pid)`，chunk 间 `sleep(0.02)`。**避免中文标点/emoji/代理对被逐 UTF-16 code unit 拆开**。
- **`pressKey`**（line 187-222）：`KeyPressParser.parse(specification)`（`KeyMapping.swift`）→ modifiers 先 down 再主键 down/up 最后 modifiers 反序 up。modifier 键也走 `postToPid`。
- `KeyMapping.swift:61-164` 的 keyCodeMap 覆盖 a-z/0-9/方向键/F1-F12/KP_* 小键盘/PageUp/Prior 等全部 xdotool alias，映射到 Carbon `kVK_*` virtual key。

### AX 语义优先 click 链路（ComputerUseService.click）

`ComputerUseService.swift:371-483` 的 element_index 模式 click：

1. `currentSnapshot(for: app)` 复用进程内 snapshot 或重建
2. `lookupElement(snapshot, index)` 按 element_index 取 ElementRecord
3. `globalClickPoint` 算 target point
4. `moveVisualCursor(to:)`（可选可视化光标，需 `OPEN_COMPUTER_USE_VISUAL_CURSOR`）
5. `performAXClickSequence`（`ComputerUseService.swift:707+`）：依次试 `AXSelectedChildren` 选择 → `AXPress`/`AXConfirm`/`AXOpen` 语义动作 → 子孙 AX 元素候选 → `AXUIElementCopyElementAtPosition` 坐标 hit-test → 最后才 `postToPid` 物理鼠标（`performNonAXClickFallback`）
6. 成功后 `pulseVisualCursor` + `refreshSnapshot` 返回新 state

**set_value**（`ComputerUseService.swift:609-650`）：必须先 `AXUIElementIsAttributeSettable(kAXValueAttribute)` 通过，否则报 `Cannot set a value for an element that is not settable`（不退到键盘/剪贴板）。settable 时 `AXUIElementSetAttributeValue(element, kAXValueAttribute, value)`。

**perform_secondary_action**（`ComputerUseService.swift:485-512`）：`AXUIElementPerformAction(element, rawAction)`，无效 action 返回 `... is not a valid secondary action for ...`。

### 权限要求（macOS）

`Permissions.swift:6-65` 明确两类权限：

| 权限 | TCC service | 检查 API | 用途 |
|---|---|---|---|
| Accessibility | `kTCCServiceAccessibility` | `AXIsProcessTrusted()` / `AXIsProcessTrustedWithOptions(["AXTrustedCheckOptionPrompt": true])` | AX tree 读取 + AXUIElementPerformAction + CGEvent postToPid（后台键鼠） |
| Screen Recording | `kTCCServiceScreenCapture` | `CGPreflightScreenCaptureAccess()` | ScreenCaptureKit 截图 |

**TCC.db 直读**（`Permissions.swift:486-547`）：`sqlite3_open_v2("/Library/Application Support/com.apple.TCC/TCC.db", SQLITE_OPEN_READONLY)` 查 `SELECT auth_value FROM access WHERE service=? AND client=? AND client_type=?`，`auth_value==2` 视为 granted。合并 TCC 持久授权 + runtime preflight（`Permissions.swift:67-86`），避免 CLI 子进程与 GUI app 对授权状态看到不一致。
- client 类型：type 0 = bundleIdentifier（`com.ifuryst.opencomputeruse`），type 1 = bundle path
- `PermissionSupport.permissionClients` 同时注册 canonical bundle id、main bundle id、primary bundle URL path、running bundle URL path，多重匹配

**不需要 Input Monitoring**——因为用 `postToPid` 而非全局 event tap，不走 `kTCCServiceListenEvent`。这是 `postToPid` 相对 HID event tap 的关键优势之一。

### CLI → App Agent Proxy（权限身份隔离）

`apps/OpenComputerUse/Sources/OpenComputerUse/MacOSAppAgentProxy.swift`：

- macOS 上 `mcp`/`doctor`/`call`/`snapshot`/`list-apps` 从终端执行时，CLI 先通过 LaunchServices 启动同一个 `.app` bundle 的**隐藏 app agent**（`LSUIElement` agent-style，无 Dock 图标），通过用户临时目录下的 **Unix domain socket** 转发请求（`MacOSAppAgentProxy.swift:68-105`）。
- 真正调 AX/ScreenCaptureKit/动作 tools 的进程始终是 `Open Computer Use.app`，不是 iTerm/Terminal/Node launcher——这样 TCC 权限授予给 `.app`，CLI 子进程无须各自重新授权。
- `.app` 以 `LSUIElement` agent-style 运行，默认不在 Dock 暴露常驻图标。
- Dev bundle 命名为 `Open Computer Use (Dev).app`，bundle id `com.ifuryst.opencomputeruse.dev`，避免与 release 同名冲突。

## 截图机制

位置：`AccessibilitySnapshot.swift:415-486`（captureImage + boundedScreenshotPNGData）。

- **API**：`ScreenCaptureKit` 的 `SCShareableContent.current` → 找 `windowID` → `SCContentFilter(desktopIndependentWindow: window)` → `SCScreenshotManager.captureImage(contentFilter:configuration:)`（line 453-471）。
- **窗口定位**：`CGWindowListCopyWindowInfo([.optionOnScreenOnly], kCGNullWindowID)` 按 ownerPID 过滤，`preferredWindowCaptureCandidate`（line 498-528）按 `layer==0 && area>=20000` 过滤、按 frontToBackIndex 排序、titleHint 命中优先。
- **Retina 2x 处理**（line 460-467）：`SCStreamConfiguration().width = max(1, Int(ceil(captureSize.width * scaleFactor)))`，`scaleFactor = NSScreen.screens.first(where: { $0.frame.intersects(bounds) })?.backingScaleFactor ?? NSScreen.main?.backingScaleFactor ?? 1`。即**按窗口所在屏幕的 `backingScaleFactor` 放大像素**（Retina 上 2x），`scalesToFit = false`、`ignoreShadowsSingleWindow = true`、`showsCursor = false`。
- **超时**：`BlockingAsyncBridge.run(timeout: 5)`（line 454，`screenshotCaptureTimeout = 5`），超时省略 image block 而不是卡住整个 get_app_state。
- **尺寸/字节限制**（`AccessibilitySnapshot.swift:87-89` + `boundedScreenshotPNGData` line 530-565）：
  - `screenshotResultMaxPNGBytes = 900_000`（900KB）
  - `screenshotResultMaxDimension: CGFloat = 1280`
  - `screenshotResultMinScale: CGFloat = 0.25`
  - 算法：原图 PNG ≤ 900KB 直接返回；否则 `scale = min(1, 1280/largestDimension)`，逐步 `scale *= 0.85` 缩放直到 ≤ 900KB 或 scale < 0.25，用 `CGContext` + `interpolationQuality = .medium` resize。**避免大 PNG 触发 MCP host 侧 result 降级**。
- **返回格式**：base64 PNG，作为 MCP `image` content block 返回（不落盘）。
- **坐标映射回传**：coordinate tools 按实际返回的 screenshot pixel 尺寸映射坐标（见下节）。

## 坐标 grounding

LLM **只能用两种方式指定位置**：`element_index`（AX tree 序号）或 `x/y`（截图像素绝对坐标）。**无 set-of-mark、无归一化、无 grounding 模型**。

### 截图像素 → window point → global point 链路

`ComputerUseService.swift:123-157`：

```
screenshotPixelScale = screenshotPixelSize / windowBounds   // width & height 分开
screenshotPixelToWindowPoint(point) = point / scale          // 像素 → point
windowPointToGlobalPoint = windowPoint + windowBounds.origin // window-local → screen-global
```

- 关键点：`windowBounds` 来自 `CGWindowListCopyWindowInfo`（**point 坐标系**，y-down），`screenshotPixelSize` 来自实际截图像素（**Retina 上 2x**）。`screenshotPixelScale` 算出 ≈2.0，把 LLM 给的像素坐标除以 2 回到 point——**避免把 2x 像素误当 1x point 导致点击落到错误位置**。
- drag/click(x,y) 的截图像素坐标先经 `screenshotPixelToWindowPointInSnapshot`（line 436）转 window point，再 `windowPointToGlobalPoint` 转 Quartz global 坐标，喂给 `CGEvent`。

### screen-space y-down ↔ AppKit y-up 转换（overlay 用）

`ComputerUseService.swift:16-61`：

```
screenStatePointToAppKitGlobalPoint(point):
  localY = point.y - mapping.screenStateFrame.minY
  return (appKitFrame.minX + localX, appKitFrame.maxY - localY)  // y 翻转
```
仅 `SoftwareCursorOverlay`（可视化光标）需要这层转换（AppKit 全局坐标是 y-up）；`CGEvent` 输入点直接用 y-down screen-space（`inputEventPoint` line 56-61 直接返回 point 不转换）。

### element frame 坐标系

`AccessibilitySnapshot.swift` 的 `localFrame` = 元素相对窗口左上角的 **window-relative point**（架构文档："element frame 当前按'窗口左上角为原点'的 window-relative 坐标输出，便于后续把 element_index 和截图坐标统一到同一套参考系"）。

### 元素定位回退链（find_element）

Linux `runtime.py:519-539` 的 find_element 是跨平台参考实现：
1. 按 `runtimeId`（child index path）优先解析
2. fallback 按 `automationId` 精确匹配
3. fallback 按 name + role 匹配
4. fallback 按 role + frame 近似匹配（容差 3px）

## agent loop + codex 集成

**agent loop 在外部 agent 侧（Codex/Claude/Gemini）**，本服务不驱动 loop，只响应 tool call。架构上 agent loop = 截图（get_app_state）→ LLM 推理 → 动作（click/type/...）→ 新 get_app_state 返回 → 重复。

### MCP server instructions（喂给 LLM 的 prompt）

完整文本，`MCPServer.swift:3-18`（一字未改）：

```
Computer Use tools let you interact with macOS apps by performing UI actions.

Some apps might have a separate dedicated plugin or skill. You may want to use that plugin or skill instead of Computer Use when it seems like a good fit for the task. While the separate plugin or skill may not expose every feature in the app, if the plugin can perform the task with its available features, prefer it. If the needed capability is not exposed there, use Computer Use may be appropriate for the missing interaction.

Begin by calling `get_app_state` every turn you want to use Computer Use to get the latest state before acting. Codex will automatically stop the session after each assistant turn, so this step is required before interacting with apps in a new assistant turn.

The available tools are list_apps, get_app_state, click, perform_secondary_action, scroll, drag, type_text, press_key, and set_value. If any of these are not available in your environment, use tool_search to surface one before calling any Computer Use action tools.

Computer Use tools allow you to use the user's apps in the background, so while you're using an app, the user can continue to use other apps on their computer. Avoid doing anything that would disrupt the user's active session, such as overwriting the contents of their clipboard, unless they asked you to!

After each action, use the action result or fetch the latest state to verify the UI changed as expected.
Prefer element-targeted interactions over coordinate clicks when an index for the targeted element is available. Note that element indices are the sequential integers from the app state's accessibility tree.
Avoid falling back to AppleScript during a computer use session. Prefer Computer Use tools as much as possible to complete tasks.
Ask the user before taking destructive or externally visible actions such as sending, deleting, or purchasing. If helpful, you can ask follow-up questions before taking action to make sure you're understanding the user's request correctly.
```

- 每个 turn 必先 `get_app_state`
- element_index 优先于坐标 click

- 破坏性动作要问用户

### 终止条件 / 错误恢复

- **无内置终止**：循环由外部 agent 控制。
- **turn-ended hook**：`notifications/turn-ended`（MCP）或 CLI `turn-ended [payload]`（distributed notification）→ 清理 `SoftwareCursorOverlay.Reset()`（`MCPServer.swift:69-73`）。对应官方 `~/.codex/config.toml` 的 `notify = [.../SkyComputerUseClient, "turn-ended"]`。
- **错误恢复**：tool result 带 `isError: true`，外部 agent 决策重试或换路径。`ComputerUseToolDispatcher.callToolAsResult`（`ComputerUseToolDispatcher.swift:110-122`）把 `ComputerUseError` 转成 `isError` 文本返回，不中断 MCP session。
- **状态进程内**：snapshot cache + element index 映射在进程内内存态（`ComputerUseService.swift:653-660`），`--calls`/`--calls-file` 序列执行复用同一 service 实例（`ComputerUseToolDispatcher.swift:287-310`），相邻成功操作间默认 sleep 1s（可 `--sleep` 覆盖），遇 `isError=true` 停止。

## artifacts/tool-comparisons 提炼

- 调用前后 `mouse_location`（是否移动用户鼠标）

**核心结论**：
- 官方 `get_app_state`：before frontmost=iTerm2 → after frontmost=iTerm2（**不抢前台**）
- 开源版 `get_app_state`：同上，**不抢前台**（修复后对齐）
- 开源版坐标 `click x=850 y=18`：before frontmost=iTerm2 → after frontmost=iTerm2（**坐标点击也不抢前台**）
- 鼠标坐标会变，但作为辅助观测（用户实时移动干扰），**"是否切走前台 app" 是更稳定信号**

**已知限制**：官方不能识别仓库内裸 fixture，所以对比改用双方都能解析的系统 app。

**开源版对比自述**（`artifacts/.../open-codex-computer-use/get_app_state-activity-monitor.json`）：
> 对比结果显示 get_app_state 不再为了读状态而切走前台 iTerm2。

这个对比的核心验证点 = **后台操作不抢前台**，即 `postToPid` + AX 语义动作的非侵入性。

## 对本项目的可借鉴点

### 1. tool surface：9-tool 聚合 vs 单 computer 工具

open-codex 用**官方同款 9 个独立 tool**（聚合 `get_app_state` + 7 个动作 + `list_apps`）。优势：prompt 简单（每个 tool 职责单一）、schema 严格（additionalProperties:false）、element_index 优先。本项目可考虑对齐这组 schema 作为兼容层，再在内部实现 OS 抽象。

### 2. macOS 后台输入：CGEvent.postToPid 是关键

`InputSimulation.swift` 的 `clickTargeted`/`dragTargeted`/`scrollTargeted`/`typeText`/`pressKey` 全部走 `CGEvent.postToPid(pid)` 而非 `.cghidEventTap`：
- **不抢前台**（前台 app 不变，artifacts 实证）
- **不移动用户鼠标**
- **不需要 Input Monitoring 权限**（仅需 Accessibility）
- 缺点：部分应用（游戏、某些自绘控件）不响应 postToPid，需 fallback 到全局 HID（默认关闭）

本项目实现 macOS computer use 应默认 postToPid，提供 `ALLOW_GLOBAL_POINTER_FALLBACKS=1` 诊断开关。

### 3. 私有 API：CGEventSetWindowLocation（后台点击增强）

`docs/references/codex-computer-use-reverse-engineering/background-click-free-tooling.md:126-142` 官方逆向出的后台点击路径：
1. `CGWindowListCopyWindowInfo` 拿 layer 0 window + CGWindowID + bounds
2. `NSEvent.mouseEvent(...)` 创建事件，`windowNumber` 传 CGWindowID
3. 从 `NSEvent.cgEvent` 取 CGEvent
4. 设置 field 3（buttonNumber）、field 91（window under pointer）、field 92（event target window）
5. 设置 `CGEvent.location`（screen-space）
6. screen point → window-local point
7. **`CGEventSetWindowLocation(event, localPoint)`**（私有符号，`dlsym(RTLD_DEFAULT, "CGEventSetWindowLocation")` 解析）
8. `CGEvent.postToPid(pid)`

私有 API，生产慎用，但研究对照很有价值。open-codex 当前主线**不依赖**此私有符号（用 AX 语义动作 + postToPid 已够），但保留了作为诊断方向。

### 4. 截图 + Retina 坐标缩放（必抄）

`AccessibilitySnapshot.swift:123-157` 的三段式坐标转换是 Retina 场景的标准答案：
```
scale = screenshotPixelSize / windowBounds   // Retina ≈ 2.0
windowPoint = screenshotPixel / scale
globalPoint = windowPoint + windowBounds.origin
```
必须按**窗口所在屏幕的 backingScaleFactor** 放大截图像素（多显示器混合 DPI 场景），用 `scalesToFit=false` + 显式 `width/height = ceil(size * scaleFactor)` 控制。

### 5. 权限模型：TCC.db 直读 + runtime preflight 合并

`Permissions.swift:67-86` 的合并策略避免 CLI 子进程 vs GUI app 看到不一致：
```
granted = (TCC.db auth_value == 2) || AXIsProcessTrusted() || CGPreflightScreenCaptureAccess()
```
本项目若做 macOS 权限引导应参考。

### 6. CLI → app agent Unix socket proxy（权限身份统一）

`MacOSAppAgentProxy.swift`：TCC 权限授予给 `.app` bundle，CLI 子进程通过 Unix domain socket 转发请求让 `.app` 执行实际操作，避免每个 launcher（iTerm/Node/Python）各自授权。本项目若做 CLI + GUI 混合可参考。

### 7. AX tree 渲染（喂 LLM 的文本格式）

`AccessibilitySnapshot.swift:110-132` 的 `renderedText` 输出格式：
```
App=<bundleId> (pid <pid>)
Window: "<title>", App: <name>.
    0 standard window <title>, Secondary Actions: Raise
        1 scroll area Secondary Actions: Scroll Up, Scroll Down
            2 outline <name>
                3 row (selectable) <value>
...
The focused UI element is 2 outline.
```
- 行首 = element_index（LLM 引用）
- 缩进 = depth
- `(...)` 内是 traits（selectable/settable/disabled/...）
- `Value:` / `Secondary Actions:` / `Description:` / `Help:` / `ID:` 是关键字段
- 文本默认截断 500 字符
- 默认 tree budget 1200 节点 / 64 层

这个文本格式 + 截图双通道（text + image content block）是官方对齐的，喂 LLM 效果稳定。

### 8. type_text Unicode chunking（中文/emoji 安全）

`InputSimulation.swift:142-185` 的 `keyboardUnicodeChunks` 按 extended grapheme cluster 聚合（≤64 UTF-16 units/chunk），避免中文标点、emoji、代理对、组合字符被逐 UTF-16 code unit 拆开在 Electron 富文本框里乱序。本项目必抄。

### 9. 元素定位回退链

`runtime.py:519-539` 的四级 fallback（runtimeId → automationId → name+role → role+frame）是跨平台稳健定位的标准做法，frame 容差 3px。

### 10. 官方闭源实现的 4 层宿主绑定（不抄）

开源版刻意去掉了 parent launch constraint / sender authorization / codex-ipc appserver / session 审批这 4 层。本项目作为自研 harness，也不应绑定单一宿主。
