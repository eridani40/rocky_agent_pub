## action 集合 + 参数（关键发现：独立工具 + 自然语言 query，非坐标）

采用 **多个独立工具**（不是 Anthropic computer-use 那种「单 computer 工具 + action 枚举参数」）。工具通过 `@tool(description, params)` 装饰器注册到全局 `tools` dict（`sandbox_agent.py:54-59`）。

| action | 参数 | 说明 / 底层调用 | 代码位置 |
|---|---|---|---|
| `stop` | 无 | 信号：任务完成，agent loop 退出 | `sandbox_agent.py:16-20, 204` |
| `run_command` | `command: str` | 同步 shell，`sandbox.commands.run(command, timeout=5)`，返回 stdout+stderr | `sandbox_agent.py:84-92` |
| `run_background_command` | `command: str` | 异步 shell，`sandbox.commands.run(command, background=True)` | `sandbox_agent.py:98-100` |
| `send_key` | `name: str`（如 `'Return'`、`'Ctl-C'`） | `sandbox.press(name)`，按键/组合键 | `sandbox_agent.py:106-108` |
| `type_text` | `text: str` | `sandbox.write(text, chunk_size=50, delay_in_ms=12)`，分组逐块输入 | `sandbox_agent.py:114-116` |
| `click` | `query: str`（**自然语言**，如 `"search box"`） | grounding 模型把 query→(x,y)，`sandbox.move_mouse(x,y)` + `sandbox.left_click()` | `sandbox_agent.py:135-136` |
| `double_click` | `query: str` | 同上，`sandbox.double_click()` | `sandbox_agent.py:142-143` |
| `right_click` | `query: str` | 同上，`sandbox.right_click()` | `sandbox_agent.py:149-150` |

**缺失（相对常见 computer-use 需求清单）**：`scroll`、`drag`、`mouse_move`（单独）、`hold`、`wait`、`triple_click`、显式 `screenshot`（截图在 loop 内自动触发，不暴露为工具）。

**最关键设计差异**：`click` 系列的参数是**自然语言 query 字符串**，**不是坐标**。LLM 输出「点击搜索框」，由独立的 grounding 模型把 query 翻译成像素坐标。坐标系是**绝对像素**（sandbox 内部 1024×768），但 LLM 永远不接触坐标——这是它和 Anthropic computer-use（LLM 直接给 `[x,y]`）最大的分歧。

## OS 抽象层

**抽象边界 = `e2b_desktop.SandboxBase`**（第三方库 `e2b-desktop ^1.7.2`，`pyproject.toml:15`）。项目里 `streaming.py:8` 的 `class Sandbox(SandboxBase)` 只扩展了 ffmpeg 流，OS 操作全部继承自 `SandboxBase`。

抽象的 OS 操作（从调用点反推 SandboxBase API）：
```
sandbox.screenshot()         → bytes (PNG)
sandbox.move_mouse(x, y)     → 绝对像素坐标
sandbox.left_click() / double_click() / right_click()
sandbox.write(text, chunk_size, delay_in_ms)
sandbox.press(key_name)
sandbox.commands.run(cmd, timeout=, background=)
sandbox.set_timeout(seconds)   # 保活沙箱
sandbox.stream.start() / get_url()  # noVNC 流
sandbox._display               # X11 display 字符串（如 ":0"）
sandbox.kill()
```

**运行模型（务必区分）**：
- 沙箱 = 一台**云端 Linux VM**（Ubuntu），由 E2B 提供，内置 X11 桌面 + ffmpeg
- agent Python 进程跑在**本地**，通过 e2b SDK 经网络调用远端 VM 的鼠标/键盘/截图/shell
- 本地另开一个 pywebview 窗口（`browser.py`）打开 noVNC URL 实时显示远端桌面（`main.py:39-43`）
- `main.py:28-33` 的 DisplayClient（ffmpeg 录屏）已被注释掉，当前走 noVNC

**不是本地 OS 抽象**——它不感知宿主 OS，所有操作都发给云端 Linux VM。README 自称「designed to work with any operating system」指**沙箱内 OS**可换，但实际只跑 Ubuntu。

## macOS 实现情况

**N/A，完全不支持 macOS。**

- E2B Desktop Sandbox 是 **Linux-only** 云 VM（Ubuntu）
- 项目零 macOS 代码、零跨平台分支
- 项目自身运行平台（Python+poetry+ffmpeg+pywebview）理论上 macOS 可装，但那只是「客户端」——被控制的始终是远端 Linux

**底层机制对 macOS 的参考价值（有限）**：
- `sandbox.press(name)` / `write(text, chunk, delay)` / `move_mouse+click` 的**语义**可复用（按键名、分组输入、绝对坐标点击），但 e2b-desktop 内部用的是 X11 + 一个远端 GUI 自动化 agent，**macOS 需替换为 Quartz CGEvent / pyobjc**
- ffmpeg x11grab 是 X11 专属，macOS 截屏需 `CGWindowListCreateImage` 或 `screencapture`
- 「分组输入 + 延迟」(chunk_size=50, delay=12ms) 这个**人类化输入模式**值得借鉴

## 截图机制

- 入口：`sandbox_agent.py:72-78 screenshot()` → `self.sandbox.screenshot()` 返回 PNG bytes
- 分辨率：**1024×768**（`streaming.py:12` ffmpeg `-s 1024x768`，sandbox 内部分辨率）
- 格式：PNG（`save_image` 存盘，`create_image_block` 用 PIL 探测格式后 base64）
- **无缩放处理 / 无 Retina 2x 概念**——云沙箱固定逻辑分辨率，LLM 看到的就是 1024×768 原图
- **无尺寸压缩 / 无 max tokens 限制**：直接 base64 整张图发给 vision_model（`llm_provider.py:122-136`）
- 频率：**每个 agent loop 迭代一次**，通过 `append_screenshot()` 强制截图+发 vision_model（`sandbox_agent.py:152-169`）
- 持久化：每张截图存 `tempfile.mkdtemp()` 下 `screenshot_N.png`，并递增计数

## 坐标 grounding（本项目的核心创新，重点）

**三模型架构**（`config.py`）：
1. `vision_model`（qwen-2.5-vl / gpt-4o / claude / pixtral 等）：screenshot → 文本描述
2. `action_model`（llama-3.3 / gpt-4o / claude 等）：文本 → tool_call 决策
3. `grounding_model`（**OS-Atlas 或 ShowUI**）：自然语言 query + screenshot → (x,y) 像素坐标

**grounding 的作用 = 把「点击登录按钮」这种语义 query 翻译成像素坐标**，让 LLM 完全不碰空间坐标。流程（`sandbox_agent.py:118-129 click_element`）：
```
screenshot()                              # 拿当前屏
grounding_model.call(query, screenshot)   # query="登录按钮" → (x,y)
draw_big_dot(img, (x,y))                  # 在截图上画红点存档（调试用）
sandbox.move_mouse(x, y)
sandbox.<click_action>()                  # left/double/right
```

**两套 grounding 实现**：

**OS-Atlas**（`osatlas_provider.py`，默认启用）：
- HuggingFace Space：`maxiw/OS-ATLAS`，模型 `OS-Copilot/OS-Atlas-Base-7B`，API `/run_example`
- 输入：image + `query + "\nReturn the response in the form of a bbox"`
- 输出：bbox 字符串如 `<|box_start|>[x1,y1,x2,y2]<|box_end|>`
- 解析（`grounding.py:13-22 extract_bbox_midpoint`）：正则提取数字，4个数→取中点 `(x1+x3)//2, (y1+y2)//2`，2个数→直接当点
- 需 `HF_TOKEN` 绕过 Gradio 限流

**ShowUI**（`showui_provider.py`，备选）：
- HF Space：`showlab/ShowUI`，API `/on_submit`，参数 `iterations=1`
- 输出：归一化 `[0,1]` 点，再 `x*image.width, y*image.height` 还原像素（`showui_provider.py:25-27`）

**关键洞察**：grounding 模型是**视觉定位专家**，解耦了「点哪个东西」（语义）和「东西在哪」（空间）。优点：LLM 不需学会读坐标、对 UI 变化鲁棒；缺点：每次 click 多一次 HF Space 网络往返、依赖外部模型可用性、query 描述不准时 grounding 会错。

**未使用 set-of-mark 预标注**、**未使用 accessibility tree**——纯视觉 grounding。

## agent loop

入口 `sandbox_agent.py:171 run(instruction)`：

```
messages.append("OBJECTIVE: " + instruction)
while should_continue:
    sandbox.set_timeout(60)                          # 防 E2B 超时回收
    thought = append_screenshot()                    # ① 截图 → vision_model → 文本描述
    content, tool_calls = action_model.call(         # ② 带 tools 调 action_model
        [system("You are an AI assistant with computer use abilities."),
         *messages,
         Message(thought),
         Message("I will now use tool calls...")],
        tools)
    messages.append(Message(content))                # 记录 THOUGHT
    for tool_call in tool_calls:
        if tool_call.name == "stop":
            should_continue = False; break
        messages.append(json.dumps(tool_call))       # 记录 ACTION
        result = call_function(name, params)         # ③ 执行（含 grounding）
        messages.append(Message("OBSERVATION: " + result))
```

**完整 vision prompt**（`sandbox_agent.py:159-165`，不可省略）：
```
This image shows the current display of the computer. Please respond in the following format:
The objective is: [put the objective here]
On the screen, I see: [an extensive list of everything that might be relevant to the objective including windows, icons, menus, apps, and UI elements]
This means the objective is: [complete|not complete]

(Only continue if the objective is not complete.)
The next step is to [click|type|run the shell command] [put the next single step here] in order to [put what you expect to happen here].
```

**system prompt**（极简，`sandbox_agent.py:184`）：
```
You are an AI assistant with computer use abilities.
```

**终止条件**：LLM 调 `stop` 工具（`sandbox_agent.py:204-205`）
**错误恢复**：`call_function` 内部 try/except 把异常字符串当 result 喂回 LLM（`sandbox_agent.py:46-50`）；`main.py:59-61` 外层 per-instruction try/except
**状态管理**：`self.messages` 线性累积所有 objective/thought/action/observation（无压缩、无 summary，长任务会膨胀）
**手动介入**：`main.py:45-58` 每轮后回到 `input("USER: ")`，用户可随时插入新指令（Ctrl-C 回到提示符不退出）

## 对本项目的可借鉴点 / 不适用点

### 可借鉴

1. **grounding 解耦架构**（最值得借鉴）：让 LLM 输出「点哪个东西」（语义 query），由专门的视觉 grounding 模型（OS-Atlas/ShowUI）翻译成坐标。LLM 不碰坐标 → 更鲁棒、prompt 更干净。本项目 macOS 场景若用 Anthropic computer-use 走坐标路线，可考虑增加 grounding 层做坐标校准/兜底。
2. **三模型分工**（vision / action / grounding）通过 `config.py` 可插拔切换——良好的 provider 抽象（`providers.py` 继承 LLMProvider，统一 `call(messages, tools)` 接口）。
3. **人类化输入**：`type_text` 的 `chunk_size=50, delay_in_ms=12` 分组逐块输入，对真实 UI（防抖、IME）更友好。
4. **每个 loop 强制 `set_timeout(60)` 保活沙箱**——长任务防回收的工程细节。
5. **结构化 vision prompt**（objective / I see / complete? / next step）——引导 vision 模型自检任务完成度，减少 hallucinate 继续。
6. **`@tool` 装饰器 + `tools` 全局 dict** 的工具注册模式，极简（10 行）但够用。

### 不适用（云沙箱模型 vs 本地 macOS）

1. **整个 E2B 云沙箱运行模型不适用**——我们要的是本地 macOS 直接控制，不是远端 VM。`SandboxBase` 抽象层的 X11 + 远端 GUI agent 在 macOS 上要整体替换为 Quartz CGEvent（pyobjc）+ CGWindowList 截屏。
2. **ffmpeg x11grab 截屏流不适用**——macOS 没 X11；noVNC 通道对本地控制也无意义（本地直接操作，无需串流）。
3. **坐标系语义可借、实现要换**：`move_mouse(x,y)` 的「绝对像素」语义在 macOS 上要注意 Retina 2x（逻辑 vs 物理像素、DPI 缩放），这是 open-computer-use 完全没处理的（沙箱固定 1024×768）。
4. **自然语言 query click 的局限**：对 macOS 原生 app，accessibility tree (AXUIElement) 比纯视觉 grounding 更精确、更快、无网络往返。可考虑 ax-tree 优先 + 视觉 grounding 兜底的混合策略，而不是 open-computer-use 的「纯视觉 grounding」。
5. **缺 scroll/drag/wait** 是它的硬缺口，本项目需求清单里这些都要补——不能照抄它的 action 集合。

## 最关键发现摘要（3-5 条）

1. **运行模型是云沙箱（E2B Linux VM），不是本地 OS 控制**——macOS 完全 N/A。整套 OS 抽象（X11 + 远端 GUI agent + ffmpeg x11grab）在 macOS 上需整体替换为 Quartz CGEvent + CGWindowList，借鉴价值仅限语义层。

2. **action 集合采用「多个独立工具」而非「单 computer 工具 + action 参数」**，且 `click` 参数是**自然语言 query** 不是坐标——LLM 输出「点搜索框」，由独立 grounding 模型翻译成像素。action 清单仅 7 个（stop/run_command/run_background_command/send_key/type_text/click/double_click/right_click），**缺 scroll/drag/mouse_move/wait/triple_click/hold**，本项目需自补。

3. **三模型架构是核心创新**（vision 描述屏幕 / action 决策 / grounding 定位坐标），三者可插拔（`config.py`）；grounding 用 OS-Atlas 或 ShowUI（皆走 HuggingFace Space），把「语义 query + 截图 → 像素坐标」解耦。这是它和 Anthropic computer-use（LLM 直接给坐标）最大的路线分歧。

4. **截图无 Retina/缩放处理**——云沙箱固定 1024×768 逻辑分辨率，直接 base64 整张发 LLM，无压缩无 token 预算管控。macOS 场景必须处理 Retina 2x（逻辑 vs 物理像素）。

5. **agent loop 极简**：每轮强制截图→vision_model 描述→action_model 出 tool_call→执行→observation 回填，靠 LLM 主动调 `stop` 终止；错误以字符串喂回 LLM 自愈；无上下文压缩（长任务 messages 线性膨胀）。vision prompt 用「objective/I see/complete?/next step」结构化模板引导自检——值得借鉴。
