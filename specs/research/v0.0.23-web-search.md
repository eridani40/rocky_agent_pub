# v0.0.23 Web Search 工具竞品调研

> 范围：web_search 工具的「协议契约 + exclusive extension point 落位」，不绑死具体搜索后端。
> 竞品：openclaw（TS，最相关）/ hermes-agent（Python）/ claude-code（TS）。
> 本仓库对齐：`specs/tech/agent/tools/[P0]overall.md`（Tool 体系）、`specs/tech/plugin_system/[P0]extension_point_interface.md`（EP cardinality）、`app/server/src/plugin/extension-point.ts`（BUILTIN_EXTENSION_POINTS）。

## 1. 策略枚举：搜索后端的可插拔抽象有三种形态

| 策略 | 代表竞品 | 抽象位置 | 注册/选择机制 |
|---|---|---|---|
| **A. Provider 契约 + manifest contract 声明（可插拔）** | openclaw | plugin-sdk 契约 `WebSearchProviderPlugin` + manifest `contracts.webSearchProviders: ["tavily"]` | 插件 manifest 声明贡献 → registry 收集 → 配置 `tools.web.search.provider` 选一个 + 凭证可用性 fallback |
| **B. Provider ABC + 中央 registry（可插拔）** | hermes-agent | `agent/web_search_provider.py` 的 `WebSearchProvider` ABC + `agent/web_search_registry.py` 中央表 | 插件 `register(ctx)` 时 `ctx.register_web_search_provider(impl)` → config `web.backend` / `web.search_backend` 选 + availability 自动选 |
| **C. 内置硬编码 + 委派给 LLM provider 原生工具（不可插拔）** | claude-code | `WebSearchTool.ts` 把请求转成 Anthropic 原生 `web_search_20250305` server tool | 不抽象后端，绑死 Anthropic firstParty / vertex / foundry（`refs/claude-code/src/tools/WebSearchTool/WebSearchTool.ts:168-193`） |

**结论**：A 和 B 都把「搜索后端」抽象成可插拔 provider，区别仅在「声明形态」（manifest contract vs 代码 register）。C 不抽象——它是 LLM provider 自带的原生工具代理，与我们的「独立 web_search 工具 + 可插拔后端」目标不同。

### 2.6 provider 选择逻辑（exclusive 语义的实战）

`refs/openclaw/src/web-search/runtime.ts:449-512` `runWebSearch`：
1. 配置 `tools.web.search.provider` 显式指定 → 用之（不 fallback）；
2. 无显式 → 按 `autoDetectOrder` + 凭证可用性选第一个有凭证者（`refs/openclaw/runtime.ts:166-205` `resolveWebSearchProviderId`）；
3. 允许 fallback 时按候选顺序逐个尝试，遇到 `missing_*_api_key` 结构化错误继续下一个（`runtime.ts:474-506`）；
4. 显式选中 → 不 fallback，直接抛错（`runtime.ts:465-470`）。

**这正是 exclusive EP（≤1 生效）+ 显式选择 + 凭证驱动 fallback 的工业级实现。**

## 3. hermes-agent 协议契约（Python ABC 版）

### 3.1 契约 `WebSearchProvider` ABC

`refs/hermes-agent/agent/web_search_provider.py`（docstring + ABC）：

```python
class WebSearchProvider(abc.ABC):
    @property
    @abc.abstractmethod
    def name(self) -> str: ...           # "tavily" / "ddgs" / "brave-free" ...
    @property
    def display_name(self) -> str: ...   # 默认 = name
    @abc.abstractmethod
    def is_available(self) -> bool: ...  # 不许做网络 I/O（注册期/每次 paint 都跑）
    def supports_search(self) -> bool: return True
    def supports_extract(self) -> bool: return False
    def search(self, query: str, limit: int = 5) -> Dict[str, Any]: raise NotImplementedError
    def extract(self, urls: List[str], **kwargs) -> Any: raise NotImplementedError
```

**Search 响应 shape（契约固化，ABC docstring 明文约束）**：
```python
{ "success": True, "data": { "web": [
    {"title": str, "url": str, "description": str, "position": int}, ... ] } }
# 失败：{"success": False, "error": str}
```

## 4. claude-code（不可插拔，作为对照）

`refs/claude-code/src/tools/WebSearchTool/WebSearchTool.ts`：
- **入参 schema** `:25-37`：`query: string(min 2)` + `allowed_domains?: string[]` + `blocked_domains?: string[]`（互斥）。
- **输出 schema** `:42-67`：`{ query, results: (SearchResult | string)[], durationSeconds }`，其中 `SearchResult = { tool_use_id, content: {title, url}[] }`。
- **不抽象后端**：`call()` `:254-400` 把请求转成 Anthropic 原生 `web_search_20250305` server tool（`:76-84` `makeToolSchema`），通过 `queryModelWithStreaming` 让 LLM provider 自己搜，硬编码 `max_uses: 8`。
- `isEnabled()` `:168-193` 按 API provider（firstParty/vertex/foundry）+ 模型名（claude-4）开关。

**对照结论**：claude-code 的 web_search 是「原生 server tool 代理」，不是我们想要的「独立可插拔后端」。但其 **入参契约**（query + allowed/blocked_domains + 长度校验）值得借鉴。

## 5. 竞品对比

| 维度 | openclaw | hermes | claude-code |
|---|---|---|---|
| 抽象 provider | ✅ `WebSearchProviderPlugin` | ✅ `WebSearchProvider` ABC | ❌ 硬绑 Anthropic |
| 注册方式 | manifest contract `webSearchProviders` | plugin `register(ctx)` 注册 | 无 |
| 选择方式 | config + autoDetectOrder + 凭证 fallback | config + availability 自动 | LLM provider 决定 |
| 入参最小集 | query + count | query + limit | query + allowed/blocked_domains |
| SearchResult | title/url/snippet/score?/published? | title/url/description/position | title/url |
| AI answer | 可选 `answer` 字段（tavily/xai） | 无（search 只返回列表） | 文本 + 链接混合 |
| 取消/超时 | `execute` context `signal: AbortSignal` | timeout 在 client 内（tavily `resolveTavilySearchTimeoutSeconds`） | abortController |
| 结果上限 | provider 自定（tavily 20，xai 10） | 100，tool 层 100k chars | max_uses: 8 次搜索 |
| 缓存 | tavily client 内 Map 缓存 + TTL | 无 | 无 |
| 安全包装 | `wrapWebContent` 包裹 untrusted content | `wrapExternalContent` + SSRF 校验 | 无 |

**共性**：(1) 都有「query 必填 + count/limit 数量」；(2) 都把 title/url/snippet 作为结果最小集；(3) 都在工具层做结果大小截断（openclaw/hermes 都 100k chars）；(4) 都允许 provider 自带 timeout。

**差异优劣**：
- openclaw 的 manifest contract 声明最干净（声明式，registry 自动收集），适合 EP 体系；
- hermes 的 ABC + 中央 registry 最直观，但 register 是命令式（依赖插件 import 副作用）；
- claude-code 不适配我们的目标（不抽象后端）。

## 6. 推荐：WebSearchProvider 协议契约（对齐我们的 Tool/EP 体系）

### 6.1 契约 interface 草案（TS）

```typescript
/** web_search 工具的执行结果（与 openclaw tavily 对齐 + 极简化） */
export interface SearchResultItem {
  title: string;
  url: string;
  snippet: string;        // 摘要（已脱敏/安全包装）
  score?: number;
  published?: string;     // ISO 日期，provider 给不出则省略
}

export interface WebSearchResult {
  provider: string;       // 哪个 provider 答的（便于观测/审计）
  query: string;
  count: number;
  tookMs: number;
  results: SearchResultItem[];
  answer?: string;        // 可选 AI 合成答案（tavily/xai 等支持）
}

/** web_search 入参（最小契约；provider-specific 字段不放协议，由 provider 在 createTool 自带 schema） */
export interface WebSearchInput {
  query: string;          // 必填
  count?: number;         // 数量上限（默认 5，上限由 provider 决定）
}

/** 取消信号 */
export interface WebSearchExecContext {
  signal?: AbortSignal;
}

/** Provider 契约：承载「搜索后端」的可插拔实现 */
export interface WebSearchProvider {
  /** provider 唯一 id（snake_case，如 "tavily" / "brave" / "ddgs"） */
  readonly id: string;
  /** 人类可读名（配置界面用） */
  readonly label: string;
  /** 是否当前可用（不许做网络 I/O；注册期/每次 inventory 都跑） */
  isAvailable(): boolean;
  /** 执行搜索（核心方法） */
  search(input: WebSearchInput, ctx?: WebSearchExecContext): Promise<WebSearchResult>;
}
```

**为何这样切**：
- `search` 返回结构化 `WebSearchResult`（不返回 `Record<string, unknown>`），便于 Tool 层格式化 + 测试断言。openclaw 的 `execute` 返回 `Record<string,unknown>` 是因为它要兼容多 provider 异构响应，我们走「协议即结构」更安全。
- 不把凭证读写/`createTool`/`runSetup` 放进契约——那些是 **plugin-level**（ExtImpl.configSchema / onboarding），不是 provider 协议职责（对齐我们 EP §3.5「契约是类型不是运行时字段」+ EP §3.8「无 point 级 config」）。openclaw 把凭证读写塞进 `WebSearchProviderPlugin` 是因为它没有独立 plugin config 体系，我们有，所以切干净。
- `isAvailable()` 必需（hermes 的 best practice：注册期判可用性，不许做 I/O）。

### 6.2 为何选 exclusive（≤1 生效）

对齐 EP §3.1：「`exclusive` = 独占 ≤1 / 注册表存唯一一个 / 显式 `setExclusive(implId)` 标记者胜」。
理由（与 openclaw/hermes 实战一致）：
1. **同一时刻只用一个搜索后端**——web_search 是 agent 显式调用的工具，一次调用一个 provider 答（openclaw `runWebSearch` 也是逐个候选跑、取第一个成功的，不是并发多 provider 融合）。
2. **凭证/计费隔离**——不同 provider 各自 API key + 计费，并发调用会让用户计费失控。
3. **结果可解释**——用户配置「用 Tavily」，agent 就该用 Tavily，不该静默换 provider（openclaw 把「显式选中不 fallback」作为强约束，见 `runtime.ts:465-470`）。
4. **EP 语义自洽**——exclusive 的配置 UI 是单选控件（EP §3.7），与「选一个搜索后端」心智一致。

> 不选 list：list 是无序并存，适合「多个都生效」（如多个 LlmProvider 并存），但 web_search 一次调用只能一个答，list 会让「哪个生效」歧义。
> 不选 ordered：ordered 是有序串联（如 prompt mapper 链），web_search 不做结果融合串联。

### 6.3 EP 落位建议

加入 `app/server/src/plugin/extension-point.ts` 的 `BUILTIN_EXTENSION_POINTS`：

```typescript
/** web_search_provider：web_search 工具的搜索后端（可插拔，同一时刻生效 ≤1） */
export const WebSearchProviderPoint: ExtensionPoint = {
  id: 'web_search_provider',
  cardinality: 'exclusive',
  group: 'web',
  description: 'web_search 工具的搜索后端 provider（可插拔，exclusive ≤1 生效；Tavily/Brave/DDGS/Google 等）',
};

// 在 BUILTIN_EXTENSION_POINTS 数组追加 WebSearchProviderPoint
```

**group 取 `web`**（新分区，未来 `web_fetch_provider` / `web_scrape_provider` 同 group）。理由：与现有 `provider`（LLM）/`context`（上下文）分区正交，web 工具自成一区。也可考虑 `tool`（如未来想统一「工具类 provider」），但 `web` 更精确（web 子系统内的 provider），推荐 `web`。

## 7. Tool 层（web_search 作为 Tool）

### 7.1 ToolDefinition（给 LLM 的声明）

```typescript
const webSearchTool: Tool = {
  definition: {
    name: 'web_search',
    description: 'Search the web for current information. Returns titles, URLs, and snippets. '
                 + 'Use for facts/news you do not already know.',
    inputSchema: {
      type: 'object',
      properties: {
        query: { type: 'string', description: 'The search query (>= 2 chars).' },
        count: { type: 'integer', description: 'Max results (default 5).', minimum: 1, maximum: 20 },
      },
      required: ['query'],
    },
  },
  async run(input, ctx) {
    const query = String(input.query ?? '').trim();
    if (query.length < 2) return errorResult('query must be >= 2 chars');
    // 从 exclusive EP 取生效的 provider
    const provider = getExclusiveExtensionImpl<WebSearchProvider>(WebSearchProviderPoint);
    if (!provider) return errorResult('web_search is disabled or no provider is available');
    if (!provider.isAvailable()) return errorResult(`web_search provider "${provider.id}" is not available (check API key)`);
    const result = await provider.search({ query, count: clampCount(input.count, 5, 20) }, { signal: ctx.signal });
    return textResult(formatResults(result));  // 格式化为 TextBlock
  },
};
```

### 7.2 Tool 与 EP 的桥（runtime 取 exclusive impl）

Tool 内部通过框架 getter 取 exclusive EP 的生效 impl（对齐 EP §3.1 getter 语义）。这是「Tool 层薄壳 + provider 协议层承载」的分层——Tool 不持有 provider 实例，每次 run 时从 registry 取（同 `defaultTools` 不持 SessionConfig 的思路）。

## 8. 共性约定（建议写进 spec）

| 项 | 建议 | 依据 |
|---|---|---|
| **超时** | provider 自带 timeout（默认 30s，可配置）；Tool 层透传 `ctx.signal` | openclav tavily `resolveTavilySearchTimeoutSeconds`；hermes tavily 同 |
| **重试** | provider 内部对 5xx / 网络瞬态重试（2 次，指数退避 1.5s 上限 5s）；Tool 层不重试（避免双倍计费） | hermes x_search `_get_x_search_retries=2` `:331-365` |
| **限流** | provider 自处理（如 ddgs 由 DDG 服务端限流，tavily 由 API 配额限）；Tool 层不做客户端限流 | hermes ddgs provider docstring |
| **结果数量上限** | 协议默认 5，provider 自定上限（tavily 20 / xai 10 / brave 10）；Tool 层 clamp 到 [1,20] | openclaw tavily/xai/brave schema |
| **截断** | Tool 层格式化后若 > 100k chars 走 context offload（同 bash/file 的大输出处理） | hermes `max_result_size_chars=100_000` `web_tools.py:1364`；claude-code `maxResultSizeChars: 100_000` `:155` |
| **安全包装** | snippet/answer 经 `wrapWebContent`（标记 untrusted + 转义），防 prompt injection | openclaw tavily `:173-180`；hermes `wrapExternalContent` |
| **domain filter** | 不放协议最小集；provider 在自己的 `search` 实现内支持（如 tavily `include_domains`） | openclaw tavily full schema `:37-46` |
| **取消** | provider 必须 respect `ctx.signal`（已发请求尽量中止） | openclaw `WebSearchProviderToolExecutionContext.signal` |
| **isAvailable 不可做 I/O** | 注册期/inventory 都跑，必须 cheap（env var 检查 / package import） | hermes ABC docstring 明文约束 |

## 9. 边界与坑

1. **不绑死具体后端**：本协议只定义 `WebSearchProvider` interface + `web_search_provider` EP，具体 provider（Tavily/Brave/DDGS/Google）作为独立 ExtImpl 后续贡献，本版本不实现任何 provider（等用户告知后端）。
2. **EP group 选 `web` 需新增分区**——inventory 会多一个 `web` tab（UI 需对应渲染）。若想最小改动可暂借 `provider` group，但语义不精确（web_search 不是 LLM provider），不推荐。
3. **isAvailable 与 exclusive 选择的关系**——exclusive EP 的「生效 ≤1」由配置 `setExclusive(implId)` 决定（EP §2 表），但若被选中的 provider `isAvailable()=false`，Tool 应返回精确错误（对齐 hermes `_resolve` rule 1「显式配置无视 availability，让用户拿精确错误」），而非静默换 provider。
4. **凭证归 plugin config，不归 provider 协议**——provider 实现从 ExtImpl.configSchema 拿自己的 API key（对齐 EP §3.8「无 point 级 config」）。协议层不暴露 `getCredentialValue`（与 openclaw 不同，因为我们的 plugin config 体系更完备）。
5. **answer 字段可选**——不是所有 provider 都能给 AI 合成答案（tavily/xai能给，brave/ddgs 不能）。Tool 层格式化时 `answer` 存在则前置，否则只列 results。
6. **不要在协议层放 `createTool`**——openclaw 让 provider 自带 createTool 是因为它要让 provider 完全拥有 tool schema；我们 Tool schema 是统一的（LLM 看到统一的 web_search），provider-specific 参数（domain filter/time range）应由 provider 在自己的 `search` 实现内消费，不暴露给 LLM（避免 schema 碎片化）。若未来要暴露 provider-specific 参数，可走「Tool schema 动态注入」但本版本不做。
