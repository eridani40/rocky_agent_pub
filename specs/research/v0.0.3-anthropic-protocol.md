# anthropic_messages 协议格式（实现依据）

> 本文件是 v0.0.3 LLM+Plugin+Chat 调研报告的一部分，完整报告见 `specs/research/v0.0.3-llm-plugin-chat.md`。
> 聚焦：request body / response / SSE 流式事件格式，作为 `protocol=anthropic_messages` ext impl 的实现依据。

## 1. Request body（非流式 / 流式通用字段）

来源：`refs/openclaw/src/llm/providers/anthropic.ts:1085-1114`（构造 `MessageCreateParamsStreaming`）。

```jsonc
// POST {baseUrl}/v1/messages
{
  "model": "claude-sonnet-4-6",          // modelId
  "max_tokens": 1024,                     // 必填，无默认；用 modelConfig.maxOutputTokens 兜底
  "system": "你是助手",                   // 可选；来自 messages[] 中 role:"system"，落点=顶层（spec §3.5 top_level）
  "messages": [
    { "role": "user", "content": [
      { "type": "text", "text": "..." },
      { "type": "image", "source": { "type": "base64", "media_type": "image/png", "data": "..." } }
    ]}
  ],
  "stream": true,                         // 流式标志（spec encode 在 params.stream=true 时设）
  "temperature": 0.7,                     // 可选；4.6+ / 开 thinking 时拒绝自定义值（refs 行 1103-1110）
  "stop_sequences": ["..."],              // 可选
  "tools": [...],                         // 可选，v0.0.3 不实现
  "thinking": { "type": "enabled", "budget_tokens": 8000 }  // 可选，v0.0.3 不实现
}
```

**Headers**（`refs/openclaw/src/llm/providers/anthropic.ts:943-947`，Anthropic SDK 默认）：

```
x-api-key: <credentials.key>
anthropic-version: 2023-06-01
content-type: application/json
accept: application/json
```

OAuth token（`sk-ant-oat` 前缀）走 `Authorization: Bearer <token>`（refs 行 918-921, 1006-1009）。**v0.0.3 只需 x-api-key 路径**。

**Path / contentType**（protocol impl 代码常量）：
- `path = "/v1/messages"`
- `contentType = "application/json"`

与 spec `[P0]llm_protocol_interface.md` §4 示例完全一致——spec 已是正确依据。

## 2. Response（非流式）

content blocks 是数组，元素类型 `text` / `thinking` / `tool_use` / `redacted_thinking`：

```jsonc
{
  "id": "msg_01...",
  "type": "message",
  "role": "assistant",
  "model": "claude-sonnet-4-6",
  "content": [
    { "type": "thinking", "thinking": "...", "signature": "..." },
    { "type": "text", "text": "最终回答" }
  ],
  "stop_reason": "end_turn",              // end_turn | max_tokens | stop_sequence | tool_use | pause_turn | refusal
  "stop_sequence": null,
  "usage": {
    "input_tokens": 320,
    "output_tokens": 12,
    "cache_read_input_tokens": 0,
    "cache_creation_input_tokens": 0
  }
}
```

stop_reason → spec `CanonicalResponse.stopReason` 映射（`refs/openclaw/src/llm/providers/anthropic.ts:1515-1527`）：
- `end_turn` / `stop_sequence` / `pause_turn` / `sensitive` → `"stop"`
- `max_tokens` → `"max_tokens"`
- `tool_use` → `"tool_use"`
- `refusal` → 特殊处理

## 3. SSE 流式事件格式（**核心，protocol impl 的 `parseStream` 依据**）

来源：`refs/openclaw/src/llm/providers/anthropic.ts:307-314, 587-771`。事件类型集：

```
ANTHROPIC_MESSAGE_EVENTS = {
  "message_start",          // 流开始，含 message.id / message.model / 初始 usage
  "content_block_start",    // 一个新 content block 开始（text / thinking / redacted_thinking / tool_use）
  "content_block_delta",    // block 增量（text_delta / thinking_delta / input_json_delta / signature_delta）
  "content_block_stop",     // 一个 block 结束
  "message_delta",          // 消息级增量（stop_reason / usage 更新）
  "message_stop"            // 流结束
}
```

SSE 帧格式（标准 SSE，每帧 `event: <type>\ndata: <json>\n\n`）：

```jsonc
// 1) message_start
{ "type": "message_start",
  "message": { "id": "msg_01", "model": "claude-sonnet-4-6",
               "usage": { "input_tokens": 320, "output_tokens": 1 } } }

// 2) content_block_start — text block
{ "type": "content_block_start", "index": 0,
  "content_block": { "type": "text", "text": "" } }

// 3) content_block_delta — text_delta
{ "type": "content_block_delta", "index": 0,
  "delta": { "type": "text_delta", "text": "你好" } }

// 4) content_block_stop
{ "type": "content_block_stop", "index": 0 }

// 5) thinking block 序列（如果开 thinking）
{ "type": "content_block_start", "index": 1,
  "content_block": { "type": "thinking", "thinking": "", "signature": "" } }
{ "type": "content_block_delta", "index": 1,
  "delta": { "type": "thinking_delta", "thinking": "让我想想..." } }
{ "type": "content_block_delta", "index": 1,
  "delta": { "type": "signature_delta", "signature": "..." } }  // 签名增量（多轮续 thinking 用）
{ "type": "content_block_stop", "index": 1 }

// 6) message_delta — 携带 stop_reason 与最终 usage
{ "type": "message_delta",
  "delta": { "stop_reason": "end_turn", "stop_sequence": null },
  "usage": { "input_tokens": 320, "output_tokens": 12 } }

// 7) message_stop
{ "type": "message_stop" }
```

**关键观察**（refs/openclaw 行 587-771）：
- `index` 字段标识 block 在 `content[]` 中的位置，多个 block 并行流式时靠 index 路由。
- `thinking_delta` 与 `text_delta` 是**独立的 block**（不同 index），UI 上自然分段。这是"thinking/answer 分段流式"的协议层基础。
- `signature_delta` 仅出现在 thinking block 内，多轮续 thinking 需要，**v0.0.3 可忽略**（不续 thinking）。
- `usage` 在 `message_start` 给初始值，`message_delta` 给最终值；某些代理会在 `message_delta` 省略 input_tokens，需保留 `message_start` 的值（refs 行 750-762 注释）。

## 4. SSE → spec `StreamEvent` 映射

spec `[P0]llm_protocol_interface.md:105-111` 定义的 `parseStream` 输出：

```typescript
type StreamEvent =
  | { type: "text_delta"; text: string }
  | { type: "tool_call_delta"; ... }
  | { type: "usage"; usage: Usage }
  | { type: "finish"; reason: "stop" | "tool_use" | "max_tokens" };
```

**问题**：spec 的 `StreamEvent` **缺 thinking_delta 类型**。anthropic SSE 有 `thinking_delta`（与 `text_delta` 平行），若 v0.0.3 chat 要展示 thinking（req 明确要求），`parseStream` 必须能区分。

**给 spec 的补充建议（arch 待定）**：在 `StreamEvent` 加一个变体：
```typescript
| { type: "thinking_delta"; thinking: string }
```
或更通用的 `{ type: "block_delta"; blockType: "text"|"thinking"; index: number; delta: string }`。这是 **arch 需要细化**的点。

## 5. chunk decoder 提示

refs 自己实现了 SSE 帧切分（`flushSseEvent` / `iterateAnthropicEvents`，行 316-485），因为标准 `ReadableStream` 不自动按 SSE 帧切。easy-harness 实现 `parseStream(chunk: string)` 时需注意：**一个 HTTP chunk 可能含多个 SSE 帧，或半帧**，decoder 要跨 chunk 缓冲未完成的帧（按 `\n\n` 分隔帧、按 `\n` 分隔行）。建议用现成 SSE 库（如 `eventsource-parser`）或参照 refs 行 295-485。
