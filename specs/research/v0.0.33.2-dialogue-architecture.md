# v0.0.33.2 架构调研地图（4-scope 对话打通）

> 调研产出（4 个 Explore agent），为 PRD/architecture 提供事实基础。结论 + file:line 引用。代码基线 = dev1 HEAD 2464cc0（含 v0.0.33.1）。

## §1 关键事实（决定 .2 的工作量）

1. **统一 SystemPromptBuilder 早已存在且成熟**：`app/server/src/agent/system-prompt-builder.ts:48-77` 的 mapper/reducer 插件链（v0.0.22 体系），builtin `rocky_context` plugin 已注册 6 个 section mapper（identity/rules/tool_guidance/skills/context_files/memory）。.2 不是"造 builder"，是**填 section + 加分流 + 接 squad 配置**的增量。
2. **AgentLoop 是单一 type-无关 eager 循环**：`agent-loop.ts:133-230`。subagent 早已完整复用同一 loop（`agent-manager.ts:188` activate → new AgentLoop）。**「差异只在 prompt build + 工具集」基本属实**（外加：HTTP 入口 + 首消息 sender 信封）。loop 本体零改。
3. **squad/leader/mate 是纯数据占位**：`handlers/session-messages.ts:190-192` 对 studio session POST messages 返 `403 studio_chat_not_ready`，不进 AgentManager、不调 LLM、不写 transcript。**.2 第一步必须拆这个 403**（spec `v0.0.33.1/change_log.md:173` 明示留给 .2）。注意：`:198-200` 的 subagent 403 **不要拆**（subagent 只读语义是设计不变量）。
4. **配置消费缺口**：`handlers/session-config.ts:60-167 buildSessionConfigFromDeps` 只有 `subAgentConfig` 一个分支。member entity 已持久化 systemPrompt/tools/skills/model（`handlers/member.ts:45-56` hire 时存），**数据就绪，缺消费方**。leader/mate session 即便绕过 403 也会用 DEFAULT_SYSTEM_PROMPT + 全集工具，member 配置完全没被消费。
5. **scope 字段已存在但硬编码**：`session-store-types.ts:99` scope='session'|'subagent'；`scope-allowed-tools.ts:38-47` 是硬编码 if。**无 profile/extension-per-type 注册表**。
6. **plugin scope 体系已通用且空转**：store/激活表/双重载/cascade 全到位（`plugin-manager.ts:84-101 getExtensionImpls(point, scopeId?)`），但**系统里只有 default 一个 scope 在跑**，无任何调用方传非 default scopeId。6 个 scope 名只在 req1.md 出现，零落地。

## §3 锁定的架构决策（research-backed，PRD/architecture 据此）

| # | 决策 | 取向 | 理由 |
|---|---|---|---|
| D1 | **scope 化（req1 想法 a/b）** | **不做** | session.type+bizType+parentSessionId 已 1:1 表达 6 类；scope 是静态配置层管不了动态差异（reachable_agents/tasks/charter 运行时算）；用户直觉「不值得」+ 调研印证；省一层 type↔scopeId 双源维护 |
| D2 | **工具可见性** | **轻量 schema 层裁剪**（assemble snapshot.tools 按 type 过滤 toolDefinitions），非 EP 化 | spec 自标 EP 化=未来增强；schema 裁剪成本 1/10 达成同样可见性（让 LLM 看不到无关工具） |
| D3 | **scope 分流机制** | **Option A**：mapper 内 `if(config.sessionType!==X) return []`；SessionConfig 加 sessionType/bizType/squadId/memberId 字段 | 比 Option B（传 scopeId 给 getExtensionImpls 激活不同 mapper 子集）简单；避免碰 EP scope 激活表；mapper 已独立，内部分流零架构改动 |
| D4 | **skill 黑白名单（req1 c）** | **做**：session-config.ts:124-128 skill 过滤层加 member.skills 交集 | member.skills 字段已就绪（`member.ts:54`），改动小 |
| D5 | **模型 default+override（req1 d）** | **做**：resolveProviderModel 回退链加 `member.model ?? squad.modelDefault` | squad.modelDefault（`squad.ts:36`）+ member.model（`member.ts:57`）字段已就绪 |
| D6 | **charter 投递（TBD#1）** | **charter = stable system_prompt section，leader only**（cache 友好，charter 低频 per-squad） | charter 稳定低频放 prompt 不破 cache；leader 专属、member 不见（spec `squad_definition.md:122`） |
| D7 | **reachable_agents tier** | **volatile → system_reminder**（非 system_prompt） | hire/bench 后下个 assemble 即变，放 prompt 会破 cache；workspace/time 已走 reminder 先例 |
| D8 | **`<EOS>` 实现** | **stop seq 优先 + 后处理 strip 兜底**（双保险，spec `agent_squad_chat.md:48`） | 不新增 StopReason，仍 no_tool_call → markIdle |
| D9 | **subagent identity bug** | **修**：subagent identity 走统一 identity mapper 读 `config.systemPrompt`（explorer），不再被 Rocky identity 覆盖；保留 parent_task/reachable(parent) section | 修正隐性 bug，行为对齐 spec（subagent 有自己人设） |
| D10 | **命名** | **mate（非 member）**，PRD/architecture/代码一律 mate | 对齐权威 spec + .1 已落 |
