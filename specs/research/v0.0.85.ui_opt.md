# v0.0.85.ui_opt 调研报告

调研自 specs（权威）+ light code 确认。5 个需求分述。

## 需求 1 — Session 消息向上滚动分页加载

**需求**：session 打开初始 50 条，向上滚动接近头部时继续加载（无限向上翻页）。

**后端现状（无需改动）**：`GET /session/:id/messages` 已支持 `limit`（默认 50，[1,200]）+ `beforeId`（ULID 字典序之前的 limit 条）+ 响应 `{items, hasMore}`。契约见 `specs/api/overall/04-agent-session.md:266-297`（AT 路径 E 即此分页契约）。

**前端现状（数据通路就位，缺滚动触发）**：
- `app/web/src/lib/chat-api.ts:125-137` `getSessionMessages(sid,{limit,beforeId})` 返 `{items,hasMore}`
- `use-session-run-state.ts:117,127-133,237` 打开时 `getMessages(sid,{limit:50})`；`hasMoreRef`；`setMessages(msgs,{hasMore,prepend})` 经 `merge-messages-by-id` 前插去重（v0.0.81）
- `page-chat.tsx:132-142` `loadMore()` 用 `messages[0].id` 作 beforeId 续载 + prepend
- **缺口**：`page-chat.tsx:268-276` 只渲染 `sr-only` 的 `<button data-testid="chat-load-more">`，**无滚动监听**；`component-message-stream.tsx:154,215,224` scrollRef 仅用于滚底，无 `onScroll`；`hasMore`/`loadMore` 未透传到 `SectionChatDetail` → `ComponentMessageStream`。

**要改**：透传 hasMore/loadMore；滚动容器加 `onScroll`（`scrollTop<threshold && hasMore && !loading` → loadMore）；**prepend 后保持滚动位置**（记录 `prevHeight=scrollHeight-scrollTop`，effect 设 `scrollTop=scrollHeight-prevHeight`），且 loadMore 期间必须跳过现有「rows 变化→自动滚底」effect（加 `isLoadingMore` ref 标记）。subagent 只读页同款缺口（`use-subagent-run-refresh.ts:77`）。

**Invariants**：消息按 createdAt 升序；messageId=服务端 ULID（字典序=时间序，分页正确性根基）；SSE 增量+transcript+loadMore 三路按 id 合并；自动滚底只在「新消息/run 状态变化」触发，loadMore 前插不能触发滚底。

## 需求 2 — 文件 tab 目录监听（file watch）不稳定

**需求**：文件夹变化不能稳定感知；session 打开 subscribe、切目录 unsubscribe+resubscribe、session 关闭 unsubscribe。

**当前机制**：后端 chokidar + SSE 推送（lazy per-session）。`SessionWorkspaceManager.startWatch`（`session-workspace-manager.ts:105`）起 chokidar → `handleFsEvent` 100ms debounce → emit `session_workspace_file_changed` 走 `session_panel` topic。生命周期经 `bootstrap.ts:754-780` `sseChannel.setSubscribeHooks` 绑「0→1 subscribe→startWatch、1→0 unsubscribe→stopWatch」。

**根因**：
1. **squad 群聊 session 完全不订阅 `session_panel`**（`section-squad-chat.tsx` 全文无 sse/useSessionRunState）→ lazy hook 不触发 → watcher 永不启动，仅 mount 时 GET tree 一次。最直接根因。
2. `SessionWorkspaceManager.startWatch` 不 await chokidar 'ready'（仅设标志位）→ 初始扫描窗口写入被 `ignoreInitial` 吞。squad_filewatch BUG-005 已修过，**UI watcher 没同步**。
3. 无 `addDir → watcher.add()` → macOS FSEvents 新子目录递归不可靠。squad_filewatch BUG-006 已修，**UI watcher 没同步**。
4. `bootstrap.ts:766,778` `void startWatch/stopWatch` fire-and-forget → 快速切 tab 时序竞争残留/漏启。

**要改**：保证所有 chat 类型（含 squad 群聊）订阅 session_panel（或把订阅上提到 SectionWorkspacePanel，与 chat 类型解耦——更干净）；`startWatch` 改 await 'ready'（5s 超时兜底）对齐 `squad-file-watcher.ts:166-173`；加 `watcher.on('addDir', abs => watcher.add(abs))`（chokidar4 add 同步禁 .catch）；bootstrap hook 改 async+await。

## 需求 3 — Squad chat 转发格式模糊

**需求**：转发内容改 3 段结构化：①说明（来自群聊xx、由router转发、按needReply决定、回来源session）②原文（来自xxx，原始内容）③相关上下文（群聊上下文，可概括改写）。

**现状（100% LLM 自构，且两 prompt 矛盾）**：
- A. `prompts/content/squad/squad_chat.md:11`（squad_role mapper 注入 system）："转发内容=用户原始query+上下文综合转述，原文一字不差，needReply=true"
- B. `handlers/session-config.ts:55-56,237-240`（硬编码 `STUDIO_SQUAD_ROUTER_SYSTEM_PROMPT`，直接当 systemPrompt）："原样转发，needReply=false"
- 矛盾：A 说原文+转述/needReply=true，B 说只原文/needReply=false。都活着 → 行为不稳定。
- 接收方看到的形态（`logical-view.ts:39-43`）：`[Message from SquadChat (squad, needReply=<bool>)]: <content blob>`，无结构信号。

**要改（纯 prompt，不动代码契约）**：
1. 重写 `squad_chat.md` 转发段为 3 段模板（`### 说明 / ### 原文 / ### 相关上下文` 分隔）
2. 消除 B 矛盾：删/清空 `session-config.ts` 硬编码 prompt，由 squad_role mapper 统一出（对齐 leader/mate）
3. needReply 统一语义（目标格式「按 needReply 参数决定」→ 保留参数化，默认 true 对齐 a2a §4.2）
4. leader.md/mate.md 补一行：收到 SquadChat 转发按说明段决定回复；回复走 send_message(to=SquadChat) 即回群聊

**数据来源**：群聊名=`squad.name`；router 名="SquadChat"固定；needReply=send_message 入参；来源 session=sender.agent.ref.sessionId；②原文 sender：user→"user"，mate/leader→name+sid（需 SquadChat 从 transcript 解析）；③上下文=SquadChat 自己从 transcript 概括（轻方案，先不代码注入）。

**Invariants**：转发仍是 send_message 的 content text blocks（不扩 a2a §5 消息体）；sender 永远是 SquadChat 自己（reply 走 to=sender.agent.ref 必回群聊，不能改成 sender=原 user）；needReply 是顶层字段不进 content；接收方前缀渲染不变；squad_chat 红线不变（不改写 user 原文、不创作 answer）。

## 需求 4 — Studio 红点（新消息未读）

**需求**：studio 有新消息显示红点，参考 playground，核心是 session 状态外线。

**Playground 现有机制**：`Session.unread: boolean` 显式字段；后端 SessionUnreadOps 订阅 session completion + `isSessionActive(sid)` → CAS `unread:false→true` → `SessionMetaBroadcaster.broadcast` → emit `session_meta_update`(含 unread) 到 `(session_meta,_all)`。前端 `use-page-chat-mount.ts:90-101` 订阅一次；`chat-slice.ts:120-137` reducer 按 id upsert（**入口守卫 `if(incoming.biz==='studio') return`** 拒纳 studio）；进会话 `markSessionRead` → `setSessionUnread(false)`；渲染 `component-conversation-item.tsx:137,157-164` 红点 `7×7 bg-[#DC2626]`。

**Studio 现状**：零红点、零 `session_meta` 订阅、`page-studio.tsx:272` onOpenChat 无 markRead。**关键**：后端 `SessionMetaBroadcaster` 已在广播 studio session 的 unread meta（`session-meta-broadcaster.ts:87` 带 `biz:'studio'`），只是 studio 前端无人订阅。

**要改（纯前端）**：studio 侧新建订阅 `session_meta _all` + reducer（反向守卫：只收 biz==='studio'，丢弃 playground）；`component-squad-tree.tsx` 的 TreeChild/BoardNode 接 `unread` prop + 红点 DOM（仿 playground，testid `squad-tree-session-{sid}-unread-dot`）；`page-studio.tsx` onOpenChat 加 `markSessionRead(sid)`。看板节点（无 sessionId）不加。

**待核**：squadChat/member session 的 unread CAS 是否走同一条 UnreadOps 路径（理论同 Session 实体，需在 `specs/tech/agent/session/[P0]session_state.md §6` 核）。

## 需求 5 — Squad UI 尺寸优化

**需求**：看板/群聊/单聊 item 尺寸对齐 playground rock；首字母展示到头像；subagent 保持小尺寸对齐 playground subagent。

**Playground 基线**：conv-item `component-conversation-item.tsx:153` `px-3 py-2.5 rounded-lg mb-0.5`，title `text-[13px] font-medium`；subagent-tree `component-subagent-tree.tsx:68-83` `padding 5px 10px 5px 48px`，dot `11×11 rounded-3px indigo`，name `text-[12.5px]`。

**Studio 现状**：
- squad 行 `component-squad-tree.tsx:89-117` `px-2.5 py-2`，图标13px，name `text-[13px] font-semibold`
- TreeChild（群聊/leader/mate）`:64-79` `py-1.5 pl-7 pr-2.5`，dot **14×14 rounded-xs**，name `text-[12.5px]`，**无首字母**
- BoardNode `:166-184` 同 TreeChild 骨架，dot 渐变方框+target 图标
- member-card `:33-67` `p-3.5`，avatar **34×34 已有首字母**（`charAt(0).toUpperCase()`）
- `MemberAvatar`（common）`member-avatar.tsx:38` 已有 `initialOf`，三档 sm=14/md=28/lg=34 — 只在 chat topbar+message-stream 用，**sidebar 树未用**，且不支持 `role='squad'` 渐变底
- studio sidebar 本版不派生 subagent（spec studio-sidebar.md:7）

**要改**：TreeChild padding `py-1.5 pl-7 pr-2.5` → `px-3 py-2.5`；dot 14×14 → MemberAvatar size='sm'+首字母（需扩 MemberAvatar 支持 squad 渐变）；name `text-[12.5px]` → `text-[13px]`。BoardNode 同步。member-card 不在范围（卡片非列表行）。subagent：studio 本版不派生，需求可能指未来派生复用 playground `component-subagent-tree`（待定位确认）。

## 跨需求决策（orchestrator 裁决）

1. **无 HTTP API 契约变更**（需求1后端已就绪、需求3纯prompt、需求4后端已广播、需求2/5无API）→ **不新增 AT case**（用户："api不需要改的就别测了"）。
2. **需求3（转发格式）是 prompt/LLM 行为变更** → 需 real-LLM 验证（mock 无法验证 LLM 行为，memory 铁律）→ 加 1 个 real-LLM E2E/AT case 验证 3 段格式落地。
3. **验证以 E2E 为主**：需求1（滚动续载 dom+vision）、需求4（红点出现/消除）、需求5（视觉对齐 playground 基线，截图 compare）。无设计稿 → 视觉 compare 参照 = 现有 playground 截图。
4. **需求2（file watch）** E2E 文件系统时序易 flaky → UT（chokidar lifecycle/await ready/addDir）为主 + E2E 1 个冒烟。
5. **needReply 默认值**：目标格式保留参数化、默认 true（对齐 a2a §4.2 缺省）。
6. **群聊名取 `squad.name`**（squad entity，语义最稳）。
