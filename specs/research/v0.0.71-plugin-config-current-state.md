# v0.0.71 现状摸底：plugin ext 配置

## 0. 范围与背景
调研对象 = 当前 worktree 的 plugin ext 配置链路（registry / scopes / inventory / UI）。锁定决策 D1-D6 详见 `reqs/[working] v0.0.71.plugin_fix/req.md`（user_query.md:831-871）。本文给「现状 + 改动触点清单」，不设计实现。

## 1. inventory 全链路
**链路（每环节 file:line）**：
1. `scopes/default.json` 代码声明（D2 唯一源）
2. `app/server/src/bootstrap.ts:254-256` `loadScopeConfigs` → `ScopeConfigValidator.validateAll` → `LoadedScopeConfigProvider` 包装
3. `app/server/src/bootstrap.ts:261-264` `PluginConfigService({ root, scopeConfigs: provider })` 注入
4. `app/server/src/plugin/plugin-config-service.ts:72-83` `inventory(scopeId)` 调 `buildGroups({registry, scopeConfigs}, scopeId)`
5. `app/server/src/plugin/inventory-builder.ts:117-182` `buildGroups` JOIN：每 pointId → groupId（`point.group:133`）→ ext impl 节点
6. `app/server/src/handlers/config.ts:37-51` `handlePluginConfig` GET → `{ tree: pluginSvc.inventory(scopeId) }`
7. `app/web/src/lib/api-client.ts:248-259` `getPluginInventory(scopeId?)` → `PluginInventory`

**根因 — `threshold_should_compact.compactRatio=0.6` 看不到（2 个独立 bug 叠加）**：
- **bug-A（数据源）**：`inventory-builder.ts:217 config: implCfg?.configValues` 仅取 `ScopeConfig.impls[implId].configValues`，**不 JOIN manifest configSchema 的 default**。`threshold_should_compact` 在 `default.json` `impls` 块**完全未声明**（只出现在 `exclusivePicks:27`），`implCfg` 为 undefined → `config: undefined`。Spec `[P0]plugin_config_service.md §3 per-domain 默认表` line 167 写「config 值 | manifest configSchema 的 default」——**代码偏离 spec**（教训 v0.0.49 类型）。
- **bug-B（UI 入口）**：`section-ext-point-area.tsx:218` 所有 EP 强制 `disabled`（v0.0.67 只读化）；`component-ext-impl-checkbox.tsx:97` 在 `disabled` 时不渲染 `ComponentImplConfigBtn` → 配置按钮不可见。

**附带事实**：`schemaConfig` 字段（per-key UI schema，含 `default`） inventory **是返回的**（`inventory-builder.ts:216 schemaConfig: entry.manifest.schemaConfig`）。modal `component-schema-config-modal.tsx:58` 内部已 fallback `draft[key] ?? def.default ?? ''`。所以即使 `config` 为空，只要 modal 能打开，`compactRatio` 会显示 0.6（来自 schemaConfig.compactRatio.default）——**真正卡点是入口按钮被 disabled 屏蔽**。

**改动触点**：
- D3 落地（impl 有 configSchema 必有只读入口）：`component-ext-impl-checkbox.tsx:97`、`-radio.tsx`、`-ordered.tsx`、`-router.tsx` 改「disabled 也渲染 config 按钮（只读 modal）」+ `ComponentSchemaConfigModal` 加 `readOnly` prop（字段不可编辑）
- bug-A 修法选一：(a) inventory-builder JOIN manifest configSchema.default 进 `config`（对齐 spec）；(b) D2 落地后 `default.json` 显式列每 enabled impl+configValues（含 `threshold_should_compact.compactRatio=0.6`），仍需 JOIN 防遗漏。**推荐 (a)+(b) 双保险**。

## 3. scopes/*.json 现状 + ScopeConfig 类型
**3 文件结构差异**：
- `app/plugins/scopes/default.json`：13 activatedPoints（全 EP）+ 4 exclusivePicks + 8 impls（**只列 ordered EP 的 order，无 enabled/configValues**）。**信息不全**——按 D2 应改为「显式列所有 enabled impl + configValues」
- `app/plugins/scopes/forked.json`：10 activatedPoints（context 子集）+ 3 exclusivePicks + 12 impls（含 enabled false + 标注 disabled reason）。`_meta.disabledImplsReason` 是文档辅助字段（Loader/Validator/Provider 全跳过，`scope-config-loader.ts:138` 注释）—— D2 删
- `app/plugins/scopes/test.json`：2 activatedPoints + 1 exclusivePick + impls={}（fixture，仅 APP_ENV=test 加载，`bootstrap.ts:807-812`）

**ScopeConfig TS 类型在 `app/server/src/plugin/scope-config-loader.ts:39-52`**（不在 spec 引用的 `[P1]scopes_config_decl.md`——spec 是文字描述，类型在代码）：
```typescript
interface ScopeConfig { scopeId, name, description?, activatedPoints[], exclusivePicks{}, impls{} }
interface ScopeImplConfig { enabled?, order?, configValues? }
```

**改动触点（D2 增量覆盖规则）**：
- Loader/Validator/Provider **不需改**（schema 不变，只是 default.json 内容大改）
- 类型层不变（`ScopeImplConfig` 字段足够）
- 内容改：`default.json` 改为「列所有激活 EP × 每 EP 列 enabled impl + configValues」；`forked.json` 删 `_meta.disabledImplsReason`；`test.json` 不变
- Validator 加 1 条（见 §6）

## 5. manifest configSchema vs schemaConfig
**两个并存**（`rocky_context/plugin.json` 多处同时声明，例如 `:11-20, :287-297`）：
- **`configSchema`**：JSON Schema 形状（`type:object / properties / default / minimum / maximum`）。**PluginManager 实例化时用**（`specs/tech/config/[P0]ext_impl_scope.md §5.2` line 144 `merged = {...extractDefaults(configSchema), ...scopeConfigs.getImplConfig(sourceScope, implId)?.configValues}`）—— **运行时生效值的合并源**
- **`schemaConfig`**：per-key UI 描述（`{ type, default?, options?, description? }`）。**inventory 暴露 + 前端 modal 渲染用**（`inventory-builder.ts:216` 透传；`component-schema-config-modal.tsx:57-122` 按 type 分发）

**两者均为规范源**（不同维度）：configSchema = 运行时值校验/默认源；schemaConfig = UI 渲染源。**当前 inventory 只暴露 schemaConfig，不暴露 configSchema**（`PluginInventoryTree` interface 字段名 `schemaConfig`，无 `configSchema`）。

**`threshold_should_compact`（`plugin.json:282-297`）两个都有**：configSchema 是「JSON Schema 形状（含 compactRatio default=0.6）」；schemaConfig 是「per-key UI（compactRatio default=0.6, description=__MSG_...__）」。两者 default 重复声明需保持一致（**漂移风险**：改一处忘改另一处）。

**改动触点**：
- D3 落地（config 必带）= 让 inventory `config` 字段非空（§1 bug-A 修法）
- **建议补**：inventory 也暴露 `configSchema`（一次性 JOIN，`inventory-builder.ts:214` 旁加 `configSchema: entry.manifest.configSchema`），让前端 modal 可二选一渲染（schemaConfig 给 UI，configSchema 给 JSON 校验回显）。需扩 `PluginInventoryTree` interface + `api-client.ts:200-220` 类型

## 6. 启动校验链路
**位置 + 现查什么**：
- `app/server/src/plugin/scope-config-validator.ts:50-117` `validateOne(cfg)` 4 条不变量：
  1. activatedPoints pointId 在 registry（`:52-58`）
  2. exclusivePicks.key 是 registry 中 cardinality=exclusive 的 EP（`:60-72`）
  3. impls.keys + exclusivePicks.values 的 implId 在 registry（`:74-87`）
  4. activatedPoints 中每个 exclusive EP 必须有 enabled exclusivePick + 归属正确（`:92-116`）
- bootstrap 调用：`bootstrap.ts:255 new ScopeConfigValidator({ registry }).validateAll(scopeConfigs)`

**加「每个 registry EP 必须在 groups.json 出现且仅一次」接入点（D6）**：
- 新增第 5 条不变量，**但需要新 context**：当前 Validator 只持有 `Registry`，需要再注入 `GroupMeta[]`（来自 groups.json loader）
- 形态：`new ScopeConfigValidator({ registry, groups })` + `validateGroups(registry, groups)` 方法
- 校验内容：(a) 每个 `BUILTIN_EXTENSION_POINTS` 的 id 在 groups.json 某 group 的 `extPoints[]` 出现且仅一次；(b) groups.json 引用的 pointId 在 registry；(c) group id 唯一

**改动触点**：

- `bootstrap.ts:240-256` 调整加载顺序：builtin-loader（registry）→ group-meta-loader → scope-config-validator（带 groups）

## 7. groups.json 落点 + 加载机制建议
**对比 scopes/*.json 模式（`[P1]scopes_config_decl.md §3`）**：
- 文件落点：`app/plugins/groups.json`（与 `scopes/` 平级，与 `builtins/` 平级）。**单文件**（不像 scopes 一 scope 一文件）——groups 是元数据全集，无 per-scope 切片需求
- 内容 schema（提案，arch 定）：
  ```json
  { "groups": [
    { "id": "context-ingest", "label": "__MSG_group.context_ingest.label__",
      "description": "...", "extPoints": ["context_ingest_handler", "system_reminder"] },
    ...
  ] }
  ```
- Loader：`GroupMetaLoader.load()` 仿 `ScopeConfigLoader.loadAll()`（单文件读 + 形状校验）。Loader 跳过 `_meta`
- Provider：`LoadedGroupMetaProvider` 实现 `GroupMetaProvider { listGroups, getGroup(pointId), getGroupMeta(groupId) }`
- 时机：`bootstrap.ts:240` builtin-loader 注册 EP 之后 → 加载 groups.json → 校验（D6：每个 registry EP 必须在 groups.json 出现且仅一次）→ 包装 provider → 注入 `PluginConfigService`（替代 `inventory-builder.ts:133` 直接读 `point.group`）
- inventory JOIN：`buildGroups` 改用 `groupMetaProvider.getGroup(pointId)` 取 groupId，groups 顺序按 `groups.json` 声明序（不按 registry 注册序，对齐 D5 七组固定排序）

**改动触点**：
- 新文件：`app/plugins/groups.json`（按 D5 七组）
- 新代码：`group-meta-loader.ts`、`group-meta-provider.ts`（仿 scope-config-*）
- `inventory-builder.ts:117-182` 重构 group 收集逻辑（source 改 GroupMetaProvider）
- `bootstrap.ts` 加载链路插入 group 加载 + 校验
- `PluginConfigService` constructor 加 `groupMeta` 注入

## 8. 风险 / 坑（参考 memory 教训）
1. **runtime 不写 policy**（`runtime-no-ext-policy-write` memory）：本版纯静态 `groups.json` + 改 `scopes/*.json`，无运行时写路径，OK。但 lazy migrate 落盘兼容仍读 plugin_policy——**别动 migrate 逻辑**（v0.0.67 D2 已固化，运行时不读）
2. **代码-spec drift 是最危险的**（CLAUDE.md 原则 12）：`inventory-builder.ts:217 config` 不 JOIN manifest default 是已存在的 drift（§1 bug-A）。本版要么改代码对齐 spec（推荐），要么改 spec 对齐代码（不推荐——会丢默认值显示）。**别两边都改一半**
3. **静默 degradation 难定位**（`scopes_config_decl.md §5.1`）：D6 校验必须 throw 不 fallback。groups.json 引用未知 pointId / 重复 EP / 漏 EP 都要硬失败
4. **configSchema vs schemaConfig 双源漂移**（§5）：default 在两处声明，改一处忘改另一处无任何校验告警。建议 validator 加「configSchema.default === schemaConfig.default」校验
5. **删 EP.group 别漏 spec**（§2）：5 份 spec 引用 EP.group，删字段需同步 spec，否则下游 agent 读 spec 被误导（教训 v0.0.49 连锁）
6. **merge 文件漂移**（`merge-file-restructure-deadcode` memory）：本版新增 `groups.json` + `group-meta-loader/provider.ts`，合并 dev1 前先 `git merge-base` + `git diff --name-status` 核对 A 类文件存活（CLAUDE.md「Worktree 合并文件校验」）
7. **disabled 屏蔽配置入口是 v0.0.67 副作用**：v0.0.67 把整页 disabled 时把齿轮按钮也藏了，但「查看只读配置」是合理 UX。修法不是「让 button 不 disabled」，而是「让 modal 只读 + button 始终渲染」——别破坏 v0.0.67 只读语义
8. **default.json 改满基线后落盘 migrate 仍跑**：lazy migrate（`plugin-policy-migrate.ts`）保留兼容旧盘，**新装无 record 行为等同**——改 default.json 内容不影响 migrate 路径，但需回归一版 UT 确认 `migrateLegacyImplKeys` 不因新 implId 列表炸
