## 1. Kimi

### anthropic 实测
- `POST https://api.kimi.com/coding/v1/messages`，headers `x-api-key` + `anthropic-version: 2023-06-01`
- **HTTP 200**：`{type:"message", model:"k3", role:"assistant", stop_reason:"max_tokens", content:[{type:"thinking"}]}`
- 请求 model=k3（配置 models[0]）原样回显。注意 thinking 内容在 max_tokens=8 下占满（k3 默认思考），协议层正常。

### 余额实测（GET api.kimi.com/coding/v1/usages，Bearer）
HTTP 200，实际响应（比 cc-switch 快照丰富）：
```json
{
  "user": { "userId": "co01***", "region": "REGION_CN", "membership": {"level": "LEVEL_ADVANCED"} },
  "usage": { "limit": "100", "used": "83", "remaining": "17", "resetTime": "2026-08-15T04:26:12Z" },
  "limits": [ { "window": {"duration": 300, "timeUnit": "TIME_UNIT_MINUTE"},
               "detail": {"limit": "100", "remaining": "100", "resetTime": "2026-08-14T16:26:12Z"} } ],
  "parallel": { "limit": "30" },
  "totalQuota": {}, "authentication": {"method": "METHOD_API_KEY", "scope": "FEATURE_CODING"},
  "subType": "TYPE_PURCHASE", "domain": "DOMAIN_NEXUS"
}
```
- 实测值：周桶已用 83/100（明晨 04:26 重置）；5h 桶剩余 100%（16:26 重置）——窗口健康。

### 与 cc-switch 预期 diff（3 点，均为向后兼容演进）
1. **数值全部是字符串**（"100"/"83"）——cc-switch 的 `parse_f64`（数字/字符串兼容）恰好已覆盖，无破坏。
2. **`usage` 新增 `used` 直读字段**——cc-switch 用 `limit - remaining` 换算仍等价（100-17=83 ✅），我们实现可直接用 `used` 并以换算兜底。
3. **新增字段**：`user.membership.level`（会员档位，可展示）、`parallel.limit`（并发额度 30）、`window.duration:300+TIME_UNIT_MINUTE`（**5h=300min 显式声明**，可做展示文案来源）、`subType`。cc-switch 未消费，纯增量。

### 结论
✅ 可用。协议走 x-api-key；额度端点 Bearer；形状按「字符串值 + used 直读 + membership 展示」实现。

## 2. 智谱 GLM（glm-1 实例）

### 余额实测（GET open.bigmodel.cn/api/monitor/usage/quota/limit，裸 api_key 无 Bearer）

```json
  "data": { "level": "max",
    "limits": [
      {"type":"TOKENS_LIMIT","unit":3,"number":5,"percentage":36,"nextResetTime":1786725307528},
      {"type":"TOKENS_LIMIT","unit":6,"number":1,"percentage":25,"nextResetTime":1787031490998},
      {"type":"TIME_LIMIT","unit":5,"number":1,"usage":4000,"currentValue":88,"remaining":3912,
       "percentage":2,"nextResetTime":1788500290998,
       "usageDetails":[{"modelCode":"search-prime","usage":88},{"modelCode":"web-reader","usage":0},{"modelCode":"zread","usage":0}]}
  ] } }
```
- 实测值：5h 桶已用 36%（今夜 00:35 重置）；周桶已用 25%（08-18 13:38 重置）——时间戳均为毫秒，重置点均在未来，语义合理。
- **裸 api_key 实证**：预研 R1 的智谱额度端点鉴权特殊（无 Bearer 前缀）在真调中成立。

### 与 cc-switch 预期 diff（2 点）
1. **周桶出现 `unit:6, number:1` 变体**——cc-switch 注释「number:7 与 number:1 两种取值都实测过，只锚 unit」再次实证 ✅，实现必须只锚 unit。
2. **发现第三类 `TIME_LIMIT`**（unit:5）：Web 工具 tokens 限额（search-prime/web-reader/zread 分项）。cc-switch 只取 TOKENS_LIMIT/CREDIT_LIMIT、跳过 TIME_LIMIT——我们同口径忽略即可（或后续版本作增强展示，不进 5h/周两桶）。

### 结论
✅ 可用。协议 x-api-key；额度端点**裸 api_key**；分桶规则（unit:3→5h、unit:6→周、忽略 TIME_LIMIT、禁按重置时间排序）全部实证。

## 7. 实现要点汇总（供 architect 出 change_plan）

1. **协议层零障碍**：四渠道 `{baseUrl}/v1/messages` + `x-api-key` + `anthropic-version: 2023-06-01` 全通，与现有 `anthropic_compatible` impl 的 buildAuthHeaders 完全一致 → 新 4 类型 impl 协议侧可直接复用 anthropic_compatible 行为，差异只在**额度查询能力**。
2. **额度查询鉴权两种**：kimi/minimax/deepseek = `Bearer`；**glm = 裸 api_key（实证）**——预研 R1 就地关闭：glm 额度 impl 必须独立实现 auth header。
3. **窗口分桶实现规则（全部实证）**：
   - glm：`type ∈ {TOKENS_LIMIT, CREDIT_LIMIT}` 且 `unit:3→5h / unit:6→周`（number 不锚定）；`TIME_LIMIT` 忽略；禁按 nextResetTime 排序。
   - minimax：取 `model_name=="general"`；已用% = 100 − remaining%；周桶仅 `current_weekly_status==1`。
   - kimi：`limits[]→5h`、`usage→周`；值可能是字符串（parse_f64 兜底）；优先直读 `usage.used`。
   - deepseek：无窗口，`balance_infos[]` 金额 + `is_available`。
4. **时间戳口径**：glm/minimax 毫秒时间戳；kimi ISO 字符串——统一转 ISO 存 tier.resets_at（cc-switch extract_reset_time 同款）。
5. **响应 model 回显陷阱（glm）**：请求 glm-5.2 回显 glm-5.3——UI/校验逻辑不得用响应 model 反推请求模型。
6. **volc 留扩展位**：AK/SK 双凭据表单 + SigV4 签名（cc-switch 有完整参考实现），v0.0.350 可先不做或做半支持（无 AK/SK 时显示「需配置凭据」）。
