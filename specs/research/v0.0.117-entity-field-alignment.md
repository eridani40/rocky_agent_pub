# v0.0.117 调研：board 管理实体「存储 ↔ UI ↔ agent 工具」三方对齐审计

> 调研产物（不改代码）。范围：squad board 管理实体全集 + Member/Squad 管理面。
> 结论先行：**已确认的 Goal description/body 错位不是孤例**——Requirement detail 同病；agent 工具面大面积落后于权威 spec（`specs/tech/squad/[P1]squad_tools.md`）：缺 edit/archive/restore action、create 静默丢字段（task priority/deadline、三实体 body）、query 读面缺长文本字段。
> 证据基线（本 worktree）：store `app/server/src/stores/board-shared.ts`；HTTP `app/server/src/handlers/board-write-*.ts` + `board-shared.ts`；UI `app/web/src/components/studio-page/`；agent tools `app/server/src/agent/tools/{goal,requirement,task,team}-tool.ts`。

## 3. 错位清单（按严重度）

### S1 用户可见数据丢失 / 编辑视图与字段不对应

1. **Goal 编辑弹层与列表字段错位**（已确认 bug）：列表渲染 `description`（component-board-goals-view.tsx:144），编辑/创建表单只载/只提交 `body`（use-board-edit-form.ts:108-110、:129-133）→ agent 写的 description 用户无法改；UI 建的 goal description 恒空（列表摘要行永远缺失）。
2. **Requirement 同病**：列表渲染 `detail`（component-board-requirements-view.tsx:98），表单只有 `body`（use-board-edit-form.ts:116-118）→ detail 无编辑/创建入口。
3. **task 工具 create 静默丢 priority/deadline**：tool description 承诺（task-tool.ts:54-56），inputSchema/实现不收（:58-77、:117-155）→ agent 侧写入数据丢失（恒 priority=none、无 deadline），且 LLM 无任何报错感知。
4. **编辑表单空值跳过 → 字段无法清空**：`if (body)/if (unit)/if (deadline)/if (owner)` 才进 patch（use-board-edit-form.ts:129-150）→ 用户无法清掉已有 deadline/unit/body/owner。
5. **agent edit KR target 后 health 不重算**：goal-tool.ts:204-211（applyKrPatch 允许 target）→ goal-store.ts:165-189 updateGoal 不派生（注释假设 edit 不改 current/target，goal-store.ts:170-171）；HTTP 路径有重算（board-write-goal.ts:118-131）→ 同一操作双通道结果不一致，看板显示脏 health。违 squad_tools:141。

### S2 字段无编辑入口（UI）

6. **status 全实体无 UI 编辑入口**：edit modal 无 status 字段、无拖拽/下拉；PATCH 端点全支持（board-write-goal.ts:74、board-write-req.ts:61、board-write-task.ts:137）。UI spec 自相矛盾：squad-board.md:11 称「全字段可编辑（含…状态）」、:58-61 字段表又缺 status/description/detail。
7. **KR.status 三方全不可达**：UI 无入口 + KrRow 不渲染（component-board-goals-view.tsx:79-113）+ agent edit 白名单无 status、update_progress 只改 current（goal-tool.ts:274-280、goal-store.ts:198-220）→ KR 永远 pending，无法 done/cancelled（仅裸 HTTP 可改）。
8. **Task.reason 不可见**：blocked/cancelled 原因落库（task-tool.ts:229-231）但卡片不渲染（component-board-task-card.tsx 全文无 reason）→ 用户看不到阻塞原因。
9. **Task/KR deadline 列表不显示**：可编辑但卡片/KR 行无渲染 → deadline 驱动的 health 变化用户无从解释。
10. **Requirement.triage 用户无入口**：UI 只显示（req-view:103-105）；triage 决策仅 agent leader 工具可做——user 角色（HTTP 全写权）无对应 UI。

### S3 agent 不可达（实现落后权威 spec squad_tools.md）

11. **三实体缺 edit action**：requirement（REQ_ACTIONS requirement-tool.ts:30 vs spec:165）、task（TASK_ACTIONS task-tool.ts:36 vs spec:115）→ agent 建完后无法改 title/detail/body/priority/deadline/dependsOn/relatedKRId；goal 有 edit 但白名单缺 body（goal）/body·deadline·status（KR）（goal-tool.ts:266-280 vs spec:141）。
12. **三实体缺 archive/restore（+task duplicate）action**：spec:116-118/143-144/167-168 全表声明，三个 tool 均未实现 → 归档管理 agent 不可达，只能 UI 做。
13. **create 丢 body**：goal.create_objective（goal-tool.ts:136-143）、goal.create_kr（:157-163）、requirement.create（requirement-tool.ts:128-134）均不传 body（spec:138/139/162 声明应收）→ agent 无法写长正文，OKF↔store 双轨里 store 长文本只能靠 UI。
14. **query 读面缺长文本与关键字段**：goal.query 无 description/body/KR 明细（goal-tool.ts:283-285）；requirement.query 无 detail/body/triage（requirement-tool.ts:226-228）；task.query 无 priority/deadline/body/reason（task-tool.ts:267-270）；reminder 注入同样只有 title/status/health/进度（squad_board.ts:151-176）→ **UI 用户写的 body/detail/摘要，agent 经设计读面完全看不见**。
15. **team.query 缺 intro、暴露 dead tools 字段**（team-tool.ts:169-179）；HTTP PATCH requirement 不收 raisedBy（board-write-req.ts:53-63，违 11b §3.5）。

## 4. 修复建议概览（供 PRD/架构，不实现）

1. **UI 表单补摘要字段**：Goal 编辑/创建加 `description`、Requirement 加 `detail`（一行 input，与 body 编辑器并存）；顺带定义「摘要 vs 正文」的产品语义并写进 squad-board.md 字段表（修正 :11 与 :58-61 的自相矛盾）。
2. **表单支持清空**：patch 组装改「dirty 才提交、空串=显式清空」语义（服务端 PATCH 已支持空串写入）。
3. **status 编辑入口**：至少给 task（列间移动或卡片下拉）与 KR（含 done 终态）补 UI；KR.status 需先决定产品语义（是否保留独立状态 vs 纯进度派生）。
4. **task 工具修字段丢失**：inputSchema+runCreate 补 priority/deadline/body（description 已承诺）；或改 description 撤承诺——建议补齐（对齐 spec）。
5. **补齐三工具 action 到 spec 全表**：edit（req/task+goal 白名单扩）、archive/restore、task.duplicate；edit KR 路径补 health 重算（复用 board-write-goal 的派生逻辑，抽共享）。
6. **agent 读面补长文本**：query 加 `detail=true`（或 get action）返 description/detail/body/triage/priority/deadline；避免 reminder 全量注入长文本（token 成本），按需读取。
7. **小项**：task 卡片渲染 deadline/reason；team.query 去 dead tools、补 intro；PATCH requirement 收 raisedBy 或改 11b spec 撤字段；dependsOn 选项是否放开跨 Req 与工具口径对齐。
8. **spec 同步**：以上任一按「维持现状」裁决的项，须回改 squad_tools.md / 11b / squad-board.md 撤销声明（消除 spec↔code 静默偏离——比过时 spec 更危险）。
