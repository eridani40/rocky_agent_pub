## 〇、重大补充 — skills.sh（Vercel）：有 API + 真实安装量的中心化聚合器

**这改变了「git 源无下载量」的绝对结论**：存在一个**格式兼容、有公开 API、有真实安装量**的第三方聚合器，值得优先评估对接。

| 维度 | 事实 | 来源 |
|------|------|------|
| 运营方 | **Vercel**（vercel-labs/skills 开源），定位「Open Agent Skills Ecosystem」 | skills.sh |
| 格式 | 托管 anthropics/skills 等，**与 SKILL.md 生态兼容** | skills.sh |
| 公开 API | **有** — `GET https://skills.sh/api/v1/skills?per_page=10`；支持搜索、取详情、查 security audit | vercel changelog |
| 认证/限流 | Vercel OIDC 短期 token（team/project 域）；**600 req/min** | vercel changelog |
| 安装量/热度 | **有真实 installs**（站上显示 2.5M、All Time 919,630）+ **Trending(24h) / Hot** 排序 | skills.sh |
| 安装 | CLI 一键：`npx skills add <owner/repo>` | vercel docs |
| 搜索/分类 | 搜索框 + topic 标签（React/Databases/Marketing…）+ Trending/Hot 过滤 | skills.sh |
| security audit | API 可查每个 skill 的安全审计结果 | vercel changelog |

**对我们的含义（重要）**：
- 之前「必须全自建索引 + 自建 installCount」的结论要**分两条路线**：
  - **路线 A（对接 skills.sh API）**：直接拿到搜索 + 安装量 + 热度 + security audit，**省掉自建索引/遥测**，市场页的 Trending/Hot/安装量排序**真能落地**（不再是空字段）。代价：依赖 Vercel OIDC token + 限流 + 外部依赖。
  - **路线 B（自建 git 聚合索引）**：不依赖第三方，但下载量/热度要自建（前述结论）。
- **建议**：MVP 可**优先对接 skills.sh API**（格式兼容 + 现成安装量/搜索），把它作为「市场」主源；官方 anthropics/skills 与自定义 git 源作为补充。待 Part C 汇总其他 hub（ClawHub/SkillsMP 等）后再定最终主源。
- skills.sh 的 `npx skills add <owner/repo>` 与 `api/v1/skills` 是最干净的对接点，命名空间 `owner/repo` 与我们前述 namespace 设计一致。

## 一、一句话结论

我们要对接的 skill 源（官方 anthropics/skills + Claude Code marketplace + 社区源）**全部是 git-backed、无中心 API、无下载量/评分**。因此市场后端的正确形态 = **自建轻量聚合索引**（拉各 git 源解析 manifest 建索引）+ **自建 install 遥测**；市场页用「star + 更新时间 + 静态质量分 + verified + 自建安装量」撑排序与信任，**不硬造空的下载量字段**。REST 接口直接对齐 MCP Registry / Smithery 的成熟范式。

> ⚠️ 见「〇、重大补充」：skills.sh(Vercel) 提供有 API + 真实安装量的中心化聚合，若对接它则可省掉自建索引/遥测——此结论待 Part C 汇总后与其他 hub 一并权衡定主源。

## 二、关键事实（决定我们能做什么）

| 事实 | 来源 | 对我们的含义 |
|------|------|-------------|
| skill 格式 = 目录 + `SKILL.md`（frontmatter 仅强制 `name`+`description`） | anthropics/skills | 与我们格式一致，可直接对接；skill 级元数据极简 |
| 最结构化的清单 = `.claude-plugin/marketplace.json`（**plugin 级**，非 skill 级） | Claude Code docs | 索引/分类/标签的主数据源；但描述的是 plugin，skill 是其子组件 |
| 分发全是 git-backed，安装 = clone/复制到本地缓存（自包含，禁外部相对路径） | Claude Code | 我们的 install = git clone/checkout subfolder → 复制到本地 skills 目录 |
| git 源无下载量/评分/热度/统一搜索 API | Part A §4 | 这些要么自建，要么降级用 GitHub stars |
| 有 search/install API 的成熟范式 = MCP Registry (`/v0/servers?search=&cursor=`) + Smithery (`/servers?q=&page=&verified=`) | Part B §1-2 | 直接抄 REST 契约 |
| 元数据 schema 权威模板 = MCP `server.json`（name/description/repository{url,subfolder}/version/packages） | Part B §1 | 平移为我们的 skill manifest，天然适配 git-backed |
| 质量分可不依赖遥测（Glama TDQS：静态分析 manifest 打分） | Part B §3 | 无下载量场景下的替代质量信号 |
| 一键安装靠标准化安装清单（Cline `llms-installation.md`） | Part B §4 | 我们 skill 需等价安装 manifest 供机械执行 |

## 三、我们的市场建议长什么样

### 3.1 架构：自建聚合索引（不代理、不做中心 registry）
- **源模型**：官方源（anthropics/skills）+ Rocky 精选源（审核过的社区 marketplace）+ 用户「添加源（git URL）」。对齐 Claude Code `marketplace add <git-url>` 机制。
- **索引**：后端定期 clone/pull 各 git 源 → 解析 `.claude-plugin/marketplace.json`（plugin 级）+ 各 `SKILL.md` frontmatter（skill 级）→ 建本地搜索索引。
- **派生字段**：读 GitHub API 补 stars/更新时间；install 事件落库累计 installCount；静态分析算 qualityScore。

### 3.2 后端接口草案（对齐 MCP Registry + Smithery）
```
# 搜索
GET /skills/market?q=<全文>&category=<枚举>&tag=<多值>
       &sort=<relevance|updated|stars|installs>&verified=<bool>&limit=<n>&cursor=<游标>
# 详情（namespace = owner/repo[/subfolder]，抄 MCP name 去重）
GET /skills/market/{namespace}
# 安装（后端按安装 manifest 执行 git clone/checkout + 落 install 事件）
POST /skills/market/{namespace}/install   body: { version? }
# 源管理
GET  /skills/market/sources
POST /skills/market/sources   body: { gitUrl, ref? }
```

### 3.3 skill manifest schema（平移 MCP server.json）
`name`(namespace) / `description` / `repository{url,source,subfolder}` / `version` / `installType+args` / `category` / `tags[]` / `author` / `license` + 派生（stars / updatedAt / installCount / qualityScore / verified）

### 3.4 市场页 UX（对齐 VS Code / Cline，裁剪到 git-backed 现实）
- **顶部**：搜索框 + 排序下拉（相关性 / 最近更新 / star / 安装量）+ 分类 filter。
- **左侧**：源筛选（官方 / Rocky 精选 / 用户添加）+ 分类（Rocky 策展 taxonomy，因各源分类非标准需归一映射）。
- **卡片**：图标 + 名称 + 作者 + 一句话描述 + 信号徽章（官方 / verified 蓝勾）+ 指标（version / 更新时间 /（可选）star / 安装量）+ 安装按钮。
- **详情**：README + 版本历史 + 源仓库链接 + 分类/tag + 文件清单 + 依赖/凭证要求 + 安装按钮（一键，缺凭证才提示）。

### 3.5 维度取舍（git-backed 无下载量）
- **能直接做**：全文搜索、分类/tag、更新时间(git commit)、star(GitHub API)、verified(所有权校验)、质量分(静态分析)。
- **要自建**：安装量（后端 install 遥测）、用户评分（起步期可缓）。
- **不做**：硬造空的上游下载量字段。

### 3.6 安全/策展分档
1. **命名空间所有权校验**（抄 MCP：GitHub OAuth/OIDC/DNS/HTTP）防冒名 → verified 徽章。
2. **官方/精选策展标记**（Rocky 人工收录，走 issue/PR + 收录理由，抄 Cline 轻量流）。
3. **内容质量分**（抄 Glama TDQS 静态打分）；进阶可加沙箱扫描（起步不做）。
