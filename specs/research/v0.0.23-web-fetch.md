## §A. 系统代理（System Proxy）

### A.1 三家支持情况总览

| 维度 | openclaw（TS） | hermes-agent（Python） | claude-code（TS） |
|------|---------------|----------------------|------------------|
| 系统代理 | **完整支持**（HTTP_PROXY/HTTPS_PROXY/NO_PROXY + 固定 ProxyAgent + 全局 dispatcher） | **隐式支持**（httpx 默认 `trust_env=True`，自动读 env） | **不支持**（裸 axios，无代理配置；只检测上游 egress proxy 的 403） |
| 实现层 | undici `EnvHttpProxyAgent`/`ProxyAgent` + 自建 SSRF/NO_PROXY 解析 | httpx 内置 env 读取 | — |
| 与 SSRF 关系 | 紧耦合：代理模式下做 DNS pinning / hostname 策略校验 | 解耦：SSRF 在 `url_safety.py` 独立做 | 靠云端 `api.anthropic.com/api/web/domain_info` 预检 |

### A.2 openclaw 的代理实现（TS/Node，最值得借鉴）

**核心：基于 undici 的 dispatcher 模式**，所有出站 fetch 走 `fetchWithSsrFGuard`（`refs/openclaw/src/infra/net/fetch-guard.ts:414`），按 `mode` 选择 dispatcher：

```typescript
// refs/openclaw/src/infra/net/fetch-guard.ts:54-60
export const GUARDED_FETCH_MODE = {
  STRICT: "strict",                    // 默认：直连，DNS pinning，禁内网
  TRUSTED_ENV_PROXY: "trusted_env_proxy",   // 读 HTTP(S)_PROXY，operator 信任
  TRUSTED_EXPLICIT_PROXY: "trusted_explicit_proxy", // 显式 proxyUrl
};
```

**三种 dispatcher 工厂**（`refs/openclaw/src/infra/net/undici-runtime.ts:218-270`，全部强制 HTTP/1.1 + 超时 + IP-safe proxy pool）：

| 工厂 | 用途 | 关键点 |
|------|------|--------|
| `createHttp1Agent(opts, timeoutMs)` (`:219`) | 直连 | 无代理 |
| `createHttp1EnvHttpProxyAgent(opts, timeoutMs)` (`:231`) | 读系统 env | 用 undici `EnvHttpProxyAgent`，自动处理 HTTP_PROXY/HTTPS_PROXY/NO_PROXY |
| `createHttp1ProxyAgent({uri}, timeoutMs)` (`:252`) | 显式代理 URL | 用 undici `ProxyAgent`，固定 proxy |

**env 解析逻辑**（`refs/openclaw/src/infra/net/proxy-env.ts`）：
- `PROXY_ENV_KEYS`（`:3-10`）：`HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` + 小写变体。
- `resolveEnvHttpProxyUrl(protocol, env)`（`:47-61`）：**小写优先于大写**；HTTPS 请求优先 `https_proxy`，回退 `http_proxy`；`ALL_PROXY` 被 `EnvHttpProxyAgent` 忽略（需手工注入，见 `resolveEnvHttpProxyAgentOptions` `:85-96`）。
- `matchesNoProxy(targetUrl, env)`（`:152-239`）：**完整复刻 undici 内部 matcher**（注释 `:128-150` 明示），支持逗号/空白分隔、`.example.com`/`*.example.com`、子域后缀、`[::1]` IPv6、`:port`。**OpenClaw 扩展**：IPv4 CIDR（`100.64.0.0/10`）+ 八段通配（`100.64.*`）—— 为 fake-ip 代理栈（sing-box/Clash）预留。

**TRUSTED_ENV_PROXY 触发条件**（`refs/openclaw/src/infra/net/fetch-guard.ts:505-528`）：
```typescript
const canUseTrustedEnvProxy =
  (mode === GUARDED_FETCH_MODE.TRUSTED_ENV_PROXY || ...) &&
  !dispatcherPolicy &&                              // 未显式指定 proxy
  shouldUseEnvHttpProxyForUrl(parsedUrl.toString()); // env 有代理且 NO_PROXY 不命中
if (canUseTrustedEnvProxy) {
  dispatcher = createHttp1EnvHttpProxyAgent(undefined, timeoutMs);
}
```

**Web 工具入口默认走 trusted env proxy**（`refs/openclaw/src/agents/tools/web-guarded-fetch.ts:82-95` `withTrustedWebToolsEndpoint`）：调用方传 `useEnvProxy: true` → 转 `withTrustedEnvProxyGuardedFetchMode` → mode=TRUSTED_ENV_PROXY。

### A.3 hermes-agent 的代理（Python，隐式）

hermes 用裸 `httpx.post(url, json=payload, timeout=60)`（`refs/hermes-agent/plugins/web/tavily/provider.py:57`、firecrawl provider 同款）。**httpx 默认 `trust_env=True`**，自动读 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY` 环境变量——无需任何代码。这是 Python 生态的"零成本系统代理"。

> 注：hermes 代码中 **grep 不到** 任何 `proxies=`/`HTTP_PROXY` 显式处理（已确认），完全靠 httpx 默认行为。

### A.4 claude-code 的代理（无）

claude-code 用 `axios.get(url, { signal, timeout, maxRedirects: 0, ... })`（`refs/claude-code/src/tools/WebFetchTool/utils.ts:272-282`），**不配置任何 proxy**。它只做两件代理相关的事：
1. **域名预检**（`:176-203` `checkDomainBlocklist`）：调 `https://api.anthropic.com/api/web/domain_info?domain=...`，由 Anthropic 云端判定能否抓取。
2. **egress proxy 403 识别**（`:316-325`）：如果上游企业 egress proxy 返回 `403 + X-Proxy-Error: blocked-by-allowlist`，识别为 `EgressBlockedError`。

> 即 claude-code 的"代理"是企业出网代理（operator 控制），不是给 web_fetch 用的系统代理。

### A.5 TS/Node/Bun 推荐方案对比

| 方案 | 原理 | 依赖 | 读 HTTP_PROXY | 读 NO_PROXY | 评估 |
|------|------|------|--------------|-------------|------|
| **(a) undici `EnvHttpProxyAgent`** | undici 内部读 env，自动按 protocol/NO_PROXY 路由 | 内置（Node 18+ / Bun 1.0+ 都自带 undici） | ✅ | ✅ | **首选**。零依赖、语义完整、与 openclaw 一致 |
| (b) undici `ProxyAgent` | 固定 proxyUrl，不读 env | 内置 | ❌（需手工） | ❌ | 用于"显式代理 URL"场景，非"系统代理" |
| (c) `https-proxy-agent` npm | 老 Node `http.Agent` 子类，配 `https.Agent`/`globalAgent` | 额外 npm | 需手工读 env | 需手工 | **不推荐**：老 API、与 fetch 集成差、社区维护降速 |
| (d) Bun 原生 `Bun.fetch` | Bun 运行时是否自动读 HTTP_PROXY？ | — | **❌ 实测不读**（Bun 文档未承诺，issue 持续 open） | ❌ | **不可依赖**。即使 Bun 也得用 undici |
| (e) `global-agent` | 启动时 patch globalAgent | npm | ✅ | 部分 | 侵入式，不推荐 |

**关键事实**：rocky_agent 跑在 Bun 上（见 CLAUDE.md 测试规范），**Bun 原生 `fetch`/`Bun.fetch` 不读 HTTP_PROXY**。但 Bun 完整支持 undici（`undici` 是 Bun 内置依赖），故 **(a) undici EnvHttpProxyAgent** 可直接用。

**推荐代码方向**（基于 openclaw `undici-runtime.ts:231-246` 简化）：

```typescript
import { EnvHttpProxyAgent, fetch, Agent } from "undici";

// 读系统代理（HTTP_PROXY/HTTPS_PROXY/NO_PROXY 自动处理）
function createProxyDispatcher(timeoutMs?: number) {
  return new EnvHttpProxyAgent({
    allowH2: false,                          // 强制 HTTP/1.1（openclaw 经验：HTTP/2 dispatcher 不稳）
    bodyTimeout: timeoutMs,
    headersTimeout: timeoutMs,
    connect: { timeout: timeoutMs },
  });
}

// 直连 dispatcher（无代理时）
function createDirectDispatcher(timeoutMs?: number) {
  return new Agent({ allowH2: false, bodyTimeout: timeoutMs, headersTimeout: timeoutMs });
}

// 工具入口：优先用代理，env 无代理则降级直连
export async function fetchUrl(url: string, opts: {...}) {
  const hasProxy = process.env.HTTP_PROXY || process.env.HTTPS_PROXY
                || process.env.http_proxy || process.env.https_proxy;
  const dispatcher = hasProxy ? createProxyDispatcher(opts.timeoutMs)
                              : createDirectDispatcher(opts.timeoutMs);
  try {
    return await fetch(url, { dispatcher, signal: opts.signal, ... });
  } finally {
    await dispatcher.close();  // 释放连接池，避免句柄泄漏（openclaw closeDispatcher ssrf.ts:710）
  }
}
```

### A.6 降级策略（代理失败 / 无代理环境）

| 场景 | 处理（参考 openclaw） |
|------|----------------------|
| env 无任何 PROXY 变量 | `hasProxyEnvConfigured()` (`proxy-env.ts:13`) 返回 false → 走 `createHttp1Agent` 直连 |
| NO_PROXY 命中目标 | `shouldUseEnvHttpProxyForUrl` (`:104`) 返回 false → 直连 |
| 代理连接失败 | undici 抛 `UND_ERR_CONNECT_TIMEOUT`/`ECONNREFUSED` → 工具返回 `isError=true`（不自动降级直连，避免 SSRF 绕过） |
| 代理 + SSRF 校验冲突 | openclaw 在 trusted-env-proxy 模式仍跑 `assertHostnameAllowedWithPolicy`（`fetch-guard.ts:524`）—— **代理不豁免 SSRF** |

**关键原则**：代理失败时 **不要静默降级为直连**——会让 SSRF 防护形同虚设（攻击者只需让代理超时即可绕过）。直接抛错让 LLM/用户感知。

## §B. 渲染与内容优化架构

### B.1 要解决的问题清单

fetch 一个 URL 得到原始字节后，直接喂给 LLM 有 7 类问题：

| # | 问题 | 影响 | openclaw 应对 | hermes 应对 | claude-code 应对 |
|---|------|------|--------------|------------|-----------------|
| 1 | **内容类型识别** | HTML/JSON/markdown/PDF/binary 处理路径不同 | `normalizeContentType` (`web-fetch.ts:584`) 分支处理 | backend 已转 markdown | `isBinaryContentType` 持久化 (`utils.ts:442`) |
| 2 | **字符编码** | 非 UTF-8 页面乱码 | `readResponseText` (`firecrawl-client.ts:8`) | httpx 自动 | axios `responseType: arraybuffer` + `toString('utf-8')` (`utils.ts:452`) |
| 3 | **HTML 去噪** | 导航/广告/script/style 噪声占 80%+ | `sanitizeHtml` 移除黑名单标签 (`web-fetch-visibility.ts:320`) | backend 处理 | turndown 整页转 md |
| 4 | **正文提取** | 只保留主内容区 | `@mozilla/readability` + `linkedom` (`web-content-extractor.ts:187`) | backend (firecrawl `onlyMainContent`) | 不提取（整页 turndown） |
| 5 | **HTML→Markdown** | LLM 读 markdown 比 HTML 省 token | `htmlToMarkdown` 正则版 (`web-fetch-utils.ts:38`) + readability 输出 turndown | backend 直出 markdown | `turndown` 库 (`utils.ts:93-97`) |
| 6 | **过大响应** | 单页可能 >1MB，爆 context | `truncateText(value, maxChars)` (`web-fetch-utils.ts:86`) + `wrapExternalContent` 标记 untrusted | LLM 二次摘要（见 B.4） | `MAX_MARKDOWN_LENGTH=100_000` 截断 + Haiku 摘要 |
| 7 | **JS 动态渲染** | SPA 页面静态 fetch 拿不到内容 | 依赖 backend (firecrawl stealth proxy) 或返回失败 | 依赖 backend | **不支持**，提示用户用 browser 工具 |

### B.2 方案光谱对比

#### 方案 1：纯静态 fetch + 服务端 readability 提取

**原理**：`fetch HTML` → DOM 解析 → readability 算法识别主内容区 → turndown 转 markdown。

**openclaw 实际用的就是这条**（`refs/openclaw/extensions/web-readability/web-content-extractor.ts:169-203` `extractWithReadability`）：

```typescript
// refs/openclaw/extensions/web-readability/web-content-extractor.ts:180-199
const { Readability, parseHTML } = await loadReadabilityDeps();
const { document } = parseHTML(cleanHtml);
const reader = new Readability(document, { charThreshold: 0 });
const parsed = reader.parse();
if (request.extractMode === "text") {
  return { text: stripInvisibleUnicode(normalizeWhitespace(parsed.textContent ?? "")), title };
}
const rendered = htmlToMarkdown(parsed.content);
return { text: stripInvisibleUnicode(rendered.text), title };
```

依赖：`@mozilla/readability`（Firefox 同款算法）+ `linkedom`（服务端 DOM，无浏览器）。

**防护**（`web-content-extractor.ts:14-15`）：`READABILITY_MAX_HTML_CHARS=1_000_000` + `exceedsEstimatedHtmlNestingDepth(html, 3000)` 防止恶意深嵌套 HTML 拖垮 DOM 解析。

- ✅ 优点：零外部 API、零浏览器进程、可控、快（<1s）、无 API 费用
- ❌ 缺点：JS 渲染的 SPA 拿不到内容；readability 对非文章页（列表/表格/文档站）效果一般
- 📦 依赖：`@mozilla/readability` (~50KB) + `linkedom` (~200KB)

#### 方案 2：动态渲染（headless 浏览器先渲染再提取）

**原理**：Puppeteer/Playwright 启 headless Chrome → 等 network idle → readability 提取。

- ✅ 优点：能抓 SPA（React/Vue 站）
- ❌ 缺点：**重**（Chrome 进程 200MB+，启动 1-3s）、**贵**、**攻击面大**（无头浏览器 RCE 历史）、运维复杂
- 📍 与 browser_use 的关系：rocky_agent 若已有 browser 工具（P0 overall.md §4 未列），web_fetch **不应内置浏览器**——动态页面应**降级提示用 browser 工具**（hermes `web_tools.py:1341` WEB_EXTRACT_SCHEMA 描述就这么写："If a URL fails or times out, use the browser tool"）

**三家都没有在 web_fetch 里内置浏览器**。openclaw 靠 firecrawl stealth proxy（云端浏览器）；hermes 靠 firecrawl backend；claude-code 干脆不支持。

#### 方案 3：第三方 reader API（jina ai reader 等）

**原理**：调 `https://r.jina.ai/<url>` → 返回干净 markdown。jina 在云端做渲染+提取。

- ✅ 优点：质量最高（含 JS 渲染）、零本地依赖、对 SPA 有效
- ❌ 缺点：**外部依赖**（服务可用性/隐私/费用）、**延迟**（2-5s）、**数据外发**（URL 和内容过 jina 服务器）
- 📍 openclaw 的 firecrawl/tavily provider 本质就是这类（`extensions/firecrawl/`、`extensions/tavily/`），但 firecrawl 是付费 API

**jina reader vs firecrawl vs tavily**：
| 服务 | 输入 | 输出 | 免费 | JS 渲染 |
|------|------|------|------|---------|
| r.jina.ai | URL | markdown | 有免费额度 | ✅ |
| firecrawl | URL | markdown/html/json | 付费 | ✅（含 stealth proxy） |
| tavily | query/URL | search results + extract | 付费 | 部分 |

#### 方案 4：混合（静态优先，失败降级）

**openclaw 实际架构就是这条**（`refs/openclaw/src/agents/tools/web-fetch.ts:601-657`）：

```
fetch HTML →
  if content-type == text/markdown → 直接用（Cloudflare "Markdown for Agents"）
  else if text/html:
    1. 试 readability 提取（本地）
    2. 失败 → 试 fetch provider（firecrawl 云端）
    3. 都失败 → extractBasicHtmlContent（正则兜底）
    4. 全失败 → 抛错
  else if application/json → JSON.stringify 美化
  else → raw
```

### B.3 三家实际选型结论

| 项目 | 主路线 | 降级 | LLM 二次处理 |
|------|--------|------|-------------|
| **openclaw** | 本地 readability（`@mozilla/readability`+`linkedom`） | firecrawl 云端 → 正则 htmlToMarkdown | **不做**（直接给 LLM markdown，靠 wrapExternalContent 标记 untrusted） |
| **hermes** | 云端 backend（firecrawl/tavily/exa/parallel，`onlyMainContent`） | — | **做**（Gemini Flash 摘要，>5000 字触发，见 B.4） |
| **claude-code** | 整页 turndown（无 readability） | — | **做**（Haiku 按 prompt 提取，强制每次调用） |

**是否依赖现成框架**：
- openclaw：**自建 readability**（用 `@mozilla/readability` 库但自己包装提取器插件）
- hermes：**全靠 firecrawl 等云端服务**（不在本地做提取）
- claude-code：**自建 turndown + Haiku 摘要**（不做 readability 正文识别）

### B.4 LLM 二次摘要（hermes 深度参考）

hermes 的 `process_content_with_llm`（`refs/hermes-agent/tools/web_tools.py:342-439`）：

**触发阈值**（`:308`、`:385`）：`DEFAULT_MIN_LENGTH_FOR_SUMMARIZATION=5000` 字符，低于此跳过摘要直返原文。

**分级处理**（`:370-402`）：
| 内容大小 | 策略 |
|---------|------|
| > 2,000,000 字符（2MB） | **拒绝处理**，返回提示 |
| 500,000 - 2,000,000 | **分块**（chunk_size=100,000），并行摘要各块，再 synthesis |
| 5,000 - 500,000 | 单次 LLM 摘要 |
| < 5,000 | 跳过，直返原文 |

**输出上限**（`:373`）：`MAX_OUTPUT_SIZE=5000` 字符硬截断。

**完整 Prompt**（`refs/hermes-agent/tools/web_tools.py:488-502`，标准全文摘要）：

```

Create a well-structured markdown summary that includes:
1. Key excerpts (quotes, code snippets, important facts) in their original format
2. Comprehensive summary of all other important information
3. Proper markdown formatting with headers, bullets, and emphasis

Your goal is to preserve ALL important information while reducing length. Never lose key facts, figures, insights, or actionable information. Make it scannable and well-organized.

User: Please process this web content and create a comprehensive markdown summary:

{context_str}CONTENT TO PROCESS:
{content}

Create a markdown summary that captures all key information in a well-organized, scannable format. Include important quotes and code snippets in their original formatting. Focus on actionable information, specific details, and unique insights.
```

**chunk synthesis prompt**（`:646-656`）：

```
You have been given summaries of different sections of a large document.
Synthesize these into ONE cohesive, comprehensive summary that:
1. Removes redundancy between sections
2. Preserves all key facts, figures, and actionable information
3. Is well-organized with clear structure
4. Is under {max_output_size} characters

{context_str}SECTION SUMMARIES:
{combined_summaries}
```

**降级**（`:421-439`）：LLM 失败 → 返回前 5000 字符原文 + 截断标记（不返错误，因为前 5000 字比错误信息更有用）。

**claude-code 的类似做法**（`refs/claude-code/src/tools/WebFetchTool/prompt.ts:23-46` `makeSecondaryModelPrompt`）：每次调用都用 Haiku 按 user 的 prompt 提取（不是通用摘要，是任务驱动），且对非预批准域名加 **125 字符引用上限**（防版权问题）。

### B.5 输出格式与截断

| 项目 | 给 LLM 的格式 | metadata | 截断 |
|------|-------------|----------|------|
| openclaw | markdown（默认）或 text（`extractMode` 参数） | `title` 字段；payload 含 `url/finalUrl/status/contentType/extractor/tookMs`（`web-fetch.ts:671-689`） | `truncateText(text, maxChars)` + `wrapExternalContent` 标记 `untrusted:true`（防 prompt injection） |
| hermes | markdown | `url/title/content/error`（`web_tools.py:1142-1151`） | LLM 摘要后 5000 字硬上限；原文存 `raw_content` |
| claude-code | Haiku 的回答（非原文） | `bytes/code/codeText/url/durationMs` | `MAX_MARKDOWN_LENGTH=100_000` 喂 Haiku 前 truncate（`utils.ts:128,493`） |

**关键设计点（openclaw）**：
- `wrapExternalContent(text, {source:"web_fetch", untrusted:true})`（`firecrawl-client.ts:505-512`）—— 给抓回来的内容包**不可信标记**，防 prompt injection。这是 rocky_agent 应当采纳的安全模式。
- `externalContent: { untrusted: true, source: "web_fetch", wrapped: true }` 显式字段，让下游 context engine 知道这段内容不可信。

### B.6 安全（SSRF 防护）

#### hermes 的 SSRF（最完整，`refs/hermes-agent/tools/url_safety.py`）

- **强制校验**：所有 URL 经 `async_is_safe_url`（`web_tools.py:967`）才能进 backend。
- **禁止的 IP 段**（`url_safety.py:96-109`）：
  - 云 metadata：`169.254.169.254`（AWS/GCP/Azure）、`169.254.170.2`（ECS）、`100.100.100.200`（阿里云）
  - 整个 link-local `169.254.0.0/16`（`:108`）
  - IPv4-mapped IPv6 同款
- **CGNAT 段**（`:123`）：`100.64.0.0/10`（RFC 6598）—— `ipaddress.is_private` 漏判，需手工加。
- **DNS 双查防 TOCTOU**（`url_safety.py:17` 注释）：第一次查得公网 IP 通过校验，第二次实际连接可能返回内网 IP（DNS rebinding）。hermes 在校验后立即冻结。
- **白名单豁免**（`url_safety.py:112-120`）：用户可配 `security.allow_private_urls:true` 放行内网（企业代理/VPN 场景），但 **cloud metadata 永不放行**（`:87-105`）。

#### openclaw 的 SSRF（`refs/openclaw/src/infra/net/ssrf.ts`）

- **Pinned DNS**（`:629-666` `createPinnedDispatcher`）：resolve 一次 → 校验 IP → 把 IP 钉进 dispatcher 的 connect 选项，防 DNS rebinding。
- **重定向逐跳校验**（`fetch-guard.ts:474-646`）：每跳重新 resolve policy + 重新 pin DNS；跨 origin 重定向剥除 Authorization/Cookie（`retainSafeHeadersForCrossOriginRedirect`）。
- **重定向上限**：`DEFAULT_MAX_REDIRECTS=3`（`fetch-guard.ts:120`）+ 循环检测（`:637` visited set）。

#### claude-code 的安全

- **协议限制**：`http:` 自动 upgrade 为 `https:`（`utils.ts:376-379`）。
- **凭据 URL 拒绝**：`parsed.username || parsed.password` → 拒绝（`utils.ts:156`）。
- **重定向限制**：`isPermittedRedirect`（`:212-243`）只允许同 host（±www）+ 同 protocol + 同 port；跨 host 重定向不自动跟随，返回 redirect info 让 LLM 再发一次。
- **无 SSRF IP 校验**：靠云端 `domain_info` 预检 + 企业 egress proxy 兜底（不做本地 IP 校验）。

#### 推荐 rocky_agent 必做的 SSRF 清单

1. **协议白名单**：只允许 `http:`/`https:`（拒绝 `file:`/`ftp:`/`gopher:` 等）。
2. **IP 段黑名单**：禁内网（10/8、172.16/12、192.168/16）、link-local（169.254/16）、loopback（127/8）、CGNAT（100.64/10）、云 metadata、IPv6 ULA（fc00::/7）。
3. **DNS pinning**：resolve → 校验 → 钉 IP 进 dispatcher（防 rebinding）。
4. **重定向逐跳校验**：每跳重新跑 SSRF，跨 origin 剥敏感头。
5. **NO_PROXY 不豁免 SSRF**：代理模式下仍校验目标 host。

## §C. 推荐架构（可直接被 tech spec 引用）

### C.1 三层分层

```
┌─────────────────────────────────────────────────────────┐
│ Layer 3: 内容优化层（Content Optimization）              │
│  - readability 提取（@mozilla/readability + linkedom）  │
│  - htmlToMarkdown 兜底（正则版）                          │
│  - wrapExternalContent 标记 untrusted                    │
│  - LLM 二次摘要（可选，>阈值触发，参考 hermes 分块）      │
├─────────────────────────────────────────────────────────┤
│ Layer 2: 抓取层（Fetch）                                 │
│  - undici fetch + dispatcher                             │
│  - 超时（bodyTimeout/headersTimeout）                    │
│  - 重定向逐跳校验（max 3-5）                              │
│  - SSRF 校验（IP 黑名单 + DNS pinning）                   │
├─────────────────────────────────────────────────────────┤
│ Layer 1: 代理层（Proxy）                                 │
│  - undici EnvHttpProxyAgent（读 HTTP_PROXY/HTTPS_PROXY） │
│  - NO_PROXY 解析（复刻 undici matcher）                   │
│  - 无 env → 直连 Agent 降级                              │
│  - 代理失败 → 抛错（不静默降级直连，保 SSRF）              │
└─────────────────────────────────────────────────────────┘
```

### C.2 每层选型与理由

| 层 | 选型 | 理由 | 依赖 |
|----|------|------|------|
| **代理** | undici `EnvHttpProxyAgent` | 零依赖（Bun 内置）、语义完整、与 openclaw 一致、读系统 env | 无（内置） |
| **抓取** | undici `fetch` + `dispatcher` 注入 | 同上；可注入 dispatcher 是关键（global fetch 不支持） | 无 |
| **正文提取** | `@mozilla/readability` + `linkedom` | openclaw 验证过、零浏览器、对文章页效果好、有防护（max chars/nesting depth） | 2 个 npm 包 |
| **Markdown 兜底** | 自建正则 `htmlToMarkdown`（参考 `web-fetch-utils.ts:38`） | readability 失败时兜底；零依赖；openclaw 同款 | 无 |
| **JS 动态页面** | **不内置浏览器**，降级提示用 browser 工具 | 三家都没在 web_fetch 内置浏览器；hermes 明示此策略 | 无 |
| **LLM 摘要** | **可选**，>5000 字触发，分块+synthesis（参考 hermes） | 大幅省 token；但增加延迟+LLM 调用，初版可关 | 复用现有 LLM 客户端 |
| **第三方 reader** | **不引入**（jina/firecrawl） | v0.0.23 范围外；外部依赖/隐私/费用；本地 readability 已够 | 无 |

### C.3 与 rocky_agent 现有架构的对接

- **Tool 接口**：实现 `Tool` 接口（`app/server/src/tools/types.ts:121`），`definition` 给 LLM 声明，`run(input, ctx)` 调三层管线。
- **超时/取消**：复用 `ctx.signal`（`types.ts:102`），传入 undici fetch 的 `signal` + 转为 dispatcher 的 `bodyTimeout`。
- **错误归集**：SSRF 拦截 → 新增 `ToolErrorCode.SSRF_BLOCKED`（`types.ts:141`）；代理失败 → `ToolErrorCode.RUNTIME_ERROR`。
- **输出**：`ToolRunResult.content = [TextBlock]`（`types.ts:68`），文本为 markdown；过大时走 context offload（web_tools.md §2 TODO 已列）。
- **注册**：在 `defaultTools()`（`registry.ts:28`）加入 `webFetchTool`。

### C.4 边界与坑

1. **Bun 代理**：Bun 原生 `Bun.fetch` 不读 HTTP_PROXY，**必须用 undici 的 fetch + EnvHttpProxyAgent**。
2. **HTTP/2**：强制 `allowH2:false`（openclaw `undici-runtime.ts:38`）—— HTTP/2 dispatcher 在代理模式下不稳。
3. **dispatcher 释放**：每次 fetch 后 `await dispatcher.close()`，否则连接池句柄泄漏（openclaw `closeDispatcher` `ssrf.ts:710`，含 100ms 超时兜底）。
4. **NO_PROXY CIDR**：若用户用 fake-ip 代理（Clash/sing-box），需支持 IPv4 CIDR（`100.64.0.0/10`）放行——openclaw `proxy-env.ts:260-298` 有完整实现可抄。
5. **readability 防护**：HTML > 1MB 或嵌套深度 > 3000 直接放弃 readability（openclaw `web-content-extractor.ts:14-15`），防 DoS。
6. **不可信内容标记**：所有抓回内容用 `wrapExternalContent(text, {untrusted:true})` 包装，防 prompt injection（openclaw `external-content.ts`）。
7. **SSRF 不被代理绕过**：trusted-env-proxy 模式下仍跑 hostname policy（openclaw `fetch-guard.ts:524`）。
8. **重定向跨 origin 剥头**：Authorization/Cookie 在跨 origin 重定向时必须剥除（openclaw `retainSafeHeadersForCrossOriginRedirect`）。

### C.5 建议的 v0.0.23 范围

**纳入**：
- Layer 1 代理（undici EnvHttpProxyAgent + NO_PROXY）
- Layer 2 抓取（undici fetch + SSRF + DNS pinning + 重定向逐跳校验）
- Layer 3 readability + htmlToMarkdown 兜底 + wrapExternalContent

**延后（后续版本）**：
- LLM 二次摘要（需设计 auxiliary client 配置）
- 第三方 reader（jina/firecrawl provider 化）
- browser 工具联动（动态页面降级提示）
