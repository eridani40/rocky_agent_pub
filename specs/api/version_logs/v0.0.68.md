# v0.0.68 API Change Log

> version: 1.0 · 2026-07-05
> 一句话：mention search 新增 `workitem` / `member` provider 取值（按 session kind 派生可见集合）；send_message needReply 改可选 default:true（schema 影响）；board POST 写端点零变更（复用 v0.0.60 已有）。

## 1. IN-SCOPE API 变更

### 1.1 GET /mention/search（schema 扩）

**变更**：`provider` 参数新增 `workitem` / `member` 取值（既有 `file` / `skill` 保留）。

| 字段 | v0.0.67 | v0.0.68 |
|---|---|---|
| `provider` query 参数 | enum `'file' \| 'skill'` | enum `'file' \| 'skill' \| 'workitem' \| 'member'`（按 session kind 派生可见子集，见 D8 resolver） |

**新 provider 取值规则**（D8 resolver，按 session kind 派生）：

| session biz/role/derivation | 允许的 provider 集合 |
|---|---|
| playground / rocky / main | `[file, skill]` |
| playground / subagent / subagent | `[file, skill]` |
| studio / squad / main | `[file, skill, workitem, member]` |
| studio / leader / main | `[file, skill, workitem]` |
| studio / mate / main | `[file, skill, workitem]` |
| studio / subagent / subagent | `[file, skill]` |

**未授权 provider 试探**：若 client 传的 `provider` 不在该 session 的允许集合内 → 404 `ProviderNotFoundError`（不返 403，避免泄露 provider 存在性；与既有「未注册 provider → 404」语义一致）。

**新 provider 返回的 MentionItem 结构**：

```jsonc
// workitem
{
  "type": "workitem",
  "path": "workitem/task/T-0001",        // kind ∈ {goal, kr, requirement, task}
  "listView": {
    "title": "实现 OAuth 登录",
    "subtitle": "task · pending",
    "icon": "workitem"
  }
}

// member
{
  "type": "member",
  "path": "01HXXXXXXXXXXXXX",              // memberId（ULID）
  "listView": {
    "title": "Alice",
    "subtitle": "leader",                   // role
    "icon": "member"
  }
}
```

### 1.2 send_message 工具 schema（needReply 改可选 default:true）

**变更**：needReply 从「★ 必填」改为可选 + `default: true`。

| 字段 | v0.0.67 | v0.0.68 |
|---|---|---|
| `needReply` | required; type=boolean; 无 default | optional; type=boolean; `default: true` |

**影响**：
- LLM 调 `send_message({to, content})` 不填 needReply → server `validateInput` 末尾 default-fill 注入 `needReply=true` → 落库 `sender.agent.needReply=true`（接收方应回）
- LLM 显式填 `needReply=false` → 不被覆盖（normalize `?? true` 不动 false） → 接收方知是 FYI
- normalize 容错链路（形态 A-D）保留；形态 E（needReply 缺失）从「error」改「视为 true」

### 1.3 看板 POST 写端点（零变更，复用 v0.0.60）

R1 看板手动新建**复用 v0.0.60 已有 POST 端点**，无新 API：

- POST /squad/:id/board/goals（11b §3.1）
- POST /squad/:id/board/goals/:gid/krs（11b §3.2）
- POST /squad/:id/board/requirements（11b §3.3）
- POST /squad/:id/board/tasks（11b §3.4）

本版本只补 web api client helpers（前端缺），后端 API 无任何变更。
