# v0.0.71 API Change Log

> 仅影响 `/config/plugin` 域 GET inventory 响应形状。其他端点（`/config/app` / `/config/dev` / `/config/connectors` / chat / provider / model）完全不变。

## 1. 概述

`GET /config/plugin`（含 `?scopeId=` query）响应的 `tree.groups[]` 结构由**扁平 `extImpls[]`**（impl 跨 point 聚合）改为**嵌套 `points[].impls[]`**（impl 显式归 point 节点下），对齐「scope → group → point → impl」用户心智（PRD 路径 P2「显式层级」）。同时响应节点新增 `configSchema` 字段透传（D7 删 schemaConfig 后单一 schema 源），`config` 字段始终是 manifest default + scope configValues 合并结果（bug-A 修复）。

**PUT 行为不变**：`PUT /config/plugin` 仍返 405（v0.0.67 只读化保留）。scope 写端点（POST/DELETE scope + activate/deactivate）仍 405。

## 3. 字段级变更

### 3.1 `tree.groups[]` —— 嵌套化（破坏性）

| 字段 | BEFORE | AFTER | 备注 |
|---|---|---|---|
| `groups[].groupId` | string | string | 不变；值改自 groups.json 声明（D5 7 组） |
| `groups[].points[]` | 平铺 `{ pointId, activated }[]` | **嵌套** `{ pointId, activated, impls: ExtImplNode[] }[]` | impl 显式归 point 节点下 |
| `groups[].extImpls[]` | 跨 point 平铺 impl 数组 | **删除** | 数据迁进 `points[].impls[]` |

### 3.2 `tree.groups[].points[].impls[]` 节点（ExtImplNode）

| 字段 | BEFORE | AFTER | 备注 |
|---|---|---|---|
| `pluginId` / `implId` / `pointId` | string | string | 不变 |
| `type` | "exclusive"/"list"/"ordered" | 同 | 不变（cardinality → type 路由术语） |
| `pluginEnabled` | true（v0.0.67 恒 true） | true | 不变 |
| `enabled` | bool | bool | 不变（来自 scopes/*.json） |
| `order` | number? | number? | 不变（仅 ordered，per-point 连续 1..n） |
| `selected` | bool? | bool? | 不变（exclusive 选中标记） |
| `description` / `pointDescription` / `pluginDescription` | string | string | 不变（三级 description，i18n 占位符透传） |
| `pointActivated` | bool | **删除** | 信息已上提到 `points[].activated`（同 point 共享，避免冗余） |
| `schemaConfig` | Record? | **删除** | D7 删 schemaConfig 字段（全系统只剩 configSchema） |
| `configSchema` | 不存在 | **新增** JsonSchema? | D7 透传 manifest configSchema（让前端 modal 可读 JSON Schema 形状） |
| `config` | Record?（裸 configValues，未声明时 undefined） | Record（始终 = manifest default + scope configValues 合并） | **bug-A 修复**：JOIN manifest default（对齐 spec per-domain 默认表） |

### 3.3 顶层不变字段

- `tree.scope` / `tree.scopes` / `tree.plugins[]`：完全不变（plugin 级 enabled 恒 true、scope 列表 default 首位、scope 元信息来自代码声明）。

## 4. 行为不变项

- `PUT /config/plugin` 仍返 `405 Method Not Allowed`（v0.0.67 只读化）。
- scope 写端点（POST/DELETE scope + POST/DELETE activate）仍返 `405`。
- `GET /config/plugin/scopes` / `GET /config/plugin/scopes/:id/activations` 形状不变（数据源仍是 ScopeConfigProvider）。
- per-EP 回退（非 default scope 未激活 EP → 取 default 视图，`points[].activated = false`）：行为不变，UI 灰显 + `ext-point-{pointId}-inactive-hint`。
- 启动校验仍硬失败 throw（D6 加第 5 条不变量「registry ↔ groups.json 双向一致」，沿用 v0.0.67 D3 风格）。

## 5. AT 影响

- **现有 case 重写**：`tests/api/plugin/` 下基于扁平 `extImpls[]` 断言的旧 case 需重写为嵌套 `points[].impls[]` 路径（如有；test-plan 阶段扫描确认）。
- **新 case `inventory_nested_tc1`**（覆盖 PRD P1-P4）：
  - P1 GET default → 7 group 出现且顺序按 groups.json 声明（context-ingest / context-assemble / context-compact / context-engine / system-prompt / provider / web）
  - P2 嵌套结构 `groups[].points[].impls[]` + 每 EP 归属正确 group（如 `context_should_compact` 在 context-compact）
  - P3 `threshold_should_compact` 节点带 `configSchema`（透传）+ `config.compactRatio=0.6`（bug-A JOIN）
  - P4 GET `?scopeId=forked` → 只激活 context 子集 EP，未激活 EP `points[].activated=false` 且 impls 取 default 回退视图
- **不调 LLM**：本组 case 不走 chat 流程，`ROCKY_TEST_MOCK_LLM` 无影响；但 SERVER_PORT 须对齐（memory 教训 `test-env-base-url-align-api-port`）。

## 6. 向后兼容性

**破坏性变更**（schema 级，无 fallback）：
1. `groups[].extImpls[]` 删除 → 旧 client 解构失败（前端同步改）
2. `ExtImplNode.schemaConfig` 删除 → 旧 client 读 undefined（modal 改读 configSchema）
3. `ExtImplNode.pointActivated` 删除 → 信息上提到 `points[].activated`（旧 client 同步改）
4. `ExtImplNode.configSchema` 新增 → 旧 client ignore 新字段（向后兼容方向）
5. `ExtImplNode.config` 行为变化（undefined → 合并 default）→ 旧 client 显示从「无值」变「显式默认值」（符合用户期望 P3）

**未引入兼容层**：v0.0.71 是内部版本，前后端同 PR 同步改，无需 deprecated 期。AT case 同期重写。
