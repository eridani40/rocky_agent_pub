# v0.0.67 API 变更日志 — plugin config refactor（写端点删，配置代码化）

> version: 1.0 · 2026-07-05
> 一句话定位：**plugin config 写端点全部废弃**（PUT 返 405）——配置迁代码声明 `app/plugins/scopes/*.json`，**GET 端点保留**（inventory + scope list + activation list）。无 API 接口新增。
> 关联：tech `specs/tech/version_logs/v0.0.67/change_log.md`（详细技术变更）+ prd `specs/prd/version_logs/v0.0.67.md`（PRD 摘要）。

---

## 1. API 变更

### 1.1 写端点删（返 405 Method Not Allowed）

| 端点 | v0.0.66 前行为 | v0.0.67 行为 |
|---|---|---|
| `PUT /config/plugin` | 写 plugin/ext impl 的 enabled/config/order/exclusive op | **405 Method Not Allowed**（handler 层 method 检查） |
| `POST /config/plugin/scopes` | 创建 scope | **405** |
| `DELETE /config/plugin/scopes/:id` | 删 scope（cascade 清 activation + impl record） | **405** |
| `POST /config/plugin/scopes/:id/activate/:pointId` | 激活某 scope 的某 EP | **405** |
| `DELETE /config/plugin/scopes/:id/activate/:pointId` | 取消激活 | **405** |

**理由**（design §3 D4 用户纠正）：所有 enabled/order/exclusivePick/activatedPoints 配置迁代码声明 `app/plugins/scopes/*.json`（每 scope 一文件，唯一源）；运行时不读落盘 `plugin_policy/`（仅 lazy migrate 兼容）；写端点保留死代码无意义，直接删 handler PUT 路径 + service 写方法。配置改动需直接改代码声明 + 重启（强约定详 `specs/tech/plugin_system/[P1]scopes_config_decl.md §4`）。

### 1.2 GET 端点保留（数据源切到 ScopeConfigProvider）

| 端点 | 行为 | v0.0.67 数据源 |
|---|---|---|
| `GET /config/plugin` | 取 inventory 全量树 | `scopes/*.json`（v0.0.66 前落盘 `plugin_policy/{kind}/`） |
| `GET /config/plugin?scopeId=<id>` | 按 scope 视图取 inventory | 同上 |
| `GET /config/plugin/scopes` | 列所有 scope | `ScopeConfigProvider.listScopes`（v0.0.66 前落盘 `plugin_scope/`） |
| `GET /config/plugin/scopes/:id/activations` | 列激活 EP（default 返全 EP） | `ScopeConfigProvider.listActivatedPoints`（v0.0.66 前落盘 `ext_impl_scope_activation/`） |

### 1.3 GET inventory 响应字段语义变化

| 字段 | v0.0.66 前 | v0.0.67 |
|---|---|---|
| `plugins[].enabled` | 落盘 `plugin_policy` plugin 级 record | **恒 true**（plugin 级 native 受信，代码声明不存 plugin 级开关） |
| `groups[].extImpls[].enabled` | 落盘 `plugin_policy` impl 级 record | 代码声明 `scopes/*.json` 的 `impls[implId].enabled`（无声明默认 true） |
| `groups[].extImpls[].order` | 落盘 record order | 代码声明 `scopes/*.json` 的 `impls[implId].order`（无声明走末尾补位） |
| `groups[].extImpls[].config` | 落盘 record configValues | 代码声明 `scopes/*.json` 的 `impls[implId].configValues`（secret 不进代码声明 D1，由 dev config/env 注入） |
| `groups[].extImpls[].selected`（v0.0.55） | 派生自落盘 enabled + effective order | **派生自代码声明**：scope 的 `exclusivePicks[pointId]=implId` 声明选中项 + enabled + effective order 最小者 |
| `groups[].points[].activated` | 落盘 `ext_impl_scope_activation/` record | 代码声明 `scopes/*.json` 的 `activatedPoints` 字段（default 全 true D6 短路） |
| `scopes[]` | 落盘 `plugin_scope/` record | 代码声明 `ScopeConfig` 的元信息（无 `createdAt` 信封字段，前端兼容用 epoch 占位） |

> **响应字段类型 / 形状不变**（向后兼容）：`PluginInventoryTree` interface 字段全部保留，前端零改动；只是值源切换。

## 2. AT 影响

### 2.1 v0.0.67 新增 AT 断言/case

- **PUT 返 405 case**：PUT `/config/plugin` 携带任意 op body → 断言响应 `405` + body `{"error":"Method Not Allowed"}`。
- **scope 写端点返 405 case**：POST/DELETE scope + activate/deactivate → 断言响应 `405`。
- **GET inventory 数据源验证 case**：GET `/config/plugin?scopeId=default` → 断言 `plugins[].enabled === true`（恒 true）+ exclusive EP 的 impl `selected` 字段与代码声明 `scopes/default.json` 的 `exclusivePicks` 一致。
- **default 短路 case**：GET `/config/plugin/scopes/default/activations` → 断言返全 EP（D6 短路，不依赖代码声明 activatedPoints）。
- **scope 视图 case**：GET `/config/plugin?scopeId=forked` → 断言 forked scope 的 activated EP（来自 `scopes/forked.json`）+ selected impl（来自 `exclusivePicks`）。

### 2.2 历史 AT case 适用性

| 历史 case | v0.0.67 影响 |
|---|---|
| v0.0.5/v0.0.18 GET inventory 路径断言 | **零影响**——响应字段结构不变（值源切换为代码声明） |
| v0.0.26 scope CRUD / activate 写端点 case | **作废**——返 405，需迁为新「写端点返 405」case |
| v0.0.18 setPointOrders PUT case | **作废**——PUT 返 405，需迁为新「写端点返 405」case |
| v0.0.55 selected 派生字段 GET case | **零影响**——派生规则不变，源切换为代码声明 |
