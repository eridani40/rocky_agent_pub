# v0.0.72 API Change Log

> 仅影响 `/config/app` 端点（新增 `web_search` group 读写）+ `/config/plugin` inventory 透传层（`web_search_provider` EP cardinality `exclusive`→`list`）。chat / provider / model / session / 其他 config group 端点完全不变。

## 1. 概述

`web_search` 凭证从 ext impl `configSchema`（v0.0.23 走 `/config/plugin` PUT `setImplConfig` 写）迁到 `app_config.web_search` group（走 `/config/app` PUT 写）；同时 `web_search_provider` EP 由 `exclusive` 改 `list`（多 provider 共存）。**PUT `/config/plugin` 仍 405**（v0.0.67 只读化保留），即 `setImplConfig`/`setExclusive` 路径已废弃——凭证写入唯一入口 = `PUT /config/app`。

## 2. `/config/app` 增 `web_search` group

### 2.1 GET

`GET /config/app?group=web_search&key=default`

响应（单实例，key 固定 `"default"`）：
```json
{
  "group": "web_search",
  "key": "default",
  "value": {
    "type": "zhipu",
    "credentials": {
      "zhipu": { "apiKey": "sk-..." }
    }
  }
}
```

- record 缺失 / `value` 为 null → tool 返 ToolError「web_search 未配置 provider type」（不回退默认）。
- `value.type` 缺失 → 同上。
- `credentials.<implId>.apiKey` 是 secret，GET 出参 **redact**（与 `dev_config.web.jinaApiKey` 同 §5.1 套路）。

### 2.2 PUT

`PUT /config/app` body：
```json
{
  "group": "web_search",
  "items": [
    { "key": "default", "data": { "type": "zhipu", "credentials": { "zhipu": { "apiKey": "sk-xxx" } } } }
  ]
}
```

- 整组提交（与现有 `/config/app` 整组提交语义一致）。
- secret 落盘原值，GET 出参 redact。

## 3. `/config/plugin` inventory 透传变化

`web_search_provider` EP 节点的 `cardinality` 字段由 `"exclusive"` 改 `"list"`。响应形状（v0.0.71 嵌套 `groups[].points[].impls[]`）不变，仅 EP 节点的 cardinality 值变。

- **不再有 `selected` 派生**（list EP 无 exclusive pick）。
- **不再调 `setExclusive`**（PUT `/config/plugin` 已 405，且 list 不需要单选）。
- 用户选择「当前 type」改在 `app_config.web_search.type` 表达，UI 渲染 choice-cards（应用设置 → 网络搜索 section）。

## 4.AT 覆盖

- `web_search` 工具真服务：apiKey 配好（path A PASS）/ apiKey 空（path A2 PASS：isError「不可用 / 凭证未配置」）/ type 未配置（path A0 PASS：isError「未配置 provider type」）。
- `app_config.web_search` 读写：GET redact + PUT 整组提交 + 重启持久化。
- 详见 `states/v0.0.72/verify/test-plan.md`。
