# v0.0.179 API Change Log

> 仅影响 `/config/plugin` inventory 的**字段派生源**（`ExtImplNode.enabled`/`selected`）+ YAML 配置层模型（`app/plugins/scopes/*.yaml` 废 `selected`/`enabled`/`exclusivePicks`/delta merge）。**HTTP 端点集合、请求/响应形状全部零变更**；PUT 仍 405。chat / provider / model / session / 其他 config group 端点完全不变。

## 1. 概述

plugin scope 配置模型从「selected/enabled/exclusivePicks + delta 兜底」简化为 **impl 列表模型**：

- **配置 = impl 列表**：一个 EP 在某 scope 的 YAML——**不出现 = 继承 default 全量；出现 = 用自己声明的完整列表（全量替换，零 delta merge）**。
- **membership = active**：impl 在列表 = active，不在 = inactive（无 `enabled` 字段、无 `?? true` 兜底）；数组序 = order（无 `order` 字段）；exclusive EP 选中 = 数组恰好 1 项（validator 启动校验，无 `selected`/`exclusivePicks` 字段）。
- **运行时统一 `getExtensionImpls`**：filter membership + 按数组序排序 + instantiate，**无 cardinality 分支**；cardinality 仅 validator（exclusive 恰好 1）+ UI（按 type 渲染）消费。

`impls: []`（空数组）= 显式声明该 EP 0 个 active impl（要继承 default 就删整个 point 节点，不要用空数组占位）。

## 2. GET `/config/plugin` inventory 字段语义变更

**响应形状零变更**（`PluginInventoryTree` / `ExtImplNode` 字段集合、类型、嵌套结构全部不变），仅两字段**派生源**切换：

| 字段 | 旧派生源（v0.0.67–v0.0.178） | 新派生源（v0.0.179 起） |
|------|------|------|
| `ExtImplNode.enabled` | `ScopeConfig.impls[implId].enabled ?? true`（无声明默认 true） | **membership**：`getImplConfig(sourceScope, implId) !== undefined`（impl 在该 EP 源 scope 的 impls 列表 = true，不在 = false，无兜底） |
| `ExtImplNode.selected`（仅 exclusive point） | 代码声明 `exclusivePicks[pointId]` 指定项 | **active 中 effective order 最小者**（validator 保证 exclusive 恰好 1 active → 正常情形 = 唯一 active 项） |

其余字段语义不变：`type`（cardinality 透传，UI 按 type 渲染 radio/checkbox/ordered）、`order`（per-point 连续 1..n，inventory 经 `computeEffectiveOrders` 末尾补位连续化）、`config`（JOIN manifest default ⊕ scope configValues）、`activated`、`scope`/`scopes`、三级 description 透传。

**行为可见差异（唯一场景）**：某 impl 已注册但**未列进** default.yaml 对应 EP 的 impls 数组——旧模型 inventory 显示 `enabled=true`（兜底），新模型显示 `enabled=false`（正确语义）。当前 default.yaml 已满基线列出全部默认 active impl，无此差异实例。

## 3. YAML 配置层模型变更（`app/plugins/scopes/*.yaml`）

| 维度 | 旧（delta 模型） | 新（impl 列表模型） |
|------|------|------|
| 文件格式 | `*.json`（扁平 ScopeConfig） | `*.yaml`（groups→points→impls 三层树，loader 转扁平 ScopeConfig） |
| active 表达 | `impls[implId].enabled`（缺省 `?? true` 兜底） | **在 impls 数组 = active**（membership，无兜底） |
| order 表达 | `impls[implId].order` 字段 | **数组序即 order**（loader 填 1-based） |
| exclusive 选中 | `exclusivePicks[pointId] = implId` | **impls 数组恰好 1 项**（validator 启动校验，0 或 >1 throw） |
| EP 未配置 | per-EP 回退 default | 不变（per-EP 继承保留）：EP 节点不出现 = 继承 default 全量 |
| EP 已配置 | delta（未列 impl 走兜底） | **全量替换**（用自己声明的完整列表，零 delta） |
| 显式 0 active | 全部 `enabled: false` | `impls: []`（空数组；要继承 default 应删整个 point 节点） |
| 旧字段出现 | — | loader **不读、不 throw、不 warn**（解析分支已删） |

**default.yaml 满基线要求**：新模型无「注册未声明 → 默认 active」兜底——default scope 必须显式列出全部期望 active 的 impl（含 `search_indexing`、`squad_workspace`、`squad_team_status` 等旧靠兜底 active 的 impl），漏列 = 功能静默 inactive。

## 4. PUT 仍 405（不变）

`PUT /config/plugin` + scope 写端点（POST/DELETE scope + activate/deactivate）全部仍返 `405 Method Not Allowed`（v0.0.67 只读化保留）。配置改动 = 直接改代码声明 `app/plugins/scopes/*.yaml` 并重启。

## 5. 向后兼容分析

- **HTTP 契约**：端点集合、请求形状、响应形状（字段名/类型/嵌套）**全部不变**——纯派生源内部切换，前端/AT 消费字段值语义不变（`enabled: boolean`、`selected: boolean`）。
- **前端**：`api-client.ts` 的 `PluginExtImpl` 字段全保留；plugin-config-page 按 `type` 渲染 + 读 inventory 派生值的逻辑零改动。
- **AT 影响**：inventory 断言（`enabled`/`selected`/`order`/`activated` 字段存在性与值）在满基线 default.yaml 下无值差异，无需重录；涉及「注册但未列进 YAML」场景的断言才需按新语义（`enabled=false`）更新。
- **破坏性（非 HTTP 面）**：YAML 配置层是代码声明（非用户数据），模型变更随代码一起发布；无运行时数据迁移（配置不进落盘，重启即新语义）。
