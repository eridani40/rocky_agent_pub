# v0.0.92.sse_opt — API 影响

> version: v0.0.92 · slug: sse_opt · 2026-07-08
> 类型：纯前端重构 / 优化型版本

## 结论：无 API 契约变更

本版本是**纯前端 transport / 生命周期重构**，对 HTTP/SSE 后端契约零改动。

- SSE 重连机制（W2）在 `SseClient`（前端）内部实现：fetch reader.read() catch 触发指数回退重连，复用既有 `GET /sse` endpoint；后端感知不到「重连」概念（每次 `GET /sse` 是新连接，backend sink Set 自动 add/remove）。
- `onResumed` 回调 + visibilitychange listener 都在前端 singleton 模块内，不发任何新 HTTP 请求类型（GET 校正走既有 `GET /session/:id` + `GET /messages`，由 caller 决定范围）。
- `useLifecycle` hook（W4）+ 试点迁移（W5）是前端抽象层重构，调的还是既有 HTTP 端点（`GET /memory/:scope` / `GET /session/:sid/summary` 等）。

## 受影响 endpoint 行为（全部不变）

| Endpoint | 行为 | 备注 |
|---|---|---|
| `GET /sse` | 不变 | SSE 长连接 fetch-stream；前端可能多次断连重连（重连 = 新建一条 GET /sse） |
| `POST /sse/subscribe` `{ topic, group, subId }` | 不变 | 前端重连后 subId 复用（handlers Map 不清），但 POST 是新调用——若 backend 也已重启（dev HMR 场景），handlers 会重新注册，listener 会重建 |
| `DELETE /sse/subscriber/:subId` | 不变 | unmount 触发，best-effort |
| `GET /session/:id` / `GET /messages` / `GET /session/:id/usage` | 不变 | 校正回调（onResumed + visibilitychange）调用，行为与 v0.0.91 一致 |
| `GET /memory/:scope` / `POST/PATCH/DELETE /memory/...` | 不变 | useMemoryCrud 迁 useLifecycle 后仍调这些端点 |
| `GET /session/:sid/summary` / `POST /session/:sid/compact` | 不变 | MemberPanelMemory 迁后仍调 |
| `GET /budget/usage` / `GET /config/connectors` / `GET /session/:sid/cron` | 不变 | 轮询保留，仅前端加后台 tab 暂停 |

## 不涉及的新增 / 删除 endpoint

无。本版本零后端代码改动（`app/server/` 不动）。
