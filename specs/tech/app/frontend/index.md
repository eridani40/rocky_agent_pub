# Frontend 子系统总起（web/ 渲染层）

## ① 是什么

frontend = **`app/web/` 渲染层的所有契约**——技术选型、设计 token + 组件词表、组件分层架构、与后端 event-hub 之间的 SSE 桥。本 KB 是「渲染层怎么搭、长什么样、怎么订阅事件」的权威源；具体每个组件的 testid/props/视觉基线在 `specs/ui/components/`（不在本 KB）。

## ④ 核心设计原则（跨文件不变量）

1. **[v0.0.165 修订] 中性壳彩色身份（light-only）**——chrome（背景/面板/边框/按钮/tab/focus）一律黑白灰；高饱和色**只**承载身份识别（8 色 hash palette 头像/icon + 4 态语义色 presence/status + brand-grad R logo）。dark mode 下线。**旧决策 v0.0.164 及之前用暖色（terracotta/sage/gold）已推翻**，历史见 `[P0]design_system.md §5.1 (归档)`。→ `specs/ui/regulation/03-principles.md §1/§2/§4`；`01-tokens.md §1/§2`
2. **token 经 CSS 变量定义，Tailwind theme 引用变量**——单一物理源 + 换肤零成本（v0.0.165 换银灰实证：只替 tokens.css 变量值 + 组件走 `var(--*)`，56 hex 一次清零）。**[v0.0.165] 双轨命名兼容**：`--color-*` 前缀 alias 保留但灌新中性值，新代码走 regulation 无前缀 token；INV-9 兼容。→ `design_system.md §3/§5.4`；`specs/ui/regulation/01-tokens.md`
3. **组件式架构，单文件单组件**——五层分层 + 单向组合 + 文件名=组件名；可复用/可测试/可维护/spec 对齐。→ `component_architecture.md §1/§2`
4. **SSE 单链路复用，零新协议**——isSessionActive 复用 `subs` Map 信号聚合「前台」，session_meta 复用 EventHub 只加 topic；不引入 registry/心跳/wildcard。→ `sse_channel.md §7/§10.1`
5. **未读+前台都是 session 层的事（关注点分离）**——session 层自治查 isSessionActive + CAS unread；agent-loop 不调、状态机不感知 SSE。→ `sse_channel.md §7`
6. **replay 仅 agent_loop 需要**——流式增量事件（subscribe 之前已 emit、未持久化的半截）需回放与 GET 拼全量；session_panel/session_meta 是快照态，replay 历史过时快照有害。→ `sse_channel.md §10.7`
7. **共享渲染内核 + 策略 hook（三视图零数据分叉）**——三视图差异不是「渲染逻辑不同」而是「策略不同」：playground/单聊/群聊复用同一 `ComponentMessageStream`，差异收敛到 4 个可选策略 hook（`resolveActor`/`messageFilter`/`blockFilter`/`sideOfMessage`）；不传 hook 全走默认（playground 视觉/行为零回归）。反例：若每视图独立实现渲染，reminder 过滤 / a2a 侧别 / member 头像逻辑会三处复制，数据层分叉。→ `[P0]component_architecture.md §3.3`
8. **run 态从 store 迁 hook + store 瘦身**——run 态本质是「当前查看 session」的派生态（SSE 驱动 + 初始 GET），不属于全局列表/拓扑，故从 `chat-slice` store 抽到 hook。**不写第三套 reducer**——复用 `chat-slice-reducer.applyAgentEventToMessages` + `session-slice-reducer.applySessionStatusUpdate`。反例：若 run 态留 store → 各写一套 SSE 订阅+reducer（逻辑漂移）或 store 膨胀挤占列表/拓扑。**[v0.0.94] 演进**：原单一 `useSessionRunState` 引擎（揽 5 区域）拆成自治 area-hooks（见概念 #17 + `[P0]chat_area_hooks.md`），三页 compose 同源；store 瘦身结论不变。→ `[P0]component_architecture.md §3.4`（历史）+ §3.11（拆解后现状）
9. **共享 UI 组装层，引擎数据与渲染解耦（消费方不再手写 JSX）**——run 态引擎吐出的字段（loading/enqueue/abort）若由各消费方各自拼 JSX 组装，容易漏接字段（单聊曾只接 loading+abort，漏了 enqueue 排队区，引擎早算好了字段却无人用）；故再抽一层共享组装件 `ComponentRunStateBar`/`ComponentRunStateAbortSlot`，playground + 单聊共用同一套，「是否渲染」的判断也统一收拢不再各写一遍同款条件。→ `[P0]component_architecture.md §3.5`
10. **[v0.0.42] session/run 两层状态严格分离**——session 层（粗：跑/中断中/停，GET /session + session_panel）驱动 stop 按钮（圆环动画+实心方框，interrupting 减速）；run/message 层（细：思考/生成/调工具/执行，agent_loop）驱动 on-message spinner（贴流式尾部，spinner+phase 同控件状态各自决定）。两层各自独立、互不耦合——session 层不依赖 runActive，run 层不依赖 sessionRunning。移除原浮动 loading 胶囊（用 run 层状态表达 session 在跑的语义混乱）。→ `[P0]sse_channel.md §9.1` + `[P0]component_architecture.md §3.7`
