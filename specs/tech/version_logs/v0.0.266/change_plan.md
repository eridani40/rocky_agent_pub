# v0.0.266 变更计划书 — attach 模式生命周期统一

> **method 级 review 合同**。架构期冻结：planner 按本表切 task，coder 按本表实现，code-reviewer 按本表查偏离。coder/doc-modifier 不改本文件；事后偏差写进 `change_log.md`。
> 技术驱动需求（无 PRD）。版本上下文：`states/v0.0.266/context.md`。上游设计：`specs/tech/agent/tools/[P1]browser_instance_manager.md`（v0.0.264 权威 spec，本版改 §3.3/§4.x「attach 保持现状」表述）+ `specs/tech/agent/tools/[P1]browser_tool.md`（§4/§7）。
> **架构期裁决**：① attach 纳入 BrowserInstanceManager（launch → 操作 → close 三模式统一；instance 用「可选字段 + mode 判别」扩展，attach 存 BrowserSession + cdpUrl，不走 worker）；② attach launch = ChromeMcpDriver.connect（经 InstanceManager 注入 attachDriver，key=sessionId:attach 幂等复用）；③ attach 操作类 action 经 `getReadyInstance` 前置校验后 tool.ts 主进程 dispatchAction（attach 的 screenshot 落盘需 ToolCtx，execute 保持 worker 语义不混入）；④ 异常自愈 = tool.ts 检查 dispatchAction 返回文本匹配 `isAttachConnectionLost` → `im.handleAttachLost`（state=dead + disconnect 清理）→ 下次 no_browser_instance；⑤ attach close = attachDriver.disconnect（不杀 chrome / 不删目录 / 不释放端口 / 不持久化）；⑥ action 枚举去 disconnect 统一 close；⑦ ConnectorManager 瘦身为「switch 门禁 + UI 状态」（删 connectForToolRun/getAttachSession/disconnect/getOwner，保留 enable/disable/bootstrap/getState/getAll）；⑧ bootstrap 共享 attachDriver 单例 + isAttachEnabled（读 switch）注入 InstanceManager；⑨ 前置校验统一三模式（attach 不再隐式 lazy connect）。

## 影响面评估

- **改动文件**：10 个代码/装配 + 3 个测试 + 4 个 specs（doc-modifier 阶段 5 同步）
- **风险点**：
  1. **BrowserInstance 可选字段**：worker-based 路径 non-null 断言集中（closeInstance/execute 的 worker 分支）——回归护栏靠 instance-manager.test.ts 全用例
  2. **ConnectorManager 接口瘦身**：删 4 方法影响 browser-connector-manager.test.ts + session-delete-connector-cleanup.test.ts + NoopConnectorManager——grep 确认无其他消费方（config-routes 只用 getAll/enable/disable）
  3. **action 枚举去 disconnect**：schema 契约变更——LLM 之前可能调 disconnect，删除后 attach close 语义 = close action（spec 同步 08-web-tools.md §4）
  4. **attach 失活判定文本匹配**：依赖 dispatchAction 返回 errorResult 文本——chrome-devtools-mcp 的错误文案可能变化（isAttachConnectError 已稳定 5+ 版本，扩展 transport 级模式）
  5. **attach 不持久化**：崩溃残留 MCP 代理进程接受（stdin EOF 自退 + 无 chrome/目录/端口/锁泄漏面）——已知边界，文档记录
- **不做**（明确排除）：attach 鉴权（单机本地不做）；attach 多 profile 维度（cdpUrl 非 profile，key=sessionId:attach 唯一）；MCP transport pid 暴露（attach 持久化记录——无泄漏面必要性）

# Delta 追加（2026-08-06 老板拍板：ActionExecutor registry 重构，T3）

> **背景**：老板审查 T1 实现指出 tool.ts L166 attach 分叉是抽象泄漏——「启动之后，任何 action 不该跟 mode 有关系」。
> **老板拍板设计**：抽象 protocol + 两 impl + registry，每个 mode 注册自己的 impl（headless/managed-profile 注册同一个 worker impl，
> attach 注册 attach impl）；tool.ts 操作 action 统一走 `im.execute()`（零 mode 分叉）；M1 的「execute 拒绝 attach」防御分支随之下线
> （execute 变正确路由而非拒绝）。**实例对象 = 句柄（handle）**：impl 方法签名 `launch(opts) → handle` / `execute(handle, action, params)` /
> `close(handle)`；manager 职责收敛为 key 计算 + 存取句柄 + 查 registry 分发 + 状态机，**不读句柄内部字段**（worker/session/userDataDir 直读
> 全收敛进 impl）；impl = 无状态策略集，一切资源操作经句柄。launch/close 保留 mode 语义（表达为 impl 内部行为而非 manager switch）。
