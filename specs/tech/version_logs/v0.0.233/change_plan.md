## PRD §4 四项待实证 — 架构决策（落本表前的方向锚）

| # | 待实证项 | 架构决策 | 理由 |
|---|---------|---------|------|
| 1 | 预检 API 形态 | **独立 `POST /squad/:id/member/derive-academy/preview`**（不复用 hire body 加 dryRun） | (a) 语义自明：预检=纯只读探查（读两侧 + 列清单 + 标同名），与 hire 写事务不同语义层级；(b) 路由天然：现有 `handleMemberRoute` 按 path 分发，新 path 不挤进 hire handler；(c) dryRun 混进 hire body 后单 handler 两套语义（dryRun 跳过事务校验只跑预检）→ AT 测预检须构造完整 hire body，绕；预检结果回程后裁决结果才生成，dryRun 复用 body 字段逻辑错位；(d) 入参三字段（classroomId/studentId/versionId）+ squadId（path），GET query 表达嵌套不优雅，POST 带 body 是项目常见模式（如 `POST /session/:id/run`） |
| 2 | 裁决 body schema | hire body `derive_academy` 分支扩 **`resolution?: { skills?: Array<{name, action: 'skip'\|'overwrite'}>; memory?: Array<{name, action}> }`**；per-item 全清单（前端同名项 toggle 直接对应）；**`resolution` undefined = 默认全 skip 同名 + 不同名 merge**（前端可省字段，向后兼容） | per-item 全清单比「只列 overwrite 白名单」更对称不易漂移；undefined 默认行为给前端兜底（旧 client 不传 → 同名全 skip，安全） |
| 3 | 预检读两侧实现 | 新增 `previewDeriveAcademySeed`（与 `seedMemberWorkspaceFromVersion` 同源）；抽内部 helper `enumerateVersionSource(sourceWorkspaceDir)` 共用源侧枚举逻辑；复用 `resolveAcademyDeriveIdentity` 三字段校验（classroom 存在 + version formal+active → 失败 throw `InvalidAcademySourceError` → 400 `invalid_academy_source`） | 复用校验保预检/hire 入参契约一致；抽 helper 避免预检/seed 源枚举逻辑双份；目标侧只对源项 `existsSync` 检测（不列全目录） |
| 4 | seed 按裁决执行 + 失败补偿 | `seedMemberWorkspaceFromVersion` 入参加 `resolution?`；替换 `copyDirTracking`（全量复制）为 **`copyDirTrackingConditional`**（逐顶层项 conditional copy：同名 + skip 跳过 / 同名 + overwrite 复制 / 不同名复制）；补偿沿用现状 `rmSync(written, {recursive, force})`——**安全不变量：written 只记本次实际写入的顶层项**（skip 不入 written → 不会误删 squad 原有同名项；written 永不含团队根 `.rocky/skills`/`.rocky/memory`/`.rocky/agents` 目录本身） | skip 不写入 = 补偿天然安全（沿用 v0.0.232 现状不变量）；AGENTS.md 个人差异文件落 `.rocky/agents/{name}-{memberId}.md` 同样记入 written，补偿精确删该文件 |

## 影响面评估

- **跨模块**：后端（academy_bridge + member-service + 2 handler + member 路由）∥ 前端（picker 组件 + api client/hook）∥ spec（tech 新机制 + api + ui）；后端契约（preview endpoint + hire body resolution schema）架构期冻结 → 前端可基于 spec 并行开发。
- **破坏性变更**：无。`seedMemberWorkspaceFromVersion` 入参 `resolution` 可选（undefined = 默认全 skip 同名 + 不同名 merge）；`copyDirTracking` 重命名 + 行为扩展（仅文件内部，外部不引用）；hire body resolution 可选。
- **行为变化**：derive_academy seed 从「同名覆盖」改为「同名默认 skip」（D3 用户决策）——这是本版本核心产品语义变更（用户可感知，PRD §12.15.3 已述）；前端 From Classroom 流程加预览面板（用户可感知，PRD §12.15.5 已述）。
- **依赖顺序**：底层 `member-academy-bridge`（preview + seed 改造）→ `member-service`（透传 resolution）→ handler（hire body + preview endpoint）→ 前端 picker。
- **风险点**：
  1. `copyDirTrackingConditional` 行为扩展须保留「源缺失返空 + 部分失败容忍」现状口径（否则 regression）；
  2. 补偿安全不变量必须 UT 覆盖（skip 项不删 squad 原有 / 补偿不删团队根目录）—— 归 UT（PRD 标「裁决为确定性文件操作归 UT」）；
  3. `member-academy-bridge.ts` 当前 174 行，加预检 + seed 改造预估 ~+85 行 → ~259 行 ≤300；若超 → coder 拆 `member-academy-preview.ts`（预检函数独立文件），属合理实现选择，不视为偏离。
