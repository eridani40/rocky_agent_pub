# v0.0.317 — 配置管理 · 保存交互全局规范

> req: v0.0.317 · PRD · 2026-08-10
> 审计依据：`outputs/page-layout-audit-2026-08-10.md`
> 功能层前置：v0.0.316（受控化 + 聚合器）已完成，本版本统一视觉/布局/交互层

## 1. 背景与目标

### 1.1 问题

v0.0.316 统一了「一个 tab 一个保存」的功能层（受控化 + dirty 聚合 + 子组件改 onChange）。但视觉和布局层未统一：
- 保存按钮有 4 种样式（TabSaveBar / GroupSaveBar / BTN_PRIMARY / 自定义 inline）
- 保存按钮位置有 5 种模式（sticky 底部 / group 底部非 sticky / 内容流底部 / 无独立保存 / 无保存）
- dirty 反馈不一致（文字提示 / 仅 disabled / 无反馈）
- 页面容器 max-width 有 3 种（880px / 920px / 无限制）
- 切 tab dirty 保护有/无不统一

### 1.2 目标

从设计思路出发，定义全局规范：
1. **三种交互范式**：明确每种页面的保存行为规则
2. **统一 SaveBar 组件**：所有需保存的页面复用同一组件
3. **统一页面布局标准**：容器/header/padding/max-width 一致
4. **全页面分类表**：每个页面归到哪种范式，当前→目标

## 2. 三种交互范式 [v0.0.317]

### 范式 A — 即时生效型

**定义**：改了就生效，不需要保存按钮，无 dirty 概念。

**适用条件**（全部满足）：
- 操作是原子单字段变更（toggle / select / 安装 / 删除）
- 无需校验组合字段（改一个不影响另一个）
- 失败可容忍（乐观更新 + 后台 PATCH，失败 toast 提示）

**规则**：
- 无 SaveBar
- toggle / select / action → 即时 API 调用（乐观更新或 await + reload）
- 失败时显示 toast/error，控件回滚或保持（按场景）

**归属页面**：通用·语言、连接器、渠道（list toggle）、技能管理、插件配置（只读）、记忆 CRUD

### 范式 B — 表单保存型（Draft → Submit）

**定义**：改了进草稿（draft），底部 sticky SaveBar 统一提交。

**适用条件**（任一满足）：
- 多字段组合校验（改 name + model 一起提交）
- 文本输入需自由编辑（不适合每次按键即 PATCH）
- 跨不同 API group 但用户视角是同一组配置（工具 tab 4 section）

**规则**：
- **一个 tab 一个 SaveBar**（底部 sticky，始终可见）
- dirty = draft !== baseline（任一字段变即 dirty）
- dirty 时 SaveBar 高亮：`● 有未保存的改动`（左）+ 取消按钮 + 保存按钮（右）
- 非 dirty 时：保存按钮 disabled（描边灰色），取消按钮 `visibility:hidden`（布局稳定）
- 保存中：按钮 disabled + 文案「保存中...」
- 取消 = draft 回 baseline（重置）
- 保存 = 提交全部 dirty 字段（原子 PATCH 或逐 group PUT + Promise.allSettled）

**归属页面**：团队管理 tab、自动工作 tab、App Config 各 tab（会话/工具/可观测性/整理）

### 范式 C — CRUD 列表型（Master-Detail）

**定义**：列表（master）+ 详情/表单（detail）。列表级无 SaveBar，进入详情后详情级有 SaveBar。

**适用条件**：
- 实体列表 + 每个实体可独立编辑（增删改）
- 每个实体有自己的字段集合和校验
- 编辑态与列表态视觉分离（详情页 / 弹层 / 抽屉）

**规则**：
- **list 级无 SaveBar**（列表只展示 + 删除/启用等即时操作）
- 进入 detail/form 后：**detail 级底部 SaveBar**（sticky，同范式 B 规则）
- 新建（create）= 空表单 + SaveBar（保存 = POST 创建）
- 编辑（edit）= 回填表单 + SaveBar（保存 = PUT 更新）
- 返回 list 时如有 dirty → 弹确认（丢弃改动/取消返回）

**归属页面**：供应商（providers list → detail）、渠道（channel list → form）

## 3. SaveBar 统一规范 [v0.0.317]

### 3.1 唯一组件

所有范式 B/C 页面复用 **同一个 SaveBar 组件**（基于现有 `component-tab-save-bar.tsx`，升级为全局通用）。

### 3.2 布局

```
┌─────────────────────────────────────────────┐
│  ● 有未保存的改动          [取消]  [● 保存]  │  ← sticky bottom-0
└─────────────────────────────────────────────┘
```

- 位置：**sticky bottom-0**，始终可见，不随内容滚动
- 结构：左 dirty 状态文 + 右操作区（取消 + 保存）
- 背景：`bg-surface border-t border-border`

### 3.3 状态

| 状态 | dirty 文字 | 取消按钮 | 保存按钮 |
|------|-----------|---------|---------|
| 干净（无改动） | `✓ 已保存`（muted 色） | `visibility:hidden`（占位） | disabled，描边灰色 |
| dirty | `● 有未保存的改动`（accent 色） | visible，描边 | `● 保存`，accent 实底高亮 |
| saving | `● 有未保存的改动` | disabled | disabled，文案「保存中...」 |
| saved 反馈 | `✓ 已保存`（emerald 色 ~1.5s） | `visibility:hidden` | disabled |

### 3.4 按钮样式（统一）

| 元素 | 样式 |
|------|------|
| 保存按钮 dirty | `min-w-24 px-4 py-1.5 rounded-md text-sm bg-accent text-white hover:opacity-90` |
| 保存按钮 disabled | `min-w-24 px-4 py-1.5 rounded-md text-sm border border-border text-fg-2` |
| 取消按钮 | `min-w-24 px-4 py-1.5 rounded-md text-sm border border-border text-fg-2 hover:bg-bg-warm` |
| dirty 文字 | `text-xs`（dirty=accent / 干净=muted / saved=emerald-600） |

**布局稳定性**：取消按钮用 `visibility:hidden` 预留空间（禁 `display:none`），dirty 切换不位移。

### 3.5 废弃组件

以下组件统一废弃，替换为全局 SaveBar：
- `component-group-save-bar.tsx`（GroupSaveBar）→ 全局 SaveBar（范式 B 页面只有 tab 级 SaveBar，不再有 group 级）
- `BTN_PRIMARY` 保存按钮（manage-tab）→ 全局 SaveBar
- autowork-tab 自定义 inline 保存按钮 → 全局 SaveBar
- provider-detail 自定义 inline save-bar → 全局 SaveBar

## 5. 多级页面保存归属规则 [v0.0.317]

### 5.1 规则

多级页面（list → detail / parent tab → child section）的 SaveBar **永远挂载在最内层有 dirty 的编辑单元上**，不越级。

| 场景 | 层级结构 | SaveBar 归属 | 理由 |
|------|---------|-------------|------|
| 供应商 | providers list → provider detail | **detail 级** | 每个 provider 独立编辑，list 级无编辑行为 |
| 渠道 | channel list → channel form | **form 级** | 每个渠道独立表单，list 级只有 toggle/删除 |
| 工具 tab | tab → 4 个 section（web_search/bash...） | **tab 级**（聚合 4 section） | 4 section 是同 tab 内的配置组，用户视角统一保存 |
| 自动工作 tab | tab → toggle + heartbeat + budget | **tab 级**（聚合 3 子组件） | 3 子组件是同 tab 的配置组 |
| 管理 tab | tab → name/desc/model + groupChat toggle | **tab 级**（聚合全部字段） | 全部字段统一提交 |

### 5.2 判断流程

```
页面是否有 dirty 编辑行为？
├─ 否 → 范式 A（无 SaveBar）
└─ 是 → 编辑发生在哪一层？
    ├─ 列表层（toggle/删除/安装）→ 范式 A（即时，无 SaveBar）
    └─ 详情/表单层 → 该层挂 SaveBar（范式 B 或 C）
        └─ 同一层有多个独立编辑单元？→ 该层聚合 dirty，一个 SaveBar（范式 B）
```

### 5.3 禁止的行为

- **禁止跨级 SaveBar**：list 级不显示 detail 的 SaveBar（detail 卸载后 dirty 随之消失）
- **禁止同级多 SaveBar**：同一 tab 内不出现两个 SaveBar（范式 B 核心）
- **禁止 SaveBar 嵌套**：tab 级 SaveBar 内不再嵌 group 级 SaveBar

## 6. 页面布局标准 [v0.0.317]

### 6.1 容器结构（统一）

```
<main className="flex-1 overflow-y-auto">
  <div className="mx-auto max-w-[880px] px-8 pt-6 pb-10">
    {/* header */}
    <header className="pb-[18px] border-b border-border mb-6">
      <h1 className="text-[20px] font-semibold">{title}</h1>
      <p className="text-xs text-muted mt-1">{description}</p>
    </header>
    {/* tab 栏（如有） */}
    {/* 内容区 */}
  </div>
  {/* SaveBar（范式 B/C，sticky bottom-0） */}
</main>
```

### 6.2 布局参数

| 参数 | 值 | 说明 |
|------|-----|------|
| max-width | **880px** | 全局统一（connector/channel/skill 已对齐） |
| 内容区 padding | `px-8 pt-6 pb-10` | header + 内容统一 |
| header 结构 | title 20px/600 + desc 12px/muted + `border-b pb-[18px] mb-6` | 对齐 connector/channel/skill |
| overflow | `main: flex-1 overflow-y-auto` | 内容区滚动 |
| SaveBar 位置 | `sticky bottom-0`（在 main 内、内容区外） | 始终可见 |

### 6.3 特例

| 页面 | 特例 | 理由 |
|------|------|------|
| 团队管理面板（SeatsPanel） | header 复用 SeatsPanel 统一 header（不单独渲染） | tab 切换在同一面板内，header 共享合理 |
| App Config | header 复用 tab 树导航结构 | 左侧 tab 树 + 右侧内容区已有 header |

> **原则**：max-width + padding + overflow 全局统一；header 结构按页面结构允许特例（复用父级 header），但内容区 padding 必须对齐。

### 6.4 团队管理面板改动

当前 SeatsPanel 内容区 `max-w-920px px-8 pb-10 pt-5` → 改为 `max-w-[880px] px-8 pt-6 pb-10`（对齐全局标准）。

SaveBar 挂载位置：管理 tab / 自动工作 tab 的 SaveBar 从内容流内移到 **SeatsPanel 内容区底部 sticky**（tab 切换时 SaveBar 跟随当前 tab 的 dirty 状态）。

## 7. 切 tab dirty 保护规则 [v0.0.317]

### 7.1 规则

有 dirty 未保存时切 tab（含切同级 tab 和返回 list），**弹确认 modal**：

```
┌───────────────────────────┐
│  有未保存的改动           │
│  切换将丢弃当前改动       │
│                           │
│         [取消]  [丢弃改动] │
└───────────────────────────┘
```

- **取消**：留在当前 tab，保持 dirty
- **丢弃改动**：确认切换，draft 丢弃

### 7.2 适用范围

| 场景 | 有 dirty 保护？ |
|------|---------------|
| 范式 B tab 间切换（管理→自动工作） | ✅ 弹确认 |
| 范式 B App Config tab 间切换 | ✅ 弹确认（已有，保持） |
| 范式 C detail→list 返回 | ✅ 弹确认 |
| 范式 A 页面切换 | ❌ 无 dirty，不弹 |

### 7.3 实现

团队管理面板（SeatsPanel）当前切 tab 无 dirty 保护。需在 tab 切换层加 dirty 门控：切 tab 前检查当前 tab dirty → dirty 则弹确认 modal → 确认后才切换。

App Config 已有此机制（`page-app-settings-merged.tsx`），保持不变。
