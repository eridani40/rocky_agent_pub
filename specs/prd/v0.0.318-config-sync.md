# v0.0.318 — 配置同步（导入导出）PRD

> 引入版本: v0.0.318 | 2026-08-10

## 1. 背景与目标

### 1.1 背景

用户在多台机器上使用 rocky_agent 时，需要重复配置模型 provider（baseUrl / apiKey / models 列表）和工具参数（web_search / web_fetch / see_image / bash）。当前无配置迁移机制，用户只能手动逐项重配。

### 1.2 目标

- **一键导入导出**模型 + 工具配置，实现跨机器配置同步
- 导出/导入均提供**树形勾选**界面，用户自主选择导入导出范围
- 导出产物为**加密 JSON 文件**，可直接传输到另一台机器导入

### 1.3 非目标

- 不做云端同步（仅本地文件导入导出）
- 不做全量应用配置同步（仅模型 + 工具两类）
- 不做增量/合并导入（模型=纯注入，工具=整 tab 覆盖）

## 2. 功能详细设计

### 2.1 入口位置 [v0.0.318]

**应用设置 → 左侧 sidebar「用户设置」区 → 「全局长期记忆」tab 下方 → 新增「配置同步」tab**

- 位于用户设置区（非系统设置收起区）
- 与 user_memory tab 同层级，为其紧邻下方 tab item
- 选中后右栏渲染配置同步功能页（含「导出配置」和「导入配置」两个操作入口）

### 2.2 导出流程 [v0.0.318]

**描述**：用户选择要导出的配置节点，系统将选中内容打包为加密 JSON 文件下载。

**优先级**：P0

**用户故事**：作为用户，我希望选择性地导出模型和工具配置，以便在另一台机器上导入使用。

#### 用户行为链路

1. 点击「配置同步」tab → 右栏显示配置同步页
2. 点击「导出配置」→ 进入导出树形选择页
3. 树结构展开：
   - **📁 模型配置**（根节点，全选/取消全选子节点）
     - ☑️ `{provider.label}`（每个 provider 一个叶子节点，显示 label + protocolId）
   - **📁 工具配置**（根节点，全选/取消全选子节点）
     - ☑️ 网络搜索（web_search）
     - ☑️ 网络抓取（web_fetch）
     - ☑️ 看图理解（see_image）
     - ☑️ 命令行（bash）
4. 用户勾选要导出的节点（支持文件夹级全选/取消）
5. 点击「导出」按钮 → 系统读取选中配置数据 → 加密 → 生成 `.json` 文件下载
6. 文件名格式：`rocky_agent_config_YYYYMMDD_HHmmss.json`

#### 界面要素

- 两棵树（模型配置树 + 工具配置树），checkbox 勾选
- 树节点：folder 级 checkbox 联动子节点全选/取消；叶子级 checkbox 独立
- 底部「导出」按钮（disabled 当无任何选中项）
- 导出成功 toast 提示

### 2.3 导入流程 [v0.0.318]

**描述**：用户选择加密 JSON 文件，系统解密解析后呈现树形结构，用户勾选要导入的节点执行导入。

**优先级**：P0

**用户故事**：作为用户，我希望从导出文件中选择性导入配置，并了解哪些会与现有配置冲突。

#### 用户行为链路

1. 点击「配置同步」tab → 右栏显示配置同步页
2. 点击「导入配置」→ 弹出文件选择器
3. 选择 `.json` 文件 → 系统解密 + 解析
4. 解析成功 → 呈现树形勾选页：
   - **📁 模型配置**
     - ☑️ `{provider.label}`（所有节点默认勾选，全部可选）
       - 本地已有同名 provider（按 `label` 判定）→ 节点后面显示**提醒标签**「存在重名」（不影响勾选，不置灰）
       - 本地无同名 → 正常显示
   - **📁 工具配置**
     - ☑️ `{工具 tab 名}`（所有节点默认勾选，全部可选）
5. 用户勾选/取消要导入的节点（重名节点也可正常勾选导入）
6. 点击「导入」→ 执行导入：
   - **模型**：每个选中的 provider 执行**注入**（生成新 id，新增到本地，不覆盖已有）
   - **工具**：每个选中的 tab 执行**覆盖**（整 tab 配置替换本地对应 group）
7. 导入完成 toast 提示 + 自动刷新相关配置页

#### 界面要素

- 文件选择入口（按钮触发系统文件选择器）
- 解密/解析失败 → 错误提示（不进树形页）
- 树形勾选页（与导出树视觉一致）：
  - 模型 provider 节点：全部默认勾选 + 可选；重名节点后面显示「存在重名」提醒标签（不置灰、不阻止勾选）
  - 工具 tab 节点：全部默认勾选 + 可选
- 底部「导入」按钮（disabled 当无任何选中项）
- 导入确认 modal：「即将导入 N 个模型配置、M 个工具配置，工具配置将覆盖现有设置。确认导入？」

### 2.4 树交互规范 [v0.0.318]

| 交互 | 行为 |
|------|------|
| 点击 folder checkbox | 联动所有子节点全选/取消全选 |
| 点击 leaf checkbox | 独立切换自身选中态 |
| folder 全选态 | 所有子节点选中 → folder 显示选中 |
| folder 部分态 | 部分子节点选中 → folder 显示半选（indeterminate） |
| 导出树 | 所有节点默认可选，初始全选 |
| 导入树·模型 | 所有节点默认勾选 + 可选；重名 provider（label 匹配）节点后面显示「存在重名」提醒标签（不置灰、不阻止勾选） |
| 导入树·工具 | 全部可选，初始全选 |

### 2.5 重名提醒规则 [v0.0.318]

- **模型 provider**：按 `label` 字段精确匹配判定重名
  - 导入文件中 provider.label === 本地任意 provider.label → 节点后面显示提醒标签「存在重名」
  - **提醒 ≠ 阻止**：用户仍可正常勾选重名节点导入；导入后本地出现 2 个同 label 的 provider（id 不同），后端支持
  - 判定时机：解析文件后，与当前本地 `GET /provider` 返回数据比对
- **工具 tab**：不做重名判定（覆盖语义，用户自主决定）
- **后端无 label 唯一性限制**：provider handler POST 校验仅要求 label/baseUrl/credentials.key 必填，不限制重名（已核实）

### 2.6 加密方案 [v0.0.318]

- **算法**：对称加密（AES-256-CBC 或同等）
- **密钥**：硬编码，由 `rocky_agent_` + `md5(固定串)` 拼接生成
  - 目的：同一版本 rocky_agent 产出的文件可跨机器互导
  - 非安全级加密（防肉眼读取），仅做信息整体编解码
- **产物**：加密后的 `.json` 文件（文件内容为加密后 base64 字符串，非明文 JSON）
- **文件结构**：`{ "v": 1, "payload": "<加密后base64>" }`（v=格式版本号，payload=加密体）

## 3. 导入导出数据结构

### 3.1 加密前 JSON Schema

```jsonc
{
  "v": 1,                          // 格式版本号
  "exportedAt": "2026-08-10T15:00:00Z", // 导出时间 ISO
  "providers": [                    // 模型 provider 列表（导出时选中的）
    {
      "label": "OpenAI Compatible",     // provider 显示名（同名判定依据）
      "name": "anthropic_compatible",   // 固定值
      "protocolId": "anthropic_messages",
      "baseUrl": "https://api.example.com",
      "credentials": { "key": "sk-xxx" },
      "enabled": true,
      "models": [
        {
          "modelId": "gpt-4o",
          "contextWindow": 128000,
          "maxOutputTokens": 16384,
          "label": "GPT-4o",
          "enabled": true,
          "pricing": {
            "inputPerMillion": 2.5,
            "outputPerMillion": 10,
            "currency": "USD"
          }
        }
      ]
    }
  ],
  "tools": {                        // 工具 tab 配置（导出时选中的）
    "web_search": {                 // group=web_search, key=default
      "type": "zhipu_api",
      "credentials": { "zhipu_api": { "apiKey": "xxx" } }
    },
    "web_fetch": {                  // group=web（提取 jina 三 key）
      "jinaApiKey": "xxx",
      "jinaEnabled": true,
      "jinaTimeoutMs": 20000
    },
    "see_image": {                  // group=see_image, key=default
      "type": "zhipu_api",
      "credentials": { "zhipu_api": { "apiKey": "xxx" } }
    },
    "bash": {                       // group=runtime, key=bash_seatbelt
      "bash_seatbelt": true
    }
  }
}
```

### 3.2 数据来源映射

| 配置类 | 导出读取 | 导入写入 | 语义 |
|--------|----------|----------|------|
| 模型 provider | `GET /provider` → items[] | `POST /provider`（body 不含 id，后端生成新 ULID） | 注入：新增，不覆盖 |
| web_search | `GET /config/app?group=web_search&key=default` | `PUT /config/app {group:'web_search', items:[{key:'default', data}]}` | 覆盖：整 tab 替换 |
| web_fetch | `GET /config/app?group=web` | `PUT /config/app {group:'web', items:[{key,data}]×3}` | 覆盖：整 tab 替换 |
| see_image | `GET /config/app?group=see_image&key=default` | `PUT /config/app {group:'see_image', items:[{key:'default', data}]}` | 覆盖：整 tab 替换 |
| bash | `GET /config/app?group=runtime&key=bash_seatbelt` | `PUT /config/app {group:'runtime', items:[{key:'bash_seatbelt', data}]}` | 覆盖：整 tab 替换 |

### 3.3 导入语义详解

**模型（注入）**：
- 导出时剥离 `id` 字段（不导出原始 id）
- 导入时 `POST /provider`，后端为每个 provider 生成新 ULID
- 结果：本地原有 provider 不受影响，新 provider 追加到列表

**工具（覆盖）**：
- 导入时整 tab 配置替换本地对应 group 的指定 key
- 例：导入 web_search → 本地 `web_search` group 的 `default` key 被替换为文件中的值
- 不影响同 group 下其他 key（如 web group 仅替换导出的 3 个 jina key）

## 5. 边界与异常

### 5.1 文件解密失败

| 场景 | 表现 | 处理 |
|------|------|------|
| 文件非本系统加密格式（随便选了个 JSON） | 解密报错 | 提示「文件格式不正确，无法解析为配置同步文件」 |
| 文件内容损坏（截断/篡改） | 解密/反序列化失败 | 提示「文件已损坏或被修改，无法导入」 |
| 文件版本号不兼容（未来 v2） | `v` 字段校验失败 | 提示「文件版本不兼容，请升级应用后重试」 |

### 5.2 导入重名 Provider

| 场景 | 处理 |
|------|------|
| 导入文件含本地已有 label 的 provider | 树形页该节点后面显示「存在重名」提醒标签，checkbox 正常可选 |
| 用户勾选重名节点并导入 | 正常注入：POST 生成新 ULID，本地出现 2 个同 label provider（后端支持，无唯一性限制） |
| 导入后本地出现两个不同 label 的 provider | 正常（注入语义，id 不同） |

### 5.3 导入数据不完整

| 场景 | 处理 |
|------|------|
| 文件中 providers 为空数组 | 模型树显示「无可导入的模型配置」空态 |
| 文件中 tools 为空对象 | 工具树显示「无可导入的工具配置」空态 |
| 文件中某 provider 缺 models 字段 | 容错：models 默认为 `[]`，导入后 provider 无 model |

### 5.4 导出空配置

| 场景 | 处理 |
|------|------|
| 本地无任何 provider | 模型树显示空态，仍可导出（providers=[]） |
| 本地无工具配置 | 工具树显示空态，仍可导出（tools={}） |
| 全部空 | 导出按钮仍可用，生成仅含 `v` + `exportedAt` 的加密文件 |

### 5.5 加密格式

| 属性 | 值 |
|------|-----|
| 算法 | AES-256-CBC |
| 密钥生成 | `rocky_agent_` + `md5("固定盐值字符串")` |
| 输出格式 | base64 编码字符串 |
| 文件后缀 | `.json`（内含 `{v, payload}` 结构） |
| 版本字段 | `v: 1`（当前格式版本） |
