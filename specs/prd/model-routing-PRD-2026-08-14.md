## 1. 产品概述与目标

### 1.1 背景与问题

当前 rocky 的 LLM 调用为**单模型直连**：resolve 一次定死模型，失败即上抛。老板 4 需求：

1. 按当地时间配置模型可用时段（特定时段可用/避开）；
2. 按顺序向下调用（降级链）；
3. 熔断开/闭/半开三态；
4. 同模型可有 1 带时间 + 1 不带时间条目（带时间必须在上面）。

### 1.2 产品目标

- **P0**：模型组合方案 = 可命名/可挂载/可编辑的有序降级链（app 级方案库 CRUD + group 挂载）；
- **P0**：attempt 内逐步决策路由（时间过滤 → 熔断 → 按序尝试 → 退避），失败自动降级；
- **P0**：三态熔断保护（方案级隔离），用户可见友好状态词；
- **P1**：条目启用/停用开关（关闭不删除）；时间条件用成熟现成控件。

### 1.3 目标用户/场景

- 老板/高级用户：多模型多账号，主模型限流/故障时自动降级；
- 团队/playground：统一挂载方案，成员会话自动享受降级链；
- 场景：「主力 Kimi 凌晨 0-2 点不可用 → 自动滑到备用模型」；「主模型连续失败 → 熔断 60s → 半开探测恢复」。

## 2. 功能需求

### 2.1 模型组合方案库（app 级 CRUD）[P0]

**描述**：app 级「模型组合方案」库——可命名、可编辑、可删除、可复制。
**用户故事**：作为高级用户，我希望创建「主力+兜底」方案，以便一次配置、多处挂载复用。

**用户行为链路**：应用设置 → 模型 tab → 模型组合方案库 → 新建/编辑/删除/复制方案。

**功能交互细节**：
- 方案 = 有序条目列表（降级链）+ 可选熔断参数覆盖（高级区）；
- 编辑条目顺序（上移/下移 = priority）；保存时校验（见 §2.8）；
- 删除方案 = 解除所有挂载方引用（挂载方回退默认模型）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-1 | 设置 → 模型 tab → 新建方案「主力+兜底」 | 方案创建成功，空条目列表可编辑 |
| UC-2 | 编辑方案 → 添加 3 个模型条目（Kimi→DeepSeek→GLM）→ 上移/下移调整顺序 → 保存 | 条目按 priority 升序保存，顺序生效 |
| UC-3 | 方案列表 → 删除已挂载方案 | 删除成功，挂载自动解除（22:22 拍板）：session 显式模型仍优先；无则回**未设置态**（400 引导重新配置）——无休眠模型接管 |
| UC-4 | 方案列表 → 复制「主力+兜底」 | 生成「主力+兜底 副本」独立编辑 |

### 2.2 条目（模型选择 + 优先级 + 启用开关）[P0/P1]

**描述**：每条目 = provider/model + priority + 启用开关 + 可选时间条件。
**用户故事**：作为用户，我希望临时停用某模型但不删除配置，以便保留设置随时恢复。

**功能交互细节**：
- 模型选择 = provider picker + model picker（ModelRef 复合防歧义）；
- priority = 1 最高（尝试顺序 = priority 升序）；
- **启用/停用开关（老板 11:16 ①）**：默认启用；停用 = 保留配置但**路由时直接跳过**（等同时间过滤跳过：不消耗尝试/不计熔断失败）；
- 同模型条目约束按「启用条目」统计；启用/停用切换实时校验（违规阻止启用并提示）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-5 | 方案编辑 → 条目 A 关停用开关 → 保存 | 条目保留，方案列表标记「已停用」 |
| UC-6 | 调用时方案含停用条目 | 停用条目不参与候选（直接 skipped），其余条目正常尝试 |
| UC-7 | 重新打开停用条目开关 → 保存 | 条目恢复参与路由 |

### 2.3 时间条件（白名单小时格 + 成熟控件）[P0]

**描述**：条目级时间条件 = 白名单小时格（0-23），当前小时命中才可用；不配置 = 随时可用。
**用户故事**：作为用户，我希望「凌晨某时段主力模型不可用」，以便低谷时段自动滑到备用模型。

**功能交互细节**：
- 数据模型 `TimeCondition = { hours: number[] }`（0-23 白名单；每天重复；**无周几/分钟/exclude**）；
- **控件选型（老板 11:16 ③）**：正式实现用**成熟现成组件**（24 格小时拖拽式时间段选择器或等效交互），**不自己造轮子**。选型标准：① 拖拽连续段 ② 多段加选 ③ 清空=全天（等价不配置）④ hover 提示小时信息；具体组件架构阶段定；
- 本地时间求值（Electron 桌面端本地时区，无服务器歧义）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-8 | 条目时间条件 → 拖拽选中 02:00-08:00 → 保存 | hours=[2..8]，该时段外条目跳过 |
| UC-9 | 时间控件 → 清空全部选中 | 等价「不限/随时可用」（无条件条目） |

### 2.4 挂载层级（app / group / session）[P0]

**描述**：四级职责——app=方案库 CRUD；group/playground=挂方案或默认模型；session=只能配 model/default。
**用户故事**：作为团队管理员，我希望团队统一挂载降级方案，以便所有成员会话自动生效。

**功能交互细节**：
- group/playground 设置 → 默认模型/方案：**二选一单 select 严格互斥**（上组「模型」、下组「方案」——老板 21:44 拍板；严格互斥 22:22 拍板「必须只保留一个有效的」）；选方案时默认模型**清空**、选模型时自动解除方案挂载——任意时刻两字段至多一个有值；**暂仅 studio/playground 可用方案**（academy 不支持）；
- session 设置 → 只能选 model / default（**不能配方案**）；
- resolve 双分支（一套代码）：
  - 无方案 → 分支 1：现有单模型逻辑（零改动）；
  - 有方案 → 分支 2：session default → 直接走方案链；session 显式模型 → **priority 0 合成插入方案顶部**（临时不写回；熔断键 = planId + session 模型）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-11 | group 设置 → 挂载方案「主力+兜底」 | 该 group 所有 session 调用走方案链 |
| UC-12 | session 设置选 model=Kimi（group 已挂方案） | Kimi 作 priority 0 插入方案顶部，优先尝试 |
| UC-13 | session 设置选 default（group 已挂方案） | 直接走方案链（无合成） |

### 2.5 路由与降级（attempt 内循环）[P0]

**描述**：resolve 下沉 llm attempt 内部——每次失败后基于 f(config, state) 决定下一个调谁/sleep 多久；非调用前定死。
**用户故事**：作为用户，我希望主模型失败自动降级到备用，无感知。

**功能交互细节**（attempt 循环）：
```
① 时间过滤（小时未命中 → skipped）
② enabled 检查（停用 → skipped）
③ 熔断检查（Open → skipped + 入 bannedModels）
④ bannedModels 检查（同模型配置已放弃/熔断 → skipped）
⑤ 发起调用（看门狗 + §2.6 差异化重试）→ 成功收敛 / 失败按策略降级
⑥ 循环耗尽 → 候选为空「当前无可用模型」/ 全失败「所有候选模型不可用」
```
- **去重键 = 模型配置（providerId+modelId），不是 item**（老板 10:55）：同模型多 item（session 合成/带时间/无条件）只尝试一次；被放弃/熔断后后续同模型 item 全 skipped；
- **Config/State 分离**：Config = 方案 + 熔断状态（跨 call 存活，内存态不持久化）；State = 本次 call 的候选处置轨迹（called/failed/abandoned/skipped + 原因 + 尝试次数 + 退避截止 + 游标 + bannedModels，call 级瞬时不落盘）；
- 决策 = f(config, state) 可复现；对 agent 透明。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-14 | 方案 Kimi→GLM，Kimi 返回 429 | Kimi 快速失败（0 重试）→ 降级 GLM 成功返回 |
| UC-15 | 方案 Kimi→GLM，Kimi 网络错误 | Kimi 重试 1 次仍失败 → 降级 GLM |
| UC-16 | 方案 Kimi→GLM，Kimi 401 | Kimi 直接熔断（abandoned）→ GLM 尝试；Kimi 状态变 🔴 异常 |
| UC-17 | 方案同模型 2 条目（Kimi 带时间 + Kimi 无条件），带时间条目 429 | 模型配置去重：无条件 Kimi 条目不再尝试 → 直接下一个不同模型 |

### 2.6 差异化重试策略 [P0]

**描述**：所有失败计入熔断；按错误类型差异化「模型内重试次数」。
**用户故事**：作为用户，我希望限流快速降级、网络抖动重试，以便最优恢复路径。

**功能交互细节**（错误类别 → 模型内重试次数 → 熔断行为）：

| 错误类别 | 重试 | 熔断 |
|---|---|---|
| RATE_LIMITED(429) / PROVIDER_OVERLOADED(529) | 0（快速失败） | 计失败，达阈值 Open |
| NETWORK / 超时 / 5xx / 流断 / 空响应 | 1（瞬态重试） | 计失败，达阈值 Open |
| MAX_TOKENS_TOO_HIGH | 1（降 maxTokens ×0.7 重试） | 计失败，达阈值 Open |
| AUTH_INVALID(401) / AUTH_FORBIDDEN(403) | 0（快速失败） | **直接熔断 Open**；全部候选 AUTH 失败 → 上抛首个 AUTH 错误引导修凭证 |
| CONTEXT_LENGTH / MAX_TOKENS_EXCEEDED | 0（走现有压缩/bump 流程，修复后成功不算路由失败） | 修复后再失败才计 |
| CONTENT_FILTERED / MODEL_NOT_FOUND / MALFORMED_TOOL_CALL / BAD_REQUEST_OTHER | 0（快速失败） | 计失败，达阈值 Open |
| ABORTED_BY_USER | — | 不算失败，直接返回 |

- 超时沿用现有看门狗（TTFB 45s / stall 30/30/120）；模型内重试走现有退避；换模型降级可 0/短 sleep（architect 定，保持可复现）。

### 2.7 熔断三态 + 状态呈现映射 [P0]

**描述**：方案级三态熔断（planId+providerId+modelId 三维，方案间隔离）；用户可见友好状态词。
**用户故事**：作为用户，我希望看到模型「正常/异常/观察中」，而不是熔断器术语。

**功能交互细节**：
- 状态机：Closed →（连续失败 ≥4 或 窗口有效样本 ≥10 且窗口错误率 ≥0.6）→ Open →（60s 后）→ HalfOpen（限流 1 真实请求探测）→（连续成功 ≥2）→ Closed；探测失败立即回 Open；
- 默认参数：failure_threshold=4 / success_threshold=2 / timeout_seconds=60 / error_rate_threshold=0.6 / min_requests=10 / window_size=20（方案级可覆盖，UI 高级区；**[2026-08-14 增量]** 错误率=最近 window_size 次请求的滑动窗口失败率（老板拍板「20 次失败 12 次就不请求」），非终身累计；窗口样本 <10 时错误率轨道沉默、连续失败轨道兜底；恢复后窗口不清、旧失败随新请求滚出；UI 暂不暴露 window_size）；
- **状态呈现映射（老板 11:16 ②）**：

| 内部熔断状态 | 用户呈现 |
|---|---|
| Closed | 🟢 正常 |
| Open | 🔴 异常（带倒计时） |
| HalfOpen | 🟡 观察中（无倒计时） |

- 同一方案多处挂载共享熔断状态；熔断状态 = 运行时内存态不持久化；与现有 per-session health 分层共存（attempt 循环先查方案熔断再查 session health）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-18 | 方案 A 里 Kimi 连续失败 4 次 | Kimi 状态变 🔴 异常（倒计时 60s）；方案 B 里 Kimi 仍 🟢 正常 |
| UC-19 | 🔴 异常 60s 后 | 进入 🟡 观察中，限流 1 个真实请求探测 |
| UC-20 | 观察中探测成功连续 2 次 | 状态回 🟢 正常 |

### 2.8 配置校验（同模型条目约束）[P0]

**描述**：方案内同模型条目约束，保存时硬拒绝。
**用户故事**：作为用户，我希望配置错误当场被拦下，以免路由行为不可预期。

**功能交互细节**（按模型分组校验）：
- 同模型最多 2 条目（1 带时间 + 1 不带时间）；
- 不允许 2 带时间 / 2 不带时间 → 保存硬拒绝 + 明确提示；
- **带时间条目必须排在不带时间条目上面** → 违反硬拒绝（提示「带时间条目必须在不带时间条目上面」）；
- 校验时机：① 保存静态校验；② 运行时防御（发现违规纠正/告警）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-21 | 方案添加 Kimi 带时间 + Kimi 无条件，带时间在下面 | 保存被拒，提示「带时间条目必须在不带时间条目上面」 |
| UC-22 | 方案添加 Kimi 带时间 ×2 | 保存被拒，提示同模型不允许 2 个带时间条目 |

## 4. 验收标准

1. 方案库 CRUD 全通（UC-1~4）：新建/编辑/删除/复制，删除解除挂载回退默认；
2. 条目启停（UC-5~7）：停用条目路由跳过，重启用恢复，不删除配置；
3. 时间条件（UC-8~10）：白名单小时格生效；清空=全天；控件为成熟现成组件（拖拽连续段/多段加选/hover 提示）；
4. 挂载层级（UC-11~13）：group 挂方案生效；session 显式模型 priority 0 合成；session 不能配方案；
5. 降级链（UC-14~17）：429 快速降级 / 网络重试 1 次 / 401 直接熔断 / 同模型配置去重；
6. 熔断呈现（UC-18~20）：三维隔离；🔴 异常带倒计时；🟡 观察中无倒计时；恢复 🟢 正常；内存态重启丢失可接受；
7. 配置校验（UC-21~23）：同模型约束硬拒绝 + 明确提示；
8. 失败语义：所有失败计入熔断；ABORTED_BY_USER 不计；看门狗沿用（TTFB 45s/stall 30/30/120）；
9. 无方案分支 1 零回归（现有单模型逻辑不变）。

## 5. 非目标（明确不做）

- ❌ 周几/分钟级时间配置、exclude（排除）模式（D3 拍板砍掉，仅白名单小时格）；
- ❌ 用量窗口路由（5h/7d quota）、成本/延迟/负载感知路由（后续）；
- ❌ 熔断状态持久化（运行时内存态）；attempt state 落盘；
- ❌ 独立健康探测任务（半开用真实请求）；
- ❌ academy 方案支持（本期仅 studio/playground）；
- ❌ session 级配置方案（只能 model/default）；
- ❌ 隐式兜底（全部不可用时报「当前无可用模型」）。
