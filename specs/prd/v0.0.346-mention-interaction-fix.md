## 1. 背景与现状

### 1.1 @ 面板触发（问题 1 现状）

| 环节 | 现状实现 |
|---|---|
| 触发检测 | `detectMentionTrigger`（chat-composer-helpers.ts）：onUpdate 每次编辑时，正则 `/@(\S*)$/` 扫**光标前 50 字符内最近的 @**，命中 → `setTrigger({query})` 弹面板 |
| 面板关闭 | `handleClose`（Esc / 点击外部 / 选中）→ `setTrigger(null)`，**只清面板 state，不清输入文本** |
| 取消后状态 | 文本中的 `@` 仍在；光标前文本形如 `@1` / `@12` / `@123`，下一次编辑的正则依然命中 → **每输入一个字符面板重弹** |

**根因**：面板触发是「每次编辑扫描光标前最近的 @」，而非「@ 字符键入瞬间」；取消只关闭面板、未抑制后续字符对旧 @ 的重复命中。

### 1.2 @ 文件搜索（问题 2 现状）

| 环节 | 现状实现 |
|---|---|
| 搜索实现 | `FileProvider.search`（file-provider.ts）：workspaceDir 下 DFS 递归，**仅文件名**包含匹配（大小写不敏感，`name.toLowerCase().includes(query)`），目录名不参与匹配；5 秒超时兜底 |
| 排除规则 | `shouldSkip`：`IGNORED_NAMES.has(name) \|\| name.startsWith('.')` —— **排除 node_modules / .git / 所有点开头名称**（含 `.rocky_project/` `.claude/` 等隐藏目录及其下全部文件，见 §2.3 排查） |
| 结果上限 | **无 100 条硬上限**：仅按 `limit`（默认 20，API 允许 1-100）分页返回 + cursor 翻页；无 truncated 概念 |
| 前端搜索 | MentionPopover `doSearch` 传 `limit: '20'`，200ms debounce + AbortController；结果列表无超限提示、无「加载更多」以外的截断提示 |
| 目录支持 | ❌ 目录不参与匹配（isDir 分支直接递归下层，不检查目录名） |

### 1.3 工作区搜索（对照基准，v0.0.320/324）

| 机制 | 实现 |
|---|---|
| 100 条上限 | `SEARCH_LIMIT = 100`（files+dirs 合计），`walkSearch` 达上限早停返回 `truncated: true` |
| 目录支持 | 目录命中 → 推入 `dirs` + **不递归其下层**；q 含 `/` 时按完整相对路径匹配（`relChild`），不含 `/` 时 basename 匹配——文件和目录都覆盖 |
| 排除规则 | `IGNORED_NAMES.has(name)` —— **只排除 `node_modules` / `.git`**；**不排除其他点开头目录**（`.rocky_project/` `.claude/` 等可遍历、可命中、可返回） |
| 超限提示 | 前端渲染「结果超过 100 条，请进一步输入以缩小范围」（zh）/ "Over 100 results, narrow your search"（en） |

## 2. 需求描述

### 2.1 问题 1：@ 面板只被 @ 字符触发，取消后不重弹

**核心需求**：面板**只由 `@` 字符本身的键入触发**；用户取消面板后，继续输入其他字符（数字/字母）不再触发面板弹出。

**行为定义**：

| 场景 | 期望行为 |
|---|---|
| 输入 `@` | 面板弹出（query 为空，展示全部候选） |
| `@` 后输入查询文本（如 `@he`） | 面板保持打开，query 实时更新 |
| 取消面板（Esc / 点击外部） | 面板关闭，输入文本原样保留 |
| 取消后继续输入数字/字母（如 `1` `2` `3`） | **面板不再弹出**，字符正常输入 |
| 取消后删除文本回到 `@` 位置 | 面板**不自动重弹**（同一次取消的抑制期） |
| 再次输入新的 `@`（光标前紧邻为 `@` 或任意位置） | 面板重新弹出（新的 @ 触发） |
| 选中候选插入 pill 后 | 面板关闭，后续正常输入不弹（与取消同语义，@ 已被 pill 消费） |

> 说明：抑制范围 = 「一次取消/选中后、到下一个 `@` 键入前」。实现机制（取消后置 suppression 标记、或仅监听 @ 键键入事件、或两者结合）由 architect 在 change_plan 定，PRD 只约束可观测行为。

### 2.2 问题 2：@ 文件搜索升级（与工作区搜索共用后端 + 文件夹/文件 + 100 上限 + 超限提示）

**核心需求**（老板 07:17-07:18 确认方向）：**@ mention 文件搜索与工作区搜索（session-workspace-search.ts）共用同一搜索后端/索引**——一套排除规则、一套缓存索引、一套 100 上限+truncated、防抖统一参考。@ 搜索支持 `@ 文件夹/文件`，结果上限 100 条保障速度，超限提示「结果超过 100 条，请细化输入」。

**行为定义**：

| 项 | 需求 |
|---|---|
| 共用后端 | @ 搜索与工作区搜索共用同一后端搜索实现（复用 `session-workspace-search.ts` 的搜索核心：遍历/匹配/排除/上限/truncated）。FileProvider 职责收敛为**适配层**（把工作区搜索核心的结果映射为 MentionItem）或**直接复用**搜索服务，具体架构由 architect 在 change_plan 定——PRD 只约束行为一致性 |
| 结果一致性 | 同一 workspace 下，@ 搜索与工作区搜索对同一 query 的**命中集合一致**（一套排除规则/一套遍历逻辑；返回格式可不同） |
| 匹配范围 | **文件名 + 目录名**都参与匹配（q 不含 `/` → basename 包含匹配；q 含 `/` → 完整相对路径包含匹配，对齐工作区搜索语义） |
| 目录命中 | 目录命中 → 作为结果条目返回（path = 相对路径），**不递归其下层**（对齐工作区搜索；mention 面板内不做目录展开，选中即插入 pill） |
| 结果上限 | 搜索收集阶段 files+dirs 合计**达 100 条即停止**（早停，与工作区搜索同一 `SEARCH_LIMIT=100`），返回 `truncated: true` |
| 超限提示 | 结果超 100 条 → 面板内提示**「结果超过 100 条，请细化输入」**（老板钦定文案，i18n 双语） |
| 分页 | cursor 翻页机制保留；`truncated=true` 时提示细化输入（用户可继续细化 query 重新搜索） |
| 排除规则 | **仅排除 `node_modules` / `.git`**（老板 07:17 确认放开：其他全部可搜，含 `.rocky_project/` `.claude/` `.env` 等点开头目录/文件——对齐 vscode 透明搜索） |

**文案**（老板钦定逐字）：zh-CN「结果超过 100 条，请细化输入」；en 对应翻译（如 "Over 100 results, please refine your input"）。

### 2.3 隐藏目录 / 点开头目录排除（排查结论 08-14 07:16 + 方向确认 07:17-07:18）

**排查发现**：FileProvider 的 `shouldSkip` 为 `IGNORED_NAMES.has(name) || name.startsWith('.')`——**排除所有点开头名称**（含目录与文件）。因此 `.rocky_project/`、`.claude/`、`.agents/` 等隐藏目录**及其下全部文件**都不会出现在 @ 搜索结果中。

**工作区搜索对照**：`session-workspace-search.ts` 的 `walkSearch` 仅 `IGNORED_NAMES.has(name)`（`node_modules` / `.git`），**不排除其他点开头目录**——`.rocky_project/` 等在工作区搜索里可命中、可返回、可递归遍历。

**结论**：**是**——点开头目录被排除是 @ 文件搜索「搜不到某些文件」的根因之一。FileProvider 与工作区搜索的排除规则不一致（一个排除全部点开头，一个只排除 node_modules/.git）。

**需求（老板 07:17-07:18 拍板）**：

| 项 | 需求 |
|---|---|
| 排除规则放开 | **只排除 `node_modules` / `.git`**（`IGNORED_NAMES`），**其他全部可搜**——含 `.rocky_project/` `.claude/` `.env` 等点开头目录/文件，**对齐 vscode 透明搜索** |
| 点开头文件 | **默认纳入**（已确认）：`.env` `.gitignore` 等点开头文件参与匹配、可命中（工作区搜索亦如此） |
| 共用后端 | @ 搜索与工作区搜索**共用同一搜索后端/索引**——一套排除规则、一套缓存索引、一套 100 上限+truncated、防抖统一参考（FileProvider 职责收敛为适配层或直接复用，架构留给 architect） |
| `.rocky_project/` | 期望可命中其下文件（如 `.rocky_project/xxx.md`）——目录本身可作为 file 条目返回（path 指向目录），其下文件递归遍历可命中 |
| 安全面 | 排除规则变更不放松路径安全：仍走 workspaceDir 根校验 + 相对路径返回；symlink 处理与现状一致（目录不跟随出 workspace） |

### 2.4 问题 4：@ file 搜索结果 item 样式优化（老板 08-14 09:26 试玩反馈）

**现状问题**：
- file 搜索结果 item **分不出是文件夹还是文件**（当前 popover item 无 icon，仅 title + subtitle 两行文本）
- 所属路径**不是一直展示**（subtitle 仅 dirname 非根时渲染；根路径 dirname='.' → subtitle=undefined → 不显示）

**期望（老板钦定）**：
- **上排**：文件名/文件夹名 + icon（文件夹和文件可区分，类似工作区搜索的图标样式）
- **下排**：所属路径（workspace 根路径显示 `/`）——始终展示
- 优化一轮

**行为定义**：

| 项 | 需求 |
|---|---|
| icon 区分 | file 结果 item 渲染 **icon**：文件 icon / 文件夹 icon 可区分（参考工作区搜索 `component-ws-tree-item.tsx`：文件夹 gold FolderIcon、文件 muted FileIcon；icons.tsx 已有 FolderIcon/FolderOpenIcon/FileIcon） |
| 上排 | 文件名/文件夹名（basename），icon + 名称同行 |
| 下排 | 所属路径（相对 workspace 的 dirname），**始终展示**；根路径（dirname 为空）显示 **`/`** |
| 全路径 | 下排路径为所属目录路径（非完整路径拼接；对齐当前 subtitle=dirname 语义，仅补根路径显示） |

**契约变更评估（dir 标记是否丢弃——已确认：丢弃）**：

| 项 | 结论 |
|---|---|
| 现状 | `workspace-search-core.searchWorkspace` 返回 `{files, dirs, truncated}`，**files/dirs 分离**；但 FileProvider 适配层合并 `[...dirs, ...files].sort()` 后统一走 `toMentionItem`，**dir 标记在合并时丢弃**——目录条目与文件条目同为 `type='file'` + `icon='file'`，前端无法区分 |
| 需求冲突 | T2 决策「目录条目复用 type='file'、MentionItem 零新增字段」与老板「文件夹/文件可区分」**冲突**——必须恢复 dir 标记（变更方向留给 architect，候选见下） |
| 变更方向候选 | ① MentionItem 加 `isDir?: boolean`（最小侵入，listView.icon 可按 isDir 给 'folder'/'file'，display.icon 同步）② type 扩展 'dir'（开放枚举，但 renderer INV-2「无 type 分支」可能受影响，pill 渲染链路需评估）③ 仅 listView.icon 用 'folder' key（Glyph registry 需注册 folder key，display.icon 仍 'file'——面板区分但 pill 不区分） |
| 前端 path 推断 | ❌ 不推荐（不可靠：无法从 path 可靠区分文件/目录，且与后端事实源不一致） |
| popover 现状 | `component-mention-popover.tsx` item 渲染**不消费 `listView.icon`**（仅 title/subtitle 两行文本）；Glyph registry（primitive-mention-pill.tsx）**无 folder key**（现 7 key：file/skill/member/goal/kr/requirement/task） |
| 选中/pill 链路 | 目录条目选中插入 pill 链路不变（走既有 type='file' 路径）；是否在 pill 上也区分文件夹由 architect 评估（老板只要求面板内区分） |

## 3. 需求边界

### 3.1 做什么

- 修 @ 面板触发：只被 @ 字符键入触发；取消后输入其他字符不重弹
- @ 文件搜索与工作区搜索**共用后端**：一套排除规则、一套缓存索引、一套 100 上限+truncated、防抖统一参考（FileProvider 收敛为适配层或直接复用，架构由 architect 定）
- 搜索能力升级：支持目录匹配（q 含 `/` 路径匹配）+ 100 条硬上限（早停 + truncated）+ 超限提示
- 排除规则放开：**仅排除 node_modules/.git**，其他全部可搜（含 .rocky_project/ .claude/ .env 等点开头目录/文件，对齐 vscode 透明搜索）
- 前端 popover：消费 truncated 渲染超限提示（i18n）
- file 结果 item 样式：icon 区分文件/文件夹 + 下排路径始终展示（根路径 `/`）

### 3.2 不做什么

- ❌ 不改 mention 面板其他行为：选中插入、pill 渲染、mention 发送格式（`<mention/>` tag 结构）、tab 结构、键盘导航
- ❌ 不新增独立搜索后端/索引：@ 搜索必须复用工作区搜索后端（不另起一套遍历/缓存/上限逻辑）
- ❌ 不新增概念：MentionItem 结构不新增字段（目录条目复用 file 类型 + path 指向目录；是否区分 type 由 architect 评估，但禁止破坏现有渲染/选中链路）
- ❌ 不改其他 provider（skill / workitem / member）搜索逻辑
- ❌ 不做面板内目录展开浏览（工作区搜索的裁剪树是 FileTree 场景，mention 面板无此交互）
