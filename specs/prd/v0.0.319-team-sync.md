# v0.0.319 — 团队同步（导入导出团队配置）PRD

> 引入版本: v0.0.319 | 2026-08-10

## 1. 背景与目标

### 1.1 背景

用户在多台机器上使用 rocky_agent 时，需要重建团队配置（AGENTS.md + 成员定义 + 技能 + 记忆 + 模板 + 命令 + 权限配置）。当前只能通过团队模板机制新建，但模板是全局预置的——用户自定义的团队无法跨机器迁移。

### 1.2 目标

- **一键导出**当前团队为 zip 文件（含全部配置，不含运行时状态/工作产物）
- **一键导入**zip → 填团队名 → 建新团队（成员/技能/记忆/模板全复用）
- **程序化实现**：纯后端代码（读目录 + manifest + adm-zip），不靠 LLM

### 1.3 非目标

- 不导出/导入运行时状态（sessionId / state / currentWork / version / createdAt）
- 不导出/导入工作产物（outputs / reports / states / specs / panorama / images）
- 不导出/导入 workspace 内容（工作目录内容由各版本自行管理）
- 不加密 zip（团队配置无 API key，明文即可）
- 不做批量导出/导入（一次一个团队）

## 2. 功能详细设计

### 2.1 入口位置 [v0.0.319]

**应用设置 → 左侧 sidebar「用户设置」区 → 「配置同步」tab 下方 → 新增「团队同步」tab**

- 与 v0.0.318「配置同步」tab 同层级，为其紧邻下方 tab item
- 选中后右栏渲染团队同步功能页（含「导出团队」和「导入团队」两个操作入口）
- 仅当当前 session 属于某个 squad 时显示此 tab（非 squad 场景无团队可导出）

### 2.2 导出流程 [v0.0.319]

**描述**：用户导出当前团队为 zip 文件，包含团队全部配置（AGENTS.md + .rocky 全套），不含运行时状态和工作产物。

**优先级**：P0

**用户故事**：作为用户，我希望将当前团队的完整配置导出为文件，以便在另一台机器上导入复用。

#### 用户行为链路

1. 点击「团队同步」tab → 右栏显示团队同步页（当前团队名 + 导出/导入入口）
2. 点击「导出团队」→ 系统读取当前 squad 目录
3. 后端按导出规则打包：
   - 读取 `members/*.json` → 生成 manifest.json（提取 slug/name/description/leaderName/leaderIntro/members[]）
   - 复制 AGENTS.md
   - 复制 .rocky/{agents,skills,memory,templates,commands,settings.json}
   - 排除：members/*.json 原文件、outputs/、reports/、states/、specs/、panorama/、images/、project symlink
   - agents/{name}-{memberId}.md → {name}.md（去 memberId 后缀）
4. adm-zip 打包为 zip → 返回下载流
5. 浏览器下载文件
6. 文件名格式：`rocky_agent_team_{squadName}_{YYYYMMDD_HHmmss}.zip`

#### 界面要素

- 当前团队名 + 成员数显示
- 「导出团队」按钮（disabled 当当前 session 无 squad）
- 导出成功 toast：`导出成功：{团队名}（N 个成员）`

### 2.3 导入流程 [v0.0.319]

**描述**：用户选择团队 zip 文件，系统解包校验后让用户填新团队名，然后程序化建队。

**优先级**：P0

**用户故事**：作为用户，我希望从导出文件创建新团队，复用全部配置但自定义团队名。

#### 用户行为链路

1. 点击「团队同步」tab → 右栏显示团队同步页
2. 点击「导入团队」→ 弹出文件选择器
3. 选择 `.zip` 文件 → 后端解包 → 校验 manifest.json 存在且结构合法
4. 校验成功 → 前端展示导入预览：
   - 显示 manifest 信息（团队名/描述/成员列表）
   - **填团队名输入框**（默认预填 manifest.name，用户可修改）
   - 如填入的团队名与本地已有 squad 重名 → 输入框下方提示「已存在同名团队，导入后会有两个同名团队」（不阻止）
5. 用户确认团队名 → 点击「导入」→ 后端执行建队：
   - 调用 `createSquadService`（用用户填的 name + manifest 中的 leaderName + modelDefault 从当前 squad 继承或用默认值）
   - 调用 `applyTemplate` 逻辑（批量 hire manifest.members + 复制配置文件到新 squad 目录）
   - 成员名直接复用 manifest 中的 name
   - agents/{name}.md → agents/{name}-{newMemberId}.md（按新 memberId 重新关联）
6. 建队完成 → toast 提示 + 导航到新团队

#### 界面要素

- 文件选择入口（按钮触发系统文件选择器，仅接受 .zip）
- 解包/校验失败 → 错误提示（不进预览页）
- 导入预览页：
  - manifest 信息卡片（团队名 / 描述 / 成员列表 N 人）
  - 团队名输入框（预填 manifest.name，必填，可修改）
  - 重名提示（条件显示，不阻止）
- 底部「导入」按钮（disabled 当团队名为空）
- 导入确认 modal：「即将创建团队「{name}」，包含 N 个成员。确认导入？」

### 2.4 导入建队机制 [v0.0.319]

导入复用现有后端服务，程序化执行：

```
1. 解包 zip → 校验 manifest.json 结构（slug/name/description/leaderName/members[] 必填）
2. 调用 createSquadService({
     name: 用户填的团队名,
     description: manifest.description,
     modelDefault: 当前 squad 的 modelDefault（或系统默认）,
     leader: { name: manifest.leaderName }
   })
3. 遍历 manifest.members → createMemberService（mode=fresh，name/intro/skillConfig 从 manifest 取）
4. copyTemplateFiles（zip 解包目录 → 新 squad 目录）：
   - AGENTS.md → 覆盖到新 squad
   - .rocky/agents/{name}.md → {name}-{newMemberId}.md
   - .rocky/{skills,memory,templates,commands} → merge 复制
   - .rocky/settings.json → 仅目标不存在才复制
5. 清理临时解包目录
```

**关键复用**：
- `createSquadService`（squad-service.ts）：建 squad 事务（leader member + session + squadChat + 目录骨架）
- `createMemberService`（member-service.ts）：批量 hire mate
- `copyTemplateFiles` 逻辑（squad-template-service.ts）：文件复制策略

**modelDefault 继承**：导入时新 squad 需要一个 modelDefault（createSquadService 必填）。策略 = 使用当前所在 squad 的 modelDefault（从当前 session 的 squadId 查），若无法获取则用系统默认 model（fallback）。

### 2.5 重名处理规则 [v0.0.319]

- **squad name**：后端不校验唯一性（已核实 createSquadService 仅校验 name 非空，squad-service.ts L113）
  - 导入时填入的团队名与本地已有 squad 重名 → **提醒但不阻止**（提示「已存在同名团队」）
  - 用户确认后正常建队，本地出现两个同名 squad（id 不同）
  - 判定方式：导入前调用 `listSquads()` 与填入的 name 比对
- **member name**：直接复用 manifest 中的名字（createMemberService 有 squad 内 name 唯一性校验——如新 squad 内 manifest 自身有重名 member 则第二个失败，best-effort 跳过）

## 3. zip 数据结构

### 3.1 zip 目录结构

```
{squadName}/
├── manifest.json                 ← 团队元数据（从 members/*.json 生成）
├── AGENTS.md                     ← 团队规则
└── .rocky/
    ├── agents/                   ← 成员定义（{name}.md，已去 memberId）
    ├── skills/                   ← 团队技能
    ├── memory/                   ← 团队记忆
    ├── templates/                ← 工作模板
    ├── commands/                 ← 命令
    └── settings.json             ← 权限配置
```

### 3.2 manifest.json 结构

```jsonc
{
  "slug": "original-squad-slug",      // 原团队 slug（导入时忽略，新 squad 用新 id）
  "name": "原团队名",                  // 原团队名（预填导入页，用户可改）
  "description": "团队描述",
  "leaderName": "Darvin",              // leader 名（直接复用）
  "leaderIntro": "团队 leader...",     // leader intro（可选，复用）
  "builtin": false,                   // 固定 false（用户导出非内置）
  "members": [
    {
      "name": "coder",
      "intro": "代码开发者",
      "skillConfig": { "mode": "inherit", "overrides": {} }
    }
    // ... 所有非 leader 成员
  ]
}
```

**manifest 生成逻辑**（导出侧）：
- 从 squad directory 的 `members/*.json` 读取每个 member record
- 提取 `name` / `intro` / `skillConfig` 字段
- leader member（role=leader）→ 提取到顶层 `leaderName` + `leaderIntro`，不放入 members[]
- 非 leader member（role=mate）→ 放入 members[]
- squad 级元数据（name/description/slug）从 squad store 读取

### 3.3 导出排除清单

| 排除项 | 原因 |
|--------|------|
| `members/*.json` 原文件 | 运行时状态（sessionId/state/currentWork/version/createdAt），导入时由 createSquadService/createMemberService 重新生成 |
| `outputs/` | 工作产物 |
| `reports/` | 工作产物 |
| `states/` | 版本状态 |
| `specs/` | 版本规格 |
| `panorama/` | 全景看板数据（运行时） |
| `images/` | 图片资产 |
| `project` symlink | 项目链接（机器特定） |

### 3.4 导入写入映射

| zip 内容 | 写入位置 | 策略 |
|----------|----------|------|
| manifest.json | 不写入（仅读取建队） | — |
| AGENTS.md | `{newSquadDir}/AGENTS.md` | 覆盖 |
| .rocky/agents/{name}.md | `.rocky/agents/{name}-{newMemberId}.md` | 改名（关联新 memberId） |
| .rocky/skills/ | `.rocky/skills/` | merge（不覆盖已有） |
| .rocky/memory/ | `.rocky/memory/` | merge（不覆盖已有） |
| .rocky/templates/ | `.rocky/templates/` | merge（不覆盖已有） |
| .rocky/commands/ | `.rocky/commands/` | merge（不覆盖已有） |
| .rocky/settings.json | `.rocky/settings.json` | 仅目标不存在才复制 |

## 5. 边界与异常

### 5.1 文件格式错误

| 场景 | 表现 | 处理 |
|------|------|------|
| 非 zip 文件（如 .json / .txt） | adm-zip 解包失败 | 提示「请选择有效的团队导出文件（.zip）」 |
| zip 损坏（截断/篡改） | adm-zip 解包失败 | 提示「文件已损坏，无法解压」 |
| zip 不含 manifest.json | 校验失败 | 提示「文件格式不正确：缺少 manifest.json」 |
| manifest.json JSON 语法错误 | JSON.parse 失败 | 提示「文件已损坏：manifest.json 无法解析」 |
| manifest 结构不合法（缺必填字段） | schema 校验失败 | 提示「文件格式不正确：manifest 缺少 {字段名}」 |

### 5.2 重名团队

| 场景 | 处理 |
|------|------|
| 导入填入的团队名与本地已有 squad 同名 | 提醒「已存在同名团队，导入后会有两个同名团队」——不阻止，用户可继续 |
| 后端是否允许重名 | 允许（createSquadService 仅校验 name 非空，不校验唯一性——已核实 squad-service.ts L113） |
| 导入后本地两个同名 squad | 正常（id 不同，UI 按创建时间/活跃度区分） |

### 5.3 成员 hire 失败

| 场景 | 处理 |
|------|------|
| manifest.members 内有重名 member（如两个 coder） | 第一个 hire 成功，第二个 createMemberService 抛 MemberNameConflictError → best-effort 跳过，记入 failed |
| manifest.members 为空数组 | 仅建 leader，无 mate（合法但异常情况，提示「导入的团队无成员」） |
| 部分 member hire 失败（其他原因） | best-effort：成功的好，失败的记 failed，不中断 |

### 5.4 配置文件复制异常

| 场景 | 处理 |
|------|------|
| zip 内 .rocky/ 某子目录缺失 | 跳过该目录（best-effort） |
| 目标目录已有同名文件 | skills/memory/templates/commands → merge 不覆盖；settings.json → 仅不存在才复制 |
| 磁盘空间不足 | 建队事务失败 → createSquadService 补偿回滚（删 record + 目录） |

### 5.5 modelDefault 继承

| 场景 | 处理 |
|------|------|
| 当前 session 有 squad | 用当前 squad 的 modelDefault 作为新 squad 的 modelDefault |
| 当前 session 无 squad（极端情况） | 用系统默认 model（appConfig 查第一个 enabled provider 的第一个 enabled model） |
| 继承的 modelDefault 在目标机器无效（provider 不存在） | createSquadService 校验失败 → 报错提示「默认模型无效，请先配置模型 provider」 |

### 5.6 导出边界

| 场景 | 处理 |
|------|------|
| 当前 squad 无 .rocky/skills 目录 | 正常导出（zip 中无该目录） |
| 当前 squad 无 .rocky/memory 目录 | 正常导出 |
| 当前 squad 的 AGENTS.md 不存在 | zip 中无 AGENTS.md（导入时跳过覆盖） |
| members/*.json 不存在 | 无法生成 manifest → 导出失败，提示「团队数据异常：无成员记录」 |
