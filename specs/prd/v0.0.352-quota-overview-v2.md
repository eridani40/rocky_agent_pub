## 1. 产品概述与目标

### 1.1 背景

v0.0.350 已引入 4 个 native coding plan 类型与额度/余额查询（列表外展示、5 分钟刷新）。老板体验后拍板：

- **08:53**：两行百分比不直观，要按「套餐额度」「充值余额」分组，每组用双横柱对比（上柱=已用、下柱=时间进度），取消旧版「展开详情」；
- **08:55**：provider 列表默认只显示启用项，停用项折叠到「已停用 (N)」入口。

### 1.2 目标

- **P0**：provider 列表启用/停用分离（默认展开启用、折叠停用）；
- **P0**：额度总览按「套餐额度」「充值余额」分组，每组内用双柱对比「已用」与「时间进度」；
- **P0**：烧快状态自动警示（已用进度超过时间进度）；
- **P1**：余额不足、凭证失效卡片状态可视化。

## 3. 功能需求

### 3.1 Provider 列表折叠 [P0]

**描述**：providers 列表页默认只渲染 `enabled=true` 的 provider 卡；底部显示折叠入口「已停用 (N)」，点击展开/收起停用列表。

**用户行为链路**：设置 → 模型 → providers 列表 →（默认看到启用项）→ 点击「已停用 (2)」→ 展开看到停用项 → 再次点击收起。

**功能交互细节**：
- 启用项：按现有 `component-provider-list-card` 渲染，logo/标题/状态徽标为**启用色**（demo 中 `.llogo` 绿底绿字 `.bdg-on`）；
- 停用项：折叠入口显示停用数量 `N`；展开后渲染停用卡，视觉为**停用色**（demo 中 `.llogo.off` 灰底灰字 `.bdg-off`）；
- 折叠入口状态：收起时边框虚线、文案「已停用 (N)」+ 右向 chevron；展开时边框实线、文案不变 + 下向 chevron；
- 无停用 provider 时**不渲染**折叠入口；
- 列表滚动时折叠入口随列表滚动（非 sticky）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-1 | 进入 providers 列表页 | 默认只看到启用 provider；底部无停用项时不显示「已停用」入口 |
| UC-2 | 存在 2 个停用 provider，点击「已停用 (2)」 | 展开停用区，看到 2 个灰色调停用卡 |
| UC-3 | 再次点击「已停用 (2)」 | 收起停用区，仅保留入口 |
| UC-4 | 在停用区点击某 provider 卡 | 正常进入 detail 编辑页（与启用卡行为一致） |

### 3.2 额度总览 v2 分组双柱 [P0]

**描述**：providers 列表页底部「额度总览」区块改为按「套餐额度」「充值余额」两个分组标题渲染；每组内每个 provider 一档，每档用上/下双横柱展示「已用 X%」「时间进度 X%」。

#### 3.2.1 分组标题

- **套餐额度**：所有 `kind='quota'` 的 native coding plan provider（kimi/glm/minimax）归入此组；标题右侧显示渠道计数（如「4 渠道」）；
- **充值余额**：所有 `kind='balance'` 的 provider（deepseek 等）归入此组；标题右侧显示渠道计数（如「2 渠道」）；
- 分组标题样式同 demo `.grp`（13px 中等灰字 + 11px 计数徽标）。

#### 3.2.2 每档模块（套餐额度）

**结构（按 demo 从上到下）**：

```
┌─ card（surface-2 灰底，r10，hover 边框加深）
│  ├─ chead：logo + provider 名 + 「套餐」徽标
│  │       └─ baseUrl（mono 字，muted）
│  └─ tier × N（一档一个窗口，如 5 小时额度、本周额度）
│     ├─ thead：档位名 + 重置文案「周几 HH:mm · 剩 X 小时 Y 分」
│     ├─ trow：上柱（已用 X%）
│     └─ trow：下柱（时间进度 X%）
```

**视觉契约**：
- **provider 名**：14px semibold，与 provider 列表卡一致；logo 32×32、绿底绿字（启用态）、徽标「套餐」绿底绿字；
- **档位名**：12px semibold，如「5 小时额度」「本周额度」「每日额度」；
- **上柱（已用）**：标签「已用」+ 黑色填充 `.f-used` + 右值「X%」mono；
- **下柱（时间进度）**：标签「时间」+ 灰色填充 `.f-time` + 右值「X%」mono；
- **重置文案**：11px mono，形如「重置 周四 13:22 · 剩 4 小时 29 分」；
- **双柱尺寸**：bar 高 6px、圆角 3px；两柱上下间距 5px；左右三栏布局 `32px 1fr 44px`。

#### 3.2.3 烧快状态

- **判定**：同档 `usageProgress > timeProgress`；
- **视觉**：
  - 上柱填充色改为琥珀色 `#f59e0b`（demo `.f-used.fast`）；
  - 右值「X%」改为琥珀色粗体（demo `.tval.fast`）；
  - 档位名右侧追加琥珀色徽标「⚠ 消耗偏快」（demo `.bdg-fast`）；
- **文案**：仅展示「消耗偏快」，不展示原始百分比差值。

#### 3.2.4 充值余额档

**结构**：

```
┌─ card
│  ├─ chead：logo + provider 名
│  │       └─ baseUrl
│  └─ amount（右对齐）：¥ 9,118.81
```

- provider 名旁无「套餐」徽标；金额 16px bold mono，右对齐；
- 余额不足时：provider 名右侧显示红色徽标「余额不足」（demo `.bdg-low`），金额正常显示；
- 不展示双柱（余额无窗口概念）。

**Use Cases**：

| ID | 用户操作链路 | 预期结果 |
|---|---|---|
| UC-5 | 列表页底部「套餐额度」组 | 看到 4 个 provider 卡，每卡有 5h/本周两档双柱；MiniMax 每日额度只渲染每日档 |
| UC-6 | 查看 Kimi 本周额度 | 上柱 39%（琥珀色）+ 「⚠ 消耗偏快」；下柱 26%；文案「重置 周四 13:22 · 剩 5 天 4 小时」 |
| UC-7 | 查看 GLM 5 小时额度 | 上柱 21%（黑色）；下柱 42%；无警示 |
| UC-8 | 查看 DeepSeek 充值余额 | 「充值余额」组内金额 ¥9,118.81；无柱 |
| UC-9 | 查看余额不足渠道 | 徽标「余额不足」红色，金额 ¥12.40 |

### 3.3 异常状态卡片 [P0]

**凭证失效**：当某 provider 额度接口返回 401/403 或业务凭证错误时，该 provider 卡不渲染双柱，只显示：
- 红色文案「凭证已失效，请检查 API Key」；
- 11px 灰色文案「上次成功获取：昨天 18:42」（LastGoodSnapshot 语义，沿用 v0.0.350 use-quota-polling hook）。

**余额不足**：同 §3.2.4，红色「余额不足」徽标 + 当前金额。

### 3.4 轮询与失败保留 [P0]

- 沿用 v0.0.350 `use-quota-polling` hook：首拉 + 每 5 分钟刷新；
- 失败保留上次成功值；倒计时文本每 30s 重渲染；不重复拉 API；
- 单渠道错误不影响其他渠道展示。

## 6. 非目标（明确不做）

- ❌ 月度额度档：demo 已预留 DOM 注释扩档位置，但当前无数据，v0.0.352 不展示；
- ❌ 保留旧版两行百分比模板：额度型统一替换为双柱，不再展示「5 小时额度 已用 X%（HH:mm 重置）」紧凑两行；
- ❌ 详情展开：取消 v0.0.350 的点击展开完整明细交互，双柱+重置文案即完整信息；
- ❌ 手动刷新按钮、额度告警阈值、用量历史曲线；
- ❌ provider 卡片本身视觉改动（除启用/停用色与折叠入口外，保持既有 list-card 行为）。

## 7. 验收标准

1. **数据正确性**：上柱=已用百分比（整数），下柱=时间进度百分比（整数），计算口径与 v0.0.350 一致；
2. **分组正确**：所有额度型 provider 进「套餐额度」组，余额型进「充值余额」组，标题计数准确；
3. **双柱可读**：同档上下两柱对齐，标签「已用」「时间」固定 32px 宽，数值右对齐 44px 宽；
4. **烧快警示**：仅当 usageProgress > timeProgress 时触发；琥珀色上柱、琥珀粗体数值、档位名「⚠ 消耗偏快」三处同时出现；
5. **折叠交互**：默认只渲染启用卡；存在停用 provider 时才显示「已停用 (N)」入口；展开/收起状态切换正确，无抖动；
6. **响应式**：在 660px 容器内双柱与文字不溢出；窄屏下 provider 名/baseUrl 截断用省略号；
7. **无障碍**：折叠入口为 `<button>` 且有 `aria-expanded`；进度条用 `role="progressbar"` + `aria-valuenow`；色彩不只作为唯一信息差异（烧快同时有徽标文案）；
8. **i18n 友好词**：用户可见文案禁内部术语（unit/TOKENS_LIMIT/base_resp 等）；错误文案「凭证已失效，请检查 API Key」「余额不足」「消耗偏快」「已停用」「套餐」「充值余额」。
