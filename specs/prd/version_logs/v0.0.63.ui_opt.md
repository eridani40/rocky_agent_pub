# v0.0.63 PRD Change Log — Playground / Squad 对话 UI 4 问题修复

> version: 1.0 · 2026-07-04
> 一句话定位：4 个对话区 UI 问题修复——(1) playground 头部 model 渲染依赖进入路径（bug）；(2) markdown 不支持 GFM 表格；(3) chat topbar provider/model 选择重复（删左侧 tag）；(4) squad 群聊 + member 单聊头部对齐 playground（model + usage + compact + clear 全套）。
> 概念权威源：`specs/ui/components/chat-page/_overview.md`（playground chat 契约 + §8 视觉）+ `specs/ui/components/studio-page/squad-chat-page.md` + `member-chat-page.md`（squad 头部契约）+ `specs/api/overall/11-squad.md §127`（model 解析回退链）。
> 根因权威源：orchestrator 已直查代码确认 4 个根因 + 用户对话确认方案（`states/user_query.md` v0.0.63.ui_opt 段）。本 PRD 直接采用，不重复调研。
> 设计稿：无（视觉保真度门禁跳过；纯 UI 改动 + UT only）。

## 1. 版本目标

修复用户在 playground / studio 对话区感知到的 4 处 UI 痛点（`reqs/[working] v0.0.63.ui_opt/req.md` 原话 4 条）：

1. **model 渲染依赖路径而非渲染时机**（bug）——从 studio 切到 playground 时头部 model 不渲染，点会话项才出来。
2. **markdown 不支持表格**——agent 回复含 `| a | b |` GFM 表格时无法正确渲染。
3. **provider/model 选择重复**——chat topbar 左侧纯文本 tag + 右侧 ModelPicker 重复展示同一信息。
4. **squad 聊天头部缺组件**——squad 群聊 + member 单聊头部没有 model / usage / compact / clear，与 playground rocky 不一致。

**约束**：UT only（用户明确「纯 UI 改动，无需 AT/ET」）；后端 API 零变更（compact/clear/usage GET/postMessage-with-providerId-modelId 都是现有端点）。

## 3. 功能需求

### 3.1 F1 — Playground model 渲染时机修复（bug）[v0.0.63]

**描述**：playground chat 头部 model 当前仅在用户点会话项（`openSession()` → `getSession(sid)` 回填）时渲染；PageChat 挂载 effect 只拉 sessions 列表 + 建 SSE，不主动恢复 model。导致从 studio 切到 playground 时头部 model 空，必须点一下会话项才出来——「渲染依赖进入路径，而非渲染时机」（用户原话）。

**优先级**：P0（bug）

**用户故事**：作为用户，我从 studio 切回 playground 时希望头部 model 立刻显示，而不是空着等我点会话项。

**期望行为（用户可见）**：

- 进入 playground（有任何 active session）→ 头部 ModelPicker trigger 立刻显示当前 session 的 `provider/model`（无需用户点任何会话项）。
- activeSessionId 变化（切会话）→ ModelPicker 立刻跟随显示新 session 的 model。
- 与现有竞态守卫协调：复用 `openSessionTokenRef` / `activeSessionIdRef`，且与现有 `useLayoutEffect` 同帧清空逻辑（line 81-83）协调，不产生闪烁或回滚。

**关键机制（待 architect 落 tech spec）**：

- 在 `page-chat.tsx` 加一个 effect：依赖 `[activeSessionId]`；mount 或 activeSessionId 变化时主动 `getSession(sid)` 拿 model 字段回填 state；与现有竞态守卫共用 token；与现有 `useLayoutEffect` 同帧清空逻辑（line 81-83）协调，不产生闪烁或回滚。
- **不发明新概念**：model state 字段、`getSession` API、竞态守卫机制都是现有概念；本版本只是补一条 effect 把它们接上「渲染时机」。

**E2E Use Cases**

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-3.1.1 | 用户在 studio → 切到 playground（有 activeSession） | 头部 ModelPicker trigger 立刻显示该 session 的 `provider/model`，无需任何点击 |
| UC-3.1.2 | playground 内切换不同 session | ModelPicker trigger 跟随显示新 session 的 model |
| UC-3.1.3 | playground 无 activeSession（首次进入） | 头部 ModelPicker 显示空态（无 model），与现状一致 |

### 3.2 F2 — Markdown GFM 表格支持 [v0.0.63]

**描述**：`primitive-markdown-view.tsx` 手写最小渲染器，当前支持 段落/加粗/行内代码/无序列表/代码块，不支持 GFM 表格。扩展支持 GFM 表格语法。

**优先级**：P1

**用户故事**：作为用户，我希望 agent 回复里的表格能正确渲染成表格，而不是看到一堆 `|` 字符乱排。

**期望行为（用户可见）**：

- assistant 气泡内 markdown 含 `| a | b |` 表头 + `|---|---|` 分隔行 + 数据行 → 正确渲染为 HTML `<table>`（含 `<thead>` / `<tbody>`）。
- 列对齐标记 `:---`（左对齐）/ `---:`（右对齐）/ `:---:`（居中）→ 对应 `text-align` 样式。
- 视觉基线对齐 `_overview.md §8` answer 气泡风格（`bg-accent-surface` 底 + `text-fg` 字 + `border-accent-light` 边框）。
- 不支持的 markdown 语法（如 HTML 标签、复杂嵌套）按现状不渲染，本版本只加表格。

**关键机制（待 architect 落 ui spec）**：

- 在 `primitive-markdown-view.tsx` 渲染流程加 GFM 表格识别（block 级别，表头 + 分隔行 + 数据行 3 段匹配）+ 输出 `<table>` 结构。
- 视觉细节（边框 / padding / 表头背景 / 对齐）由 architect 在 ui spec 补「表格视觉基线」（参考 chat-page/_overview.md §8 answer 气泡风格）。

**E2E Use Cases**

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-3.2.1 | agent 回复含 GFM 表格 markdown（表头 + 分隔行 + 数据行） | 气泡内正确渲染 `<table>`（含表头单元格 + 数据行） |
| UC-3.2.2 | 表格列标记 `:---` / `---:` / `:---:` | 列对齐按标记生效（左 / 右 / 居中） |
| UC-3.2.3 | agent 回复含 `|` 字符但非合法表格（缺分隔行） | 按现状渲染（不强制成表格，不崩） |

### 3.3 F3 — 删 chat-model-tag（非 readOnly 分支）[v0.0.63]

**描述**：chat topbar 左侧 `chat-model-tag`（纯文本展示 `provider/model`）+ 右侧 `ModelPicker`（trigger 按钮已显示当前 model，`ModelPicker.tsx:70`）二者重复展示同一信息。删左侧 tag（非 readOnly 分支）；subagent readOnly 分支保留 tag（ModelPicker 不挂载，需 model 展示）。

**优先级**：P1

**用户故事**：作为用户，我不希望头部看到两遍同样的 model 信息（左 tag + 右 picker trigger）。

- 切会话不产生位移（删 tag 后 ModelPicker 占位稳定）。

**关键机制（待 architect 落 ui spec）**：

- `chat-page/_overview.md §4.4 component-chat-topbar` 修订：非 readOnly 分支删 `chat-model-tag` 节点 + testid；readOnly 分支保留 tag。

**E2E Use Cases**

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-3.3.1 | playground chat（非 readOnly）→ 看头部 | topbar 仅 ModelPicker trigger 显示 model；左侧无 tag |
| UC-3.3.2 | subagent readOnly chat → 看头部 | topbar 保留 `chat-model-tag`（不可点选） |

### 3.5 F5 — Studio 右侧双重 tab bar 重复修复（用户补充）[v0.0.63]

**描述**：studio chat 右侧功能区「工作区/长期记忆」入口 tab 出现 **2 行完全重复**，且工作区、长期记忆内容各有两份。根因：`SectionRightTabs`（v0.0.55，studio 右侧，自造 workspace/memory tab bar）tab=workspace 时渲染 `SectionWorkspacePanel`——而后者 v0.0.55 同批次也加了 `ComponentWsTabBar`（workspace/memory tab bar）+ memory tab。**双重 tab bar** = 2 行重复 + 内容两份。playground 侧只挂 `SectionWorkspacePanel`（一套）故不重复。

**优先级**：P0（功能性 bug，视觉混乱 + 内容重复）

**用户故事**：作为 studio 用户，我不希望右侧功能区看到两遍 tab + 两份内容。

**期望行为（用户可见）**：
- studio chat（群聊/单聊）右侧只有**一套**「工作区/长期记忆」tab bar（由 `SectionWorkspacePanel` 的 ws-tab-bar 提供）。
- 切 workspace/memory tab 正常切换内容，无重复、无两份。

**关键机制（待 architect 落 ui spec）**：
- `SectionRightTabs` 退化为薄 wrapper：删自造 tab bar + memory 分支，直接渲染 `<SectionWorkspacePanel sessionId={...}/>`（由它提供单一 tab bar）。

- 废止 `squad-tab-workspace` / `squad-tab-memory` testid（原 SectionRightTabs 自造 tab 的 testid），统一用 ws-tab-bar 的 ws-* testid。
- **不发明新概念**：`SectionWorkspacePanel`（含 ws-tab-bar）是现有组件，本版本只是删掉 SectionRightTabs 里与之重复的 tab bar，让 studio 右侧复用单一 tab bar。

**E2E Use Cases**
