## 1. 背景与现状 [v0.0.324]

### 1.1 v0.0.320 搜索框基础

v0.0.320 引入工作区文件搜索（`ComponentWsSearchBox`）：

- **输入**：搜索框在 PathBar 上方，直接输入 + 300ms 防抖，空输入不请求后端。
- **匹配**：后端 `GET /session/:id/workspace/search?q=` 按 **basename substring**（大小写不敏感）匹配，上限 200 条，返回 `{files: string[], dirs: string[], truncated?: boolean}`；忽略 node_modules/.git，symlink→dir 不递归。
- **结果渲染**：搜索框下方渲染**扁平结果列表**（`ws-search-results` / `ws-search-hit-*`），只列命中项，支持点击打开文件 / 切换目录。
- **搜索态互斥**：`searching=true` 时 **FileTree 整体隐藏**、PathBar 隐藏，界面只剩搜索框 + 扁平列表。

### 1.2 现状问题

| # | 问题 | 表现 |
|---|------|------|
| ① | **初始视图屏蔽内容** | 搜索时 FileTree 被整体隐藏，用户失去文件树上下文——看不到命中项在目录树中的位置，无法判断文件归属 |
| ② | **后续交互路堵死** | 扁平结果列表只能「打开文件 / 切换目录」；目录不能展开、不能继续浏览命中项的父目录内容，搜索结束后上下文清零 |

## 2. 需求描述 [v0.0.324]

### 2.1 核心需求

将搜索结果的展示从「扁平列表」升级为「**裁剪式结果树**」：搜索时 **FileTree 常驻**，数据源切换为裁剪树——只保留命中项 + 其祖先路径，形成一棵只含相关节点的迷你文件树；用户在裁剪树内可以像正常文件树一样展开/折叠/打开。

- **初始视图不再屏蔽内容**：FileTree 不隐藏，搜索态以裁剪树形态展示命中结果及其目录上下文。
- **后续交互路不堵死**：裁剪树目录可继续展开（lazy GET）、文件可点击打开，清空搜索恢复原始树。

### 2.2 用户故事

作为用户，我希望在工作区搜索文件时，结果以**带上下文的树**呈现（而不是孤立扁平列表）——我能看到命中文件在哪个目录下，能展开父目录继续浏览，也能一键清空回到完整文件树。

**优先级**：P1

## 3. 交互设计 [v0.0.324]

### 3.1 搜索态 = 数据源切换（非隐藏/显示）

- **FileTree 常驻渲染**：去掉 `!searching` 互斥条件，搜索态不隐藏 FileTree。
- **数据源切换**：`searching && filterResult` 时 FileTree 的数据源 = 裁剪树（`tree` / `childrenCache` / `expanded` 均按裁剪结果）；非搜索态 = 原始 `state`。
- **PathBar 仍隐藏**：搜索态 PathBar 保持隐藏（不变）。

### 3.2 裁剪式结果树（buildFilterTree）

前端**纯函数**从扁平命中 `{path, type}[]` 构建裁剪树（`ws-filter-tree.ts`，零新 UI 组件，复用 `ComponentWsFileTree` + `ComponentWsTreeItem` 渲染）：

- **路径拆解**：每个命中 path（如 `src/auth/login.ts`）拆出所有祖先段：`src`、`src/auth`、`src/auth/login.ts`。
- **祖先补全**：祖先段创建为 dir 节点（`hasChildren=true`），命中节点保留原始 type（file/dir）。
- **同路径合并**：同一 parent 下多个命中合并为一个 children 数组（Map 分组 + 按 path 去重）；非命中兄弟节点不创建（裁剪）。
- **展开列表**：所有祖先路径 + **命中目录路径** → `expandedPaths`（全展开到命中层，搜索态 expanded 覆盖原始 expanded）。
- **目录命中补全**：命中目录若在 `existingChildrenCache` 有已加载子项 → 用真实子项替换裁剪子项（该目录展示全部子项，而非仅命中路径上的）；缓存无 → 只展示裁剪路径上的子项，目录保持可展开（手动展开 lazy GET）。
- **限量截断**：超 100 条截断 + `truncated=true`。

### 3.3 裁剪树内交互（不堵死）

| 操作 | 行为 |
|------|------|
| 点击命中文件 | 复用 `handleOpen`（与正常树一致：按类型分流打开预览/编辑器/图片等） |
| 展开目录 | 复用 `handleExpand`（lazy GET `?parent=<path>` → children-loaded dispatch，写入与原始树**共享的 childrenCache**） |
| 折叠目录 | 复用 `handleCollapse` |
| 清空搜索（× 或删空） | `onResult(null)` → 恢复原始 tree + 原始 expanded，childrenCache 不丢（两态共享按 path key 合并） |

### 3.4 后端搜索语义升级（D1）

- `SEARCH_LIMIT` 200 → **100**。
- 匹配分叉：
  - q **不含 `/`**：basename substring 匹配（现状不变）。
  - q **含 `/`**：**完整相对路径** substring 匹配（`relChild` 相对 workspaceDir，大小写不敏感），文件和目录都覆盖。
    - 示例：q=`auth/login` 命中 `src/auth/login.ts`；q=`src/auth` 命中 `src/auth/` 及其路径含 `src/auth` 的后代。
  - 目录命中后不递归其下层（现状不变）；`{files, dirs, truncated?}` 返回格式不变；安全面（realpath + whitelistResolve + ignore node_modules/.git）不变。

### 3.5 搜索框瘦身（D3）

- **删除结果列表 JSX**（`ws-search-results` 扁平列表整段退役）。
- Props 变更：删 `onOpenFile` / `onToggleDir`；新增 `onResult: (result: {hits: {path, type}[], truncated} | null) => void`（结果上报父级构建裁剪树；null = 清空搜索态）。
- 防抖 effect：前端已加载树过滤（basename 匹配 / q 含 `/` 时 path 匹配）+ 后端补全 → 合并去重 `{path,type}[]` → 超 100 截断 → `onResult({hits, truncated})`。
- loading spinner / × 清空按钮 / 输入交互不变；`tooMany` state 退役（改由 onResult 上报 truncated）。

### 3.6 容器数据源切换（D4）

`SectionWorkspacePanel`：

- 新增 `filterResult: FilterTreeResult | null` state + `searchTruncated` state。
- `handleSearchResult`：result=null → 清搜索态；result 非 null → `buildFilterTree(hits, {limit: 100, existingChildrenCache: state.childrenCache})` → 设搜索态。
- 渲染态：搜索态 → `{...state, tree: 裁剪树顶层, childrenCache: 合并, expanded: 裁剪展开覆盖}`；非搜索态 → 原始 `state`。
- FileTree 常驻（去 `!searching` 条件）+ `tooMany` 提示 prop。

### 3.7 限量提示（D5）

- `ComponentWsFileTree` 新增 `tooMany?: boolean` prop：true 时 TreeLevel 下方渲染居中提示文案（`searchTooMany`，`px-2 py-3 text-[12px] text-muted text-center`）；非 tooMany 不渲染（零影响）。

### 3.8 文案（D7）

- `workspace.preview.searchTooMany`：zh-CN「结果超过 100 条，请进一步输入以缩小范围」/ en "Over 100 results, narrow your search"。

## 4. 需求边界 [v0.0.324]

### 4.1 做什么

- 搜索结果渲染从扁平列表 → 裁剪式结果树（FileTree 常驻 + 数据源切换）。
- 后端搜索语义升级：路径匹配（q 含 `/`）+ 上限 100。
- 搜索框瘦身：删结果列表，改 onResult 上报。
- 限量提示 + i18n 文案。

### 4.2 不做什么

- ❌ 不新增 UI 组件（裁剪树复用 FileTree / TreeItem 渲染）
- ❌ 不改后端返回格式（仍 `{files, dirs, truncated}` 扁平列表）
- ❌ 不改 handleOpen / handleExpand / handleCollapse / handleStaleRefetch 既有逻辑
- ❌ 不改 PathBar 搜索态隐藏行为
- ❌ 不改搜索结果上限以外的前端过滤语义（basename 匹配现状保留）
- ❌ 不动区域1/2/3/4 布局、不动预览区、不动 chat

## 7. 范式归属（逐控件） [v0.0.324]

| 控件/操作 | 范式 | 理由 |
|-----------|------|------|
| 搜索框输入 | 直接输入 + 防抖（不变） | 无配置提交语义 |
| 搜索结果渲染 | **数据源切换**（非隐藏/显示） | FileTree 常驻，搜索态切换数据源为裁剪树 |
| 裁剪树目录展开/折叠 | 即时操作（toggle，复用 lazy GET） | 与正常文件树展开完全一致 |
| 裁剪树文件点击 | 即时操作（onOpen） | 复用 handleOpen 分流 |
| 清空搜索恢复原树 | 即时操作（filterResult=null） | 数据源切回原始 state |
| 限量提示 | 静态文案 | 底部居中文案，非交互 |

**结论**：所有控件走「即时操作 / 数据源切换」，不引入新范式、不引入 SaveBar。
