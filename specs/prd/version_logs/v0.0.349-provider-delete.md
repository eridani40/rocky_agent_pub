## 1. 需求（老板 2026-08-14 22:00 拍板：dangling 双语义）

v0.0.347 模型路由方案落地后，引用已删 provider 的方案条目成为 dangling item：挂载方案全 dangling 时发消息 **500 无容错**；provider **无删除 UI 入口**（DELETE 端点早已存在但前端零调用方）；编辑器无逐条失效视觉。拍板双语义：

1. **runtime 拿不到就跳过（容错）**：单候选 dangling 由既有防御跳过；**全 dangling → 400 `MODEL_NOT_CONFIGURED`**（message「方案内所有模型不可用（provider 已删除或模型已禁用）」），与无方案分支 1 跑空同时机同构；MUST NOT 静默回退默认模型（D11）。
2. **重新编辑有失效 item 拦保存（严格）**：服务端既有 400 `model not found or disabled` 语义确认 + 前端本地预检同步（红描边 + `itemModelInvalid` 提示，与服务端双保险）。
3. **provider 删除入口**：详情页 SaveBar 右侧 danger 按钮 + ConfirmModal（通用警示文案；不做删除前引用扫描端点——dangling 双语义已兜底）。删除即时生效不进 diff-save。
