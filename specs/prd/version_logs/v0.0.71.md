# v0.0.71 PRD Change Log — plugin ext 配置重构（层级清晰 + config 不丢 + group 细分）

> version: 1.0 · 2026-07-05
> 一句话定位：**plugin ext 配置展示重构**——显式层级树（scope → group → EP → impl）+ config 数据不丢（统一 `ExtImpl.configSchema` 单一源）+ group 细分（7 组）。**无用户可见行为变更**（运行时两级 enabled 门 / cardinality 不变；管理页 v0.0.67 起只读化保留）。
> 概念权威源（**PRD 对齐**）：`specs/ui/overall/03-config-center.md` + `specs/ui/components/plugin-config-page/*`（D4 UI 形式不变）+ `specs/tech/config/[P0]plugin_config_service.md` + `[P0]ext_impl_scope.md` + `specs/tech/plugin_system/[P0]ext_impl_and_manifest_interface.md`（D7 删 schemaConfig / D8 删 plugin 级 configSchema+config 是 spec 同步点）+ `[P1]scopes_config_decl.md`（D2 default 满基线 + 删 _meta）。
> 方案锁定：4 轮对话确认，决策 D1-D8 详见 `states/user_query.md` v0.0.71 节（行 831-871）+ `states/v0.0.71/task-board.md`。

## 1. 背景与目标

v0.0.67 把 plugin/ext 配置代码化后，inventory 展示链路暴露**三个展示层痛点** + 一个潜在 instantiate bug：

1. **层级乱**：enabled 是隐式推导（"未列 = true"），UI 看到的"启用项"与运行时实际启用项信息对不上。
2. **config 丢**（bug-A + bug-B 双因）：`threshold_should_compact.compactRatio=0.6` 在配置页完全看不到。bug-A = inventory 不 JOIN manifest configSchema.default（代码偏离 spec）；bug-B = v0.0.67 全页 disabled 把齿轮按钮一起藏了。
3. **group 太大**：14 EP 里 10 个 `group="context"` 堆一个 tab = 42 impl，用户找不到东西。
4. **BUG-PLUGIN-004**（`states/v0.0.35/bugs/BUG-PLUGIN-004-...[open].md`）：`PluginManager.instantiate()` 浅 merge（spread）+ 缺层，spec §3.5 偏离。当前 7 个 configSchema 全扁平所以运行零影响，但 spec↔code 偏差必须裁决。

**本版本目标**：用「groups.json 唯一源 + 显式 scopes 增量覆盖 + 删 schemaConfig/config 死字段」把展示层对齐 spec、把 config 全链路打通（schema 形状 → UI 可见 → 实例化注入）；BUG-PLUGIN-004 改 deepMerge 收尾。

**非目标**：
- 不改运行时生效语义（两级 enabled 门 `plugin.enabled ∧ impl.enabled` 不变；exclusive/list/ordered cardinality 不变）
- 不恢复 v0.0.67 删的写端点（PUT 仍 405）
- 不动 chat/session/compact 核心路径
- UI 布局/组件不改（D4 形式不变；唯一新增 = impl 配置按钮恢复 + modal 改只读）

## 2. 范围

### 2.1 IN-SCOPE（9 项核心改动）

| # | 决策 | 摘要 |
|---|---|---|
| 1 | D1 groups.json | 新增 `app/plugins/groups.json`（group meta 唯一源）；删 `ExtensionPoint.group` 字段（消除冗余） |
| 2 | D2 scopes 增量覆盖 | `default.json` 改满基线（所有 EP × 每 EP 列 enabled impl+config）；`forked/test.json` 仅列激活 EP；删 `_meta.disabledImplsReason` |
| 3 | D3 config 只读展示 | impl 有 configSchema 必有「配置」入口（只读 modal），空/默认/已填都显示 |
| 4 | D4 UI 形式不变 | 布局/组件不动；group 拆分数据驱动；config 按钮 + 只读 modal 是唯一新增 |
| 5 | D5 7 group | context-ingest / context-assemble / context-compact / context-engine(session_store) / system-prompt / provider / web |
| 6 | D6 启动校验 | 每个 registry EP 必须在 groups.json 出现且仅一次，否则硬失败（沿用 v0.0.67 D3 风格） |
| 7 | D7 删 schemaConfig | `ExtImpl.schemaConfig` 字段/类型/spec 全删；7 个 impl manifest 的 schemaConfig 内容并进 configSchema；UI modal 改读 configSchema |
| 8 | D8 删 plugin 级 configSchema + config | `PluginManifest.configSchema?` + `config?`（0 plugin 声明 + 0 代码读，死字段）→ 删；instantiate spread → deepMerge（复用 `@app/server/llm`） |
| 9 | bug-A JOIN default | `inventory-builder` JOIN manifest configSchema.default 进 `config` 字段（对齐 spec） |

### 2.2 OUT-OF-SCOPE

- 不改运行时生效语义（运行时两级 enabled 门、cardinality、scope 回退算法均不变）
- 不动 chat/session/compact 核心路径（compact ratio 仅在 inventory 可见，运行时已生效）
- UI 布局/组件不改（D4 形式不变；modal 加 readOnly prop 是最小改动）
- 不恢复写端点（v0.0.67 只读化保留）

## 3. 关键用户路径（plugin 配置页，v0.0.67 起只读）

| 路径 | 用户操作链路 | 预期结果 |
|---|---|---|
| **P1** | 进 plugin 配置页 → 扩展点 tab → sidebar 选 group | 看到 **7 个 group**（拆分后的 context-ingest / context-assemble / context-compact / context-engine / system-prompt / provider / web） |
| **P2** | group 内 → 看 EP 列表 → 看 EP 下 enabled impl | **数据驱动显式层级**：UI 看到的 enabled 项与 scopes 声明 enabled 项一致（消除「隐式推导」） |
| **P3** | impl 有 configSchema → 点「配置」按钮 → 只读 modal | modal 展示 configSchema 形状 + 有效 config 值（空/默认/已填都显示，例如 `compactRatio=0.6`）；全部字段 readonly、无保存按钮 |
| **P4** | scope-switcher 切到非 default scope（forked/test）→ 看 EP 区 | 只看激活的 EP + enabled impl；未激活 EP 显 `ext-point-{pointId}-inactive-hint`（v0.0.67 行为保留）；对比 default scope（P1/P2 进页即满基线：所有 EP × enabled impl） |

> 每条路径 = 测试最低覆盖要求（test-plan 阶段逐条对应 AT/ET case）。P3 是本版本核心新增（config 不丢 + 只读入口），P1/P2 是 D1+D2 数据驱动的展示正确性回归（default 进页即满基线），P4 是 v0.0.67 只读化保留 + 非 default 增量。
