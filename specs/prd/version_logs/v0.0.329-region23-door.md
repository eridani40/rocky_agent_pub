# v0.0.329 — 区域2(chat)/区域3(预览)布局重构：门模型（可横向滑动的门）

> PRD 增量 | 版本：v0.0.329 | 日期：2026-08-11
> worktree：`worktrees/v0.0.329-region23-door`（分支 v0.0.329-region23-door，基于 dev1 0.0.328）
> 需求来源：老板亲自敲定（门模型），替代被推翻的旧方案（菱形双向切换器 / clip-path / focusMode 三态移位 / region-switcher）

## 1. 需求描述 [v0.0.329]

区域2(chat) 与 区域3(预览编辑) 之间的分隔是一扇「**可横向滑动的门**」。

- **2+3 是固定门框**：区域2+区域3 合并区的**总宽、位置永不变**（左边区域1 不动、右边区域4 不动）。
- **门滑到哪头就遮哪头、露另一头**：门在 2+3 门框内横向滑动，停在最左 = 遮住区域2、露出区域3；停在最右 = 遮住区域3、露出区域2；停在居中 = 2/3 共存（现状）。

### 1.1 用户故事

作为用户，我希望 chat 与文件预览之间的分隔像一扇门：想看满屏文档时把门滑到最左（预览占满门框），想专注聊天时把门滑到最右（chat 占满门框），平时门居中两栏共存——一键滑门，而不是只能单向收起预览。

**优先级**：P1

## 2. 两个零件（全部复用现有，零新造） [v0.0.329]

### 2.1 线（分隔线）

| 形态 | 语义 | 说明 |
|------|------|------|
| **细线** | 2/3 共存的分隔 | 现状 `.pv-resize-left` 那条 2/3 分界细线，**形态、逻辑不动** |
| **粗线** | 收起侧边缘（可点击恢复） | 现状区域3 收起后那条粗线 rail（`pv-collapsed-rail`），**形态、逻辑原样不动**，可点击恢复 |

### 2.2 把手（chevron 手柄）

- **单独组件**，复用现在的 `component-preview-collapse-toggle`（`ComponentPreviewCollapseToggle`，VSCode 风格竖长条手柄 `w-[8px] h-[44px] rounded-full`，chevron 图标；v0.0.329 视觉微调 7→8px 水平加粗）。
- 组件形态、hover 样式、点击手感**零改动**，只在三态下复用/组合。

### 2.3 把手位置铁律（MANDATORY）

> **左把手永远贴线的左侧，右把手永远贴线的右侧。**

任何状态下都不允许把手跑到线的异侧（左把手在线右 / 右把手在线左 = 实现错误）。

## 3. 三态定义 [v0.0.329]

| 状态 | 线 | 把手 | 点击行为 |
|------|----|------|----------|
| **门居中（默认）** | 细线（2/3 分界，居中） | 细线左侧一个 ◀ + 细线右侧一个 ▶ | 点 ◀ → 门滑最左；点 ▶ → 门滑最右 |
| **门滑最左（遮2露3）** | 左侧粗线（贴门框左缘） | 粗线右侧一个 ▶ | 点粗线或 ▶ → 门回居中 |
| **门滑最右（遮3露2）** | 右侧粗线（贴门框右缘，= 现在区域3 收起那条） | 粗线左侧一个 ◀ | 点粗线或 ◀ → 门回居中 |

### 3.1 门居中（默认态）

- 区域2/区域3 按现状宽度共存（chat flex-1 + preview `pv-width-<sid>`）。
- 门 = 2/3 分界的**细线**，位置 = 现状 `.pv-resize-left` 所在处。
- 细线**左侧**贴一个 ◀ 把手、细线**右侧**贴一个 ▶ 把手（复用 `ComponentPreviewCollapseToggle`）。
- 点 ◀：门滑到最左（进入「门滑最左」态）。点 ▶：门滑到最右（进入「门滑最右」态）。

### 3.2 门滑最左（遮 2 露 3）

- 区域2(chat) 被门遮住（宽 0 不可见），区域3(预览) 露出并**占满 2+3 门框**。
- 门 = **左侧粗线**，贴门框左缘（区域1 右边界处），形态 = 现状 `pv-collapsed-rail` 粗线。
- 粗线**右侧**贴一个 ▶ 把手。
- 点粗线或点 ▶：门回居中（恢复 2/3 共存）。

### 3.3 门滑最右（遮 3 露 2）

- 区域3(预览) 被门遮住（宽 0 不可见），区域2(chat) 露出并**占满 2+3 门框**。
- 门 = **右侧粗线**，贴门框右缘（区域4 左边界处）——**就是现在区域3 收起后那条粗线的位置与形态，原样复用**。
- 粗线**左侧**贴一个 ◀ 把手。
- 点粗线或点 ◀：门回居中（恢复 2/3 共存）。

### 3.4 状态机

```
        点 ◀                    点 ▶
  居中 ────────► 门滑最左    居中 ────────► 门滑最右
  居中 ◄────────            居中 ◄────────
     点粗线/▶                  点粗线/◀

  门滑最左 ──×──► 门滑最右 （禁止直接互跳，必须经居中中转）
```

- 居中 → 最左：点细线左侧 ◀
- 居中 → 最右：点细线右侧 ▶
- 最左 → 居中：点粗线或 ▶
- 最右 → 居中：点粗线或 ◀
- **最左 ↔ 最右 禁止直接切换**（必须先回居中）

### 3.5 持久化

- 门状态 per-session localStorage（对齐 `pv-collapsed-<sid>` 模式）：key `pv-door-<sid>`，值 `'center' | 'left' | 'right'`，缺省 `'center'`。
- 刷新/重进会话恢复上次的门位置。

## 4. 三个不变（红线，MANDATORY） [v0.0.329]

1. **粗线形态逻辑不动**：现在区域3 收起那条粗线（`pv-collapsed-rail`）+ 手柄（`ComponentPreviewCollapseToggle`）**原样复用**，不改样式、不改交互手感。
2. **门框（2+3）总宽位置不动**：区域2+区域3 合并区的总宽度与位置在三态间恒定（只由区域1/4 宽度 + 窗口宽度决定）；左区域1、右区域4 不动。
3. **内容不移位**：区域2 永远在门的左侧、区域3 永远在门的右侧；任何态下**绝不出现区域互相跑位、某区内容跑到另一区、或门框内出现空白区**。

## 6. 需求边界 [v0.0.329]

### 6.1 做什么

- 只动 2/3 分隔这条「门」：三态渲染（细线+双把手 / 左粗线+右把手 / 右粗线+左把手）+ 三态点击切换。
- 复用 `component-preview-collapse-toggle` 把手组件（零新造组件）；粗线 = 现 `pv-collapsed-rail`。
- 门状态 per-session 持久化（`pv-door-<sid>`）。

### 6.2 不做什么（禁止）

- ❌ **菱形**、**clip-path**、focusMode 三态移位、region-switcher 新组件（被老板推翻的旧方案，一律禁止）
- ❌ 不碰区域1（ConvPanel）/区域4（WorkspacePanel）的显隐、宽度、分隔线
- ❌ 不碰布局引擎大改（`useThreeColLayout` / `computeThreeColLayout` 拖拽宽度模型不重写；门态在上层控制槽位显隐/宽度分配）
- ❌ 不发明新组件、不改 `ComponentPreviewCollapseToggle` 与 `pv-collapsed-rail` 的形态逻辑
- ❌ 不动预览区内部组件（TabBar/viewer/editor/floating-actions/dirty modal）与 chat 内部组件（message-stream/input/usage）
- ❌ 不影响无预览区场景（academy section-version-chat 无 Provider → 无门）
- ❌ 不做通知/badge（区域2 被遮时新消息不可见是用户显式选择，不做提示）

## 8. 视觉基线 [v0.0.329]

- **细线**：现状 `.pv-resize-left` 2/3 分界分隔线样式不动（区域2/3 共存的视觉不变）。
- **粗线**：`pv-collapsed-rail`（**[v0.0.329 视觉修复·方案 A 老板验收] 完整粗条：`w-[7px] bg-bg-warm` 深一档 + 左右双 border（`border-l-[2px] border-r-[2px]`），hover `bg-surface-3`**）；左态贴门框左缘、右态贴门框右缘（右态 = 现区域3 收起那条线的原位置）。
- **把手**：`ComponentPreviewCollapseToggle` 竖长条手柄（**[v0.0.329 视觉微调] `w-[8px] h-[44px] rounded-full`（7→8px 水平加粗 20%）**，chevron size 12，`bg-surface border border-border shadow-sm`，hover `bg-accent text-white`）原样；垂直居中（`top-1/2 -translate-y-1/2`）；handle 保持 `bg-surface` 白底（对比深色 rail 更清晰）。
- **把手与线相对位置**：左把手贴线左侧、右把手贴线右侧（铁律，§2.3）；贴线偏移 8px（`-left-[8px]` / `-right-[8px]`，= handle 宽同步，消除 1px 重叠，v0.0.329 视觉修复 3）。
- **过渡**：门滑动/区域显隐用 `transition-[width] duration-200 ease`（与既有 collapse 过渡一致），避免瞬间跳变。
- 不引入新色彩、新阴影、新圆角体系。

## 13. 注意事项 [v0.0.329]

- **拖拽 resizer 与门的关系**：居中态细线上的拖拽调宽（`.pv-resize-left`）保留现状；门滑到最左/最右后该 resizer 不可见（粗线不可拖拽调宽，只能点击回居中）——与现状 collapsed 态行为一致。
- **dirty 守卫**：门切换只是显隐区域，不涉及 tab 打开/关闭/切换，不触发 dirty modal。
- **区域2 被遮时新消息**：SSE 仍到达但不可见，是用户显式选择；恢复居中后可见；不做 badge/通知。
