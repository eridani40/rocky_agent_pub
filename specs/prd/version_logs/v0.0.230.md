## 1. 版本主题（产品语义）

**核心原则（用户澄清）**：每个 session 的 model picker 有两层——「使用默认模型」置顶项 + 底下全量模型枚举。而「默认模型」的位置取决于场景：

| 场景 | 默认模型来源 |
|---|---|
| **playground**（个体） | app config `default_models.chat` |
| **academy classroom session**（群体） | `classroom.defaultModel` |
| **studio session**（群体） | `squad.modelDefault` |

**群体级默认模型配置必须选一个具体模型**——没有上一级可继承，也不存在「应用层面默认模型」的概念（那是 playground 个体级逻辑，误用到群体级是错的）。

本版修两个与上述原则相悖的现状：

- **问题 1（显示不一致）**：配置页默认模型 picker（`component-key-model-picker`，管 `default_models.chat`）trigger 只显纯 modelId，无 provider 前缀；而新建 squad 的 `ModelPicker` 和会话下 `InputModelPicker` 都用 `formatModelDisplay`（`provider / model`）。同是模型选择器，显示口径不一致。
- **问题 2（逻辑错误）**：教室 head（`section-classroom-detail` 的 defaultModelSlot）用 `ModelPicker` + `inheritLabel`「跟随应用默认」+ `onInherit` 清空 defaultModel——把「个体级默认可继承」误用到群体级。群体级默认模型必须选具体模型（对齐 studio squad manageTab 形态，无继承选项）。

## 2. 功能需求（用户可感知）

### 2.1 块1 — 配置页默认模型 picker 显示 provider 前缀 [v0.0.230]

**优先级**：P0
**用户故事**：作为用户，我在应用配置里看到默认模型（playground 的 `default_models.chat`）是 `glm-5.2` 这种裸模型名，而别处（新建 squad、会话下）都是「MiniMax / glm-5.2」带 provider——两个同概念控件显示口径不同，我要一眼看出这个模型是哪个 provider 的。

**产品规则**：
- **trigger 显示对齐**：配置页默认模型 picker trigger 已配置时显示 `providerLabel / modelLabel`（复用 `formatModelDisplay` 口径，与 `ModelPicker` / `InputModelPicker` trigger 完全一致），不再只显纯 modelId。
- **provider 反查来源**：picker 已按 enabled provider 展平 item（`currentItem` 含 providerId），从命中 item 取 provider 展示；**provider 不可用降级不变**（providers 未加载 / 对应 provider 被删 → 仍显纯 modelId、无 IconBox）——不因前缀补齐引入误导。
- **仅 trigger 展示变更**：面板列表（IconBox + 模型名 + modelId 副标）、x 清除、搜索、选择语义一律不动；落盘值仍为纯 modelId（`default_models.chat` 数据契约不变）。
- **布局稳定（MANDATORY 铁律）**：trigger 加 provider 前缀可能变长 → 超长 truncate（`ModelPickerTrigger` 既有 `whitespace-nowrap overflow-hidden text-ellipsis`），不改变任何布局占位与相邻元素。

#### E2E Use Cases（块1）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-230-1 | 打开应用设置 → 默认模型 key 卡片 → 看已配置的 trigger | trigger 显示 `providerLabel / modelLabel`（如「MiniMax / glm-5.2」），不再只有裸 modelId |
| UC-230-2 | 打开默认模型 picker → 搜索并选中另一模型 → 保存 | 保存后 trigger 刷新为新模型的 `provider / model` 前缀显示 |
| UC-230-3 | （降级路径）删除该 provider 后重开配置页 | trigger 仍显示该 modelId 文本（无 IconBox），不崩不误显示其他 provider |

### 2.2 块2 — 教室 head 群体级默认模型必须选具体模型 [v0.0.230]

**优先级**：P0
**用户故事**：作为用户，我在教室 head 配置「教室默认模型」——这个模型是教室所有 session（head/coach/student）的默认缺省来源。现在下拉里有「跟随应用默认」这一项，可教室是群体，没有上一级可继承、也没有「应用层默认模型」这回事——这个选项是错的，我要只能选一个具体模型（和 squad 管理 tab 一样）。

**产品规则**：
- **去掉继承选项**：教室 head 默认模型 picker 去掉 `inheritLabel`「跟随应用默认」+ `onInherit` 清空逻辑——**下拉里不再有「跟随应用默认」项**；改与 studio squad manageTab 同款形态（`ModelPicker` 无 inherit 选项）。
- **必须选具体模型**：配置教室默认模型 = 从模型枚举中选一个具体 provider/model；**没有「不选 / 跟随上级」的状态**。
- **未配置呈现**：教室尚未配置默认模型（新建后、存量教室）→ picker trigger 显「选择模型」占位（ModelPicker 无 inherit 时的既有 placeholder 口径），不显「跟随应用默认」误导项。
- **缺省策略（运行时语义）**：教室默认模型是教室会话模型缺省的**唯一来源**——未配置时教室会话没有可用的「默认模型」：
  - 会话 model picker 顶部不再有「使用默认模型」置顶项（chrome.defaultModel = null，`session-chrome.ts` 已按 classroom.defaultModel 投影）；
  - 会话未显式选具体模型时发消息 / 训练 → 报「请配置模型」类错误（对齐 squad：`squad.modelDefault` 未设 → 链跑空 → `MODEL_NOT_CONFIGURED`），并引导去教室 head 配置；
  - **academy 运行时链不再下探 app 默认**（现 v0.0.216 起三档链 `session → classroom.defaultModel → app_config.default_models.chat` 的第三档即「个体级默认误用」，本版收窄为 `session → classroom.defaultModel → 报错`，对齐 squad 两档链）。
- **创建即必填（用户确认 2026-07-31）**：新建教室表单加「默认模型」必选字段（对齐 squad wizard `modelDefault` required）；未选模型提交被阻（表单校验拦截）。存量教室（创建时无 defaultModel）head 显「未配置」占位 + 运行时明确报错引导，不强制回填。

> **已确认决策（用户 2026-07-31）**：academy 运行时链收窄去 app 默认兜底（无「应用层默认」概念，只能报错）；**创建教室即必填默认模型**（对齐 squad wizard modelDefault required）——见 §6。

> 技术注记（归 architect，PRD 定语义）：resolver 链收窄 + 错误体 `detail.sessionType` 已含 `'academy'`（v0.0.216 已扩）；`MODEL_NOT_CONFIGURED` 提示文案可带「去教室设置配置默认模型」引导。

#### E2E Use Cases（块2）

| ID | 用户操作链路 | 预期结果 |

| UC-230-4 | 教室详情 head → 点默认模型 picker → 看下拉项 | 下拉里**没有**「跟随应用默认」项；顶部即模型枚举，必须选具体模型 |

## 5. 验收口径

- **功能**：P-A / P-B / P-C 全 PASS（UT + ET 冒烟共同覆盖）。
- **显示一致不变量**：全站模型选择器 trigger 显示口径一致——已配置一律 `provider / model`（KeyModelPicker / ModelPicker / InputModelPicker）；provider 不可用降级显纯 modelId。
- **群体级默认不变量**：教室 head 与 squad manageTab 同款——无继承选项、必须选具体模型；教室未配置 → 会话无默认项 + 运行时明确报错（对齐 squad 未设语义）。
- **academy 链收窄**：教室会话 model 缺省解析不再下探 app 默认（session → classroom.defaultModel → `MODEL_NOT_CONFIGURED`）。
- **数据契约不变量**：`default_models.chat`（纯 modelId）、`classroom.defaultModel`（复合 `{providerId?, modelId}`）落盘 schema 不变；`/config/app` 与 `/academy/classroom` 端点契约不变。
- **回归不变量**：playground / studio 现有 model picker 行为（两层语义等）不回归。
- **视觉保真**：无设计稿 → vision_check compare 跳过。
