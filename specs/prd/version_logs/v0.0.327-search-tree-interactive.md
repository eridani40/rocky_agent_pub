# v0.0.327 — 文件树搜索结果可交互性增强

> PRD 增量 | 版本：v0.0.327 | 日期：2026-08-11
> 324 后续：老板体验搜索后发现「初始视图屏蔽了内容，但后续交互的路不能堵死」

## 1. 需求描述 [v0.0.327]

老板核心理念（原话）：「搜索只是提供了一个缩减版的文件目录的初始视图，有些内容被屏蔽了，但是后续交互的路不能堵死，不然搜索没有意义了。」

2 点需求：

1. **命中的文件夹默认不展开其内容**：搜索到的目标节点如果是文件夹，只显示它命中了（作为搜索结果出现在裁剪树里），**不自动展开其子内容**；祖先路径照旧展开（否则看不到命中节点）
2. **搜索态节点完整交互不堵死**：搜索结果中的节点保留和正常文件树（非搜索态）完全一致的交互能力——文件夹可手动展开/收起、右侧「打开文件夹」（系统文件管理器）、点击文件打开

### 1.1 用户故事

作为用户，我在搜索文件时看到一个缩减版的结果树，但我希望能继续在结果树里自由操作——展开命中文件夹看里面有什么、打开文件夹到系统文件管理器、点击文件直接打开——就像没有搜索时一样。

**优先级**：P1

## 2. 现状问题（324 搜索态 bug 分析） [v0.0.327]

### 2.1 问题①：命中文件夹被自动展开

**根因**：`ws-filter-tree.ts` `buildFilterTree` L134-138 把命中目录 path 也加入 `expandedPaths`：

```ts
// 6. 展开列表：祖先路径已加入 expandedSet；命中目录也加入
for (const hit of truncated) {
  if (hit.type === 'dir') {
    expandedSet.add(hit.path);  // ← BUG：命中文件夹被自动展开
  }
}
```

**现象**：搜索 `src` → 命中 `src/` 文件夹 → `src/` 自动展开 → 里面全部子项（含未搜索命中的子文件夹/文件）暴露 → 结果树爆炸，失去「缩减视图」初衷。

**期望**：命中文件夹只显示自身命中（出现在裁剪树里），**不自动展开**；用户想看内容自己手动点开。

### 2.2 问题②：搜索态手动展开/收起被覆盖无效

**根因**：`section-workspace-panel.tsx` L302-310 搜索态 FileTree 的 `state` prop 每次 render 用 `filterResult.expandedPaths` **完全覆盖** `state.expanded`：

```tsx
state={searching && filterResult
  ? {
      ...state,
      tree: filterResult.tree,
      childrenCache: { ...state.childrenCache, ...filterResult.childrenCache },
      expanded: Object.fromEntries(filterResult.expandedPaths.map((p) => [p, true])),
      //  ↑ 完全覆盖：用户手动展开/收起的 reducer 操作被丢弃
    }
  : state}
```

**现象链路**：
1. 用户在搜索态点文件夹 twisty → `handleExpand(path)` → `dispatch({ type: 'toggle-expand', force: true })` → `state.expanded[path]` 正确更新为 true
2. React 重渲染 → FileTree 拿到的 `state.expanded` 被 `filterResult.expandedPaths` 覆盖 → 手动展开被还原为「filterResult 初始态」
3. 视觉上「点了没反应」——交互被堵死

### 2.3 交互回调已全接线（入口无屏蔽）

**好消息**：`onExpand` / `onCollapse` / `onOpen` 从 `section-workspace-panel` → `ComponentWsFileTree` → `ComponentWsTreeItem` 全程无搜索态门控。交互入口没堵死，**问题纯粹在 expanded 状态被覆盖**。

## 4. 改动设计 [v0.0.327]

### 4.1 改动①：命中文件夹不自动展开

**文件**：`ws-filter-tree.ts` `buildFilterTree`

**改动**：删除 L134-138 命中目录加入 expandedSet 的循环。

```diff
   // 6. 展开列表：祖先路径已加入 expandedSet
-  for (const hit of truncated) {
-    if (hit.type === 'dir') {
-      expandedSet.add(hit.path);
-    }
-  }
+  // [v0.0.327] 命中文件夹不自动展开——只显示命中（出现在裁剪树），不暴露子内容；
+  //   用户想看内容手动展开。祖先路径在 L106 路径拆解时已加入 expandedSet（路径可见性必需）。
```

**效果**：
- 祖先路径仍展开（L106 `expandedSet.add(currentPath)` 保留——命中节点路径可达性必需）
- 命中文件夹显示为收起态（有 twisty，用户可手动展开）
- 命中文件夹的 childrenCache 数据仍保留（L111-128 补全逻辑不变）——用户手动展开时直接渲染缓存，未缓存则 lazy GET

### 4.2 改动②：搜索态手动展开/收起生效

**文件**：`section-workspace-panel.tsx` L302-310

**问题本质**：搜索态传给 FileTree 的 `expanded` 每次 render 被 `filterResult.expandedPaths` 完全覆盖，`handleExpand`/`handleCollapse` 的 dispatch 更新（写入 `state.expanded`）被丢弃。

**方案**：filterResult 的 `expandedPaths` 只作为**初始展开建议**——新搜索结果到达时合并入 `state.expanded`，之后用户的手动操作通过 reducer 正常更新 `state.expanded`，render 时直接用 `state.expanded` 不再覆盖。

**不变量**（architect 实现时必须满足）：

1. **新搜索结果到达**（filterResult 变化）：filterResult.expandedPaths 作为初始展开合并入 state.expanded（MERGE 不覆盖——保留用户可能已有的手动展开）
2. **搜索态手动展开文件夹**：dispatch `toggle-expand force:true` → state.expanded[path]=true → 搜索态 FileTree 看到展开生效（lazy GET 子目录正常走）
3. **搜索态手动收起文件夹**：dispatch `toggle-expand force:false` → state.expanded[path]=false → 看到收起生效
4. **render 时**：搜索态 FileTree 的 expanded 字段直接用 `state.expanded`（不覆盖），tree/childrenCache 仍用 filterResult 的裁剪树数据

**实现提示**（给 architect，非强制）：
- 方案 A（effect 合并）：filterResult 变化时，effect 把 expandedPaths merge 进 state.expanded（dispatch 一个新的 action 如 `merge-expanded`）；render 时 FileTree 的 state 不再覆盖 expanded 字段
- 方案 B（本地 overlay state）：维护一个搜索态 expanded overlay（初始 = filterResult.expandedPaths，用户操作时更新 overlay）；render 时 tree/childrenCache 用 filterResult，expanded 用 overlay
- 两种方案都可，architect 按代码结构选最简洁的

## 11. 注意事项 [v0.0.327]

### 11.1 清空搜索后 expanded 保留

搜索态用户手动展开的目录（写入了 state.expanded），清空搜索回到正常树后**保留**（不做快照/回退）——展开是用户显式操作，state.expanded 是 reducer 权威，自然继承合理。

### 11.2 命中文件夹 childrenCache 补全不变

L111-128 的命中目录 childrenCache 补全逻辑（`existingChildrenCache` 有缓存则用真实子项）**保留**——数据缓存是「展开能力」（用户手动展开时直接渲染不需重新 GET），展开状态是「用户选择」，两者独立。改动①只改 expandedSet（不自动展开），不改缓存补全。
