# v0.0.325 — html 预览态「浏览器打开」按钮

> PRD 增量 | 版本：v0.0.325 | 日期：2026-08-11

## 1. 需求描述 [v0.0.325]

html 文件在预览区打开后，**预览态（只读 mode='view'）**时，在胶囊容器（`ComponentPreviewFloatingActions`）内新增一个「**浏览器**」按钮，点击后在**系统默认浏览器**打开该 html 文件。

**一句话**：用户在 app 内看 html 源码（pre 朴素渲染），想看渲染效果 → 一键甩到系统浏览器。

### 1.1 用户故事

作为开发者，我希望在预览区查看 html 文件源码时，能一键在系统浏览器打开看渲染效果，以便快速验证页面呈现。

**优先级**：P1

## 2. 需求边界 [v0.0.325]

### 2.1 做什么

| 维度 | 约束 |
|------|------|
| 文件类型 | **仅** `.html` / `.htm`（FileFormat = `'code'`，扩展名 `.html`/`.htm`） |
| 显示态 | **仅预览态**（`mode='view'`）；编辑态不显示 |
| 位置 | 胶囊容器内，**编辑按钮之后第 2 位** |
| 行为 | 点击 → 系统默认浏览器打开该 html 文件 |
| 图标 | feather 单色 stroke 图标（沿用 preview-icons.tsx 族） |

### 2.2 不做什么

- ❌ 不改 html 在预览区的渲染方式（当前 `<pre>` 朴素渲染 → code 分类，**不引入 iframe/webview 沙箱渲染**——本版本不做 html 渲染态）
- ❌ 不动编辑态按钮（保存/撤销/格式化/校验）
- ❌ 不动胶囊容器本体样式（`rounded-xl border bg-surface p-1 shadow-sm`）
- ❌ 不动其他文件类型（md/json/txt/... 仍无浏览器按钮）
- ❌ 不动 viewer/editor 组件本身

## 3. 交互设计 [v0.0.325]

### 3.1 按钮位置与顺序

胶囊容器（`ComponentPreviewFloatingActions`）在 **只读态** 当前只有 1 个「编辑」按钮。本版本加第 2 个「浏览器」按钮：

```
只读态胶囊容器（html 文件）：
┌──────┐
│ 编辑 │  ← 第 1 位（PencilIcon，既有）
├──────┤
│浏览器│  ← 第 2 位（新增，GlobeIcon）
└──────┘
```

> **非 html 文件的只读态**：胶囊容器仍只有「编辑」1 个按钮（浏览器按钮不渲染）。

### 3.2 按钮样式

沿用胶囊容器内图标按钮规范（对齐 chat-float-menu）：

- 尺寸：`h-8 w-8 rounded-lg`（与编辑/保存等按钮完全一致）
- 色调：`text-muted hover:bg-bg-warm hover:text-fg`（普通非主色调，与编辑按钮同款）
- 图标：size 统一 16，feather stroke 风格（`strokeWidth=2, strokeLinecap='round'`）
- tooltip：`title` + `aria-label` = 「在浏览器打开」（i18n key `workspace.preview.openInBrowser`）

### 3.3 图标选择 [v0.0.325]

**推荐：`GlobeIcon`**（feather globe，地球仪）——语义最准确（= 浏览器/网络），单色 stroke 与族一致。

候选对比：

| 候选 | feather 原型 | 语义贴合度 | 备注 |
|------|-------------|-----------|------|
| **globe** ✅ | globe（地球仪） | ★★★★★ | 通用「浏览器/网页」语义，最直觉 |
| external-link | external-link（外链箭头） | ★★★★ | 「外部打开」语义，但偏向「跳转链接」非「浏览器」 |
| chrome | — | ★★ | 非 feather 族，平台绑定（Chrome≠系统默认浏览器），排除 |

> 决策：用 **globe**。需在 `preview-icons.tsx` 新增 `GlobeIcon` 组件。

### 3.4 点击行为

点击「浏览器」按钮 → 调系统默认浏览器打开当前 tab 对应的 html 文件。**异步操作，不阻塞 UI**；失败静默 `console.warn`（best-effort，不弹 error——与既有 `openWorkspaceItem` / `openPath` 调用方一致）。

## 4. 打开方式（关键技术决策） [v0.0.325]

> **核心发现**：预览区 tab 有两种文件源（`source: 'workspace' | 'absolute'`），磁盘路径获取方式不同 → 对应两条已有打开链路。**无需新增 IPC 或 API**。

### 4.1 html 在 app 内的渲染现状

html 当前 **不渲染为网页**——`.html`/`.htm` → FileFormat `'code'` → category `'code'` → `<pre>` 朴素渲染源码（`ComponentPreviewViewer` §5.2）。app 内看的是 html 源码文本，不是渲染态。本版本不改变此行为。

### 4.2 两条打开路径（按 source 分流）

#### A. workspace 源（`tab.source === 'workspace'`）

- **路径形态**：相对 workspaceDir 的路径（如 `reports/index.html`），renderer 不可知磁盘绝对路径。
- **打开方式**：调已有 HTTP `POST /session/:id/workspace/open`（`openWorkspaceItem(sessionId, { path: tab.path, kind: 'file' })`），后端 spawn 系统默认应用打开（html → 系统默认浏览器）。
- **依据**：`workspace-api.ts` L38 `openWorkspaceItem`；后端契约 `specs/api/overall/04-agent-session.md §2.6.2`。

#### B. absolute 源（`tab.source === 'absolute'`）

- **路径形态**：已是磁盘绝对路径（如 `/Users/x/report.html`），可能含 `~` / `file://` 前缀。
- **打开方式**：调已有 IPC `window.rockyShell.openPath(tab.path)`，main 侧 `computeResolveLocalPath` 展开（strip `file://` / 展开 `~`）→ `shell.openPath(absPath)` → 系统默认应用。
- **依据**：`open-external-ipc.ts` L245 `shell:openPath` handler；`preload.ts` `openPath`。

### 4.3 分流逻辑（renderer 侧）

```ts
function openInBrowser(tab: PreviewTab, sessionId: string): void {
  if (tab.source === 'workspace') {
    // A: HTTP → 后端 spawn
    void openWorkspaceItem(sessionId, { path: tab.path, kind: 'file' })
      .catch((e) => console.warn('openInBrowser(workspace) failed:', e));
  } else {
    // B: IPC → main shell.openPath
    void window.rockyShell?.openPath(tab.path)
      .catch((e) => console.warn('openInBrowser(absolute) failed:', e));
  }
}
```

> **复用既有链路，零新增 IPC/API/后端改动。** 整个功能 = renderer 侧按钮 + 一个分流函数。

## 5. 显示条件 [v0.0.325]

「浏览器」按钮在胶囊容器内的渲染条件：

```
mode === 'view'           // 只读态
&& tab.format === 'code'  // code 分类
&& /\.(html?|htm)$/i.test(tab.fileName)  // 扩展名 .html/.htm（大小写不敏感）
```

> **不用 `tab.format === 'code'` 单独判定**——code 分类含 `.py`/`.js`/`.ts`/... 所有编程语言，只有 html 才需要浏览器按钮。必须额外校验扩展名。
