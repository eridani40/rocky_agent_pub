## 1. 需求描述 [v0.0.339]

调整本地文件的打开分流策略，三条老板铁律：

1. **CSV/TSV 无条件不内置打开** → 系统默认程序打开（Numbers/Excel 等），与文件大小无关。
2. **所有内置文本 >5MB 不内置打开** → 系统默认程序打开。
3. **图片不动**：6 格式图片（png/jpg/jpeg/gif/webp/svg）保持内置弹层查看器，**不做大小限制**。

### 1.1 用户故事

作为用户，我希望 CSV/TSV 数据文件直接交给 Numbers/Excel 打开（内置纯文本编辑体验差），大文本（>5MB）也交给系统默认程序（避免内置编辑器加载卡顿），而图片仍走内置查看器——打开文件的行为符合直觉且不卡。

**优先级**：P1

## 2. 现状梳理 [v0.0.339]

### 2.1 文件打开统一分发（openLocalPath）

本地文件（workspace 相对 / absolute 绝对）打开统一走共享分发 lib `app/web/src/lib/open-local-path.ts`（v0.0.280，聊天链接与右侧文件树共用，老板铁律：两处行为一致）。五路分流顺序固定：

```
① kind==='folder'   → 系统文件管理器
② isRemoteLinkPath  → 嗅探浏览器（.url，失败降级 editor txt）
③ isImagePath       → 内置只读 viewer（6 格式图片）
④ getFileFormat≠null → 内置可编辑 editor（12 格式文本进预览区 tab / 弹层）
⑤ 其余              → 系统默认应用打开
```

### 2.2 文本格式权威（file-format.ts）

`app/web/src/lib/file-format.ts` 是单一权威：

- **13 格式**：md / json / jsonl / yaml / xml / toml / csv / tsv / txt / ini / env / log / code（40+ 编程语言后缀 → code）。
- 附加识别：无扩展名已知文本（Dockerfile/Makefile/.gitignore 等 basename/stem 白名单）+ 附加 txt 后缀（.example/.sample/.lock/.diff/.patch/.properties/.conf/.cfg）。
- `getFileFormat(path)`：返回 FileFormat 或 null（null = unsupported → 走系统打开）。
- 图片 6 格式：`isImagePath`（png/jpg/jpeg/gif/webp/svg），独立于文本格式表。

### 2.3 当前问题

- CSV/TSV 走 ④ 内置 editor（structured 分类，带格式化/校验按钮）——数据文件在纯文本编辑器里体验差，且大 CSV 打开卡顿。
- 大文本（>5MB）仍内置 editor——加载大文件占内存/渲染慢。

## 3. 期望行为定义 [v0.0.339]

### 3.1 打开分流新策略（在 openLocalPath ④ 文本分支前插入大小/类型前置判断）

```
① kind==='folder'    → 系统文件管理器（不变）
② isRemoteLinkPath   → 嗅探浏览器（不变）
③ isImagePath        → 内置只读 viewer（不变，无大小限制）
③.5 CSV/TSV          → 系统默认应用打开（新增，无条件，与大小无关）
③.7 文本 >5MB        → 系统默认应用打开（新增，仅内置文本格式，>5MB）
④ getFileFormat≠null → 内置可编辑 editor（≤5MB 文本，不变）
⑤ 其余               → 系统默认应用打开（不变）
```

### 3.2 规则明细

| # | 文件 | 打开行为 | 条件 |
|---|------|---------|------|
| 1 | `.csv` / `.tsv` | **系统默认程序**（Numbers/Excel 等） | 无条件（与大小无关，即使 1KB 也不内置） |
| 2 | 内置文本（12 格式：md/json/jsonl/yaml/xml/toml/txt/ini/env/log/code/已知文本） | **系统默认程序** | 文件大小 **>5MB** |
| 3 | 内置文本 ≤5MB | 内置 editor（现状不变） | — |
| 4 | 6 格式图片（png/jpg/jpeg/gif/webp/svg） | 内置弹层 viewer | 不变，**无大小限制**（即使 >5MB 也内置） |
| 5 | 其余（未知扩展名 / 非 6 格式图片） | 系统默认程序（现状不变） | — |

### 3.3 大小判定（行为定义，实现路径架构确认）

- 判定阈值：**5MB**（`5 * 1024 * 1024` bytes）。
- 语义：文件 **>5MB** 走系统打开；**≤5MB** 走内置。边界 5MB 整 = 内置（不越界）。
- 判定时机：在 openLocalPath 文本分支（④）**之前**，需要先取文件大小（stat）。
  - workspace 源：后端 stat（架构定实现路径，如 GET workspace stat 接口或复用现有）。
  - absolute 源：IPC stat（`window.rockyShell` 侧）。
- 大小判定**仅用于文本分支**：CSV/TSV 不 stat（无条件系统打开）；图片不 stat（无条件内置）。

### 3.4 系统打开复用

- 系统打开复用现有 `openWorkspaceItem`（workspace 源，`kind='file'`）/ `rockyShell.openPath`（absolute 源）——与 ⑤ 分支同一机制，不新造。

## 4. 需求边界 [v0.0.339]

### 4.1 做什么

- openLocalPath 文本分支前插入 CSV/TSV 无条件系统打开 + 文本 >5MB 系统打开。
- 大小判定 stat（workspace/absolute 双源）。

### 4.2 不做什么（边界，MANDATORY）

- ❌ **不改图片**：6 格式图片仍内置弹层 viewer，不做大小限制（即使 >5MB）。
- ❌ **不改变 12 格式 editor 内 view 分流**：≤5MB 文本进 editor 后，md→markdown 渲染 / structured→pre + 格式化校验 / plain→pre / code→pre 无按钮，**全部保留**。
- ❌ **不改变系统打开机制本身**：复用 openWorkspaceItem / openPath，不新造打开方式。
- ❌ **不扩大格式集**：不加新文本格式、不加新图片格式、不改 file-format 表。
- ❌ 不改聊天链接与文件树的铁律（两处共用 openLocalPath，行为自动一致）。
- ❌ 不改 .url 嗅探、文件夹打开、dirty 守卫、预览区 tab 逻辑。

## 6. 验收标准 [v0.0.339]

1. ✅ `.csv` / `.tsv` 任何大小 → 系统默认程序打开，不进预览区（文件树 + 聊天链两处一致）
2. ✅ 内置文本 >5MB → 系统默认程序打开，不进预览区（文件树 + 聊天链两处一致）
3. ✅ 内置文本 ≤5MB → 内置 editor 打开进预览区（无回归）
4. ✅ 恰好 5MB → 内置打开（边界不越界）
5. ✅ 6 格式图片（含 >5MB）→ 内置弹层 viewer（无回归，无大小限制）
6. ✅ 非 6 格式图片 / 未知扩展名 → 系统打开（现状不变）
7. ✅ 系统打开复用 openWorkspaceItem / openPath（无新机制）
8. ✅ editor 内 view 分流不变：≤5MB 文本 md/structured/plain/code 分类行为全保留（格式化/校验按钮仍在）
9. ✅ .url 嗅探、文件夹打开、dirty 守卫、预览 tab 逻辑零变化
10. ✅ 聊天链接与文件树行为一致（共用 openLocalPath，无需双实现）
