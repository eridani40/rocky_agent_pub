## 1. 概述

### 1.1 定位

本版本解决两类问题：
- **web search 重构（7 条）**：把 zhipu 的 apiKey 凭证从 ext impl `configSchema` 迁出到 **app_config `web_search` group**；EP 由 `exclusive` 改 `list`（可多选枚举，但仍按 config.type 单点路由）；`WebSearchProvider` 协议 `search` 加 `cfg` 入参（map 传递，D1=A）；tool 改读 app config → 按 `config.type` 路由对应 impl → 传 map{key}。
- **UI bugs（3 条）**：右侧 ws-tab 文案换行 / 模型名字框宽度可变 / ws-path-bar 缺 hover「打开文件夹」按钮。

### 1.2 交付项分工

| 交付项 | 一句话 | 范围 |
|------|--------|------|
| `WebSearchProvider` 协议 | `search(query, opts, cfg, signal)` 加 cfg map 入参 | 协议契约改 |
| `web_search_provider` EP | cardinality `exclusive` → `list` | EP 元数据改 |
| app_config `web_search` group | type 选择 + zhipu 选中时动态 key input | 新 group |
| `web_search` tool | 读 app config → 多 impl 枚举 → 按 type 路由 → 传 map | 调用逻辑改 |

| 应用配置「网络搜索」section | 自渲染 section（type choice-cards + 动态 key input） | 前端新增 section |
| UI bug 修复 | ws-tab nowrap / ModelPicker 固定宽 + nowrap / ws-path-bar hover 打开按钮 | 前端契约补 + 实现 |

## 2. 功能需求 — web search 重构

### 2.1 zhipu impl 硬编码 key 配置项移除（Bug1.1）

- 删 `app/plugins/builtins/zhipu_web_search/plugin.json` 的 `configSchema.properties.apiKey` + `required` 中的 `"apiKey"`。
- impl 不再从 plugin config 读 key；改从 tool 传入的 map（cfg）读（§2.5）。
- 兼容性：旧落盘的 plugin config apiKey 不再被读取（运行时不依赖）；迁移由 doc-modifier 阶段统一记录，不做数据迁移脚本。

### 2.2 EP cardinality `exclusive` → `list`（Bug1.2）

- `app/server/src/plugin/extension-point.ts:193` `WebSearchProviderPoint.cardinality` 改为 `'list'`。
- 语义变化：PluginManager 可枚举多个 web_search_provider ext impl（即使只激活一个）；不再强制单选。
- **不引入「多 provider 并发融合」**（§5.4 旧决策推翻但仍单点路由）：tool 按 app_config `web_search.type` 精确选一个 impl 调用，多 impl 共存只为「未来增加其他供应商」铺路（Bug1.7）。

### 2.3 新增 app_config `web_search` group（Bug1.3）

归属 `app_config`（D2），端点 `GET/PUT /config/app?group=web_search`。schema：

```json
{
  "group": "web_search",
  "key": "default",
  "data": {
    "type": "zhipu",
    "credentials": { "zhipu": { "apiKey": "<secret>" } }
  }
}
```

- **`data.type`**：选中的 provider implId（snake_case，与 ext impl implId 对应，如 `zhipu`）。来自 web_search_provider ext impl 列表（PluginManager.inventory）。
- **`data.credentials`**：map<implId, {apiKey?: string}>，按 type 选中动态展示对应字段。当前仅 `zhipu.apiKey`（secret）。
- 单实例（`key` 固定 `"default"`），全局一份。
- group 集合扩展：原 `{ appearance, providers, locale, llm_request, user_memory }` → 追加 `web_search`（PRD 定义，不动态扩展）。

### 2.4 web_search tool 改逻辑（Bug1.4）

`app/server/src/tools/web-search/tool.ts` `resolveProvider` 由「取 exclusive EP 首个」改为：

```
1. configService.get("web_search", "default") → 拿 { type, credentials }
2. PluginManager.getExtensionImpls(WebSearchProviderPoint) → 拿所有 impl（list EP）
3. 按 config.type 匹配 impl.id → 取对应 impl
4. cfg = credentials[config.type] ?? {}   // map 传给 impl
5. 调 impl.search(query, opts, cfg, signal)
```

- `type` 未配置 / 对应 impl 不存在 → 返回 ToolError「web_search 未配置 provider type」。
- impl.isAvailable(cfg) === false → 返回 ToolError「provider X 不可用（凭证未配置?）」。
- 不静默回退其他 impl。

### 2.5 `WebSearchProvider` 协议加 cfg 入参（Bug1.5 = D1 A 方案）

`app/server/src/tools/web-search/types.ts:48` 协议改为：

```typescript
interface WebSearchProvider {
  id: string;
  label: string;
  isAvailable(cfg: WebSearchCfg): boolean;
  search(query: string, opts: WebSearchOptions, cfg: WebSearchCfg, signal?: AbortSignal): Promise<WebSearchResult>;
}
type WebSearchCfg = Record<string, unknown>;   // tool 每次 call 传 map
```

- cfg 由 tool 从 `app_config.web_search.credentials[type]` 构造，每次调用传入（不破坏 PluginManager 统一实例化——impl 构造器仍 `(implId, cfg)`，但 cfg 由 tool 在调用点传，而非构造时注入）。
- 协议**仍不定义 apiKey 字段**：cfg 是不透明 map，由各 impl 自定义字段（zhipu 读 `cfg.apiKey`）。

### 2.6 zhipu impl 改：接收 map（Bug1.6）

`app/plugins/builtins/zhipu_web_search/zhipu-provider.ts`：
- `resolveApiKey(cfg)` 改为只从 `cfg.apiKey` 读，删 `process.env.ZHIPU_SEARCH_API_KEY` 回退（凭证唯一源 = app_config）。
- `isAvailable(cfg)`：`!!cfg.apiKey`。
- key 空 → `isAvailable` 返回 false；`search` 抛 `Error('zhipu provider 未配置 apiKey')`（tool 层捕获转 ToolError）。

### 2.7 保留未来扩展（Bug1.7）

- EP 改 list 后，新增其他 search 供应商（Tavily/Google/Bing）= 新增 ext impl，不改协议、不改 tool 路由逻辑。
- app_config `web_search.credentials` map 可扩展（`credentials.tavily.apiKey` 等）。
- 应用配置 UI type 选择控件由 ext impl 列表驱动（动态）。

## 3. 功能需求 — UI bugs

### 3.1 右侧 ws-tab 文案换行（UIBug1）

- 现状：`app/web/src/components/chat-page/component-ws-tab-bar.tsx` tab 文案在窄宽度下换行。
- 修：tab 文案 `white-space: nowrap` + `flex-shrink: 0`；tab 容器 `.ws-tabs` `overflow: hidden`（超长不撑宽面板）。
- spec 缺口：`specs/ui/components/chat-page/component-workspace-panel.md §6.3` 未写 nowrap 契约 → 需补 ui spec（§8）。

### 3.2 模型名字框宽度可变（UIBug2）

- 现状：非 readOnly 分支 `app/web/src/components/chat/ModelPicker.tsx:80` 仅 `min-w-[160px]`，长 modelId 撑宽 topbar；readOnly 分支 `chat-model-tag` 也无 nowrap。
- 修：
  - **非 readOnly 分支** `ModelPicker` trigger：固定宽度 `w-[180px]`（替换 `min-w-[160px]`）+ 内容 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`（长 modelId 截断，hover title 全名）。
  - **readOnly 分支** `chat-model-tag`：`max-w-[180px]` + nowrap + ellipsis + hover title。
- spec 缺口：`specs/ui/components/chat-page/_overview.md §4.4` 无 width/nowrap 契约 → 需补 ui spec（§8）。

### 3.3 ws-path-bar 缺 hover「打开文件夹」按钮（UIBug3）

- 现状：`app/web/src/components/chat-page/component-ws-path-bar.tsx:18` 纯文本，无打开按钮。
- 修：path-bar 右侧加 hover 按钮（`ws-path-open` testid），点击 → POST `/session/:id/workspace/open` `{ path: ".", kind: "folder" }`（打开根 workspaceDir，复用现有 `handleOpen`）。
  - path 字段语义对齐 `component-workspace-panel.md §3.1`：相对路径；根目录用 `"."`（后端 `path.resolve(workspaceDir, ".")` = workspaceDir 本身）。
- 布局稳定性 MANDATORY（对齐 §4.4 ws-tree-item 模式）：按钮**绝对空间预留**（`opacity: 0` 默认 + path-bar hover 时 `opacity: 1`），不出现/消失导致路径文本位移。
- spec 缺口：`component-workspace-panel.md §4.4` hover 按钮契约只覆盖 `ws-tree-item`（`ws-item-{path}-open`），path-bar 无 hover 按钮 → 需补 ui spec（§8）。
