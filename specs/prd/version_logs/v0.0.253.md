# v0.0.253 PRD — 聊天区链接渲染 + 可点击打开（http→浏览器 / 本地→内置 viewer 或系统打开）+ system prompt 配套

> 版本：v0.0.253 · 主题：消息 markdown 链接可点击，按 target 类型分发（web→系统浏览器；本地 viewer 型→内置只读 viewer；本地其它→系统默认应用）；system prompt 提示 LLM 用 markdown 链接语法
> PRD 边界（用户裁决 2026-07-14）：本文只覆盖**用户可感知**的产品逻辑/体验/反馈；Electron IPC 实现（openExternal / openPath / 绝对路径读取通道）、点击路由 lib/hook 抽象、preload bridge 命名、路径解析实现归 architect 落 `specs/tech/version_logs/v0.0.253/change_plan.md`；组件 spec 由编码期补/改 `specs/ui/components/`。PRD 不发明技术细节，只描述产品语义到可落地。

## 1. 版本主题（产品语义）

**现状（用户痛点）**：聊天消息里的 markdown 链接 `[文本](target)` 实际**已渲染**成 `<a target="_blank">`（自研渲染器 `PrimitiveMarkdownView`，`renderInline` 单一渲染点 + `isSafeUrl()` 危险协议过滤），但**点击无正确路由**——
- HTTP/HTTPS 链接：点开走 Electron 默认开窗行为（新开 Electron 窗口或无反应），**不走系统默认浏览器**
- 本地路径：点开尝试在 Electron 窗口内导航，**失效无反应**

Electron main 未装 `setWindowOpenHandler` / `will-navigate`，preload 也未暴露通用 `openExternal` / `openPath` 桥（仅 1 个硬编码屏录深链）。

**目标**：让聊天里的 markdown 链接「能点开、按类型正确分发」：
1. **web scheme**（http / https / mailto 等）→ **系统默认浏览器**打开
2. **本地路径**（file:// / 绝对路径 / `~` / workspace 相对）→
   - 扩展名属**内置 viewer 支持集**（v0.0.241 锁定的 12 种文本格式）→ **内置 viewer 打开（v1 只读）**
   - 其它（图片 / pdf / 代码 / 未知等）→ **系统默认应用**打开
3. **system prompt 配套**：提示 LLM 指文件/URL 时用 markdown 链接语法 `[文本](路径)` 输出

**安全基线（保留）**：现有 `isSafeUrl()` 拦截 `javascript:` / `vbscript:` / `data:` 协议（降级纯文本不可点）——本版本**保留**，不放宽也不收紧。

## 2. 范围与代决（orchestrator 代 AFK 用户拍板）

### 2.1 「支持类型」= v0.0.241 的 12 种文本格式（复用，不新建 viewer）

| 分类 | 格式 | 点击后行为 |
|---|---|---|
| markdown | md | 内置 viewer（markdown 渲染，只读） |
| structured | json / jsonl / yaml / xml / toml / csv / tsv | 内置 viewer（`<pre>` 朴素预览，只读） |
| plain | txt / ini / env / log | 内置 viewer（`<pre>` 朴素预览，只读） |
| 其它扩展名 | png / jpg / pdf / py / js / xlsx / 无扩展名 / ... | **系统默认应用**打开 |

**不新建图片 viewer**：v1 图片 / pdf / 音视频 / 代码高亮一律走系统打开（用户裁决：v1 不为本地链接新建任何 viewer 类型）。

### 2.2 chat 链接打开的本地文件 = 只读（v1 不做写回）

- 内置 viewer 打开 chat 链接文件时**强制只读**（隐藏 mode-toggle 与「保存」按钮，复用 `ComponentModalMdEditor` 既有 `readOnly=true` 能力）
- **workspace 面板**打开的文件**保留现有 edit 能力**（不在本版本范围，不变）
- 理由：chat 链接的本地路径来源是 LLM 输出，v1 只做「查看」语义；写回链路（编辑 chat 链接文件并落盘）留后续版本

### 2.3 个人 agent app 信任任意路径（v1 不加目录白名单）

- chat 链接的本地路径（绝对路径 / `~` / `file://` / workspace 相对）**直接打开**，不做目录白名单校验
- 现有 workspace whitelist（`whitelistResolve`）仅管 workspace 面板，**不延伸到 chat 链接**（两套机制独立）
- 理由：个人 agent app 是单用户信任环境；LLM 给的路径直接打开是用户期望行为。多用户/沙箱场景留后续

### 2.4 渲染范围：凡 PrimitiveMarkdownView 消费处一律生效

链接渲染 + 点击路由的统一规则覆盖所有 PrimitiveMarkdownView 消费方：
- agent 回复气泡（playground / studio 单聊 / studio 群聊 / academy）
- ComponentModalMdEditor 的 md category view（链中链：viewer 里 md 内容的链接同样可点）
- skill 预览
- feishu doc 渲染

**不动**：user 气泡走 `MentionRender`（非 markdown，用户不打 md 链接），本版本不触及。

## 3. 功能需求

### 3.1 Markdown 链接渲染（现状确认，零改）

**描述**：聊天消息 markdown 中的 `[文本](target)` 渲染为可点击 `<a>`。
**现状**：`PrimitiveMarkdownView.renderInline()` 已渲染 `<a target="_blank" rel="noreferrer">`，`isSafeUrl()` 已拦危险协议。**本版本不动渲染逻辑**——只补点击路由（§3.2）。
**优先级**：P0（确认现状，渲染层无新工作）

### 3.2 链接点击按 target 类型分发（核心）

**描述**：点 markdown 链接 → 按 target 类型分发到正确打开方式。
**优先级**：P0
**用户故事**：作为用户，我希望点 agent 回复里的文件名/URL 链接能直接打开对应位置（浏览器看网页 / viewer 看文件 / 系统应用看图片），而不是点了没反应或开错窗口。

**分发逻辑（按 target 字符串解析）**：

| target 形式 | 分支 | 打开方式 |
|---|---|---|
| `http://` / `https://` / `mailto:` / 其它 web scheme | web | 系统默认浏览器（Electron `shell.openExternal`） |
| `file://` / 绝对路径（`/` 或盘符开头）/ `~` 开头 / workspace 相对路径 | local | 见下「local 子分支」 |
| `javascript:` / `vbscript:` / `data:` | 危险协议 | **`isSafeUrl` 已拦，降级纯文本不可点**（现状保留） |
| 无法解析 / 其它 | fallback | 系统默认应用（`openPath`）尝试打开 |

**local 子分支**（按扩展名，大小写不敏感）：

| 扩展名 | 打开方式 |
|---|---|
| 12 格式之一（md / json / jsonl / yaml / xml / toml / csv / tsv / txt / ini / env / log） | 内置 viewer（`ComponentModalMdEditor`，`readOnly=true`） |
| 其它（含图片 / pdf / 代码 / 未知 / 无扩展名） | 系统默认应用（Electron `shell.openPath`） |

**交互细节**：
- 鼠标 hover 链接 → cursor pointer + 链接色下划线（现状已有，零改）
- 点击 → 立即分发，**不弹二次确认**（个人 agent app 信任环境）
- web 链接打开后**不在 app 内导航**（Electron main 加 `setWindowOpenHandler` + `will-navigate` 拦截）
- 内置 viewer 打开 = 在 app 内弹 modal（复用现有 ws-file-editor 同款挂载方式，但走只读 + chat 链接路径源）

**路径解析规则（产品语义，实现归 architect）**：
- `file://` → strip scheme 后按本地路径处理
- 绝对路径 → 直接用
- `~` 开头 → 展开为用户 home（复用 server `resolveDataDir` 同源 `expandTilde` 逻辑，BUG-004 教训）
- workspace 相对路径 → 相对当前 session 的 workspaceDir 解析为绝对路径（复用现有 workspace 路径解析）

### 3.3 内置 viewer 只读打开 chat 链接文件

**描述**：12 格式的本地文件链接 → 点击后在 app 内弹出只读 viewer。
**优先级**：P0
**复用**：`ComponentModalMdEditor` 的 `readOnly=true` 模式（v0.0.227 既有能力）——
- modal shell（720px，同款视觉基线）
- md-head：fileName + subtitle（subtitle 标识「来自聊天链接」或文件来源上下文，区别于 workspace 面板打开）
- md-body：view 模式按 category 分流（md → markdown 渲染；structured / plain → `<pre>` 朴素预览，对齐 v0.0.241 §2.2）—— **不显示 mode-toggle、不显示「保存」「格式化」「校验」按钮**（强制只读）
- md-foot：仅「关闭」按钮

**文件内容读取（按路径来源分流）**：
- workspace 相对路径 → 复用现有 `readWorkspaceFile`（`POST /workspace/file`，已有路径白名单）
- 绝对路径 / `~` / `file://` → 新增读取通道（架构期定：Electron IPC readFileText 或新 HTTP endpoint；**PRD 不预设**）
- 读取失败（文件不存在 / 权限拒绝）→ modal 不开，聊天区原链接位给一行 muted 错误提示（i18n，如「文件未找到：{path}」）

### 3.4 system prompt 配套

**描述**：在 system prompt 提示 LLM「指文件/URL 时用 markdown 链接语法输出」，让前端可渲染可点。
**优先级**：P0
**落点**：编辑 `app/server/src/prompts/content/rules.md`（全局规则片段，map→reduce→build 拼装时插入 standalone + subagent + academy 三类角色的 prompt；不需要新注册 mapper，mtime 热更）。

**新增指令文案（语义，最终措辞由编码期定）**：
> 当你引用文件路径或网页 URL 时，使用 markdown 链接语法 `[显示文本](路径或URL)` 输出，不要输出裸路径。例：引用 workspace 文件 `[config.yaml](config.yaml)`；绝对路径 `[日志](/var/log/app.log)`；网页 `[文档](https://example.com/docs)`。

**覆盖范围**：
- ✅ standalone（playground 主会话）
- ✅ subagent（playground 子 agent）
- ✅ academy（学员 agent）
- ❌ studio squad 角色（leader / mate / squad_chat 走独立 prompt 文件，**v1 不同步**——是否扩到 squad 由架构期裁决，PRD 不预设）

**不冲突**：现有 prompt 都是纯文本路径提及（如 agent_profile / context_files 渲染绝对路径为纯文本），加链接指令不破坏既有片段顺序/内容。

## 4. 关键用户路径（MANDATORY — 测试最低覆盖）

|----|-------------|---------|

## 6. 边界 / 不做（v1）

- **新建 viewer 类型**：图片 / pdf / 音视频 / office / 代码高亮 viewer——一律走系统默认应用（用户裁决）
- **chat 链接文件写回 / 编辑保存**：v1 内置 viewer 强制只读；写回链路留后续
- **路径目录白名单 / 权限模型**：个人 agent app 信任任意路径直接打开，v1 不加白名单（区别于 workspace 面板的 whitelistResolve）
- **链接预览卡片**（og card / favicon / 缩略图）：不做，链接就是可点击文本
- **bare URL 自动链接**：仅显式 `[text](url)` 触发；裸 URL 不自动转链接（现状保留）
- **含空格 URL 自动匹配**：链接正则 `[^)\s]+` 不变，含空格的 URL 需用户用 `<url>` 或 `%20`（现状保留）
- **studio squad 角色 prompt 同步**：v1 仅 rules.md（覆盖 standalone / subagent / academy），squad leader / mate / squad_chat 不同步
- **中间页 / 打开确认弹窗**：点链接直接打开，不弹「确定要打开吗」（信任环境）

## 7. 验收口径

- **功能**：UC-A~F 全部 pass（UT：primitive-markdown-view 点击分发 + isSafeUrl 危险协议 + rules.md 含链接指令 + system-prompt-builder 拼装含 rules；ET：UC-A/B/C 打开行为）
- **能力不变量**：
  - web 链接 → 系统浏览器（**不在 app 内导航、不开 Electron 窗口**）
  - 12 格式本地链接 → 内置只读 viewer（无编辑/保存按钮）
  - 其它本地链接 → 系统默认应用
  - 危险协议 → 降级纯文本不可点
- **渲染范围不变量**：4 处 PrimitiveMarkdownView 消费方（agent 回复 / md-editor view / skill 预览 / feishu doc）链接均可点；user 气泡（MentionRender）不动
- **回归不变量**：
  - 既有 `<a target=_blank>` 渲染 UT（`primitive-markdown-view.test.tsx` L171+ 链接 case）需同步更新（点击行为从「默认」→「分发路由」）
  - workspace 面板打开文件（edit 能力）不变
  - system prompt 拼装既有片段顺序/内容不破坏（rules 加一条 bullet）
- **布局稳定性**（CLAUDE.md MANDATORY）：链接 hover/active 状态变化不影响相邻元素位移（链接无按钮显隐问题；hover 下划线/换色用 color / text-decoration，不改盒模型）
- **持续可打包护栏**（CLAUDE.md MANDATORY）：新增 Electron IPC（openExternal / openPath / readFileText）走主进程 `shell.*` / `fs.readFile`——packaged 模式下 main 进程能正常调用（dev / packaged 行为一致，无 asar 路径问题）；runtime-config 白名单**不引入新 env 键**（IPC channel 名硬编码非 env）；路径展开复用 server `resolveDataDir` / `expandTilde` 单一权威（BUG-004 教训）。coder 按护栏自检
- **视觉保真门禁**：**无设计稿** → 链接视觉复用现有 markdown `<a>` 样式（链接色 + 下划线 hover）→ 本项跳过 `vision_check compare`
