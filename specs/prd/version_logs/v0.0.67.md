> version: 1.0 · 2026-07-05

## 1. 背景与目标

v0.0.26 引入 scope 维度时设计了「落盘稀疏 delta + 动态 scope CRUD 端点」模型——`PUT /config/plugin` 写 enabled/order/config，POST/DELETE scope 动态创建/删除 scope，POST/DELETE activate 动态激活/取消激活。但实际使用中暴露三类问题：

1. **流氓启动写盘代码**：`ensureForkedScope`（bootstrap 每次启动跑 12 次写盘）+ `registerTestFixtures`（写 setExclusive）+ PluginConfigService constructor lazy migrate（保留兼容）。
2. **dev/test 落盘 drift**：v0.0.66 注释说写 enabled=true 实测落盘 false；subagent scope drift（无代码创建者）；forked reducer 与 default 不一致。
3. **配置静默 degradation 难定位**（v0.0.64 P1 教训）：落盘 record drift 后 inventory 显示错配但无报错。

**本版本目标**：彻底消除落盘 drift + 流氓写盘——所有 plugin/ext impl 配置迁代码声明 `app/plugins/scopes/*.json`（每 scope 一文件，唯一源），运行时不读落盘 `plugin_policy/`；管理面 PluginConfigService 写方法全删（HTTP PUT 返 405），plugin 管理页只读化；启动硬校验（misconfig 启动崩，不静默 fallback）。

**非目标**：
- 不变更 chat/session/compact 等核心用户路径行为（forked scope 行为完全等同 v0.0.66 后期对齐 default reducer）
- 不变更 PRD 关键用户路径（plugin 管理页仍可访问，仅 UI 只读化）
- 不删除落盘 entity SchemaDef（保留 lazy migrate 兼容旧盘升级）

## 2. 范围

### 2.1 IN-SCOPE（8 项核心改动）

| # | 项 | 摘要 |
|---|---|---|
| 1 | 配置代码化 | `app/plugins/scopes/{default,forked,test}.json`（每 scope 一文件，声明 activatedPoints/exclusivePicks/impls） |
| 2 | 加载/校验/读视图三件套 | ScopeConfigLoader + ScopeConfigValidator + ScopeConfigProvider（替代落盘 policy 读取） |
| 3 | 落盘 policy deprecated（D2） | 运行时不读 `plugin_policy/`；PluginPolicyStore + PluginScopeStore 保留 lazy migrate 兼容 |
| 4 | 删流氓代码 | `ensureForkedScope` + `forked-scope-bootstrap.ts` 整删；`registerTestFixtures` 改 D5（不写 policy） |
| 5 | 删写死代码（D4） | handlers PUT 写端点 + PluginConfigService 写方法 + ScopedWriter + scope-snapshot + 前端 api 写函数 + scope 写函数。保留 GET inventory/scope list/activation list。实测写端点返 405 |
| 6 | 前端只读化 | 编辑控件 disabled + 删激活 UI + readonly banner + scope 切换保留（只读看）+ 非默认 scope 未激活 EP 渲染 inactive-hint |
| 7 | 启动校验（D3 硬失败） | ScopeConfigValidator.validateAll（exclusive 唯一/impl+point 存在/cardinality 一致），失败 throw |
| 8 | secret 不进代码（D1） | zhipu apiKey 等 secret 移 dev config/env，不在 scopes/*.json |

### 2.2 OUT-OF-SCOPE（遗留 → 后续）

- **真 LLM AT 待配 provider**：UT 全绿 + code review CONDITIONAL PASS；AT 因 forked scope 黑盒难观测 + 需真 LLM provider 配置，遗留后续版本。
- **dev/test 落盘清理待跑**：drift 清理脚本未在本次 worktree 跑（新装实例无 drift，老 dev 环境按需手动 rm）。

## 3. 用户路径（plugin 管理页只读查看）

PRD 关键用户路径——**plugin 管理页**（v0.0.67 起只读查看）：

| 路径 | v0.0.66 前 | v0.0.67 |
|---|---|---|
| P1：进入 plugin 管理页 → 看到 plugin tab + 扩展点 tab | 同 | 同（顶部多 readonly banner） |
| P2：plugin tab → 看 plugins 列表 + toggle plugin 启停 | toggle 可点 | **toggle disabled**（plugin 级恒 enabled=true，代码声明不存开关） |
| P3：扩展点 tab → 切 scope 查看 → 看 EP 配置（exclusive/ordered/list） | 可编辑 enabled/order/exclusive/config | **全部 disabled**（仅查看） |
| P4：扩展点 tab → 切非 default scope → 未激活 EP | 显示「激活此 EP」按钮 | **不渲染 impl 列表**，改显 inactive-hint（i18n） |
| P5：扩展点 tab → 切 scope → 创建/删除 scope | scope-switcher 有创建/删除按钮 | **创建/删除 UI 已删**（scope-switcher 仅切换查看） |

> 用户路径 P1-P5 行为整体保留（页面可达 + 数据展示正确），仅编辑控件 disabled / 编辑入口隐藏。功能正确性靠 AT（写端点返 405 + GET inventory 数据正确）+ UT（启动校验 + Loader/Validator/Provider 链路）覆盖。
