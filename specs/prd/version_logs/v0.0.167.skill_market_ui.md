## 1. 背景 & 目标

v0.0.166 已交付 skill 市场**后端**：`SkillMarketProvider` 协议 + skills.sh 首个源 + `/skills/market/{capabilities,search,detail,install}` HTTP 端点 + skill_manage 的 search/install action。当前 skill 入口（`page-skill`）仅有「我的（manage）」1 个 tab，市场后端**没有任何 UI 入口**。

本版本做**前端消费 + 少量后端 install 元数据补齐**：

1. skill 入口新增「市场」tab，复用 v0.0.166 后端做搜索 / 列表 / 详情 / 一键安装。
2. 已安装 skill 标注**来源**（市场 vs 本地），让用户区分「我装的市场货」与「我本地建的」。
3. 市场内识别与已安装 skill 的关系：**同源已安装**显示「已安装」；市场版本比已安装的新则显示「可更新」，并可一键更新。
4. 全部按 v0.0.165 银灰 light-only 视觉体系（`specs/ui/regulation/`）呈现。

**目标**：让用户在 app 内「逛市场 → 装 skill → 看清来源 → 保持更新」形成闭环，不用离开 app 或走命令行。

## 2. 概念对齐：能力协商驱动渲染（关键约束）

v0.0.166 后端是 **capability negotiation** 模型：UI **先问** `GET /skills/market/capabilities`，据返回的 `capabilities` 决定渲染哪些维度。**skills.sh（当前唯一 exclusive 源）只声明 `stats: ['installs']`**——不声明 categories / collections / sorts / stars / version / updatedAt。

因此本版本 UI 的**真实可渲染集**（据 skills.sh 能力）：

| 维度 | 是否渲染 | 依据 |
|------|---------|------|
| 搜索框（q + 可选 owner） | ✅ | search 支持 q/owner/limit |
| 列表卡片：name + ref | ✅ | 通用核心必有 |
| 列表卡片：安装量 installs | ✅ | `stats:['installs']` 声明 |
| 列表卡片：description | ⚠️ search 不返回 → 列表不渲染；详情 modal 才有 | §3 核心可选，getDetail 从 SKILL.md 补 |
| 分类过滤 / 源切换侧栏 / 排序下拉 | ❌ 不渲染 | 未声明 categories/sorts；exclusive 单源无「多源切换」 |
| version / updatedAt / stars | ❌ 不渲染 | 未声明 |
| 详情：name + description + readme + repository | ✅ | getDetail 返回 |

> **强制规则**：所有维度**由 capabilities 门控**，缺失维度不渲染、不造假、不报错。未来换能力更强的源（声明 categories/sorts）时，UI 自适应多渲染几维——**无需改前端**。这是本版本 UI 与设计稿富余（多源侧栏 / 分类 / 排序 / 版本号 / stars）的**分歧解决方式**（详见 §7）。

## 3. 功能范围

### 3.1 市场 tab（tab 切换 + 搜索 + 列表 + 详情 + 一键安装）

- **tab 切换**：`page-skill` 的 `component-skill-tabs` 从 1 个 tab（`manage`「我的」）扩为 2 个（`manage`「我的」+ `market`「市场」）。tab 已预埋多 tab，加项即可（`TAB_IDS` 加 `market` + i18n key + `tab==='market'` 条件渲染市场内容区）。默认激活 `manage`。
- **搜索**：市场内容区顶部一个搜索框（输入 q），回车/停顿触发 `GET /skills/market/search?q=`。空 q 默认展示（skills.sh 无 q 也可返回——按后端实际；若必须 q 则展示引导空态）。
- **市场列表 / 卡片**：搜索结果渲染为卡片网格。每卡显示：icon-box（hash 色，01-tokens §1.7）+ name + ref（作者/来源行，mono）+ 安装量 installs + 右下角**状态区**（见 §4：安装/已安装/可更新按钮或 badge）。**不渲染** description（search 无）、version、stars、分类。
- **详情**：点卡片 → 打开市场详情 modal（`GET /skills/market/detail?ref=`）：icon-box + name + description + readme（SKILL.md 正文渲染）+ repository 链接 + 包含文件列表 + 底部操作区（安装 / 更新 / 检查更新，见 §3.4/§4）。
- **一键安装**：详情或卡片点「安装」→ `POST /skills/market/install { ref }` → 202 → 安装成功后该 ref 变「已安装」态（列表卡 + 详情同步）。

### 3.2 已安装来源标记（「我的」tab）

- 「我的」tab 现有交互**不变**（列表 / toggle enabled / toggle evolvable / 预览 / 删除照旧），仅**新增来源 badge**。
- 每张 `component-skill-item` 卡在 name 行新增**来源 badge**：
  - skill 有 `marketRef`（从市场安装）→ 显示「市场」badge（中性 badge 样式，02-components §2）。
  - 无 `marketRef`（本地拖拽/创建）→ 显示「本地」badge。
- badge 只读，不可点，**布局稳定**：预留固定空间，出现/消失不导致 name/desc 位移。

### 3.3 同源「已安装」标识（市场 tab）

- 判定规则（D2）：**明确同源** = 市场 `item.ref` **精确等于**某已安装 skill 的 `marketRef`（**ref 精确匹配，非同名**）。回答用户「同名 vs 明确同源」= **明确同源**。
- 命中 → 市场卡右下角显示「已安装」badge（success 态），**不显示「安装」按钮**。
- 判定为**列表即时**：前端把已安装 skill 列表（含 marketRef）与市场 items 的 ref 做本地比对，**零额外网络请求**。

### 3.4 「可更新」检测 + 更新动作

- 判定规则（D3）：基于 **content hash** 比对（skills.sh 无 version，`/api/download` 返回 `hash`；安装时存 `installed_hash`）。
- **惰性判定**（避免列表 N 次网络请求）：列表阶段只即时判「已安装」；「可更新」**仅在详情页 / 点「检查更新」时**触发——拉市场当前 hash（复用 detail 或专用检查端点）与 `installed_hash` 比对，不同 → 「可更新」，相同 → 「已是最新」。
- **更新动作**（D4）：详情页对「已安装」项显示「检查更新」按钮；判定「可更新」后按钮变「更新」。点「更新」= **同 ref 覆盖重装**（v0.0.166 install 遇同名返 409 → 需 overwrite/force 语义或 update 能力，见 §6），成功后刷新 `installed_hash`，态变「已是最新」。

### 3.5 空态 / 加载 / 错误 / 无 provider(503)

- **加载**：搜索/详情请求期显示加载占位（骨架或 spinner，视觉沿用现有 loading 态）。
- **空态**：搜索无结果 → 「没有找到匹配的 Skill」空态（mono 虚框，沿用 `section-skill-list` 空态风格）。
- **错误**：请求失败（网络/5xx）→ 错误占位 + 重试按钮，文案见 §5。
- **无 provider（503）**：`capabilities`/`search` 返回 503（无 active provider）→ 市场 tab 显示「市场未配置」引导态（文案 §5），不 crash、不显示搜索框。

## 4. 状态机与状态区渲染

市场卡 / 详情底部**状态区**按 skill 与已安装库的关系渲染其一（互斥）：

| 态 | 触发条件 | 渲染 | 位置 |
|----|---------|------|------|
| 可安装 | ref 不在已安装库 | 「安装」primary 按钮 | 卡右下 / 详情底 |
| 安装中 | 点安装后、202 处理中 | 「安装中…」禁用按钮 | 同上 |
| 已安装 | ref === 已安装 marketRef | 「已安装」success badge | 卡右下 |
| 已安装（详情） | 同上，详情页 | 「检查更新」secondary 按钮 + 「已安装」badge | 详情底/头 |
| 可更新 | 详情检查后 hash 不同 | 「更新」primary 按钮 + 「可更新」info badge | 详情底 |
| 已是最新 | 详情检查后 hash 相同 | 「已是最新」中性提示（无动作按钮） | 详情底 |

**布局稳定性**：状态区尺寸固定，按钮/badge 切换不导致卡片其余元素位移。

## 6. 数据依赖（交 architect 的后端能力清单）

PRD 只描述「需要什么行为」，实现归架构。本版本要求后端提供/变更以下能力：

1. **install 写来源元数据**（D1）：`POST /skills/market/install` 及 `skill_manage install` 落盘时，向 skill 的 SKILL.md frontmatter 写入：
   - `market_ref`：安装用的 provider ref（如 `github/awesome-copilot/git-commit`）。
   - `market_source`：provider id（如 `skills_sh`）。
   - `installed_hash`：安装时 `provider.fetchSkillFiles` 返回的 `hash`（内容锚点，供可更新比对）。
   - 影响：`installer-core` 的治理写入链（applyGovernance/finalizeStagedSkill）需扩展；治理已硬编码 `production_method:download`+`evolvable:false`，此处**追加** 3 个来源字段。
2. **SkillEntry 暴露来源字段**：后端 `SkillEntry` type + resolver.parseSkillDir 读 frontmatter → 暴露 `marketRef` / `marketSource`（前端 api-client `SkillEntry` 同步）。`installedHash` 供比对（是否暴露到前端由架构定；hash 比对可在后端做，前端只收「可更新」布尔）。
3. **可更新检查能力**（D3）：提供「给定已安装 skill / ref，判定市场当前 hash 是否与 installed_hash 不同」的能力。可选实现（architect 决策）：
   - (a) 复用 `GET /skills/market/detail?ref=` 让其返回当前 hash，前端比对；或
   - (b) 新增专用 compare 端点（输入 ref + installed_hash → 返回 `{ updatable: bool }`）。
   - 约束：**列表不做**（惰性，避免 N 次请求），只在详情/主动检查时调用。
4. **更新 = 覆盖安装能力**（D4）：install 当前遇同名返 409。需支持**同 ref 覆盖重装**——新增 `overwrite`/`force` 参数或 update 语义，覆盖后**刷新 `installed_hash`**（及必要时 market_ref/source）。约束：覆盖只针对**同源**（同 marketRef）项，避免误覆盖本地/异源同名 skill。
5. **来源字段不破坏现有语义**：来源字段是**新增可选** frontmatter，legacy skill（无这些字段）= 本地来源，resolver 缺字段不报错。

> 以上为「需要什么」；method 级变更契约由 architect 落 `specs/tech/version_logs/v0.0.167.skill_market_ui/change_plan.md`。

## 8. 非目标（OUT）

- **不做非 skills.sh 源的特殊 UI**：UI 完全 provider 无关，由 capability negotiation 驱动；不为任何具体源硬编码维度。
- **不做多源侧栏 / 分类过滤 / 排序下拉**：exclusive 单源无「多源切换」；skills.sh 未声明 categories/sorts（设计稿画的多源侧栏、分类、排序**本版本不实现**，见 §7 对齐性）。
- **不做评分 / stars / 版本号展示**：skills.sh 无 stars/version 维度。
- **不做「添加源（git URL）」**：设计稿的加源入口本版本不实现（换源是配置/架构层，非本 UI）。
- **不改「我的」tab 现有交互**：仅新增来源 badge，toggle/预览/删除/安装（本地上传）全不动。
- **不做卸载入口的新增语义**：现有删除即卸载，本版本不改（详情 modal 的「卸载」按钮是否接现有 delete 由架构定，非新能力）。

## 9. 对齐性检查（PRD ↔ 现有 spec）

**引用的现有组件（与 spec 一致，不发明）**：
- `component-skill-tabs`（`specs/ui/components/skill-page/component-skill-tabs.md`）：已预埋多 tab，加 `market` 项即可，视觉沿用（2px 下划线 active，02-components §8 tabs 用 `--fg` 非橙）。

- `section-skill-list` / `page-skill` / `component-skill-preview-modal`：结构复用；page-skill 加 `tab==='market'` 分支。
- 视觉体系：全部走 `specs/ui/regulation/` 银灰 token（badge 02-components §2、icon-box §4、按钮 §1）。

**需架构阶段新增的组件 spec（本 PRD 不发明，标注交 architect 落 `specs/ui/components/skill-page/`）**：
- 市场内容区容器（`section-skill-market` 类）：搜索框 + 结果列表布局。
- 市场卡片（`component-market-item` 类）：name/ref/installs + 状态区，区别于本地 `component-skill-item`。
- 市场详情 modal（`component-market-detail-modal` 类）：readme + 文件列表 + 状态区操作。
- 各新组件 testid 契约由架构/coder 落 spec（先 spec 后实现），供 e2e-test-designer 读。

**已知分歧（设计稿 vs 后端能力）**：设计稿（skill-market.html）呈现了多源侧栏、分类过滤、排序下拉、版本号、stars、更新时间——**这些超出 v0.0.166 skills.sh 后端能力**。本 PRD 裁定：**视觉风格（银灰 token / 卡片布局 / badge 形态）照设计稿，信息维度由 capabilities 门控**（§2）。设计稿的富余维度作为「未来能力更强的源」的前瞻，不在本版本实现。**视觉保真度比对（vision compare）须以「能力门控后的实际渲染」为准**，不比对设计稿里不渲染的维度。
