## 1. 版本主题（产品语义）

**现状（用户痛点）**：workspace panel 点 `.md` 文件 → `handleOpen` → `POST /session/:id/workspace/open` → 后端 spawn 系统默认应用（mac `open` / win `start` / linux `xdg-open`）——跳出 app 外部打开，体验割裂、与 academy 内已有的统一 md editor 视觉/交互不一致。

**目标**：`.md` 文件在前端拦截，改用**内置 md viewer/editor** 打开（查看 + 编辑 + 保存一体），复用 academy 既有的 `component-modal-md-editor`（spec §8.2 已预告「待跨 ≥2 页复用时再提升到 common/」，本版本正是触发此提升）。非 `.md` 文件 / 文件夹**行为不变**（仍走系统打开 / 展开收起）。

**产品不变量**：
- **能力 = 查看 + 编辑 + 保存**（完整 editor，对齐 academy，非只读预览）。
- **复用不创新**：modal shell / mode-toggle / view-edit 切换 / onSave 回调模型全沿用 `component-modal-md-editor`，不新造第二套 md editor。
- **三处 chat 页统一覆盖**：`SectionWorkspacePanel` 被 chat-page / academy section-version-chat / studio section-right-tabs 三处复用，拦 `handleOpen` 一处全覆盖（已确认决策，PRD 不重述技术细节）。

## 2. 功能需求（用户可感知）

### 2.1 拦截 .md 打开 → 内置 viewer/editor（默认查看）[v0.0.227]

**优先级**：P0
**用户故事**：作为用户，我在 workspace panel 点一个 `.md` 文件（如 `notes.md` / `README.md`），希望直接在 app 内弹出一个 markdown 查看器看到渲染后的内容，而不是跳出 app 用外部编辑器打开——和 academy 里点版本 AGENTS.md「查看」是同一个体验。

**产品规则**：
- **拦截判定**：workspace 文件树点击事件中，命中 `文件节点 && 文件名以 .md 结尾` 的分支 → 走内置 editor；其余分支（文件夹 / 非 .md 文件）行为不变（见 §2.4 回归）。
- **默认进入查看模式（view）**：与 academy 一致（`component-modal-md-editor` mode 缺省 `'view'`）；用户可主动切编辑（§2.2）。
- **modal 呈现**：复用 `component-modal-md-editor` 的 modal shell（720px / max-h 88vh / `rounded-xl` + 遮罩 + 点遮罩关闭 + ESC 关闭）——视觉与 academy 完全一致（无设计稿，复用 academy 视觉基线，见 §4）。
- **fileName 显示**：弹层 md-head 显示被点文件的**文件名**（basename，如 `notes.md`）；subtitle 显示该文件**相对 workspaceDir 的路径**（如 `docs/notes.md`，让用户知道是哪个目录下的文件）——与 academy 的「小红书文案 · v2.0 · system prompt」同位语义（来源上下文）。**subtitle 具体文案归 §6 开放点**。
- **加载态**：打开瞬间需读文件文本（新增后端读端点，见 §4），未就绪时 modal body 显示 loading（不空窗不闪烁）；读失败（文件不存在 / 路径非法 / 权限）显示明确错误文案 + 关闭按钮（不卡死）。
- **L3 modal 不变式（硬约束，沿用 spec）**：走 `<Portal>` 挂 overlay-root + Portal 根节点显式 `pointer-events-auto`——`component-modal-md-editor.md §状态/交互` 已声明，本版本不改此机制（漏则整弹层按钮全不可点）。

**与既有 spec 的对齐**：
- 拦截点概念源 = `component-workspace-panel.md`（handleOpen + 文件树点击交互）。
- editor 主体 = `component-modal-md-editor.md`（modal shell + md-head/body/foot + mode-toggle + onSave 回调模型）。
- 提升预告 = `academy-page/_overview.md §8.2`（design §8.2「未来做成统一 md 编辑器组件保持全站一致」）——本版本正是落实此预告（跨 ≥2 页复用：academy + workspace）。

#### E2E Use Cases（拦截打开）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-227-OPEN-1 | workspace panel 文件树点 `notes.md` | app 内弹出内置 md editor modal（非外部应用），默认查看模式渲染 markdown |
| UC-227-OPEN-2 | 点子目录 `docs/guide.md` | modal 内 subtitle 显示 `docs/guide.md`（相对 workspaceDir） |
| UC-227-OPEN-3 | 点一个不存在的 .md（竞态：外部刚删） | modal 显示错误文案（非空窗非卡死），可关闭 |
| UC-227-OPEN-4 | 点 .md 后立刻 ESC / 点遮罩 | modal 正常关闭（与 academy 同行为） |

### 2.2 切编辑模式 → 改内容 → 保存 [v0.0.227]

**优先级**：P0
**用户故事**：作为用户，我在查看模式下发现 `notes.md` 有个错字或想补充内容，希望点一下「编辑」直接改、改完点「保存」就落盘——不用跳出 app 开外部编辑器。

**产品规则**：
- **mode-toggle（沿用 academy）**：md-head 右侧二段「👁 查看 / ✏️ 编辑」开关；切到编辑 → md-body 切 textarea（mono 字体、全宽全高）；保存按钮仅编辑模式显示（view 模式 `display:none`，布局不变；对齐 spec §状态/交互）。
- **保存动作**：点「保存」→ 触发 `onSave(newValue)` 回调（纯回调，不耦合后端，对齐 academy Props 模型）→ workspace 侧挂载层接 `onSave` 调新增的 file 存端点落盘（落盘细节归架构期）。
- **保存反馈（关键体验，用户可见）**：
  - **进行中**：保存按钮显示 loading 态（防重复点击）。
  - **成功**：明确成功反馈（候选：toast「已保存」/ 按钮短暂变「已保存 ✓」/ 静默切回 view 模式显示新内容）——**具体反馈形式归 §6 开放点**，但必须有可见反馈（不能点了没反应）。
  - **失败**（路径非法 / 权限 / 磁盘满）：明确错误文案，编辑内容不丢失（停留编辑态、textarea 内容保留，用户可重试或复制自救）。
- **未保存离开提示**：编辑过且未保存时点关闭 / ESC / 点遮罩 → 弹确认「有未保存修改，确认放弃？」（防误丢内容；与 academy 一致行为，academy 现有实现归架构期核对是否已有，无则补）。
- **布局稳定性（CLAUDE.md MANDATORY）**：保存按钮的出现/消失（view↔edit 切换）必须用预留固定空间（`visibility:hidden` / `display:none` 在固定槽位）或绝对定位，**不得导致相邻元素位移**。

**与既有 spec 的对齐**：
- mode-toggle + onSave 回调 + 仅 edit 显示保存按钮 = `component-modal-md-editor.md §状态/交互 + Props`（完全沿用）。
- workspace 侧落盘接线参照 academy `component-academy-modals.tsx` 的 `handleMdSave`（academy 落 academy API；workspace 落 file/save 端点）——挂载层模式照搬，差异仅落盘目标。

#### E2E Use Cases（编辑保存）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-227-EDIT-1 | 打开 notes.md → 点「✏️ 编辑」→ 改文本 → 点「保存」 | 保存成功，见可见成功反馈，内容落盘 |
| UC-227-EDIT-2 | 编辑过未保存 → 点关闭 | 弹「未保存确认」，确认后才关；取消则停留编辑态 |
| UC-227-EDIT-3 | 保存时后端失败（权限/磁盘） | 错误文案显示，textarea 内容保留可重试 |
| UC-227-EDIT-4 | 快速连点保存 | loading 态防重复提交（不发出第二次保存） |

### 2.3 持久化（保存后重开看到新内容）[v0.0.227]

**优先级**：P0
**用户故事**：作为用户，我保存了 `notes.md`，关闭弹层后再次点开，希望看到刚才保存的新内容（而不是旧内容或空），确信修改真的落盘了。

**产品规则**：
- **重开取最新**：关闭后再次点同一 .md → 重新走「读端点」取最新内容（不复用 modal 内 stale state；每次打开重新读）。
- **与文件树 watch 协同**：workspace 已有 chokidar watch + SSE 推文件变化（`component-workspace-panel.md` 已概念化）——保存落盘后，文件树刷新逻辑不变（不重复刷新 / 不抖动）；其他会话/外部对该 .md 的修改经同一 watch 通道反映到树。
- **编辑中外部变更冲突**（产品体验开放点）：若用户编辑过程中该 .md 被外部（其他会话 / 外部编辑器 / watch 事件）改了，保存时如何处理？候选：① last-write-wins（默认，无提示，简单）；② mtime 校验 + 冲突时弹确认「文件已被外部修改，是否覆盖？」——**归 §6 开放点**，倾向 last-write-wins（简单直接，对齐「保存即落盘」语义，匹配「编辑器对齐 academy」最小改动原则）。

**与既有 spec 的对齐**：
- workspace watch/SSE 机制 = `component-workspace-panel.md`（stalePaths / SSE 文件变化）已有，本版本不新增 watch 行为。

#### E2E Use Cases（持久化）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-227-PERSIST-1 | 编辑保存 notes.md → 关闭 modal → 再次点开 notes.md | 查看模式显示刚保存的新内容 |
| UC-227-PERSIST-2 | 保存后查看 workspace 文件树 | 文件树不异常抖动 / 不重复刷新（watch 行为不回归） |

### 2.4 回归（非 .md 文件 / 文件夹 行为不变）[v0.0.227]

**优先级**：P0（回归保护，不能误伤）
**用户故事**：作为用户，我点 `.png` / `.json` / `.txt` 文件仍希望走系统默认应用打开（行为不变），点文件夹仍希望展开/收起子目录——只有 .md 是新行为。

**产品规则**：
- **非 .md 文件**：仍走原 `openWorkspaceItem` → `POST /session/:id/workspace/open` → 后端 spawn 系统默认应用（mac `open` / win `start` / linux `xdg-open`）——行为零变更。
- **文件夹**：仍走展开/收起（lazy 加载子目录，`component-workspace-panel.md §4.3`）——行为零变更。
- **拦截判定必须精确**：仅 `.md` 后缀命中内置 editor；大小写敏感性（`.MD` / `.Md`）归架构期（倾向不区分大小写以匹配跨平台用户预期，但属于实现细节）。

#### E2E Use Cases（回归）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-227-REG-1 | 点 `.png` / `.json` / `.txt` 文件 | 仍走系统默认应用打开（不弹内置 editor） |
| UC-227-REG-2 | 点文件夹 | 展开/收起子目录（lazy 加载，行为不变） |
| UC-227-REG-3 | 在 academy / studio 复用同一 panel 的入口点 .md | 三处都弹内置 editor（拦一处全覆盖） |

## 5. 验收口径

- **功能**：UC-227-OPEN / EDIT-SAVE / PERSIST / REG 全 PASS（UT + 既有 workspace 冒烟集回归 + ET 视情况）；本版本无新持久 AT/ET case（普通 feature 铁律）。

- **回归不变量**：非 .md 文件仍走系统打开；文件夹仍展开/收起；workspace watch/SSE 行为零变更。
- **拦截精确性**：仅 `.md` 命中内置 editor；三处复用入口（chat-page / academy / studio）全覆盖。
