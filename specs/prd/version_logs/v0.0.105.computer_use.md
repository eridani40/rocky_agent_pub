## 1. 背景与定位

**用户诉求**（req.md）：新增 1 个 computer use 工具；调研对比 e2b/iFurySt/openclaw；设计 action 集合 + OS 抽象层 + macOS 实现。

**核心定位**：computer use 把 agent 的控制边界从「chrome tab」（browser connector）扩到「整个 macOS 桌面」——通过截图回灌 LLM 决策 + AX/坐标双路定位 + CGEvent.postToPid 后台键鼠注入（不抢前台、不需 Input Monitoring）。

**与 browser connector 的关系（并列、非替代）**：

| 维度 | browser connector | computer connector |
|---|---|---|
| 控制边界 | chrome 进程内（一个浏览器 tab） | 整个 macOS 桌面（所有 app + 系统） |
| 驱动模型 | a11y tree + element ref（CDP） | AX tree + 截图像素坐标（postToPid + AX） |
| 截图角色 | 辅助（vision 校验） | **主交互通道**（每 turn 开头截图回灌 LLM） |
| 连接器状态机 | 双状态（switch + connection） | 双状态 + **多一层系统权限态**（Accessibility + Screen Recording） |
| connector id | `'browser'` | `'computer'`（ConnectorState[] 第 2 项） |

**browser tool §6 已锁决策的关系**：browser_tool.md §8「截图+坐标（computer-use 路线）本版本不支持（P2 再说）」——本版本（P2 兑现）正式引入，作为独立 connector + 独立工具集，不并入 browser tool。

## 2. 功能需求（对齐 design.md §2-§8）

### 2.1 computer_use 工具集（~9 独立工具 + disconnect）[P0]

详见 PRD 主文档 `specs/prd/overall/09-computer-use.md` §2.1。核心要点：

- 独立工具形态（D2）：每个 action 一个独立 ToolDefinition，schema 简洁、policy 可单独 bound
- P0 action（本版本必交付）：`list_apps` / `get_app_state` / `click` / `scroll` / `type_text` / `press_key` / `disconnect`
- P1 action（视进度后置）：`perform_secondary_action` / `set_value` / `drag`
- grounding（D3）：AX element_index 优先 + 坐标兜底；截图不单独成 tool——`get_app_state` 返 key window 截图 + AX tree
- 坐标系：绝对像素 + Retina scale 链
- OS 抽象层：`ComputerDriver` / `ComputerSession` 一套接口 + 每 OS 一实现（macOS 首发）

### 2.2 computer 作为连接器页第 2 tab [P0]

- 落地 `connector-tabs`（v0.0.23 预埋）第 2 tab：`connector-tab-computer`
- `connectors: ConnectorState[]` += `'computer'`；`onToggle` id 类型扩 `'browser' | 'computer'`
- 复用 browser 双状态机（switch + connection）+ 多一层系统权限态
- 沿用 nav 底部 `nav-connector` 入口（不新增 nav 项）

### 2.3 权限双重防线 [P0]

**macOS 权限 2 类**：Accessibility（键鼠+AX）+ Screen Recording（截图）；不需 Input Monitoring。

**防线 1 — UI 主动监测**（`computer-connector-permissions` 面板）：
- 两行（accessibility + screen-recording），每行 ✓绿已授权 / ✗红未授权 + 「去授权」按钮（仅 missing，预留空间防位移）
- 三重动态监测：① app/window 重新获焦立即重检；② tab 打开 + switch on 时 ~3s 轮询；③ 手动「重新检测」按钮
- 后端 `GET /connector/computer/permissions` → Swift helper 预检 → `{accessibility, screenRecording}`
- 引导深链系统设置（`Privacy_Accessibility` / `Privacy_ScreenCapture`）+ 回 app 焦点回检 ✓

**防线 2 — 运行时硬门禁**（tool 层）：
- 每个 action 声明所需权限（§2.1 表）
- `tool.run()` 流程：解析所需权限 → Swift helper 预检（或缓存态）→ 任一 missing → `ToolRunResult{status:'failed', content:[{type:'text', text: reason 引导}]}`
- 防御深度：用户授权后中途撤销 → 下次 action 门禁拦下
- UI 面板与 tool 门禁共享同一权限预检后端

### 2.4 computer-connector-card 状态矩阵

详见 PRD 主文档 §2.4（6 态：未启用/需要系统权限/已启用未连接/连接中/已连接/连接失败）。**不变量**：permission missing 时 switch=on 也不进 connecting（连接前置门禁）。

### 2.5 ImageBlock 全链路打通（P0 前置，独立 Task 最先做）

`message/types.ts:174-180 ContentBlock` union 砍了 ImageBlock（协议层 + spec 已就绪）。打通 5 点：
1. ContentBlock 加 ImageBlock（`{type:'image', source: ImageSource, mediaType}`）
2. spec/protocol 两形态对齐（encode 适配）
3. `ToolResultBlock.content: ContentBlock[]` 承载 image + CrudStore 序列化 base64
4. context assemble 不过滤 image（typecheck + UT 验）
5. 前端渲染 image content block（P1 最小占位 + click 展开）

**这是 computer use 接入的最大前置工作量**，拆独立 Task 优先做。

### 2.6 安全红线 + HITL 审批

三层防线：
1. **TOOL_POLICY bound 分级**：`playground-rocky` 默认加；`subagent` **不**加（控 OS 风险高）；`studio-*` 视场景
2. **switch flag 默认 off**：用户主动开启
3. **HITL 审批**（复用 v0.0.101 tool-approval pending）：computer use 工具挂 `interaction()` 钩子，首次截图/点击前转 pending；破坏性动作（发送/删除/购买）二次确认

## 3. 关键用户路径（MANDATORY — 测试最低覆盖，采用 design.md §11 P1-P5）

| 路径 | 链路 | 关键断言 |
|---|---|---|
| **P1** 首次启用+权限授权 | 连接器页 → computer tab → 开 switch → 权限面板显 missing → 去授权 → 系统设置开启 → 回 app 焦点回检 ✓ → 「已启用（未连接）」 | missing 时阻止 connecting；焦点回检 ✓；granted 后 status 切灰 |
| **P2** agent 控制（screenshot → click → disconnect 全链路） | agent 调 `get_app_state` → lazy connect（owner 锁）→ 截图回灌 → LLM 决策 → click → … → disconnect | 首次 get_app_state 触发 lazy connect + owner；ToolResultBlock.content 含 ImageBlock；disconnect 释放 owner |
| **P3** 缺权限运行时报错 | agent 调 `get_app_state` 但 Screen Recording 未授权 | tool 返 failed + reason 引导（含「屏幕录制」+「系统设置」+「Rocky Computer Use」） |
| **P4** 权限中途撤销 | 已授权 + 已 connect → 用户系统设置撤销 → agent 下次调 action | 门禁拦下 + failed + 引导；owner 锁不自动释放 |
| **P5** owner 锁冲突 | session A 已 connect（owner=A）→ session B 调 computer use | 第二个 session 返 `in_use_by_other` + 引导；不抢占不排队；UI 无 toast |

每条路径 ≥1 个 AT case（E2E 仅 dogfood 不进 run_all——真 OS 不可控 + CI 无 Accessibility 权限）。

## 5. 范围与非目标（对齐 design.md §10）

**本版本范围**：macOS only（Swift helper binary）+ §2.1 P0 action 集合 + ImageBlock 全链路打通 + connector 多 tab UI + 权限双重防线 + 工具接入/连接治理集成 + Swift helper `.app` bundle（D6 预编译进项目）。

**非目标**：
- ❌ Linux/Windows 实现（仅接口签名）
- ❌ Anthropic 原生 computer_use beta（D4 自定义 schema）
- ❌ P1 action（perform_secondary_action / set_value / drag）后置
- ❌ 视觉 grounding 模型（e2b OS-Atlas/ShowUI，D3 排除）
- ❌ E2E 进 run_all（真 OS 不可控）
- ❌ osascript/screencapture 生产路径（仅开发期 fallback）
