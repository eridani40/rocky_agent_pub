# v0.0.96.ui_fix — UI/架构修复三件套（usage 格式 / loading 双源兜底 / studio chat 自给）

> 类型：UI 修复 + 内部架构重构（用户无显著新功能感知，修复稳定性/视觉问题）
> 范围：纯前端，**无 API 契约变更**（chat 自给全用现成 GET /session + GET /squad）
> 前置概念权威源（已读对齐）：
> - `specs/ui/components/chat-page/_overview.md` §4.10 两层分离（runActive vs sessionRunning）/ §loading panel 视觉基线
> - `specs/ui/components/chat-page/component-usage-panel.md` §3.2 / §4.3（k 格式）
> - `specs/ui/components/studio-page/member-chat-page.md` Props（当前父透传耦合）
> - `specs/ui/components/studio-page/squad-chat-page.md` Props
> - `specs/tech/app/frontend/[P0]chat_area_hooks.md`（5 area-hooks 契约）
> - `specs/api/overall/11-squad.md` §2（Session schema：squadId/memberId）

## 1. 背景

三个互相关联的问题：

1. **usage 面板视觉不规范**：内部不固定尺寸，「来源」「会话」等固定词折行；流量值纯数字无单位（用户原话：「现在很过分，很多固定的词都是折行的，很怪」）。
2. **「生成回答…」气泡切会话时不稳定**：气泡可见性只认 `runActive`（agent_loop 派生），切会话时 useLifecycle `setCtx(null)`→runActive=false；恢复完全依赖后端 sticky replay 重放 `run_start`，前端零兜底。sticky 失效/订阅时序竞态 → 气泡该有却没有。
3. **studio chat 与父选中 squad 耦合**：MemberChatPage/SquadChatPage 接收父透传 `member`/`squadId`/`squadModelDefault`/`tag`，全来自 page-studio 共享 `detail`；router 用 `detail` 判 isGroup + detail 门控渲染 chat-loading 占位。用户要求：「chat 页面只认 sessionId，自己加载要显示的一切……从任何地方、任何路径进 chat 行为完全一致」。

## 2. 功能需求

### 2.1 usage 面板固定尺寸 + 流量单位格式化 [v0.0.96.ui_fix]

**描述**：usage 展开面板内部布局规范化——固定列宽防折行 + 流量值走 K/M/B/T 分级单位（1 位小数）。

**优先级**：P0

**用户故事**：作为对话区用户，我希望 usage 面板的标签和数值排列整齐不折行、流量数字用人类可读单位（K/M/B/T），以便一眼扫读不视觉抖动。

**功能交互细节**：

- **流量值格式化 util**（一个纯函数 `formatTraffic(n: number): string`）：
  - `n < 1000` → 原值字符串（如 `123`）
  - `1000 ≤ n < 1_000_000` → `${(n/1000).toFixed(1)}K`（如 `12345`→`12.3K`）
  - `1_000_000 ≤ n < 1_000_000_000` → `${(n/1e6).toFixed(1)}M`（如 `1234567`→`1.2M`、`12345678`→`12.3M`）
  - `1_000_000_000 ≤ n < 1_000_000_000_000` → `${(n/1e9).toFixed(1)}B`（如 `1234567890`→`1.2B`）
  - `n ≥ 1e12` → `${(n/1e12).toFixed(1)}T`
  - 边界：0 / 负数 / NaN 直接返原值字符串。
  - 替换范围：usage-panel 表格行**累积消耗**区（来源/会话两列的 input/output/cache 值）；**不动**圆环外的「已用/总」概览（沿用现状 k 单位格式，详见开放点 O1）。
- **面板内部固定尺寸**：
  - 展开面板宽度维持 280px（`component-usage-panel.md §3.2` 不变）。
  - 表格行**列宽固定**：标签列（「来源」「会话」等）`white-space: nowrap` + 固定宽度（值待 arch 定，参考 `w-[64px] shrink-0`）；值列预留固定长度（约 7 位字符位宽，参考 `w-[64px] tabular-nums`）防 K/M/B/T 切换时左右跳动。
  - 数字字体走 tabular-nums（等宽数字）防视觉抖动。

**界面要素**：仅渲染层（一个 util + CSS 类）。**不改 usage 数据契约**（SessionUsageView 不动）。

**约束**：
- 严禁把 K/M/B/T 用于「已用/总」概览区（那里 spec §4.3 已固定 k 格式，改动属扩大范围——见开放点 O1）。
- 列宽固定值由 arch 拍板，PRD 不预设具体像素。

### 2.2 「生成回答…」气泡双源兜底 [v0.0.96.ui_fix]

**描述**：on-message spinner（`chat-run-spinner` testid）可见性从「仅 runActive」扩展为「runActive || sessionRunning」，让切会话/SSE 重连时由 `sessionRunning`（REST GET /session + session_panel 兜底）独立保住气泡。

**优先级**：P0

**用户故事**：作为对话区用户，当 AI 正在生成回答时，无论我怎么切会话切回来、或者网络抖动重连，都应该持续看到「生成回答…」气泡，知道 run 还活着没卡死。

**功能交互细节**：

- **可见性双源**：`ComponentMessageStream` 内 spinner 渲染条件从 `{runActive && ...}` 改为 `{(runActive || sessionRunning) && <ComponentLoadingStatus phase={loadingPhase ?? 'thinking'} />}`。
- **phase 兜底**：当只有 `sessionRunning` 触发（runActive=false，loadingPhase=null）时显默认「思考中…」（`'thinking'`）——不误报「生成回答」，避免没事件流却显「生成回答」误导。
- **注入点**：父组件（page-chat.tsx / section-member-chat.tsx）传给 ComponentMessageStream 的 `runActive` 改为 `runActive || sessionRunning`（sessionRunning 已在父 scope 可用），最小改动。
- **不破 spec §4.10 数据源两层分离**：spec 已明确「spinner 可见性跟 runActive，phase 跟 loadingPhase」是当前现状；本修复**追加** sessionRunning 作为可见性兜底第二源，不动 phase 数据源（phase 仍跟 agent_loop loadingPhase）。spec §4.10 已说「两源独立：sessionRunning 含 interrupting/interrupted 中间态更准」——本修复正是把这句从描述对齐到代码实现。

**约束**：
- **群聊不在范围**：SquadChatPage 不订 useRunState（`chat_area_hooks.md` 行 84 明确「不订 run 态」），仍 GET 轮询拉 a2a inbox，本修复**不覆盖群聊**。仅 playground（page-chat）+ studio 单聊（MemberChatPage）生效。
- **已知小代价（接受）**：run_end 后 sessionRunning 滞留约一个 GET 延迟才翻 false，气泡可能多停一瞬。useRunState 为防 D6 快速重跑刻意保留此滞留（详见 `chat_area_hooks.md §4` run_end GET 校正），可接受。

### 2.3 studio chat 自给化（仅认 sessionId） [v0.0.96.ui_fix]

**描述**：MemberChatPage / SquadChatPage props 收敛为仅 `sessionId`（+ 纯交互回调 onOpenMember / prefill 保留），member / squad detail / squadModelDefault / tag 由 chat 自查；router 脱 detail 门控，消除 chat-loading 占位 + SquadChatPage↔MemberChatPage 抖动 race（顺带治问题 2 的 studio 次要项）。

**优先级**：P0

**用户故事**：作为 studio 用户，无论我从 sidebar 树点 member、从看板 @ 按钮跳进单聊、还是从 bookmark 直接进某个 member chat URL，行为完全一致——chat 自己根据 sessionId 拉齐所有需要的数据，不依赖父组件恰好选了哪个 squad。

**功能交互细节**：

- **新增自查 hook（暂名 `useStudioChatChrome(sessionId)`，arch 定形状）**：
  - 入参：仅 `sessionId`。
  - 内部流程：`GET /session/:id` 拿 `squadId` + `memberId` → `GET /squad/:squadId` 拿 detail（含 members / modelDefault）→ 按 `memberId` 定位 member（单聊时）。
  - 输出：`{ member?, squad, squadModelDefault, tag }`（群聊 member=undefined；单聊 member=对应 member）。
  - loading：自查期间 chat 自管 loading 态（替代 router 的 chat-loading 占位）。
- **MemberChatPage props 收敛**：
  - 删：`member` / `squadId` / `squadModelDefault` / `tag`（改自查）。
  - 留：`sessionId`（必填）/ `onOpenMember`（纯交互回调，点角色头像进 member 面板）/ `prefill?`（看板 @ 按钮预填，纯交互）。
- **SquadChatPage props 收敛**：
  - 删：`squadModelDefault` / `tag` / `title`（改自查）。
  - 留：`sessionId`（必填）/ `prefill?`。
- **router 脱 detail**（`component-studio-chat-router.tsx`）：
  - isGroup 判定从 `node.sessionId === detail.squadChatSessionId` 改为从 session 自查结果（`memberId` 空=群聊）。
  - 删 `memberForChat = detail.members.find(...)` 分支 + 删 `chat-loading` 兜底占位（chat 自管 loading）。
  - **顺带干掉 SquadChatPage↔MemberChatPage 抖动 race**：detail 异步窗口内旧 detail 不匹配 → 兜底 SquadChatPage → detail 到位切 MemberChatPage 的同 sessionId 类型抖动消失（spec `component-studio-chat-router.tsx:62-73` 注释已点名「未解：detail 异步加载时 MemberChatPage↔SquadChatPage 兜底抖动」）。
- **入口一致性**：所有进入路径（sidebar 树点 member / 看板 @ 按钮 / 未来的 bookmark URL）都只给 chat 一个 sessionId，行为统一。

**约束**：
- **零后端改动**：全用现成 `GET /session/:id`（API spec §2 已含 squadId/memberId）+ `GET /squad/:squadId`（API spec §3 已存在）。
- **接受重复拉 GET /squad**（方案 A）：page-studio 仍持有 detail 管 squad 面板/看板；chat 自查另拉一份。理由：彻底解耦 chat 与父选中态，重复 GET 成本可接受（squad detail 体积小 + 可加 client cache，见开放点 O3）。
- **群聊一并自给**（建议 arch 拍板）：router 统一脱 detail，一致性更好。如 arch 决定群聊暂不自给（保留 detail 透传避免 squad 面板/chat 数据双源失同步），PRD 接受，仅单聊自给。

## 3. 关键用户路径（MANDATORY — 测试最低覆盖要求）

| 路径 | 描述 | AT 覆盖 | ET 覆盖 |
|------|------|---------|---------|
| **A** | 打开 usage 面板 → 看到固定尺寸 + 流量单位格式（`12345`→`12.3K`、`12345678`→`12.3M`） | n/a（纯前端渲染） | ET-A：vision check 面板无折行 + 数值带 K/M 单位 |
| **B** | 会话正在生成（run 活着）→ 切到别的会话再切回 → 「生成回答…」气泡**仍显示**（sessionRunning 兜底） | n/a | ET-B：DOM 断言 `chat-run-spinner` 在切回后仍存在 + vision 气泡可见 |
| **C** | 网络抖动/SSE 重连后（run_start 丢帧）→ 气泡由 sessionRunning 兜底恢复 | n/a（难模拟网络抖动） | 不强制覆盖（理由：网络抖动难稳定复现，靠 AT-B 单元覆盖 reducer 兜底逻辑） |
| **D** | studio 里跨 squad 直接点某 member（不先点 team item）→ chat 直接渲染该 member，不再卡在 chat-loading 占位 | n/a | ET-D：DOM 断言 `squad-chat-role-avatar` 出现（member chat 已挂）+ 不出现 `chat-loading` |
| **E** | 从非 studio sidebar 路径（看板 @ 按钮跳转 / bookmark URL）进某个 member chat → 仅凭 sessionId 渲染该 member | n/a | ET-E（看板 @ 跳转）：DOM 断言切到 member chat 后 member 信息正确（avatar/role） |

> 路径 C 不覆盖理由：网络抖动场景在 E2E 难稳定复现（不可控的时序竞态），改由 coder 单元测试覆盖 `useRunState` 的 GET /session 兜底逻辑（onInit 拿 detail.running + run_end GET 校正）。

## 4. 契约变更面

- **API 契约**：**无变更**。chat 自给全用现成端点：
  - `GET /session/:id`（`specs/api/overall/04-agent-session.md §2.3` + `11-squad.md §4.2`）— 已返 squadId/memberId（11-squad §2）。
  - `GET /squad/:squadId`（`specs/api/overall/11a-squad-endpoints.md §1` GET/:id）— 已返 detail 含 members/modelDefault。
  - `POST /session/:id/abort` / `POST /session/:id/messages` 等运行态端点沿用。
- **数据契约**：usage 数据契约（SessionUsageView）**不动**；Message / Member / Squad 数据契约**不动**。
- **UI testid 契约**：**无新增**。沿用 `chat-run-spinner`（气泡）/ `squad-chat-page` / `squad-chat-role-avatar` / `usage-trigger` / `usage-expand` 等。
- **CSS/视觉契约**：usage 面板内部列宽规则变更（待 arch 落 spec `component-usage-panel.md §4.x` 视觉基线）。
