## 1. 目标 + 动机

### 1.1 问题

当前 bash engine 写死逻辑：darwin → `SecureBashEngine`（sandbox-exec seatbelt），非 darwin → passthrough。用户无法控制。

问题场景：Rocky agent 自身运行在 macOS seatbelt 沙箱内时，agent 调 bash 工具 → bash-engine spawn `sandbox-exec` → **嵌套沙箱被系统拒绝**（exit 71 Operation not permitted），导致命令执行失败（UT、部分 bash 命令全挂）。

### 1.2 目标

让用户能在应用设置 → 工具 tab 下切换 bash 执行引擎：
- **开（默认）**：走 `SecureBashEngine`（sandbox-exec，seatbelt 沙箱）
- **关**：走 `PassthroughBashEngine`（直接 spawn，不走 sandbox-exec）

一个 toggle 开关解决嵌套沙箱问题。

---

## 2. 范围

### 2.1 三件事

1. **app config `runtime` group 加 key `bash_seatbelt`**（boolean，默认 `true`）：走既有 `GET/PUT /config/app?group=runtime&key=bash_seatbelt`，无需新端点
2. **bash-engine.ts**：`getBashEngine()` 读配置 → `true` = SecureBashEngine / `false` = PassthroughBashEngine
3. **前端工具 tab 加 bash section**：一个 toggle switch（复用 `primitive-toggle-switch`），saveMode='item'（自管 save/reset，同 web_search 范式）

### 2.2 明确不做（边界）

- 不改 seatbelt profile 内容 / 安全策略（`BUILTIN_POLICIES` 不动）
- 不改 `SecureBashEngine` 内部逻辑（sandbox-exec 调用方式不变）
- 不改 `wireChildLifecycle` / `runShell` / `killProcessGroup`（子进程生命周期管理不变）
- 不改 `BashEngine` 接口（仍是 `exec(command, opts)` 一个方法）
- 不新增 API 端点（runtime group 已有通用 GET/PUT）
- 非 darwin 平台无变化（本来就走 passthrough）

## 3. 功能设计

### 3.1 配置数据契约

| 字段 | 值 |
|------|-----|
| entity | `app_config` |
| group | `runtime`（已有 group，observability 也在此 group） |
| key | `bash_seatbelt`（新增 key） |
| data | `true` \| `false`（boolean，默认 `true`） |
| 缺失语义 | record 缺失 → 默认 `true`（保持现有行为，向后兼容） |

**GET**：`GET /config/app?group=runtime&key=bash_seatbelt` → `{ value: true | false | null }`（null = 未配置，前端按 true 处理）

**PUT**：`PUT /config/app` body `{ group: 'runtime', items: [{ key: 'bash_seatbelt', data: <boolean> }] }`

### 3.2 引擎切换逻辑

`bash-engine.ts` 的 `getBashEngine()` 改为**按配置决策**：

```
getBashEngine(config):
  if config.bash_seatbelt === false → PassthroughBashEngine（直接 runShell）
  else（true / 未配置 / 读取失败）→ SecureBashEngine（现有行为）
```

**新增 `PassthroughBashEngine`**：实现 `BashEngine` 接口，`exec()` 直接调 `runShell()`（与 SecureBashEngine 非 darwin 分支相同）。

**配置读取时机**：getBashEngine 是进程级单例（惰性初始化），配置在单例创建时读取。**配置变更需重启生效**（与 observability 配置一致，UI 需提示）。

### 3.3 UI 设计

**位置**：应用设置 → 工具 tab → 现有三个 section（web_search / web_fetch / see_image）之后，新增第四个 **bash section**。

**组件**：新增 `SectionBashConfig`（自渲染 section，saveMode='item'，同 web_search / see_image 范式）。

**UI 元素**：
- section 标题：「Bash 工具」（`group.bash.label`）
- section 描述：「沙箱（seatbelt）保护 — 在嵌套沙箱环境（如 Rocky agent 自身运行在沙箱内时）可关闭以避免 exit 71」
- 一个 toggle switch（`ToggleSwitch`），label「使用沙箱」
- save/reset 按钮（saveMode='item'）

**交互**：
- 挂载时 `GET /config/app?group=runtime&key=bash_seatbelt` 读 baseline
- toggle 翻转 → draft 标 dirty → save/reset 按钮激活
- 点 save → `PUT /config/app` → 提示「重启生效」
- 点 reset → draft 回 baseline

**布局稳定性**：toggle switch 固定尺寸（36×20），不导致周围元素位移（沿用 `primitive-toggle-switch` 视觉基线）。

## 4. 关键用户路径（MANDATORY — 测试最低覆盖）

### 路径 1：查看 bash 沙箱配置

- 链路：应用设置 → 工具 tab → 滚动到底部见 bash section → toggle 默认「开」
- 关键断言：toggle 可见 + 默认 true（baseline 为 true / null 均显示开）

### 路径 2：关闭沙箱并保存

- 链路：工具 tab → bash section → 点 toggle 关 → save 激活 → 点 save → PUT 成功 → 提示重启生效
- 关键断言：toggle 翻转 → dirty → save 落库 → baseline 更新为 false

### 路径 3：重置未保存改动

- 链路：工具 tab → bash section → 点 toggle 关（dirty）→ 点 reset → toggle 回到开
- 关键断言：reset 恢复 baseline，dirty 清除

### E2E Use Cases

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-1 | 应用设置 → 工具 tab → 见 bash section（在 see_image 下方） | section 标题 + 描述 + toggle（默认开）可见 |
| UC-2 | 点 toggle → toggle 变关 → save/reset 按钮激活 | dirty 状态正确；toggle 视觉切换（knob 左移 + bg 变 border-strong） |
| UC-3 | toggle 关 → 点 save → 看「重启生效」提示 | PUT 成功；baseline = false；toggle 保持关 |
| UC-4 | toggle 关（dirty）→ 点 reset → toggle 回开 | draft 恢复 baseline；dirty 清除 |
| UC-5 | save 后重启应用 → agent 执行 bash 命令 → 不走 sandbox-exec | 命令成功执行（无 exit 71）；PassthroughBashEngine 生效 |
