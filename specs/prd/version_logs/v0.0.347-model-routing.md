## 1. 需求描述 [v0.0.347]

**模型路由降级**：为 session 配置「模型组合方案」（有序候选链 + 时间条件 + 熔断参数），LLM 调用失败时按候选链降级切换，避免单模型故障导致会话中断。核心决策（D1-D17）：

1. **组合方案**：每条目 = provider + model + enabled + 时间条件（小时白名单）；同模型（providerId+modelId）按启用条目分组 ≤2 条、禁 2 带时间、禁 2 不带时间、带时间条目必须排在不带时间上面。
2. **attempt 内路由**：`llm_caller.invokeCore` 检测 routingPlan → 走新路由循环（时间过滤→enabled→熔断→banned→调用→失败决策），复用现有 attemptLoop 单次调用（看门狗/classify/buildRequest overlay 全保留）。
3. **三态熔断**：Closed→Open（连续失败≥4 **或 窗口有效样本≥minRequests(10) 且窗口错误率≥0.6**（T5 滑窗口径，老板 2026-08-14 拍板，非终身累计）/ directOpen）→HalfOpen（60s 到期限流 1 并发）→Closed（连续成功≥2）；默认 4/2/60/0.6/10/windowSize=20，方案级 circuit 覆盖。进程内存 registry，不持久化。
4. **差异化重试**：429/529/401/403/请求类=0 次快速降级；瞬态=1 次；AUTH 直接 Open。
5. **挂载**：studio=squad.modelRoutingPlanId / playground=model_routing.default.playgroundPlanId（T6 起与默认模型**合并单 select 严格互斥**二选一，老板 21:44+22:22 拍板；PATCH null=解除挂载）。**academy 排除**（走 classroom 三档链，集成=非目标）。
6. **删除方案**：通用 KV DELETE + group 白名单（仅 model_routing_plans）；删除时扫描解除挂载，挂载方回退默认模型（分支 1 天然生效）。
7. **状态查询**：`GET /model-routing/plans/:planId/status` 只读内存快照；UI 红绿灯消费 presentation（D16：normal→正常 / abnormal→异常带倒计时 / observing→观察中，**禁熔断词**）。

**优先级**：P1（新功能）

## 2. 现状与目标

**现状**：单模型调用，失败仅按既有 attemptLoop 重试，无跨模型降级；provider 故障 = 会话中断。

**目标**：方案库 CRUD（app 设置 models tab）+ squad/playground 挂载 + attempt 内自动降级 + 熔断红绿灯可见性；无挂载时现有 resolveModel 分支 1 **零改动**（D4 不隐式兜底）。

## 3. 验收要点

1. 方案 CRUD 全通过（校验 400 + 错误形状 `{ error: message }` 对齐全仓 KV 统一形状）。
2. 挂载/解除挂载（squad PATCH 三语义：undefined 不写 / null 清空 / 非空校验 plan not found）。
3. 候选链降级（首候选失败 → 下一候选；耗尽聚合错误 NO_AVAILABLE_MODEL）。
4. 熔断三态 + 红绿灯呈现（友好词 正常/异常/观察中）。
5. AT 4 条 + ET 5 条（路径→case 映射见 test-plan `204848d61`）。
