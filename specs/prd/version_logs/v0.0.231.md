## 1. 版本主题（产品语义）

playground 会话列表（conv-panel 220px 栏）两个现状问题：

- **问题 1（排序不即时）**：新建会话出现在列表最后；已有会话对话后位置不动——「谁最新谁在上面」不成立，用户要在长列表里翻找刚建的/刚聊的会话。
- **问题 2（无置顶）**：常用会话无法固定，列表一沉就要翻。

**已确认决策（2026-08-01，用户裁决，task.json decisions）**：
1. **排序口径 = 统一比较器**：先 pinned 降序（置顶组在前）、同组内 `updatedAt desc`；新建/对话/置顶任何变化列表自动归位，单一数据源。
2. **置顶范围 = 仅 playground**；academy/studio 会话列表本期不接置顶 UI。
3. **pinned 数据面**：Session 新增可选布尔 `pinned`，复用 unread/titled lazy-default 模式（历史 session 缺省 false，**无 migration**）；写路径复用现有 `PUT /session/:id` 部分更新透传（同 effort/approvalMode）。

## 2. 功能需求（用户可感知）

### 2.1 块1 — 会话列表即时排序（统一排序规则） [v0.0.231]

**优先级**：P0
**用户故事**：作为用户，我新建会话或回到某个旧会话聊了几句，希望这个会话立刻浮到列表（其分组内）最上面，不用手动刷新、不用翻列表找。

**产品规则**：
- **统一排序规则（唯一口径）**：列表顺序 = 置顶组在前、非置顶组在后，**同组内按更新时间倒序**（最新在上）。新建会话 createdAt/updatedAt 最新 → 出现在（非置顶组）最上面。
- **即时归位**：任何引起排序变化的事件——新建会话 / 会话收到新消息（run 推进 updatedAt）/ 置顶状态切换 / 标题等 meta 更新 / 页面刷新重拉——列表**立即自动重排归位**，无需手动刷新。排序是列表的常驻属性，不是一次性初始顺序。
- **单一数据源**：排序由前端会话列表 store 统一计算（权威数据仍来自 `GET /session` + `session_meta` 广播，与 v0.0.27 列表实时刷新契约一致）；后端 `GET /session` 返回顺序契约不变（`updatedAt desc`，置顶分组是展示层归位）。
- **重排不动状态**：重排只改位置——active 选中态、unread 红点、running spinner / suspended「?」、subagent 展开树（twisty/三段）行为不变；subagent 子项不作顶层项的过滤逻辑（page-chat topSessions）不受影响。
- **布局稳定（MANDATORY 铁律）**：重排是 item 位置变化，不得导致 conv-panel 其他结构（header / 新建按钮）位移。

#### E2E Use Cases（块1）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-231-1 | playground 点新建会话 → 看列表 | 新会话出现在列表最上面（无置顶会话时为全表第 1 条；有置顶时为非置顶组第 1 条），不再沉底 |
| UC-231-2 | 选中一个列表中部的旧会话 → 发一条消息 → run 完成 | 该会话浮到其分组内最上面（updatedAt 最新），无需刷新 |
| UC-231-3 | 对话中途观察列表（收到 meta 更新如 AI 起名） | 列表按统一规则即时归位，无错位/无重复项/无闪烁 |

### 2.2 块2 — playground 会话置顶（pinned） [v0.0.231]

**优先级**：P0
**用户故事**：作为用户，我有几个常用会话想钉在列表顶部，右键置顶后它们固定在上方一组、一眼可见（pin 图标 + 背景加重），取消置顶就回到普通时间序里。

**产品规则**：
- **入口**：playground 顶层会话 conv-item 右键菜单新增「置顶」项；已置顶会话该项变为「取消置顶」。与既有「复制 Session ID」并列（菜单项顺序交组件 spec，置顶项在复制 ID 之上为默认推进）。
- **两个分组**：置顶会话构成列表顶部一组、非置顶在其下一组，**两组各自按更新时间倒序**（§2.1 统一排序规则）。无置顶会话时列表 = 纯时间序（不出现空组）。
- **无组头分隔线（默认推进）**：不引入组标题/分隔线 UI——分组边界靠置顶 item 自身视觉区分（pin 图标 + 背景）即可辨识；用户原需求只要求 item 级区分。
- **置顶 item 视觉契约**：
  - **pin 图标**：置顶 item 最右侧常驻 pin 图标（非 hover 才显），非置顶 item 无。
  - **背景加重**：置顶 item 整个背景灰色**进一步加重**（比非置顶常态更深一档），一眼区分两组；配色走 design token（INV-2 禁字面 hex，具体 token 由组件 spec 视觉基线定，交 coder 先 spec 后实现）。
  - **态叠加**：hover / active 选中态语义不变且优先可辨——active 态仍是最强视觉（置顶 + active 叠加时不丢失选中指示）；pin 图标与 unread 红点 / running spinner / suspended「?」错位共存、互不遮挡（图标占位固定，不出现/消失不推动其他元素，布局稳定铁律）。
- **持久化与同步**：置顶状态跨 app 重启保留（落盘 per session）；历史会话一律默认非置顶（无需迁移）。置顶/取消经 `PUT /session/:id` + `session_meta` 广播，多 tab 即时一致。
- **操作范围**：置顶入口仅 playground 顶层会话 conv-item——subagent 树内子项、academy/studio 会话列表不出现置顶项（本期范围外）。

#### E2E Use Cases（块2）

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-231-4 | 右键一个非置顶会话 → 点「置顶」 | 该会话进入列表顶部置顶组；item 最右侧出现 pin 图标、背景加重；组内按时间排 |
| UC-231-5 | 置顶多个会话 → 在其中一个置顶会话里发消息 | 该会话在**置顶组内**浮到最上，不跌出置顶组 |
| UC-231-6 | 右键已置顶会话 → 点「取消置顶」 | pin 图标与加重背景消失；会话回到非置顶组，按 updatedAt 归位（不固定在原位） |
| UC-231-7 | 置顶若干会话后重启 app | 重启后置顶组/非置顶组与各组内顺序保持（pinned 持久化） |

## 5. 验收口径

- **功能**：P-A ~ P-E 全 PASS（UT + ET 冒烟共同覆盖）。
- **排序不变量**：任意时刻列表 = 置顶组（updatedAt desc）+ 非置顶组（updatedAt desc）；新建/对话/置顶/刷新后自动归位，无需手动刷新。
- **置顶视觉不变量**：置顶 item 最右侧常驻 pin 图标 + 背景灰色加重（token，非字面 hex）；active/hover 态语义不丢；图标出现/消失不推动相邻元素。
- **数据不变量**：`GET /session` 排序契约不变（updatedAt desc）；历史 session pinned 缺省 false（无 migration）；置顶状态跨重启保留。
- **回归不变量**：编辑态改名 / 删除会话 / 复制 Session ID / subagent 树展开 / unread 红点行为不回归；academy/studio 会话列表零变化。
- **视觉保真**：无设计稿 → vision_check compare 跳过。

## 6. 边界（OUT OF SCOPE）

- academy / studio 会话列表不接置顶 UI、排序行为本期不变（后续版本按需接）。
- subagent 树内子项不置顶（置顶仅 playground 顶层会话）。
- 不引入组头/分隔线 UI、不支持拖拽手动排序、不做置顶数量上限。
- 不改 `GET /session` 后端排序契约；不做多端冲突处理（PUT 后写赢，单端 electron 场景够用）。
