## 1. 版本主题（产品语义）

**现状（用户痛点）**：v0.0.227 已落地「点 `.md` → 内置 modal 查看/编辑/保存」完整链路（`component-modal-md-editor` + `GET/POST /session/:id/workspace/file[/save]`，后端**不限扩展名**）。但其它常见配置/数据格式（`.json` / `.yaml` / `.xml` / `.csv` 等）点文件仍走 `POST /workspace/open` 系统默认应用——跳出 app 外部打开，体验割裂；用户改坏格式无任何提示，需借助外部工具才能发现错误。

**目标**：把拦截范围从 `.md`-only 扩到 **11 种常见配置/数据格式**（xml / yaml / json / jsonl / txt / csv / tsv / toml / ini / .env / .log）；**结构化格式**（7 种）提供 **pretty format（缩进/对齐）+ 格式校验**能力，让用户在 app 内即可查看/编辑/整理配置与数据文件。

**产品不变量**：
- **复用 v0.0.227 弹层骨架**（modal shell + view/edit 双模式 + onSave 纯回调 + last-write-wins + L3 Portal），不新造第二套 editor。
- **后端零改**：`/workspace/file[/save]` 已通用（UTF-8 + 路径白名单，不限扩展名），本版本仅扩**前端拦截** + editor 加**格式化能力**。
- **渲染朴素**：原生 `<textarea>` + `<pre>` 朴素预览，**不引入** CodeMirror/Monaco/重度语法高亮（用户原话「渲染不需要花里胡哨」）。
- **不做编程语言**（java/cpp/py/js 等）：用户铁律——只覆盖配置/数据语言。

## 2. 格式范围与体验分级

### 2.1 11 种格式分类（锁定，不区分大小写）

| 分类 | 格式 | 拦截后缀 | view 渲染 | edit | 格式功能 |
|------|------|---------|----------|------|---------|
| 结构化（配置/数据语言） | JSON | `.json` | `<pre>` 朴素 | textarea | pretty format + 校验 |
| 同上 | JSONL | `.jsonl` | `<pre>` 朴素 | textarea | pretty（逐行）+ 校验 |
| 同上 | YAML | `.yaml` / `.yml` | `<pre>` 朴素 | textarea | pretty format + 校验 |
| 同上 | XML | `.xml` | `<pre>` 朴素 | textarea | pretty format + 校验 |
| 同上 | TOML | `.toml` | `<pre>` 朴素 | textarea | pretty format + 校验 |
| 同上 | CSV | `.csv` | `<pre>` 朴素 | textarea | pretty（列对齐）+ 校验 |
| 同上 | TSV | `.tsv` | `<pre>` 朴素 | textarea | pretty（列对齐）+ 校验 |
| 纯文本类 | TXT | `.txt` | `<pre>` 朴素 | textarea | 无 |
| 同上 | INI | `.ini` | `<pre>` 朴素 | textarea | 无 |
| 同上 | ENV | `.env` / `.env.*` | `<pre>` 朴素 | textarea | 无 |
| 同上 | LOG | `.log` | `<pre>` 朴素 | textarea | 无 |

> **md 仍走 v0.0.227 链路**（view 模式 markdown 渲染 + edit 模式 textarea），本版本不动。

**纯文本类说明**：txt/ini/env/log 文件结构松散（无统一 schema），按 txt 处理——仅查看/编辑，不解析、不格式化、不校验。

### 2.2 view 模式渲染（所有格式统一规则）

- **md** → markdown 渲染（v0.0.227 `PrimitiveMarkdownView`，不动）。
- **结构化 + 纯文本类** → `<pre>` 朴素预览（保留缩进/换行，**无**语法高亮、**无**行号、**无**折叠——保持极简）。
- **view 模式不显示「格式化」「校验」按钮**（只读场景，格式功能仅 edit 模式可用，避免误以为会改源文件）。

## 3. 格式功能详述（仅 edit 模式可用）

### 3.1 通用规则（所有结构化格式共用）

- **入口**：edit 模式下 md-foot 按钮区（与「保存」同区）显示「格式化」+「校验」按钮——**仅结构化格式显示**（纯文本类隐藏，按钮位用 `visibility:hidden` 预留固定槽位，避免相邻元素位移，对齐 CLAUDE.md 布局稳定性硬规则）。
- **格式化（Format）**：取 textarea 全文 → 解析 → 规范序列化重写（统一缩进/对齐/分隔）→ **替换 textarea 内容**（用户可见缩进/对齐变化）；解析失败时**不可格式化** → hint 区提示「格式错误，无法格式化（先校验看错误位置）」，**不动 textarea 内容**（防把坏内容洗成空）。
- **校验（Validate）**：取 textarea 全文 → 解析 → 失败时 hint 区显示错误信息（**尽量带行号/列号/上下文**，如 `JSON 第 3 行: Unexpected token }`），**不阻塞保存**；成功时 hint 区显示「✓ 格式正确」（轻量正向反馈）。
- **不阻塞保存（关键不变量）**：校验失败 ≠ 不可保存——last-write-wins 语义不变（v0.0.227 §6.3）；用户可选择保存「坏」格式文件（可能是 deliberate 半成品/渐进编辑中间态）。
- **布局稳定性**：「格式化」「校验」按钮的出现/消失（结构化 vs 纯文本）必须用预留固定空间（`visibility:hidden`）或绝对定位，**不得导致相邻元素位移**。

### 3.2 各格式行为（能力描述，库选型留架构期）

| 格式 | 格式化能力（产品行为） | 校验能力（产品行为） |
|------|---------------------|---------------------|
| JSON | 解析 → 2 空格缩进 pretty 序列化（中文字符保留不转义） | 解析失败 → 报错位置（行/列 + 错误 token） |
| JSONL | 逐行解析 → 每行 pretty → 重新换行拼接 | 逐行解析 → 报**第几行**出错 + 错误信息 |
| YAML | 解析 → 规范缩进序列化（block 风格优先，避免 flow） | 解析失败 → 报错位置（行 + 错误描述） |
| XML | 解析 → 规范缩进序列化（保留属性/文本节点） | 解析失败（标签未闭合/非法字符）→ 报错位置 |
| TOML | 解析 → 规范序列化（表/键值结构） | 解析失败 → 报错位置 |
| CSV | 按行解析 → **列对齐**（每列宽度 = 该列最长字段 + 1 空格填充，不破坏性变更引号） | 校验**各行字段数一致性** → 不一致时报「第 N 行字段数为 M，与首行 K 不符」 |
| TSV | 同 CSV，分隔符 `\t` | 同 CSV |

> **CSV/TSV 的「格式化」目标** = 列对齐（让用户肉眼能扫到列对应关系），**不做** Excel 式表格网格渲染。

## 5. UX 决策（推荐方案 — 待用户确认）

> 以下 5 条为产品倾向方案，PRD 据此落稿但**未作定论**；标注「待确认」，由 orchestrator 转用户裁决后再进架构期。

1. **【待确认】统一弹层**：所有 11 种格式走**同一个弹层**——复用 `component-modal-md-editor` 的 modal shell + view/edit 双模式骨架；view 模式按格式分流（md → markdown 渲染；其余 → `<pre>` 朴素预览）；edit 模式统一 textarea。**组件结构（新组件 vs 扩展现有 / 命名泛化「md-editor」→「通用 file editor」）留架构期**，PRD 只定义产品行为，不预设拆分。
2. **【待确认】CSV/TSV 体验** = 朴素文本编辑 + 列对齐 pretty + 行列字段数校验，**不做 Excel 式表格网格**（偏华丽、超范围、复杂度高）。
3. **【待确认】格式按钮位置**：沿用 md_editor 的 md-foot 区——edit 模式下结构化格式显示「格式化」+「校验」按钮；纯文本类不显示（预留固定槽位）；view 模式一律不显示。
4. **【待确认】格式错误 UX**：校验失败**不阻塞保存**（last-write-wins 语义不变），只在 hint 区显示错误信息（尽量带行号/位置）；用户仍可选择保存「坏」文件。
5. **【待确认】拦截范围扩展**：点 xml / yaml / json / jsonl / txt / csv / tsv / toml / ini / env / log 文件 → 内置弹层（不再丢给系统默认应用）；**其它扩展名**（含二进制、图片、编程语言 `.py`/`.js`/`.java` 等）维持现状走 `POST /workspace/open`。

## 6. 边界 / 不做

- **编程语言（明确排除）**：java / cpp / c / py / js / ts / rs / go 等编程语言源码——用户铁律「yaml 之类属于配置语言；java cpp 属于 coding 语言」，**不做**。仍走系统默认应用。
- **重度语法高亮**：不引入 CodeMirror / Monaco / shiki / prism 等高亮库；保持原生 `<textarea>` + `<pre>` 朴素风格。
- **Excel 式表格网格**：CSV/TSV 仅做列对齐文本 + 校验，**不做**表格化渲染（不做单元格选中/合并/公式/排序）。
- **后端契约改动**：`/workspace/file[/save]` 后端零改（已通用 UTF-8 + 路径白名单）；本版本纯前端 + 纯编辑器逻辑。
- **新建文件**：本版本只覆盖既有文件查看/编辑，不在弹层内新建文件（last-write-wins 仅覆盖既有，对齐 v0.0.227 §2.6.7）。
- **查找替换 / 行号 / 代码折叠**：不做。朴素 textarea 不加编辑器增强特性（防功能蔓延）。
- **冲突提示 / mtime 校验**：不做。沿用 v0.0.227 last-write-wins（无 mtime 校验、无冲突提示）。

## 8. 验收口径

- **功能**：UC-241 全部 PASS（UT：拦截判定 + 每种结构化格式的 format/validate + 按钮显隐分支；既有 v0.0.227 workspace 冒烟集回归）。
