# v0.0.216 PRD 变更日志 — chat 区域统一复用（chat_unify）

> 版本：v0.0.216 · 主题：chat 区域统一复用架构（用户可感知部分）
> 创建：2026-07-29 · 需求源：`reqs/[working] v0.0.216.chat_unify/req.md`（用户已确认方案）
> PRD 边界：本版主体为**架构重构**（前端装配层收敛 + 后端同构会话装饰接口）。纯技术部分（组件/接口设计、文件收敛、行数）**不进本 PRD**，归 architect 落 `specs/tech/` + `specs/api/`。本 PRD 只覆盖三类用户可感知变化：① academy 会话能力拉齐；② 既有 chat 页面零回归；③ 各类会话默认模型正确回填。

---

## 1. 版本主题（产品语义）

**所有 chat 页面共用同一个「统一 chat 区域组件」**：任何页面嵌入会话区后，自动获得与主聊天（playground）同等的全部会话能力——HITL 卡（提问卡/审批卡）、停止（abort）、effort picker、审批模式 picker、排队区（enqueue view）、usage、历史 query minimap、右上悬浮菜单、可拖拽分栏。能力**缺省全开**，按后端返回的能力配置门控（如群聊无 run 态则不显 stop / 不放两 picker，沿用 v0.0.152 裁决），前端不再按页面各自实现或硬编码降级。

**直接动因（用户投诉）**：academy chat 与主 chat「长得一样但功能不一样」——ask question 提问卡不显示、effort/审批 picker/abort 未迁移，每加一个能力要逐页面补课。

## 2. 功能需求（用户可感知）

### 2.1 academy 三处可交互会话 — 能力拉齐到主 chat 基线 [v0.0.216]

**优先级**：P0
**用户故事**：作为 academy 用户，我希望与班主任/教练/学生版本对话时拥有与主聊天完全相同的会话能力，以便 LLM 提问时我能作答、危险操作我能审批、跑偏时我能中断。
**用户裁决**：academy 能力**默认全开**（2026-07-29「对，目前可以这样」）。

**交互细节**：
- 提问卡/审批卡/排队区的挂载位置、互斥关系、交互流程**完全沿用既有契约**（`03-llm-chat.md` 路径 AAA/DDD、`10-tool-permission.md` §10.3/§10.7），academy 不做任何变体。
- 布局稳定性：卡片/按钮出现或消失不得导致输入区及相邻元素位移（沿用 `10-tool-permission.md` §10.3 占位固定口径）。
- 各页保留的差异仅剩**身份 header / 空态文案 / 输入 placeholder / 返回行为**等页面身份要素；会话能力零差异。

#### E2E Use Cases

### 2.2 subagent 只读观察页 — 保持只读 [v0.0.216]

**优先级**：P0（边界约束）
训练观察的 subagent 只读 transcript（session-readonly）**维持只读语义**：无输入区，HITL/abort/picker/enqueue 等输入侧能力不适用、不出现。统一组件按「只读」形态渲染，不得因能力全开而给只读页带出输入能力。

#### E2E Use Cases

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-6 | 训练观察页 → 点开 working subagent 只读 transcript | 消息流可看，无输入区、无 picker/stop/HITL 卡 |

### 2.3 各类会话默认模型正确回填 [v0.0.216]

**优先级**：P0
**描述**：打开任一 chat 页面，输入区 model picker 回填该会话类型的默认模型，差异逻辑收敛在后端（前端零类型分支）：

| 会话类型 | 默认模型来源 |
|---|---|
| playground | 全局应用配置 |
| studio（leader/mate/squad） | squad 配置 |
| academy（班主任/教练/学生版本） | classroom 配置 |

含存量 gap 顺带修复：academy 会话运行时模型解析此前缺失专属分支，本版补齐——academy 会话按 classroom 配置解析模型（用户可感知：academy 会话实际使用的模型与教室配置一致）。

#### E2E Use Cases

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-7 | 依次打开 playground / studio 单聊 / academy 班主任会话 | model picker 分别回填全局配置 / squad 配置 / classroom 配置的默认模型 |

### 2.4 既有 chat 页面零回归（回归契约） [v0.0.216]

**优先级**：P0
playground / studio 单聊 / studio 群聊迁移到统一组件后，**全部既有能力与行为不变**：HITL 两卡、abort、两 picker（群聊仍不放两 picker——v0.0.152 裁决不变）、enqueue、usage、minimap、悬浮菜单（群聊仍 hideCron）、拖拽分栏、清空会话 modal、群聊无 run 态（无 stop 按钮）。这是回归契约，不是新功能；验收以「能力清单逐项核对」为准。

#### E2E Use Cases

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| UC-8 | playground 发消息 → 观察 HITL/usage/minimap/拖拽 | 与 v0.0.215 行为一致，无缺失无位移 |
| UC-9 | studio 群聊打开 → 检查输入区 | 无 effort/审批 picker、无 stop（既有裁决保持） |

### 2.5 一致性承诺（产品原则，长期有效） [v0.0.216]

今后所有 chat 页面能力**自动一致**：新会话能力（新卡片/新 picker/新面板）只需在统一 chat 区域组件实现一次，全部页面同步生效；新增 chat 页面以极低成本接入即获得全量能力。「复用 = 能力清单」将固化进 UI 契约（`specs/ui/components/chat-page/base-chat-page.md` 消费方必备清单，由 architect/coder 落 spec），作为后续版本验收断言，防止再次出现「长得一样但功能不一样」。
