## 1. 版本目标

支持中英双语（`zh-CN` / `en`）。建立 i18n 基础设施（locale bundle + 占位符替换 + 兜底链 + 缺 key 报错），打通「前端 t() 查表」+「后端按 locale 选 UI 文案」两条链路，并用 `displayReason` 迁移验证后端范式。本版本**只搭框架 + 梳理清单 + 迁移样板**，页面级迁移分批走后续版本。

判定原则（划分线）：**UI 上能看到的 → i18n**；逐元素按此一刀切，不再分类纠结。

### 2.2 OUT-OF-SCOPE（硬边界 — Non-goals）

**LLM 向内容不翻译**：
- 提示词（system / agent prompt）
- 用户输入
- LLM 回复正文

**用户数据（字面数据，原样展示）不翻译**：

## 3. 产品行为（用户可感知）

### 3.1 语言切换
- 设置页提供语言选择器，选项：**「中文」** / **「English」**（按当前语言本地化展示选项名）
- 切换后**全局 UI 立即生效**，无需刷新；切换写入 `app_config.locale.language`，持久化
- 一个开关驱动三件事：前端 t() 查表 + 后端按 locale 选 UI 文案 + LLM 输出语言引导（输出引导非本版本功能，仅开关语义预留）

### 3.2 占位符渲染
- UI 文本按当前语言从 locale bundle 查表展示
- 后端/配置返回的「占位符 key」按当前语言翻译后展示；返回字面文本则直接展示（用户数据走这条）
- 同一 UI 在 zh-CN 下显示中文、en 下显示英文

### 3.3 兜底链
- 当前语言缺翻译时按 **当前语言 → en → zh-CN** 顺序兜底（始终有文本可见，不出现空白）
- 三级全缺时按缺 key 处理

### 3.4 缺 key 报错（开发期）
- 占位符 key 完全不存在（locale bundle 没有这个 key）→ 开发期报错「资源 xxx 不存在」
- 用于抓漏迁移的 key；面向开发者，不面向终端用户

## 4. 关键用户路径（MANDATORY — 测试最低覆盖）

> 每条路径 = 至少 1 个 API/E2E case。本版本基础设施特性，E2E 走「设置页切换 → 全局生效」主路径，displayReason 走 API 路径。

| ID | 路径 | 涉及功能 | 测试类型 |
|----|------|---------|---------|
| **P1** | **切换 English → 全局 UI 立即变英文**：用户进设置页 → 选「English」→ 全局 UI 文本（按钮 / 标题 / tab / placeholder / 菜单 / tooltip 等）立即显示英文（无需刷新） | S1 + S3 + S4 | E2E（DOM 断言 i18n 容器文本切换 + vision_check 看英文 UI） |
| **P2** | **切换中文 → UI 变中文**：用户进设置页 → 选「中文」→ 全局 UI 文本切回中文 | S1 + S3 + S4 | E2E（同 P1，反向） |
| **P3** | **某 key 当前语言无翻译 → 兜底显示**：构造一个 zh-CN 缺翻译但 en 有的 key → 切到 zh-CN → 该 key 位置兜底显示 en 文本（不空白） | S4 兜底链 | API/E2E（断言兜底文本 = en 文案，非空） |
| **P4** | **LLM 报错 → displayReason 按当前语言显示**：用户在 zh-CN 下触发 LLM 限流类错误 → SSE error 事件 / RunRecord.error.displayReason 在前端按 zh-CN 显示本地化理由（如「服务商限流，已自动重试…」） → 切到 en 后同样错误显示英文理由 | S2 + S5 | API（构造限流 mock，断言 displayReason category code 返回 + 前端按 locale 查表文案；或断言后端按 locale 选文案） |
| **P5** | **刷新页面 → 语言偏好持久**：用户切到 English → 刷新页面 → UI 仍是英文（语言从 app_config 读取） | S3 | E2E（断言刷新后 DOM 仍是英文态） |

## 7. 验收标准

### 7.1 功能验收

- **S1 + S4 基础设施可用**：前端任何硬编码文本可经 t(key) 替换为当前语言；切换 locale 立即生效；缺翻译走兜底链；缺 key 开发期报错。
- **S2 + S5 displayReason 范式落地**：LLM 报错时 displayReason 在 zh-CN 显示中文、en 显示英文；后端 category code 契约清晰（架构 phase 定）。
- **S3 locale 开关**：设置页有语言选择器；切换写入 `app_config.locale.language` 并持久化；刷新读回。
- **S6 清单产出**：配置体系 + 前端静态菜单体系的待 i18n 清单成文（可作为 Batch 2 输入）。

### 7.2 边界守护（回归 + 范围纪律）

- **LLM 向内容零翻译**：system/agent prompt、用户输入、LLM 回复正文原样透传，不进 i18n 链路。
- **用户数据零翻译**：squad name/desc/charter、member name、session title、provider/model label、board 工作项、user_memory、用户自建 skill 原样展示。
- 切换 locale **不破坏**现有功能（chat / squad / settings 等回归绿）。

### 7.3 测试 / 门禁

- **API**：P4（displayReason 按当前语言）有 API case 覆盖（mock 限流 / 真服务构造错误皆可）；locale 开关读写有 case。
- **E2E**：P1/P2/P5 视觉 + DOM 双断言；P3 兜底链有断言。
- **代码质量**：`bun run typecheck` 通过。

## 9. 待 architect / coder 落地的细节（PRD 不发明）

1. **locale bundle 物理结构** — JSON 文件组织 / 命名空间拆分（按 page 模块 vs 按功能域）。
2. **KKV 占位符协议具体格式** — key 的字面形态（如 `chat.sendButton` vs `chat.send_button` vs 其他）。
3. **后端 locale 读取链路** — HTTP request 怎么传 locale（header / query / body 字段），server 怎么读到。
4. **displayReason category code 契约** — 17-19 个 LlmErrorCategory → code 字符串映射；前端查表的 key 命名。
5. **语言选择器 UI 形态** — 下拉 vs 段控 vs 其他；testid 命名（如 `settings-locale-select` / `locale-option-zh-CN`）。
6. **缺 key 报错的视觉形态** — console.error + UI 红色提示 vs 仅 console；面向开发者的可见度。
