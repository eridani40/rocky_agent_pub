## 1. 版本主题（产品语义）

把业务全景「更多」固定 tab 的空态引导卡（`PanoramaIdle`）按钮行为，从「去群聊 @leader」（被动指路）改为「跳 leader 单聊 + composer 预填模板请求」（一步开干）——让「找 leader 搭个看板」这条最常见意图一步到位，用户删掉模板里的 `...` 填上具体内容即可发送。

**产品不变量**：
- 复用现有 `PanoramaIdle` 卡片视觉骨架（v0.0.243 恢复版），不重设计——仅按钮文案/行为变更（守 ui-out-requirements-not-design）。
- 复用现有「预填待发」语义（与现状 @ 预填一致：注入到 composer 但**不自动发送**，用户掌控发送）。
- 兜底不变：无 leader 场景仍走 `flash(t('studio:toast.noLeaderAvailable'))`，不跳转。

## 2. 背景与问题（痛点）

业务全景（panorama）「更多」固定 tab 激活时渲 `PanoramaIdle` 白卡引导（v0.0.243 恢复版，权威 spec `component-panorama-idle.md`）。现状：

- 单按钮「去群聊 @leader」→ 触发 `onAtLeader` 回调（外层 `page-studio.tsx:169` handler）→ 切 **群聊 squadChat**（`d.squadChatSessionId`）+ composer 预填 `@leader` mention chip（`page-studio.tsx:186`）。
- 痛点：引导只到「指路（@ 到 leader）」，没到「让 leader 知道要搭什么」——用户到了群聊还得自己想、自己敲「帮我搭个看板，展示 XXX」。「找 leader 搭看板」这条最常见意图被拦在「指路」一步，没一步到位。

**核心问题**：引导停在指路，没承接「搭看板」意图本身。

---

## 3. 方案（3 个锁定决策 — 用户 2026-08-04 拍板）

### 3.1 跳转目标：leader 单聊（非群聊）

点击引导按钮 → 切 **leader 单聊**（`leader.sessionId`，1 对 1），不再是群聊 squadChat。

- 产品语义：leader 单聊 = 直接对话 leader，**无需 @leader mention**（mention 是群聊圈人的机制，单聊场景语义错位）→ 删除 mention chip 预填。
- 对齐 `06-studio.md §7.2` 单聊页（leader/mate session 直接接 user POST → final text 回复，不经 SquadChat）。

### 3.2 预填提示词：模板填空

切到 leader 单聊后，composer 预填文本 **`帮我搭建一个看板，展示…`**（字面 `...` 作填空标记）。

- 产品语义：模板把「请求结构」搭好，用户只需把 `...` 替换成具体内容（如「帮我搭建一个看板，展示本周各成员任务状态」）即可发送，降低冷启动成本。
- `...` 是用户**可识别的填空标记**（不是省略号语义）——用户看到就知道要替换它。

### 3.3 预填方式：预填待发，不自动发送

预填文本注入 composer 后**不自动发送**——用户补完（删 `...` 填内容）后主动按发送。

- 与现状 @ 预填「预填不发送」语义完全一致——预填是「帮你起头」，不是「替你说话」。
- 用户掌控发送：可在发送前自由编辑模板（删 `...` / 改写 / 加细节 / 全删重写）。

## 6. 非目标（OUT OF SCOPE — 显式不做）

- **不改 panorama schema / kanban / task entity**：只动「更多」tab 的 idle 引导出口，panorama DSL / views / kanban 渲染 / 拖拽 / 归档等全部不动。
- **不改群聊 squadChat 任何行为**：队长卡「群聊」按钮仍进群聊 squadChat（不变）；本版本只换 PanoramaIdle 按钮的出口，不动队长卡操作行。
- **不自动发送、不自动跑 leader**：守「预填待发」语义——用户掌控发送时机（避免「点了一下就发出去了」的失控感 + 避免 leader 在用户没准备好时被调度）。
- **不做引导卡视觉重设计**：守 ui-out-requirements-not-design——卡片视觉骨架（白卡 / 图标 / 标题副标题 / 按钮规范）沿用 v0.0.243 版；本版本是**小行为改动**，无新设计稿需求。
- **不改 leader 单聊页本身的渲染**：单聊页（topbar / message stream / input-bar / InputModelPicker）全部不动；只在进入单聊时 composer 多了预填文本。
- **不新增 AT/ET 持久 case**：守 CLAUDE.md 持久化测试用例库铁律——普通 feature = 冒烟集回归 + UT，不顺手建 case。
