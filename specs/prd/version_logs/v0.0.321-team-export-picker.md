# v0.0.321 — 团队导出选择器（导出时选择团队）PRD

> 引入版本: v0.0.321 | 2026-08-10 | 纯前端（后端零改动）
> 需求来源: reqs/[working] v0.0.321.team-export-picker/req.md（老板 2026-08-10 19:29 反馈 + 19:31 拍板）

## 1. 背景与目标

### 1.1 背景

当前「应用设置 → 团队同步 → 导出团队」按钮：自动取**最近活跃 studio 会话**的 squadId 直接下载 zip，**无法选择导出哪个团队**。多团队场景下用户只能导出最近活跃的那个，无法按需选择。

### 1.2 目标

- 点「导出团队」→ 弹出**简版团队列表**（列出本机全部团队）
- 用户选择一个团队 → 点击「确定」→ 下载该团队的 zip
- 一次导出一个，选哪个导哪个

### 1.3 非目标

- 不改导出 zip 内容结构（已验证：zip 含 manifest + AGENTS.md + .rocky 全套 132 条目，隐藏目录看不见是正常现象）
- 不碰导入流程
- 不新增后端端点（GET /squad/:id/export 已支持任意 squadId）
- 不做多选批量导出

## 2. 功能详细设计

### 2.1 现状与改造点 [v0.0.321]

**现状**（section-team-sync.tsx）：
- 挂载时 `listStudioSessions()` 取最近活跃 studio 会话的 squadId（`squadId` state）
- 点「导出团队」→ `exportSquad(squadId)` → `<a href download>` 下载 zip → flash「导出成功」

**改造**：
- 点「导出团队」→ 弹**团队选择 modal**（`listSquads()` 列全部团队）
- 选中一个团队 → 点「确定」→ `exportSquad(selectedSquadId)` → 下载 + flash
- 取消 / 关闭 modal → 不下载

### 2.2 团队选择弹层（TeamPickerModal）[v0.0.321]

**描述**：简版团队列表弹层，用户从中选一个团队导出。

#### UI 形态
- **modal 标题**：「选择要导出的团队」
- **列表**：垂直滚动列表，每项一行：
  - 团队名（主文案，`SquadSummary.name`）
  - 成员数（次文案 muted，`N 个成员`，来自 `memberCount`）
  - 点击整行 → 选中（高亮 accent 边框/背景，同既有选择控件范式）
- **底部按钮**：「确定」（primary，disabled 当未选中）/「取消」（secondary）
- **默认选中**：最近活跃的团队（`squadId` state 当前值对应的团队）；`listSquads()` 本身按 updatedAt desc 排序 → 列表第一项 = 最近活跃，默认高亮第一项
- **关闭**：× 按钮 / ESC / 点遮罩 / 点「取消」→ 关闭弹层，不下载

#### 状态
| 态 | 表现 |
|----|------|
| 加载中 | 列表区显示 loading（轻量 spinner 或「加载中…」muted 文案），确定 disabled |
| 加载失败 | 显示错误文案「团队列表加载失败」，提供「重试」按钮；确定 disabled |
| 空（无团队） | 显示空态「没有可导出的团队」，确定 disabled |
| 正常 | 列表 + 默认高亮第一项，确定可点 |

#### 交互
1. 点「导出团队」→ 打开 modal → `listSquads()` 拉列表
2. 点某团队行 → 高亮切换选中
3. 点「确定」→ `exportSquad(选中.id)` → 关闭 modal → flash「导出成功：{团队名}」
4. 点「取消」/ × / ESC / 遮罩 → 关闭 modal，不下载

### 2.3 复用与不变量 [v0.0.321]

- **`listSquads()`**（squad-api.ts L61）：GET /squad → `SquadSummary[]`（id/name/description/memberCount/createdAt/updatedAt…）
- **`exportSquad(squadId)`**（team-sync-api.ts L36）：`<a href download>` 触发浏览器下载，不经 fetch
- **后端零改动**：GET /squad/:id/export 已支持任意 squadId
- **保留**：无 studio 会话时「导出团队」按钮 disabled + no_squad_hint 提示（原语义不变——弹层需要先有 squadId 作默认选中；无 squadId 但列表有团队时也可导出，见 §5 边界）

## 3. 数据结构

### 3.1 弹层状态（前端内部）

```ts
interface ExportPickerState {
  open: boolean;
  loading: boolean;          // listSquads 加载中
  error: string | null;      // 加载失败文案
  squads: SquadSummary[];    // 团队列表
  selectedId: string | null; // 当前选中 squadId（默认 = 最近活跃 squadId ?? 列表第一项）
}
```

### 3.2 SquadSummary 消费字段

| 字段 | 用途 |
|------|------|
| `id` | exportSquad 参数 |
| `name` | 列表主文案 |
| `memberCount` | 列表次文案「N 个成员」 |

## 4. 关键用户路径

### UC-1：导出指定团队（主路径）

| 步骤 | 用户操作 | 预期结果 |
|------|----------|----------|
| 1 | 进入 应用设置 → 团队同步 | 右栏显示团队同步页 |
| 2 | 点「导出团队」 | 弹出团队选择 modal，列表列出全部团队，默认高亮最近活跃团队 |
| 3 | 点选另一个团队（如「项目B」） | 高亮切到「项目B」 |
| 4 | 点「确定」 | modal 关闭，`exportSquad(项目B.id)` 触发下载 zip |
| 5 | — | flash「导出成功：项目B」 |

### UC-2：取消导出

| 步骤 | 用户操作 | 预期结果 |
|------|----------|----------|
| 1 | 点「导出团队」 | 弹层打开，列表加载完成 |
| 2 | 点「取消」 | 弹层关闭，**不下载** |
| 3 | （或点 × / ESC / 遮罩） | 同上，不下载 |

### UC-3：默认选中最近活跃团队

| 步骤 | 用户操作 | 预期结果 |
|------|----------|----------|
| 1 | 本机有团队 A（最近活跃）、B、C | — |
| 2 | 点「导出团队」 | 弹层列出 A/B/C，**A 默认高亮**（最近活跃 = 当前 squadId state） |
| 3 | 直接点「确定」 | 导出 A（无需手动选择） |

### UC-4：弹层加载失败

| 步骤 | 用户操作 | 预期结果 |
|------|----------|----------|
| 1 | 点「导出团队」 | 弹层打开，listSquads 失败 |
| 2 | — | 显示「团队列表加载失败」+ 重试按钮，确定 disabled |
| 3 | 点「重试」 | 重新 listSquads；成功 → 正常列表 |

### UC-5：无团队可导出

| 步骤 | 用户操作 | 预期结果 |
|------|----------|----------|
| 1 | 本机无任何 squad | — |
| 2 | 点「导出团队」 | 弹层打开，显示空态「没有可导出的团队」，确定 disabled |
| 3 | 点「取消」 | 弹层关闭 |

## 5. 边界与异常

| 场景 | 处理 |
|------|------|
| 无任何团队（listSquads 返回空数组） | 弹层显示空态，确定 disabled，用户只能取消 |
| 仅 1 个团队 | **仍弹层**，默认高亮该团队，点确定导出（老板要的是「可选择」，保持交互一致，不因数量跳过） |
| listSquads 加载失败 | 弹层内错误态 + 重试按钮；确定 disabled |
| 无 studio 会话（squadId state 为空）但 listSquads 有团队 | 弹层仍可打开，默认选中列表第一项（按 updatedAt desc = 最近活跃），可正常导出 |
| 无 studio 会话且 listSquads 空 | 「导出团队」按钮 disabled + no_squad_hint（原语义保留） |
| 确定时选中项被删（竞态） | exportSquad 触发下载失败 → flash 错误提示（浏览器下载失败）；不崩溃 |
| 导出期间重复点确定 | busy 防重（导出按钮/确定按钮 busy disabled） |
| 列表过长 | modal 内垂直滚动（max-h 限制，如 60vh） |
| 团队名过长 | 单行 ellipsis（布局稳定，不换行撑破） |
