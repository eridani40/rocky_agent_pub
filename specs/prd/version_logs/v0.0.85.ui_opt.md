## 1. 背景与目标

5 个独立需求合并发版（用户一次性提），共享一次 worktree + 验证周期。需求间相互独立、无依赖，可并行实现；共享的概念权威源是 chat-page / studio-page 的 ui spec 与 squad / session 的 tech spec。

**目标**（每项一句话）：
1. **分页**：长会话（>50 条）打开后能向上滚动续载历史，且续载时滚动位置不跳。
2. **文件 watch 稳定**：所有 chat 类型（含 squad 群聊）打开 session 时按需启动 chokidar watcher，切目录/关 session 时取消，新建子目录事件不丢。
3. **转发 3 段格式**：SquadChat 把 user 消息转发给 member 时，content 含「说明 / 原文 / 相关上下文」3 段结构化模板，消除现存两处矛盾 prompt。
4. **Studio 红点**：member/squad session 有新消息完成时，studio sidebar 该 session 节点出现红点；打开后消除。复用 playground unread 机制。
5. **Squad UI 尺寸**：studio sidebar 看板/群聊/单聊 item 的 padding/字号/首字母头像对齐 playground conv-item；subagent 保持小尺寸对齐 playground subagent-tree。

**跨需求决策**（沿用调研 D1-D7，本 PRD 不重新讨论）：
- D1：无 HTTP API 契约变更 → 不新增 AT case（API 不需要测的就别测）。
- D2：需求 3 转发格式是 prompt/LLM 行为变更 → real-LLM 验证（mock 无法验证 LLM 行为）。
- D3：验证以 E2E 为主；无设计稿 → 视觉 compare 参照 = 现有 playground 截图。
- D4：需求 2 文件 watch E2E 易 flaky → UT 为主（chokidar lifecycle/await ready/addDir）+ E2E 1 个冒烟。
- D5：needReply 默认 true（对齐 a2a §4.2 缺省）。
- D6：群聊名取 `squad.name`（squad entity 字段，语义最稳）。
- D7：单端 electron，红点布尔不计数（沿用 v0.0.27）。

**非目标（OUT OF SCOPE，明确不做）**：
- **subagent 派生**（studio sidebar 本版不派生 subagent，沿用 `studio-sidebar.md` 既有声明）。
- **member-card 卡片样式不改**（卡片非列表行；视觉调整限于 sidebar 树节点）。
- **squad 群聊名取 squad.name 不取 title**（D6；不引入「群聊 title」独立字段）。
- **needReply 计数 / 多端同步**（沿用 v0.0.27 OUT OF SCOPE）。
- **新增 HTTP 端点 / schema 字段**（D1；后端已就绪）。
- **看板节点加红点**（看板节点无 sessionId，本版不挂红点；仅 session 节点）。
- **MemberAvatar sm 档 squad 渐变底以外的扩展**（不扩 lg/md 档；不动 conv-item playground 红点视觉）。

## 2. 功能需求（5 项分述）

### 2.1 F1 — Session 消息向上滚动分页（初始 50 + 滚动续载 + 保持滚动位置）

**现状**（调研 §1）：
- 后端 `GET /session/:id/messages` 已支持 `limit`（默认 50，[1,200]）+ `beforeId`（ULID 字典序之前 limit 条）+ 响应 `{items, hasMore}`（`specs/api/overall/04-agent-session.md §3.1`）。
- 前端数据通路就绪：`use-session-run-state.ts` 已有 `hasMoreRef` + `setMessages(msgs,{hasMore,prepend})` 经 `merge-messages-by-id` 前插去重；`page-chat.tsx` 已有 `loadMore()` 用 `messages[0].id` 作 beforeId。
- **缺口**：UI 无滚动监听触发——`component-message-stream.tsx` scrollRef 仅用于滚底，无 `onScroll`；`hasMore`/`loadMore` 未透传到 `ComponentMessageStream`；现仅 `sr-only` `<button data-testid="chat-load-more">`（不可见、无点击触发）。
- subagent 只读页（`use-subagent-run-refresh.ts`）同款缺口。

**目标行为**：
1. 打开 session：GET /messages（无 beforeId）拿最近 50 条 + `hasMore` 标志。
2. 用户上滑至接近顶部（threshold，coder 定，约 100-200px）且 `hasMore && !loading` → 触发 `loadMore()`：用 `messages[0].id` 作 beforeId 拉前 50 条，**前插**渲染（已由 `merge-messages-by-id` 去重）。
3. **前插后保持滚动位置（MANDATORY）**：prepend 前记 `prevHeight = scrollHeight - scrollTop`；prepend 后 effect 设 `scrollTop = scrollHeight - prevHeight`，使视觉上原顶部条目保持在原位（不跳到新加载的旧消息顶）。
4. **跳过自动滚底 effect**：loadMore 期间必须跳过现有「rows 变化→自动滚底」effect（加 `isLoadingMore` ref 标记），否则前插触发滚底会跳到顶（视觉灾难）。
5. `hasMore=false` 后停止触发；loading 期间防重入。
6. 兼容 SSE 增量 + transcript + loadMore 三路按 messageId 合并（v0.0.81 已就绪，本版不动）。

**Invariants**（不可破）：
- 消息按 createdAt 升序；messageId=服务端 ULID（字典序=时间序，分页正确性根基）。
- 自动滚底只在「新消息/run 状态变化」触发；loadMore 前插**不能**触发滚底。

**验收标准**：
- 打开 >50 条消息的 session：dom 中只渲染最近 50 条（performance 改善）。
- 上滑到 threshold：触发 loadMore，旧消息前插渲染。
- 视觉上滚动位置不跳（原顶部条目仍在视口可见位置）。
- 持续上滑可一直续载到 hasMore=false。
- 鼠标停留在新加载的旧消息上不会自动滚到底。

### 2.2 F2 — 文件 tab 目录监听稳定（subscribe/unsubscribe 三时机 + chokidar ready/addDir）

**现状**（调研 §2）：
- 后端机制完整：chokidar + SSE 推送，lazy per-session 启动；`bootstrap.ts` 已绑 `sseChannel.setSubscribeHooks`（0→1 subscribe → startWatch、1→0 unsubscribe → stopWatch）。
- **根因 1**：squad 群聊 session 完全不订阅 `session_panel` → lazy hook 不触发 → watcher 永不启动（仅 mount 时 GET tree 一次）。
- **根因 2-3**：`SessionWorkspaceManager.startWatch` 不 await chokidar 'ready'、无 `addDir → watcher.add()`（squad_filewatch BUG-005/006 已修同款问题，UI watcher 没同步）。
- **根因 4**：bootstrap hook `void startWatch/stopWatch` fire-and-forget → 快速切 tab 时序竞争残留/漏启。

**目标行为**（三时机）：
1. **session 打开 → subscribe**：所有 chat 类型（playground rocky / studio leader / mate / squad 群聊 / subagent 只读）打开时**都订阅** `session_panel`（topic=`session_id:<sid>`），触发 lazy watcher 启动。最干净方案：把订阅上提到 `SectionWorkspacePanel`（与 chat 类型解耦，所有 ws-panel 共享）。
2. **切目录 → unsubscribe 旧 + resubscribe 新**：用户在 ws-panel 切换 monitored 目录时，前端 unsubscribe 旧 group + subscribe 新 group，触发后端 stopWatch(旧) + startWatch(新)。
3. **关闭 session / 切到别的 session → unsubscribe**：原 session 的 session_panel 订阅清掉，触发 stopWatch 释放 chokidar fd。

**后端修复**（对齐 squad_filewatch BUG-005/006 模式）：
- `SessionWorkspaceManager.startWatch` 改 await chokidar 'ready'（5s 超时兜底防 hang）。
- `startWatch` 加 `watcher.on('addDir', abs => watcher.add(abs))`，对新子目录强制纳入监听（chokidar4 `add()` 同步非 Promise，禁 `.catch()`）。
- `bootstrap.ts` setSubscribeHooks 改 async + await startWatch/stopWatch（消除 fire-and-forget 竞争）。

**验收标准**：
- UT：`startWatch` 内 chokidar 实例发 'ready' 后才 resolve（5s 超时兜底）；`addDir` 触发 `watcher.add(absDir)` 被调用；`stopWatch` 调 `watcher.close()` + 清 timer。
- UT：subscribe/unsubscribe 三时机正确触发 hook（mock sseChannel 计数）。
- E2E 冒烟：打开 playground session 的 ws-panel → 在 monitored 目录 `touch newfile` → 近实时（≤2s）UI 文件树出现新文件。
- E2E 冒烟：切目录 → 旧目录 touch 不再触发刷新、新目录 touch 触发刷新；关闭 session → watcher.stop 被调（资源释放）。
- 回归：squad 群聊打开 ws-panel → 同样能感知文件变化（修复根因 1）。

### 2.3 F3 — SquadChat 转发 3 段格式（说明 / 原文 / 相关上下文 + 消除 prompt 矛盾）

**现状**（调研 §3）：
- A 路 prompt（`prompts/content/squad/squad_chat.md:11`，mapper 注入 system）：「原文一字不差 + 上下文转述，needReply=true」。
- B 路 prompt（`handlers/session-config.ts:55-56,237-240` 硬编码 `STUDIO_SQUAD_ROUTER_SYSTEM_PROMPT` 当 systemPrompt）：「原样转发，needReply=false」。
- 两路都活、矛盾 → 行为不稳定。接收方看到的形态（`logical-view.ts:39-43`）：`[Message from SquadChat (squad, needReply=<bool>)]: <content blob>`，无结构信号。

**目标行为**（纯 prompt + 配置统一，**不动 a2a 消息契约**）：
1. **3 段模板**（SquadChat 转发给 member 的 content text blocks）：
   - **`### 说明`**：这是一条来自群聊 `{squad.name}` 的转发，由群聊 router（SquadChat）向你转发；请根据 needReply 参数决定是否回复；如果需要回复，必须回复给来源 session（即群聊）。
   - **`### 原文`**：本条消息在群聊中来自 `{sender}`（user 时显「user」，否则显「`{name}` (`{sid}`)」），对话原始内容为：`{原始 query 文本}`。
   - **`### 相关上下文`**：群聊中相关上下文包括：`{上下文}`。注意：无就是无；有可概括/改写以便收信人理解。
2. **消除矛盾**：删/清空 `session-config.ts` 中 `STUDIO_SQUAD_ROUTER_SYSTEM_PROMPT` 硬编码（由 squad_role mapper 统一出 prompt，对齐 leader/mate 的 prompt 构建链路）。
3. **needReply 默认 true**（D5）：保留 needReply 参数化，send_message 入参缺失时 normalize 为 true（对齐 a2a §4.2 缺省）。
4. **leader.md / mate.md 补一行**：收到 SquadChat 转发按「说明」段决定回复；回复走 `send_message(to=SquadChat)` 即回群聊。

**数据来源**（不改 a2a 消息体，纯 prompt 内文本组装）：
- 群聊名 = `squad.name`（D6）。
- router 名 = "SquadChat" 固定。
- needReply = send_message 入参（默认 true）。
- 来源 session = `sender.agent.ref.sessionId`（a2a 已 enrich）。
- 「原文 sender」字段：user → "user"；mate/leader → `name + sid`（SquadChat 从 transcript 解析，先轻方案，不代码注入）。
- 「相关上下文」= SquadChat 自己从 transcript 概括（轻方案，LLM 行为，不代码注入）。

**Invariants**（不可破）：
- 转发仍是 `send_message` 的 content text blocks（**不扩** a2a §5 消息体结构）。
- sender 永远是 SquadChat 自己（reply 走 `to=sender.agent.ref` 必回群聊；不能改成 sender=原 user）。
- needReply 是顶层字段，不进 content。
- 接收方前缀渲染（`[Message from SquadChat (squad, needReply=...)]:`）不变。
- squad_chat 红线不变：**不改写 user 原文、不创作 answer**。

**验收标准**（real-LLM，D2）：
- 触发群聊 user → router 转发给 member → member 收到的 message.content 含 3 段（说明/原文/相关上下文，可 vision_check 段标题或文本断言）。
- needReply=true 时 member 在群聊有回复（落群聊 transcript）；needReply=false 时 member 不回复。
- `grep STUDIO_SQUAD_ROUTER_SYSTEM_PROMPT` 在 `session-config.ts` 0 残留。
- 群聊名展示 = `squad.name`（不取 title，D6）。
- 历史回归：a2a 消息结构（sender.source='agent' + sender.agent.ref.type∈{leader,mate}）不变。

### 2.4 F4 — Studio 红点（subscribe session_meta biz=studio + 渲染 + markRead）

**现状**（调研 §4）：
- Playground 红点机制完整（v0.0.27）：`Session.unread: boolean` 显式字段；后端 SessionUnreadOps 订阅 session completion + `isSessionActive` → CAS `unread:false→true` → `SessionMetaBroadcaster.broadcast` → emit `session_meta_update`(含 unread) 到 `(session_meta,_all)`。
- 前端 playground：`chat-slice.ts:120-137` reducer 入口守卫 `if(incoming.biz==='studio') return` 拒纳 studio；进会话 markSessionRead；conv-item `unread && !active` 渲染 `7×7 bg-[#DC2626]` 红点。
- **关键**：后端 `SessionMetaBroadcaster` 已在广播 studio session 的 unread meta（`session-meta-broadcaster.ts:87` 带 `biz:'studio'`），**只是 studio 前端无人订阅**。
- Studio 现状：零红点、零 `session_meta` 订阅、`page-studio.tsx:272` onOpenChat 无 markRead。

**目标行为**（纯前端）：
1. **studio 侧新建订阅**：page-studio 挂载时 `subscribe("session_meta", "_all", onMeta)` **一次**（共享广播，与 playground 同机制）。reducer 反向守卫：**只收 biz==='studio'**，丢弃 playground（避免双视图互相污染列表）。
2. **studio sidebar 渲染红点**：`component-squad-tree.tsx` 的 TreeChild（群聊/leader/mate session 节点）接 `unread: boolean` prop + 红点 DOM（仿 playground：`absolute top-2 right-2 w-[7px] h-[7px] rounded-full bg-[#DC2626]`，条件 `unread && !active`，testid `squad-tree-session-{sid}-unread-dot`）。
3. **打开 session 消除红点**：`page-studio.tsx` `onOpenChat(node)` 加 `markSessionRead(node.sessionId)`（POST /session/:id/read，CAS `unread:true→false` → session_meta 广播 unread=false → reducer 整条替换 → 红点消失）。
4. **看板节点不加红点**（看板无 sessionId，本版排除）。
5. 红点颜色 `#DC2626`（danger，对齐 playground，沿用 v0.0.27 决策）。

**Invariants**：
- 后端 unread CAS 路径不动（产生=session 层订阅 completion + isSessionActive + CAS true；消除=POST /read CAS false）。
- studio 与 playground reducer 互不串扰（biz 守卫双向）。
- 红点显示/消失完全由 `unread` prop 驱动（GET /session + session_meta SSE 实时刷）。

**验收标准**：
- studio member session 触发 run → 切回 playground → run 完成（markIdle emit）→ studio sidebar 该 session 节点出现红点（dom `squad-tree-session-{sid}-unread-dot` 存在）。
- 点击该 session 节点 → 红点消失（dom 不存在）。
- 看板节点无红点（`squad-tree-board-{squadId}-unread-dot` 不存在）。
- playground 列表不被 studio session meta 污染（双向守卫）。

## 3. 关键用户路径（MANDATORY — 测试最低覆盖）

> 5 条路径，每条至少 1 个 case（AT/ET/UT 类型按需求性质定）。无设计稿 → 视觉保真度 compare 用 playground 截图作 design 参考（D3）。

| 路径 ID | 路径名 | 用户操作链路 | 预期结果 | 覆盖类型 |
|---|---|---|---|---|
| **A** | 分页续载 | 打开 >50 条消息的 session（playground / squad 单聊）→ dom 渲染最近 50 条 → 上滑到接近顶（threshold）→ 旧消息前插加载 → 滚动位置不跳（原顶部条目仍在视口）→ 持续上滑到 hasMore=false | 用户能流畅翻历史，无视觉跳动 | ET（dom + vision）+ UT（loadMore state 机） |
| **B** | 文件 watch | 打开 session 的文件 tab（任一 chat 类型含 squad 群聊）→ 在 monitored 目录新建文件 → UI 近实时（≤2s）看到新文件；切目录 → 旧目录不再推送、新目录开始推送；关闭 session → watcher 停止（资源释放） | 文件变化稳定感知；切目录/关 session 不残留 watcher | UT（chokidar lifecycle 主）+ ET（1 个冒烟，F2 D4） |
| **C** | 转发格式 | 群聊 user 发消息触发 router 转发给 member → member 收到的 message.content 含 3 段（说明/原文/相关上下文）→ needReply=true 时 member 回复落在群聊 session；needReply=false 时 member 不回复；群聊名显 squad.name | 转发内容结构化、可读、消除 prompt 矛盾；needReply 语义统一 | ET（real-LLM，D2）+ UT（prompt 模板） |
| **D** | 红点 | studio sidebar 看 member/squad session → 该 session 有新消息完成（markIdle emit + isSessionActive=false → CAS unread=true）→ sidebar 该 session 节点出现红点（`squad-tree-session-{sid}-unread-dot`）→ 点击该节点 → 红点消除；看板节点无红点 | studio 用户能看到未读、点开即清；不污染 playground 列表 | ET（dom + vision）+ UT（reducer biz 守卫） |
| **E** | 视觉对齐 | studio sidebar 看板/群聊/单聊 item 与 playground conv-item 视觉基线一致（padding/字号/首字母头像）；vision_check compare 4 维度（layout/font/border/color）基本一致；subagent 派生时复用 playground subagent-tree 小尺寸 | studio sidebar 不再「视觉风格迥异于 playground」 | ET（vision_check compare vs playground 截图） |

**E2E Use Cases 汇总**（每条路径完整用户链路 + 断言落用户价值）：

| ID | 路径 | 用户操作链路 | 预期结果 |
|----|------|-------------|---------|
| UC-A-1 | 分页 | 打开 >50 条 rocky session → 看到最近 50 条（dom 计数=50）→ 上滑 → 旧消息前插 → 用户视觉无跳动 → 持续滑到 hasMore=false | 长会话历史可翻、视觉稳定 |
| UC-B-1 | 文件 watch | squad 群聊打开 ws-panel（修复根因 1）→ 在 monitored 目录 touch 新文件 → ≤2s UI 文件树出现 | squad 群聊也能感知文件 |
| UC-B-2 | 文件 watch | playground ws-panel → 切目录 → 旧目录 touch 不推送、新目录 touch 推送 → 关 session → watcher.stop 被调 | 三时机正确 |
| UC-C-1 | 转发格式 | 群聊 user 「帮我看下 outputs/x.md」→ leader/member 收到含「### 说明 / ### 原文 / ### 相关上下文」3 段 → needReply=true → member 在群聊回复 | 转发结构化、语义清晰 |
| UC-D-1 | 红点 | member session 触发 run → 用户在 playground → run 完成 → studio sidebar 该 member 节点出现红点 → 点击 → 红点消失 | studio 未读感知 + markRead |
| UC-D-2 | 红点 | 看板节点（`squad-tree-board-{squadId}`）永不出现红点 | 看板节点排除（无 sessionId） |
| UC-E-1 | 视觉对齐 | 截图 studio sidebar + 截图 playground conv-panel → vision_check compare 4 维度 → 整体风格基本一致 | 视觉对齐 playground |
