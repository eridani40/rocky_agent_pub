# v0.0.320 — 文件预览区（三栏布局 + 多 tab 预览 + 编辑 + 冲突检测）PRD

> 引入版本: v0.0.320 | 2026-08-10 | 纯前端大活 + 少量后端（搜索端点 + 文件版本标记）

## 1. 背景与目标

### 1.1 背景

当前文件查看/编辑依赖 `component-modal-md-editor` 弹层（modal），存在两个问题：
- 弹层每次只能看一个文件，多文件对比/切换体验差
- 文件树打开文件是弹层，与聊天区链接打开弹层是两套挂载，交互割裂

老板拍板：新增**文件预览区**（独立中间栏），chat 链接 + 工作区点文件都进预览区开 tab，弹层退役（chat 场景），并扩展编程语言文件支持 + 文件搜索 + 编辑冲突检测。

### 1.2 目标

- **三栏布局**：chat | 文件预览 | 工作区（新增独立中间栏，**动态显隐 + 双分隔条拖拽 + 大范围可调**）
- **预览区独立存在**：独立渲染容器 / 独立状态 / 独立收起展开，chat 链接 + 工作区文件点击都是「打开到预览区」的入口
- **多 tab 预览**：预览区上方多 tab 切换，tab 区可横滑 + 左右按钮
- **文件类型扩展**：12 格式基础上支持所有常见编程语言后缀（纯文本 view，无语法高亮）
- **workspace tab item 逻辑改造**：文件点击即打开（内置 viewer 或系统），文件夹点击展开/收起，保留「打开文件夹」hover 按钮
- **工作区搜索框**：文件树上方搜索，前端过滤 + 后端补全量（防抖）
- **viewer 编辑模式**：edit 按钮进编辑态，dirty 守卫（保存/取消才能切文件）
- **冲突检测**（VSCode 参考）：编辑态检测文件被外部改动，提示取消（重新加载）或覆盖（强制写入）

### 1.3 非目标

- 不做语法高亮/代码智能（纯文本 view）
- 不做 image 预览区化（image 6 格式保持既有 WsImageViewer 弹层）
- 不做 absolute IPC 源冲突检测（v1 仅 workspace HTTP 源；absolute 保持 last-write-wins）
- 不做编辑器分栏/多光标等 IDE 能力

### 1.4 布局核心原则（老板拍板 MANDATORY）[v0.0.320]

文件预览区必须**独立于 chat 区域和右侧功能区（工作区）**——它是三栏布局里的**独立中间栏**，不隶属 chat、不挂在工作区内部：

1. **独立渲染容器**：预览区是独立组件（非 chat 区/工作区的子模块），在 chat-page 布局中单独挂载
2. **独立状态**：tab 列表、当前选中 tab、dirty 守卫、编辑态均为预览区自己的状态，**不与 chat/工作区共享**
3. **独立可收起/可拖宽**：预览区有自己的显示/隐藏控制 + 宽度拖拽（参考现有 workspace panel 的收起/拖宽交互）
4. **独立存在**：chat 链接、工作区文件点击都是「打开到预览区」的入口；预览区本身独立存在——即使 chat/工作区收起也不受影响

## 2. 功能详细设计

### 2.1 三栏布局 [v0.0.320]

**chat-page 布局改为三栏**：`chat-detail（flex-1）| 文件预览区（新栏）| ws-panel（工作区）`

- **文件预览区**：`SectionChatSession` 之后、`SectionWorkspacePanel` 之前插入（独立中间栏，独立挂载）
- **高度**：header/tab 区高度与 ws-panel header 对齐（同高 tab bar，视觉同一行基线）
- **空态**：无任何 tab 时显示占位（「打开文件以预览」muted 文案），栏仍占位（布局稳定，不随 tab 数量位移）
- **挂载场景**：chat-page（playground + studio 单聊/群聊）。academy / studio section-right-tabs 复用 SectionWorkspacePanel 但无预览区 Provider → 打开文件降级既有弹层（兼容，非死代码）

#### 三栏动态布局（老板拍板 MANDATORY）[v0.0.320]

**1. 预览区可 toggle 出现/消失**：
- 预览区 header 有独立显示/隐藏控制（参考 workspace panel 的收起交互——chevron 按钮 + 收起窄栏/完全隐藏）
- 收起后预览区隐藏，chat 和工作区自动扩展回收；展开后 chat 和工作区自动压缩让位（**两侧宽度随预览区显隐联动调整**，非固定 flex 死区）

**2. 三栏之间双分隔条拖拽**：
- **chat | 文件预览** 之间 1 条拖拽分隔条（`.pv-resize-left`）
- **文件预览 | 工作区** 之间 1 条拖拽分隔条（`.pv-resize-right`，复用 workspace panel 既有 `.ws-resize` 模式）
- 每条分隔条独立拖拽，三栏宽度均可独立调整
- 复用 `component-col-resize-handle` 通用拖拽手柄（delta 算法，无死区——mousedown 捕获 startRef，mousemove 算 dx，clamp 后 onResize）

**3. 可调范围大**：
- 每栏宽度可在大范围内变化：**很窄（最小可用）→ 很宽（接近全屏）**
- chat 区：clamp [最小可用 320px, 接近全屏]
- 预览区：clamp [最小可用 240px, 接近全屏]（展开时）
- 工作区：clamp [232px, 接近全屏]（沿用既有 ws-panel 宽度范围扩展上限）
- 任意栏拖到极限时其他栏压缩到各自最小可用；不强制保留固定比例
- 宽度 + 收起态 localStorage per session 持久化（`pv-width-<sid>` + `pv-collapsed-<sid>`，对齐 ws 既有 `ws-width-<sid>` 模式）

### 2.2 预览区多 tab [v0.0.320]

**描述**：预览区上方 tab 区，多个文件可同时打开切换。

#### 交互
- **打开文件**（chat 链接点击 / workspace 文件树点击）→ 预览区开 tab：同 path 已存在 → 激活该 tab；不存在 → 新建 tab 并激活
- **tab 切换**：点击 tab → 激活；dirty 守卫见 §2.6
- **tab 关闭**（每个 tab 卡片右侧有 × 关闭按钮，与其他 tab 文件卡一致）：
  - 点击 × → 关闭对应文件 tab
  - **dirty 守卫**：该 tab 处于编辑态且有未保存改动（dirty）→ 走 dirty 守卫（提示 保存/取消/放弃，不能直接丢）
  - **焦点切换**：关闭的是当前激活 tab → 焦点切换到相邻 tab（**左优先**，同 VS Code 习惯）；无相邻（仅剩一个）→ 空态
  - **最后一个 tab 关闭** → 预览区显示空态占位（预览区本身还在，不自动消失）
- **tab 区横滑**：tab 超出容器宽度时可横向滑动；**左右按钮**（chevron）在「有剩余内容时」显示（点击滚动一屏），无剩余内容隐藏（`opacity/visibility` 切换，不位移）
- **tab 结构**：`fileName` 短名（basename）+ 关闭 ×；active 高亮；dirty tab 显示 ● 圆点标记（未保存提示）

### 2.3 文件类型扩展 [v0.0.320]

**描述**：`file-format.ts` 的 12 格式基础上，新增编程语言后缀支持。

#### 设计
- `FileFormat` union 新增 **`'code'`** 值（编程语言统一归类，不逐一枚举——viewer 不需要语言名）
- `EXT_TO_FORMAT` 映射表并入编程语言后缀（全映射 `'code'`）：

| 分类 | 后缀 |
|------|------|
| 既有 12 格式 | md + json/jsonl/yaml/xml/toml/csv/tsv + txt/ini/env/log（不变） |
| **新增 code** | py/js/ts/jsx/tsx/java/go/rs/c/cpp/h/hpp/cs/rb/php/swift/kt/sh + 常见其他（vue/svelte/dart/lua/r/pl/scala/groovy/zig/erl/ex/hs/clj/md 已有）……「能想到的都加」，全部映射 `'code'` |

- `getCategory('code')` → **`'code'` 分类**（新分类，行为 = plain：`<pre>` 朴素渲染，无高亮无行号；edit 模式同 textarea，无「格式化/校验」按钮）
- `getFileFormat` 算法不变（扩展名查表 → `'code'`）；`.env` 特殊处理保留
- **效果**：`getFileFormat(path) !== null` 命中范围扩大 → 编程语言文件从「系统打开」改走内置 viewer（openLocalPath 分支 ④ 自动覆盖）

### 2.4 workspace tab item 逻辑改造 [v0.0.320]

**描述**：文件树节点点击行为重定义。

| 节点 | 当前行为（v0.0.280） | 新行为 |
|------|---------------------|--------|
| 文件夹 item（名字/图标区） | openWorkspaceItem(kind=folder) 系统打开 | **展开/收起**（toggle expanded，同 twisty 语义） |
| 文件夹 twisty | 展开/收起 | 不变（与 item 点击等价，双入口同一 toggle） |
| 文件夹 hover「打开文件夹」按钮（`.ws-act`） | 系统文件管理器打开 | **保留**（hover 显示，openWorkspaceItem kind=folder） |
| 文件 item | openLocalPath 五路分流（onEditor → 弹层） | openLocalPath 五路分流不变，**消费端改**：onEditor → 预览区开 tab（不再弹层） |
| 文件 hover「打开」按钮 | 同 item 点击 | 不变（同 item 点击） |

- 文件夹 item 点击与 twisty 点击合并为同一 toggle 处理（防双发）；「打开文件夹」按钮点击 `stopPropagation`（不触发展开）

### 2.5 工作区搜索框 [v0.0.320]

**描述**：文件树上方新增搜索框，混合实现（前端过滤已加载树 + 后端补全量搜索，防抖）。

#### 交互
- **空输入**：展示所有内容（恢复原文件树）
- **输入关键词**（防抖 300ms）：
  - **前端过滤**：已加载树（tree + childrenCache）中文件名匹配（大小写不敏感 substring）→ 显示匹配文件全路径
  - **后端补全**：GET 新端点全量递归搜索 → 匹配**文件名**的全路径 + 匹配**文件夹名**的全路径（其下层内容前端一并展示）
  - 结果合并渲染（前端结果 + 后端结果，去重）
- **结果项点击**：文件 → 预览区开 tab；文件夹 → 展开/收起（同 §2.4）
- **清空搜索**：× 按钮或删空输入 → 恢复原树

#### 后端新端点
`GET /session/:id/workspace/search?q=<keyword>`（递归全量，ignore node_modules/.git，白名单校验同 tree）

```jsonc
// 200
{
  "files": ["src/app.ts", "src/utils/helper.ts"],   // 文件名匹配的全路径
  "dirs":  ["src/components"]                        // 文件夹名匹配的全路径
}
```

- 空 q → 400 或空结果（前端防抖保证非空才发）
- 返回上限（如 200 条，超限截断提示）

### 2.6 viewer 编辑模式 + dirty 守卫 [v0.0.320]

**描述**：预览区文件默认只读 view，edit 按钮进编辑模式；未保存改动阻止切换。

#### 状态机
```
view ──点 edit──▶ edit(draft=content, dirty=false)
edit ──输入改动──▶ edit(dirty=true)
edit(dirty=false) ──切 tab/关 tab──▶ 直接放行
edit(dirty=true) ──切 tab/关 tab──▶ 弹确认 modal：保存并切换 / 放弃修改 / 取消
edit ──保存成功──▶ view(dirty=false, content=draft)
edit ──保存失败──▶ 留在 edit，显示错误（textarea 保留供重试）
```

- **保存**：POST save（带 expectedVersion，冲突见 §2.7）→ 成功 toast「已保存」+ 切回 view
- **不点保存不落盘**：程序挂了丢（无 autosave）
- 保存成功后 tab 版本标记更新为返回的新 version

### 2.7 冲突检测 [v0.0.320]（VSCode 参考，后端配合）

**描述**：编辑/保存时检测文件是否被外部（他人/agent）改动。

#### 协议（workspace HTTP 源）
- **读**：`GET /session/:id/workspace/file` 响应新增 `version` 字段（`mtimeMs + size` 组合或内容 hash）
- **存**：`POST /session/:id/workspace/file/save` body 新增 `expectedVersion`（可选）+ `force`（可选）
  - `expectedVersion` 匹配当前文件 → 200 保存成功，返回新 `version`
  - **不匹配** → `409 { error: 'conflict', currentVersion }` → 前端弹冲突提示
  - `force: true`（或无 expectedVersion，向后兼容旧调用方）→ 强制覆盖 last-write-wins（现行为）

#### 前端冲突提示（modal）
- **查看时**：进入 edit 前后端无感知；**编辑态检测** = 保存时校验（简单可靠）。附加：edit 模式挂载时可选主动 re-check（读一次对比 version，发现外部改动 → 提示「文件已被外部修改」）
- **保存冲突弹窗** 两选项：
  - **取消**：放弃本地修改 → 重新加载最新内容（GET 拉新 content + version）→ 回 view
  - **覆盖**：强制写入（带 force 重发）→ 覆盖外部改动 → 成功回 view

#### 边界
- **absolute IPC 源**（Electron shell readFileText/writeFileText）：v1 不做冲突检测，保持 last-write-wins（IPC 层不动）
- **image**：不进预览区，无编辑无冲突

## 3. 数据结构

### 3.1 预览区 tab

```ts
interface PreviewTab {
  id: string;                    // `${source}:${path}` 唯一
  path: string;                  // workspace 相对 / absolute 原样
  fileName: string;              // basename（tab 标题）
  subtitle: string;              // 全路径（tab tooltip / 编辑副标题）
  source: 'workspace' | 'absolute';
  format: FileFormat;            // 12 格式 + 'code'
  version: string;               // 后端返回版本标记（absolute 源为空串）
  mode: 'view' | 'edit';
  dirty: boolean;
  content: string;               // 已加载内容
  draft: string;                 // 编辑草稿（dirty 才有意义）
}
```

### 3.2 dirty 守卫确认 modal

```
「文件「{fileName}」有未保存的修改」
[保存并切换] [放弃修改] [取消]
```

### 3.3 冲突检测 API 变更（后端）

| 端点 | 变更 |
|------|------|
| `GET /session/:id/workspace/file` | 响应加 `version: string`（mtimeMs+size 组合，如 `"1750000000000:1234"`） |
| `POST /session/:id/workspace/file/save` | body 加 `expectedVersion?: string` + `force?: boolean`；版本不匹配且非 force → `409 {error:'conflict', currentVersion}`；成功返回 `{ ok:true, version }` |
| `GET /session/:id/workspace/search?q=` | 新增；返回 `{ files: string[], dirs: string[] }`；ignore node_modules/.git；上限 200 条 |

**后端边界**：仅这 3 处。其余（tree/watch/read binary/open）零改。

|------|----------|----------|
| 1 | 预览区 header 点显示/隐藏控制（chevron） | 预览区收起/隐藏，chat + 工作区自动扩展回收 |
| 2 | 再点展开控制 | 预览区恢复，chat + 工作区自动压缩让位 |
| 3 | 拖 chat|预览 分隔条 | chat 变宽 / 预览区变窄（反向亦然），互不越界 |

| 5 | 拖某栏到极限（很窄） | 其他栏压缩到各自最小可用，不强制固定比例 |

### UC-9：tab 关闭 + 焦点切换

| 步骤 | 用户操作 | 预期结果 |
|------|----------|----------|
| 1 | 打开 tab A（激活）、B、C（tab 序 A-B-C） | — |
| 2 | 点 C 的 × | 关闭 C，焦点切到 B（左优先） |
| 3 | 点 B 的 × | 关闭 B，焦点切到 A |
| 4 | 编辑 A（dirty）→ 点 A 的 × | 弹 dirty 守卫（保存/放弃/取消），不直接丢 |
| 5 | 点「放弃修改」 | A 关闭，预览区空态占位（预览区本身还在） |

## 5. 边界与异常

### 5.1 文件读取失败

| 场景 | 处理 |
|------|------|
| 文件被删 / 路径不存在 | tab 显示错误 pill「文件未找到」，不崩溃 |
| 读取超时 / 网络错误 | 错误 pill「打开失败」，tab 保留可重试 |

### 5.2 保存失败

| 场景 | 处理 |
|------|------|
| 保存网络错误 | 留在 edit 模式，显示错误，textarea 保留供重试 |
| 保存 409 冲突 | 弹冲突 modal（取消/覆盖，见 UC-5） |
| 保存 404（文件被外部删除） | 提示「文件已不存在」，提供 [重新加载] / [关闭 tab] |

### 5.3 冲突检测边界

| 场景 | 处理 |
|------|------|
| absolute IPC 源编辑 | 不做冲突检测（last-write-wins，v1 边界） |
| force 覆盖时文件被再次外部改动 | 最后一次写入胜（last-write-wins 语义） |
| version 格式不兼容（旧后端） | 缺 version 字段 → 前端跳过冲突检测（降级 last-write-wins） |

### 5.4 搜索边界

| 场景 | 处理 |
|------|------|
| 搜索词为空 | 不请求后端，展示原树 |
| 结果超 200 条 | 截断 + 提示「结果过多，请细化关键词」 |
| 搜索期间文件树变化 | 结果列表不自动刷新（手动重搜）；点结果文件仍正常开 tab |

### 5.5 布局边界

| 场景 | 处理 |
|------|------|
| 预览区无 tab | 空态占位，栏不消失（布局稳定） |
| 预览区收起/隐藏 | chat + 工作区自动扩展回收；展开时自动压缩让位（显隐联动） |
| 窗口过窄（三栏挤压） | 各栏压缩到各自最小可用（chat 320px / 预览 240px / 工作区 232px），极端窄窗口允许整体横向滚动 |
| dirty 时关闭最后一个 tab | 弹确认 modal（同切换守卫） |
| 拖拽到极限 | 目标栏到最大/最小 clamp，其他栏压缩到最小可用；不强制固定比例 |
