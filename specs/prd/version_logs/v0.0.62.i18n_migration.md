## 1. 背景与目标

v0.0.59 已搭好 i18n 基础设施（react-i18next + 10 ns locale bundle 骨架 + `app_config.locale.language` 开关 + 启动期 init + KKV 占位符协议 + 缺 key 报错 + displayReason 范式样板，已合并 dev1）。**骨架就位，但 8 ns（chat/studio/providers/plugin-config/app-dev-config/skill/connector/framework）+ common 仍是空壳**——现有 UI 文案仍为硬编码中文，切语言只有 displayReason + locale 选择器跟着切，其余 UI 不动。

**本版本目标**：把前端 components/ 下硬编码可见中文（~93 条按 9 ns 分）+ 配置体系预置文本（session 默认占位「新会话」、stopReason 等 type code）+ HTTP 错误体（保留 code 契约 + localized message）+ 内置 plugin.json label/desc（前端按 plugin id 映射，manifest 不改）**全量迁移到 v0.0.59 架构**。

**非目标**（不变更机制）：KKV 协议、兜底链、缺 key 报错、locale 开关、bundle 物理结构、key 命名规范——以上全部沿用 v0.0.59，本版本只**填文案 + 替换 t()**。

### 2.2 OUT-OF-SCOPE（❌ 硬边界 — 沿用 v0.0.59，不迁）

| 类别 | 字段示例 | 不迁理由 |
|---|---|---|
| **system skill 的 SKILL.md label/description** | `app/plugins/builtins/skills/okf-skill/SKILL.md` description 等 | SKILL.md 是给 LLM 的**标准协议契约**（单一 description，无 locale 变体）；多语言无标准机制，强加 locale 反破坏协议。skill 文案保持原样 |
| **LLM 向内容** | prompt / 用户输入 / 回复正文 | 模型输出层，不翻译（v0.0.59 §2.2 硬边界） |
| **用户数据**（字面数据） | squad name/desc/charter、member name、session title（一旦命名）、provider/model label、board 工作项、user_memory、用户自建 skill·plugin | 用户字面输入，原样直展（v0.0.59 §2.2） |
| **动态自由文本** | error_message、benchReason | 厂商/模型/用户原始返回，无法提前枚举，类同模型输出 |
| **HTTP 错误响应体**（4xx/5xx） | `json(status,{error:'msg'})`（全 handler） | 实测无机器可读 `code` 字段（与 SSE `errorCategory` 不同——那是 type code，已归 M3）；属动态自由文本，原样直展不翻译 |

> **skill-page 区分**：system skill **SKILL.md 内容**不迁（协议约束）；skill-**page 前端管理 UI** 的按钮/label/删除确认等前端文本仍走 i18n（`skill.page.*` / `skill.item.*` / `common.modal.close`，已在 M1 范围）。

### 2.3 不引入新概念（架构不变量）

本版本**不改 v0.0.59 已定的任何机制**（task.json `invariants.arch_unchanged`）：
- KKV 占位符四规则 + 兜底链 当前→en→zh-CN（不改）
- 缺 key 报错「【资源 xxx 不存在】」+ `parseMissingKeyHandler`（不改）
- locale 开关 `app_config.locale.language` + 启动期 init + 切实时生效（不改）
- bundle 物理结构 `app/web/src/i18n/locales/{zh-CN,en}/<ns>.json` + 10 ns 划分（不改）
- key 命名 `<ns>.<scope>.<leaf>` camelCase（不改）
- type 走映射 / 自由文本走直展（不改）
- displayReason 后端范式契约（零 API breakage）（不改）

## 3. 关键用户路径（MANDATORY — 测试最低覆盖）

> 每条路径后续至少 1 个 API/E2E case 覆盖。本版本是迁移性质，路径聚焦「切换生效 / 启动读取 / 兜底 / type 映射」四类。

| ID | 用户操作链路 | 预期结果 |
|----|-------------|---------|
| **UC-1** | 用户打开 `page-app-settings` → 找到 locale group `key-card-locale-language` → 点 `key-card-locale-language-en` | 全局 UI 文本**即时切换**为英文（chat/studio/providers/plugin-config/app-dev-config/skill/connector/framework/common 全 ns 跟切）；**无需刷新**；刷新后仍为英文（持久化 PUT `/config/app?group=locale`） |
| **UC-2** | 用户首次进入应用（任何 page） | main.tsx 启动期 `await initI18nFromConfig()` 读 `app_config.locale.language` → UI 显示对应语言（zh-CN 或 en）；无首屏闪烁 |
| **UC-3** | 开发环境下，前端调用 `t('chat.<scope>.<missing-leaf>')` 而 locale bundle 三级（zh-CN/en/兜底）均缺该 key | 渲染位置出现红字「【资源 chat.<scope>.<missing-leaf> 不存在】」+ console.error；用于抓漏迁移 key |
| **UC-4** | 用户在 chat 页收到一个 `Run.stopReason = 'doom_loop'` 的运行结束事件（或 connector `connection = 'connected'`、member `state = 'deployed'`） | 前端按当前 locale 查 `chat.run.stopReason.doomLoop`（或 `connector.browser.connection.connected` / `studio.memberState.deployed`）显示对应语言文案，**非直展 code 字面**；切语言即时跟切 |

> 路径 1/2 复用 v0.0.59 已建基础设施（locale 选择器 + 启动期 init），本版本验证「全 ns 跟切」（v0.0.59 只有 displayReason 跟切，本版本扩展到 9 ns 全部跟切）。
