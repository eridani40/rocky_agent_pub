## §1 背景与目标

v0.0.88 已收敛 SSE 通道为「1 单例 + 组件级订阅 + subId 路由（方案 B）」，但调研发现两份 spec↔code 偏离 + 多处轮询残留 + 生命周期管理缺抽象：

- **G1【严重 spec 偏离】**：`app/web/src/components/studio-page/use-studio-unread-meta.ts:46` 显式 `new SseClient()` + `:95 sse.destroy()`，违反 `[P0]sse_client_singleton.md §1 S1/S3`（全局唯一 + 组件不碰连接）。后果：切 page 反复建/拆第二条 GET /sse、backend sinks fan-out 给两个连接造成 N×M 帧浪费。spec §5 R3 注脚反而声明「不存在」，需修。
- **R2【SSE 重连完全缺失】**：`sse-client.ts:108-129` reader.read() 循环任何中断（网络抖动/Electron 卡顿/HMR 重启/macOS 唤醒）→ `finally: active=false` 终态，handlers 静默不再收帧，红点/run 态全部卡死，无 onError 自愈、无 visibilitychange 校正。
- **轮询残留（G5/G6 + 散点）**：`component-conversation-item.tsx:101-108` pollRef/stopPolling 是 v0.0.88 后 dead code；`component-mention-popover.tsx:85` debounce 未在 unmount clear；`budget-meter.tsx:47-51` 30s 轮询（spec §8 列 P2 待消）；`page-connector.tsx:49` 2s 轮询过密；`section-cron-panel.tsx:85-95` 60s 轮询合理（cron nextFireAt 漂移）。
- **生命周期管理缺抽象**：当前各 hook 各写 `useEffect + cancelled flag + cleanup`，无统一约束（裸 setInterval / 裸 setTimeout 残留 / `new SseClient` 破口正是缺约束的后果）。

**本版本目标（一句话）**：补齐 spec↔code 一致 + SSE 自愈机制 + 引入 `useLifecycle` hook 抽象统一管理组件订阅/数据/定时器生命周期并全迁「非引擎非轮询」4 个 hook，建立后续全项目收敛的契约基线。

## §3 useLifecycle 机制契约（核心「功能」）

> 抽象形态：**`useLifecycle` hook**（非 OOP base class）。代码路径：`app/web/src/lib/use-lifecycle.ts`（新建）。规范记录到 `[P0]component_architecture.md`（新增 §3.10）+ 本节。

### 3.1 接口定义

```typescript
// app/web/src/lib/use-lifecycle.ts
type LifecyclePhase = 'init' | 'destroy' | 'refresh';

interface LifecycleOptions<TCtx> {
  /** init: mount/deps 变化时调（拉 api + 建订阅）；返回 ctx 传给 destroy/refresh */
  init: (ctx: { signal: AbortSignal }) => Promise<TCtx> | TCtx;
  /** destroy: unmount/deps 变化时调（清订阅 + 释放内存）；init 抛异常时也调（catch 兜底）；必须幂等 */
  destroy?: (ctx: TCtx | null) => void;
  /** refresh: 仅轮询场景——setInterval 内调（数据更新后重渲染） */
  refresh?: (ctx: TCtx | null) => Promise<void> | void;
  /** 启用轮询（必须显式 + 写 justification，缺则 dev 警告 + 报错） */
  poll?: { intervalMs: number; justification: string };
  /** deps: 变化时 destroy + 重 init（替代 useEffect dep） */
  deps: ReadonlyArray<unknown>;
}

function useLifecycle<TCtx>(opts: LifecycleOptions<TCtx>): {
  ctx: TCtx | null;
  loading: boolean;
  error: Error | null;
  reload: () => Promise<void>;  // 命令式刷新（手动触发 init）
};
```

### 3.2 不变量（MUST NOT 违反）

1. **`init` 必须接 AbortSignal**：所有 fetch/async 操作 `signal.aborted` 校验后才能 setState，杜绝 setState on unmounted。
2. **`destroy` 必须幂等**：可被多次调用（StrictMode 双 mount + React 18 concurrent）；不抛异常。
3. **`poll` 必须显式 + 写 justification**：缺 justification 触发 dev 警告 `[lifecycle] polling enabled without justification`；PR review 强制检查。
4. **禁止在 `init` 内调 setState**（除返回的 ctx 外）：state 由 hook 内部管（loading/ctx/error）。
5. **`destroy` 内禁 fetch**：仅清本地资源 + unsubscribe 句柄；网络层 fire-and-forget 不阻塞 unmount。

### 3.3 禁忌（写进规范文档，落地为代码注释 + dev 警告）

- ❌ 禁止 render 期间订阅（必须在 `useEffect`/`init` 内）。
- ❌ 禁止裸 `setInterval` 不在 `useLifecycle` 或 `useEffect` cleanup 内 clear。
- ❌ 禁止裸 `setTimeout` 不在 unmount cleanup clear（除 React 18 一次性 setState 由库抑制）。
- ❌ **禁止 `new SseClient()`**（必须 `getSseClient()`）—— 违反 `[P0]sse_client_singleton.md §1 S1`。
- ❌ 禁止 `init` 内 await 后直接 `setState`（必须校验 `signal.aborted`）。
- ❌ 禁止把「全局 store 不释放」当成「组件已清理」——store 释放是独立议题。

### 3.4 与 SseClient 单例的关系（兼容、不动）

`useLifecycle` 的 `init` 内仍调 `getSseClient().subscribe(...)` 拿句柄；`destroy` 内调 `handle.unsubscribe()`（spec §1 S3：组件不碰连接）。**SseClient 单例的连接生命周期归 app 级，与组件生命周期解耦**——本提案不变更此契约。SSE 重连（W2）在 SseClient 内部实现，不暴露给 useLifecycle。

### 3.5 轮询策略

- **显式 justification**：每个轮询点必须在代码注释中写明「为什么必须轮询」（端点无 SSE / SSE 不可靠 / nextFireAt 漂移显示等）。
- **dev 警告**：`useLifecycle` 内 `poll` 启用时 `console.warn('[lifecycle] polling:', justification)`（仅 dev，build 静默）。
- **后台 tab 暂停 + reload-on-resume = poll-only（正式契约，非实现细节）**：`useLifecycle` 内部接 `visibilitychange` listener，`document.hidden` 时暂停 setInterval（W3 的 budget-meter/connector 也享受此机制）；切回 visible 时**仅当 `poll` 启用才 `reload()` 一次**——**非 poll hook 不重载**（数据 holder 走订阅/SSE `onResumed` 刷新、命令式 API 不在 tab 切换时重载）。根因：`useSubagentChildren`（T6）借 useLifecycle 只为用其 unmount cleanup（abort in-flight），不传 poll；若 onVisibility 无条件 reload → destroy 清 controllersRef → 切回 tab 静默丢 in-flight 请求（code-review 抓出 Major 后定）。代码：`use-lifecycle.ts:198-209 onVisibility`。
- **保留的合理轮询**：`section-cron-panel.tsx` 60s（cron nextFireAt 漂移，端点无 SSE）。
- **建议改 SSE**：`budget-meter.tsx` 30s（session_usage_update 已有 SSE 推送）、`page-connector.tsx` 2s（无 SSE，建议延长 + 后台暂停）。具体决策见 §6 模糊点。

### P3：网络断开 / 恢复（R2 新增，核心）

- **链路**：SSE 长连接因网络抖动/HMR/macOS 唤醒中断 → SseClient reader.read() throw → `onError` 触发指数回退重连（1s/2s/4s/8s/.../cap 30s，jitter ±20%）→ 重连成功后 `visibilitychange` 触发一次 GET /session + GET /messages 校正当前活跃 session 态（replayable=false topic 靠 GET 兜底，agent_loop 靠 hub replay）。
- **验收**：(a) 断连后 ≤30s 内自动重连成功，handlers 残留可继续收帧；(b) 重连后单活跃 session 状态准确（无 stuck running / 无漏帧）；(c) 重连期间用户操作（发消息/abort）正常，POST /messages 走独立 HTTP 不受影响；(d) DevTools 不出现两条 GET /sse（重连 = 旧 abort + 新建，不是叠加）；(e) 新增 UT `lib/__tests__/sse-client.reconnect.test.ts`（mock fetch throw → 断言重连调用次数 + 退避时序 + GET 校正触发）。
- **覆盖 case**：新增 UT 上述；ET 可选（模拟 offline/online 事件）。

### P4：组件卸载清理（useLifecycle 全迁 4 hook 核心）

- **链路**：用户切走 tab / 关闭 popover / 切 page → useLifecycle 全迁 hook（useMemoryCrud + MemberPanelMemory + SectionWorkspacePanel + useSubagentChildren）unmount → destroy 调（清订阅 + clear interval + AbortController.abort；useSubagentChildren 的 destroy abort 所有 in-flight controllersRef）；ComponentConversationItem dead pollRef 代码删干净。（注：ComponentMentionPopover debounce 研究初稿误报「未 clear」，W3 核实 line 132-140 已有 cleanup，no-op。）
- **验收**：(a) 全迁 hook unmount 后无残留 setInterval/闭包引用（heap snapshot diff 干净）；(b) useSubagentChildren unmount 后 in-flight 请求被 abort（不残留 setState）；(c) ComponentConversationItem 渲染等价（删 dead code 无行为变化）；(d) 新增 UT 验证 destroy 幂等（连调 2 次不抛异常）+ signal.aborted 守卫生效；(e) reload-on-resume poll-only——非 poll hook（useSubagentChildren）切回 visible 不重载（不丢 in-flight）。
- **覆盖 case**：新增 UT `lib/__tests__/use-lifecycle.test.ts`（destroy 幂等 + poll.justification 警告 + signal.aborted 校验 + reload-on-resume poll-only）。

### P5：后台 tab 暂停轮询（可选，时间允许则做）

- **链路**：用户切到其他 Electron 窗口或浏览器 tab → `document.visibilityState === 'hidden'` → useLifecycle 内部暂停 setInterval（budget-meter 30s 不再跑）→ 切回前台立即 refresh 一次。

- **标注**：W3 若保留 budget-meter/connector 轮询则必做本项；若全部改 SSE 则本项跳过。决策见 §6。
