## 1. 背景与目标

v0.0.60 把看板改可编辑（POST/PATCH/archive/restore 全上），但**前端只接了 edit**——empty-state 文案「让 leader 在对话中创建」暴露了**写操作让渡给对话**的产品定调：用户得离开看板、去群聊/单聊让 leader 调 LLM 工具才能新建 workitem。这违背「看板是 CRUD 工具」的用户预期，也让 AI 显得多管闲事。

同时对话侧的 @mention 系统（v0.0.45 上线）只有 file+skill 两个 provider，无法把 workitem/member 当一等引用对象塞进对话——用户在对话里讨论某个 goal/task 时无法精确指向它。

加上两类已暴露 bug：squad chat 一直显示「请选择 model」（modelOverride 不播种 + 不传 inheritLabel）+ LLM 错误没进 langfuse（llm_caller invoke() 外层 catch 只写 dev log 就 rethrow，违反 spec 不变量）。

**本版本目标**：
1. **看板一等公民**：各 tab 直接手动新建 goal/KR/requirement/task，empty-state 改 CTA。Task→Requirement、KR→Goal 约束在 UX 里强制。
2. **对话 @mention 扩展**：新增 WorkItemProvider + MemberProvider，按 session kind 启用不同 provider 集合（D8 resolver 抽象）。
3. **看板→对话回路**：卡片 @ 按钮 → 开 leader 对话 + 输入区预填 @对象（ChatComposer 暴露 `insertMention`/`initialContent`）。
4. **工具参数默认值通用机制**：schema default + 运行时 default-fill（放 `validateInput` 末尾），首个消费者 `send_message needReply=true` default。
5. **修 squad chat model 展示 bug**：照搬 member chat 模式，父路由透传 squad.modelDefault。
6. **修 LLM 错误进 langfuse**：补 `endGenerationError`（invoke 外层 catch）+ endTrace trace-level ERROR。

**非目标**：
- 不加硬删除（D1-c，archive 已够）
- 不动 squad chat 的 ModelPicker **per-call override 语义**（不改 squad.modelDefault 持久化，仅显示从 squad.modelDefault 派生）
- 不引入实时 event 推送（编辑感知仍靠下次启动重建）
- 不动 chat 渲染内核 / a2a 协议核心机制
