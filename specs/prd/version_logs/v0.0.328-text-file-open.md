# v0.0.328 — .env/.example 等纯文本文件打开支持

> PRD 增量 | 版本：v0.0.328 | 日期：2026-08-11

## 1. 需求描述 [v0.0.328]

`.env`、`.example`、`.gitignore`、`Dockerfile`、`Makefile` 这类纯文本文件，应该能像 `.txt`/`.py` 一样在预览区打开查看/编辑。当前它们走系统默认应用打开（甚至可能无关联应用→打不开），用户体验断裂。

### 1.1 用户故事

作为开发者，我希望 `.env`、`.gitignore`、`Dockerfile`、`Makefile`、`.eslintrc` 等项目常见纯文本文件能在 app 内预览区直接打开查看和编辑，就像 `.txt`/`.py` 一样，而不是被甩到系统默认应用（或根本打不开）。

**优先级**：P1

## 2. 现状问题 [v0.0.328]

### 2.1 文件类型识别单一权威

`app/web/src/lib/file-format.ts` 的 `getFileFormat(path)` 是全链路唯一判定入口：

```
getFileFormat(path) → FileFormat | null
  ├── .env / .env.* → 'env' ✅ 已支持
  ├── 扩展名查表 EXT_TO_FORMAT → json/yaml/md/py/ts/.../code ✅ 已支持
  └── 无扩展名 / 未命中扩展名 → null ❌ 不支持
```

### 2.2 分流链路（open-local-path.ts）

点击文件 → `openLocalPath()` 五路分流（顺序固定）：

| 分支 | 条件 | 去向 |
|------|------|------|
| ① | kind='folder' | 系统文件管理器 |
| ② | `.url` | 嗅探浏览器 |
| ③ | image 6 格式 | 内置 image viewer |
| ④ | `getFileFormat(path) !== null` | **预览区**（onEditor） |
| ⑤ | 其余（getFileFormat 返 null） | **系统默认应用打开** |

**问题**：`.example`/`.gitignore`/`Dockerfile`/`Makefile` 等 → `getFileFormat` 返 null → 走 ⑤ 系统打开 → **不进预览区**。

### 2.3 各文件类型现状

| 文件 | basename 特征 | getFileFormat 现状 | 打开行为 |
|------|--------------|-------------------|----------|
| `.env` | 点文件，basename='.env' | **'env'** ✅ | 预览区（已支持） |
| `.env.local` | 以 '.env.' 开头 | **'env'** ✅ | 预览区（已支持） |
| `.example` | 点文件，basename='.example' | null（dot<0 走点文件分支不命中） | ⑤ 系统打开 ❌ |
| `.gitignore` | 点文件 | null | ⑤ 系统打开 ❌ |
| `Dockerfile` | 无扩展名（无点） | null（dot<0） | ⑤ 系统打开 ❌ |
| `Makefile` | 无扩展名 | null（dot<0） | ⑤ 系统打开 ❌ |
| `.eslintrc` | 点文件 | null | ⑤ 系统打开 ❌ |
| `config.example` | 扩展名 '.example' | null（未命中表） | ⑤ 系统打开 ❌ |

> **注意**：`.env` 已被 `getFileFormat` L131 特判命中（`name === '.env' || name.startsWith('.env.')`）。但 `.example` 虽然也以点开头，不满足 `.env.` 前缀，走通用扩展名逻辑 → `lastIndexOf('.')` 找到点 → ext='.example' → 查表未命中 → null。

### 2.4 后端读取

后端 `session-workspace-file.ts` GET handler 用 `readFileSync(absPath, 'utf8')` 读文本——**不做 text/binary 分流**，全部由前端 `getFileFormat` 决定能否进预览区。后端无需改动。

## 3. 支持方案 [v0.0.328]

### 3.1 方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A. 扩展名/basename 白名单扩充** | 在 `getFileFormat` 加已知纯文本 basename/扩展名映射 | 精确、可控、无误判 | 需维护白名单，新文件类型需手动加 |
| B. 无扩展名 + 未知扩展名 fallback 为文本 | dot<0 或查表未命中 → 返 'txt' 而非 null | 零维护，覆盖一切 | 二进制文件（.exe/.zip/.so）也会进预览区→乱码 |
| C. 内容嗅探 | 读文件内容，`looksBinary` 判定 | 最智能 | 需先读文件才能判定→分流延迟；改动面大 |

### 3.2 选定方案：A（白名单扩充）+ 有限 fallback

**方案 A 为主**：扩充 `getFileFormat` 的已知纯文本 basename/扩展名白名单——覆盖项目常见纯文本文件。

**不加无限制 fallback**（方案 B 被否）：二进制文件（.exe/.zip/.so/.dll/.woff 等）会误进预览区显示乱码。但可考虑**有限 fallback**——只对「无扩展名的 basename 匹配已知文本文件名」做兜底（如 Dockerfile/Makefile），而非所有无扩展名文件。

### 3.3 白名单清单（v0.0.328）

**新增 basename 精确匹配**（无扩展名 / 点文件）：

| basename（大小写不敏感） | FileFormat | 说明 |
|--------------------------|------------|------|
| `.gitignore` | 'txt' | Git 忽略规则 |
| `.gitattributes` | 'txt' | Git 属性 |
| `.editorconfig` | 'txt' | 编辑器配置 |
| `.eslintrc` | 'txt' | ESLint 配置 |
| `.prettierrc` | 'txt' | Prettier 配置 |
| `.npmignore` | 'txt' | npm 忽略 |
| `.dockerignore` | 'txt' | Docker 忽略 |
| `.env.example` | 'env' | 环境变量模板（已有 .env. 前缀逻辑命中 → 'env'，确认覆盖） |
| `Dockerfile` | 'txt' | Docker 构建文件 |
| `Dockerfile.*` | 'txt' | Dockerfile.dev / Dockerfile.prod 等 |
| `Makefile` | 'txt' | Make 构建文件 |
| `makefile` | 'txt' | 小写变体 |
| `LICENSE` | 'txt' | 开源协议 |
| `LICENSE.*` | 'txt' | LICENSE.md/LICENSE.txt 等（部分已被 .md 命中） |
| `CHANGELOG` | 'txt' | 变更日志 |
| `README` | 'txt' | （无扩展名时；.md/.rst 已被扩展名命中） |

**新增扩展名匹配**（EXT_TO_FORMAT 追加）：

| 扩展名 | FileFormat | 说明 |
|--------|------------|------|
| `.example` | 'txt' | 配置示例文件（config.example） |
| `.sample` | 'txt' | 配置示例文件 |
| `.env` 扩展名形态 | — | 已由 basename 特判覆盖（.env/.env.local） |
| `.lock` | 'txt' | 锁文件（package-lock 不命中因为 .json→json；yarn.lock/.pnpm-lock） |
| `.log` | — | 已支持 |
| `.diff` | 'txt' | patch 文件 |
| `.patch` | 'txt' | patch 文件 |

> **分类策略**：新增文件统一归 `'txt'`（category='plain'，pre 渲染 + 无格式化/校验按钮）。不引入新的 FileFormat 类型——'txt' 已是纯文本通用格式，行为完全匹配。

### 3.4 实现方式（给 architect 参考）

`getFileFormat` 改动（`file-format.ts`）：

```ts
// 1. 新增：已知纯文本 basename 集合（大小写不敏感精确匹配）
const KNOWN_TEXT_BASENAMES: ReadonlySet<string> = new Set([
  'dockerfile', 'makefile', 'license', 'changelog', 'readme',
  '.gitignore', '.gitattributes', '.editorconfig',
  '.eslintrc', '.prettierrc', '.npmignore', '.dockerignore',
]);

// 2. 新增：已知纯文本前缀（Dockerfile.xxx / LICENSE.xxx / README.xxx）
const KNOWN_TEXT_PREFIXES: readonly string[] = ['dockerfile-', 'license-', 'readme-', 'changelog-'];
//   注：basename 如 'Dockerfile.dev' → lower='dockerfile.dev' → 命中 'dockerfile' 前缀 + '.' 分隔

// 3. EXT_TO_FORMAT 追加：'.example'/'.sample'/'.lock'/'.diff'/'.patch' → 'txt'

export function getFileFormat(path: string): FileFormat | null {
  const lower = path.toLowerCase();
  const name = basename(lower);

  // .env / .env.* → env（既有，不变）
  if (name === '.env' || name.startsWith('.env.')) return 'env';

  // [v0.0.328] 已知纯文本 basename 精确匹配（Dockerfile / Makefile / .gitignore / ...）
  if (KNOWN_TEXT_BASENAMES.has(name)) return 'txt';

  // [v0.0.328] 已知纯文本 basename 前缀匹配（Dockerfile.dev / LICENSE.txt / ...）
  //   Dockerfile.dev → 'dockerfile' prefix 命中；但 Dockerfile 本身已被精确匹配
  const baseBeforeExt = name.split('.')[0]!;
  if (KNOWN_TEXT_PREFIXES.some((p) => baseBeforeExt === p.slice(0, -1))) return 'txt';

  // 扩展名查表（既有逻辑，EXT_TO_FORMAT 追加了 .example 等）
  const dot = name.lastIndexOf('.');
  if (dot < 0) return null;
  const ext = name.slice(dot);
  return EXT_TO_FORMAT[ext] ?? null;
}
```

> 具体实现由 architect 定（basename 集合 vs 逐个 if-else、前缀匹配策略），PRD 只定义**哪些文件该被识别为纯文本 + 归 'txt'/'env' 分类**。

## 4. 需求边界 [v0.0.328]

### 4.1 做什么

- `getFileFormat` 白名单扩充：已知纯文本 basename + 扩展名 → 返 `'txt'`（或 `'env'`）
- 扩充后这些文件自动走 ④ 分支 → 预览区打开（view + edit）

### 4.2 不做什么

- ❌ 不加无限制 fallback（不把所有 null → txt，防二进制误进）
- ❌ 不改后端读取逻辑（utf8 读文本不变）
- ❌ 不改预览区 viewer/editor（'txt' → category='plain' → `<pre>` 渲染，既有行为）
- ❌ 不改 image 白名单 / `.url` 嗅探 / 系统打开逻辑
- ❌ 不加内容嗅探（`looksBinary` 已有但保留作 editor 内防御，不作主判定）
- ❌ 不改 `open-local-path.ts` 分流链路（白名单扩充后自动走 ④）

## 11. 注意事项 [v0.0.328]

### 11.1 `.env.example` 覆盖确认

`.env.example` 的 basename 以 `.env.` 开头 → 走既有 `.env.` 前缀逻辑 → 返 `'env'`（不是 'txt'）。这是合理的——`.env.example` 本质是环境变量模板，归 'env' 分类语义更准。回归保护需确认。

### 11.2 大小写不敏感

`Dockerfile` / `DOCKERFILE` / `dockerfile` 都应命中（`getFileFormat` 已做 `toLowerCase()` 归一化，basename 集合用小写）。`Makefile` / `makefile` 同理。

### 11.3 白名单可维护性

KNOWN_TEXT_BASENAMES 是一个渐进扩充集合——v0.0.328 覆盖项目最常见纯文本文件，后续可按需追加。代码结构应便于扩充（Set 集合，加一行即可）。
