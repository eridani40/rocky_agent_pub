# v0.0.192.delete_cleanup — 删除链路修正（保留工作数据 + 级联删子孙 session）

> 类型：**bug 修正**（删除链路两类缺陷）—— 纯后端行为修正，**UI 不变、无新功能/新界面**
> 决策原则权威：`reqs/[working] v0.0.192.delete_cleanup/req.md`（本 PRD 对齐引用，不重新探讨）
> 前置概念权威源（已读对齐）：
> - `specs/tech/squad/[P1]squad_workspace.md` §1/§2（squad 办公室目录布局：workspaces/outputs/reports/board 各职责）
> - `specs/tech/scheduling/[P1]cron_subsystem.md` §8（cron 注销机制 / onSessionDestroyed 语义）
> - `specs/api/overall/11-squad.md`（dissolveSquad 入口）+ `04-agent-session.md`（DELETE /session 入口）

## 1. 背景（两类用户可感知的删除缺陷）

1. **解散团队误删工作产出**：`dissolveSquad` 末步 `rmSync(squads/{squadId}/, recursive)` 把整个团队办公室连根删——含 `workspaces/` `outputs/` `reports/` 等 agent 帮用户做出来的工作内容。不可逆、无备份、无迁移。
2. **删 session 不级联 → 孤儿 + 潜伏调度**：删 parent session 不递归删 children（无论 playground 还是 squad spawn 出的 child）；children 若挂 cron，删 parent 也不触发它们的 `onSessionDestroyed` → 内存 cron job 继续被引擎调度、继续烧 token。

## 2. 决策原则（对齐 req，不在本 PRD 重新探讨）

用户铁律 2026-07-23（详见 req §决策原则）：

| 数据类别 | 处理 | 典型 |
|---|---|---|
| **工作数据** | ✅ **保留** | workspaces（agent 写的代码/文件/草稿）/ outputs（交付物）/ reports（报告） |
| **过程数据** | ✅ **保留** | dev-logs / langfuse trace / search.sqlite |
| **程序性·管理性数据** | ❌ **删除** | session record / squad record / members 档案 / 调度（cron/heartbeat）/ watcher / inbox |

> 隐喻：员工离职——他写的代码（产出）不删；员工档案/账号（存在记录）删。
> **细化分类（用户裁决 2026-07-23："用户看不懂/程序用的/解散后没用的删，用户工作产出保留，你来决策"）**：
> - **保留** `workspaces/` `outputs/` `reports/` `board/`（用户可直接看懂的工作产出；board 含可读 .md 主面）
> - **删** `charter.md`（团队章程，解散失效）`charter_history/` `members/` `index.md`（程序生成 OKF 入口）`log.md`（变更审计）`panorama/`（纯程序格式 yaml/json/jsonl，需 UI 渲染）整个 `.rocky_squad/`（state 调度 + memory.md agent 记忆 + skills agent 配置）
> - 判据：用户可直接看懂/回收的产出保留；只有程序能看懂的内部数据/索引/配置/历史删除。board（有 .md）保留 vs panorama（纯程序格式）删即此判据。

## 3. 行为变化（用户可感知契约）

### 3.1 解散团队：保留工作内容，只删管理性数据 [v0.0.192.delete_cleanup]

**优先级**：P0
**用户故事**：作为 team leader，我解散团队后，agent 们做出来的工作产出（代码、报告、交付物）仍然保留在原地可供我查阅/回收——不要因为「解散」这个动作把大家的工作成果一键清空。

**行为契约**：
- **保留**（用户可读工作产出，可查可回收）：`workspaces/`（agent 代码/文件）、`outputs/`（交付物）、`reports/`（报告）、`board/`（OKR 工作内容，含可读 .md 主面）。
- **删除**（程序内部/管理性/解散后无用）：`squad/{squadId}.json` record、各 session record + `sessions/{sid}/`（含 cron.json）、`members/*.json` 档案、`charter.md`（团队章程解散失效）、`charter_history/`、`index.md`/`log.md`（OKF 框架元数据）、`panorama/`（程序格式业务数据无用户可读主面）、整个 `.rocky_squad/`（state 调度状态 + memory.md agent 记忆 + skills agent 配置）。
- **语义**：解散 = 注销团队的「存在」+ 清掉程序内部状态，保留用户能看懂的「产出」。

### 3.2 删任意 session：子孙 session 一并级联删 [v0.0.192.delete_cleanup]

**优先级**：P0
**用户故事**：作为用户，我删除一个 session 时（playground 单聊、squad spawn 出的 child 均同样），它下面派生出来的所有子孙 session（含挂 cron 的定时 child）都跟着一起干净清除——不会留下一堆没人管的孤儿 session 还在后台偷偷跑 cron 烧 token。

**行为契约**：
- 删除一个 session → 递归收集其全部子孙（**多层，不限一层**）→ 逐个删 session record + `sessions/{sid}/` 目录。
- **每删一个都触发 `onSessionDestroyed`** → 子孙挂的 cron job 在内存引擎中注销，堵住「删 parent 后 child cron 继续烧 token」的潜伏调度。
- **覆盖所有入口**：squad 解散级联、playground `DELETE /session` 级联都走同一语义。

## 4. 关键用户路径（MANDATORY — 测试最低覆盖）

| 路径 | 描述 | AT | ET |
|------|------|----|----|
| **A** | 解散团队 → squad record / 各 session / members 档案 / 调度全删；`workspaces/` `outputs/` `reports/` 工作内容保留可查 | AT-A：解散后验工作内容存活 + record/members 已删 | n/a |
| **B** | 删一个有子孙的 session（playground）→ 全部子孙 session 全删、无孤儿 | AT-B：删 parent 后列 children 为空 | n/a |
| **C** | 删一个挂 cron 的子孙的 parent → 重启 app 后该 cron 不复活、不再 fire | AT-C（可并入 B）：删除后查调度引擎无该 job | n/a |

> **不覆盖 ET 理由**：本版本纯后端删除链路行为修正，无用户可感知界面/交互变化（解散入口、删除 session 入口 UI 均不变，已有 ET 回归即可）。UT（dissolveSquad 保留工作数据、级联 BFS 收集器、onSessionDestroyed 触发）+ AT（真调 API 验文件系统/调度状态）足够覆盖用户可感知行为。

## 5. 验收口径

1. **解散团队后**：`squads/{squadId}/{workspaces,outputs,reports,board,...}` 工作内容保留可查；`squad/{squadId}.json` record / 各 session / `members/*.json` / `.rocky_squad/state/` 调度状态已删。
2. **删任意 session**（playground / squad / spawn child）：其所有子孙 session（含挂 cron 的）全删，无孤儿 session record、无残留 `sessions/{sid}/`。
3. **无潜伏调度**：删除后重启 app，已删 squad/session 的 cron/heartbeat 不复活、不 fire、不烧 token。
4. **过程数据**（dev-logs / langfuse / search.sqlite）不动。

## 6. 不在范围

- **过程数据**（dev-logs / langfuse trace / search.sqlite）**不动**（用户认可保留）。
- **UI 不变**：解散团队入口、删除 session 入口、交互流程均无变化。
- **不新增功能/界面**：纯修正既有删除链路，不引入新能力。
- **工作数据分类已明确**（用户裁决 2026-07-23）：保留 `workspaces/` `outputs/` `reports/` `board/`（用户可读产出）；删 `charter.md`/`charter_history/`/`members/`/`index.md`/`log.md`/`panorama/`/`.rocky_squad/`（程序内部/管理性/解散后无用）。
- **技术实现**（dissolveSquad 步骤拆分、children BFS 收集器形状、onSessionDestroyed 触发点）归 architect 的 `change_plan.md`，本 PRD 只记行为契约。
