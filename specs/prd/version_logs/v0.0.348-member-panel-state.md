## 1. 根因（一句）

`useStudioUnreadMeta` 三张 map（unread/running/state）唯一写入源是 SSE 增量帧——v0.0.165 删初始拉取且无重连校正，订阅冷启动/断连窗口丢的帧**永远补不回**，面板状态永久错态（左侧 squad 列表对、右侧面板错——老板实证）。

## 2. 修复（方案 A：四层 hydration，老板拍板「视图级数据生命周期」）

`useStudioUnreadMeta`（`studio-page/use-studio-unread-meta.ts`）数据源升级为四层：

| 层 | 机制 |
|---|---|
| ① 订阅 | onInit **同步** subscribe `session_meta _all`（在前，时序禁令：await 会阻塞 onInit resolve → 丢帧窗口扩大） |
| ② 冷启动补水 | fire-and-forget `GET /session?biz=studio`（`listSessionsByBiz` 前端封装）→ `mergeFromSessions` 纯函数合并进 ctx（重建语义） |
| ③ 竞态仲裁 | ctx 内部第四张 `metaMap`（sid→updatedAt，不外露）：GET 在途新帧先到时，GET 响应后到**不回退**更新的帧（updatedAt 更新者胜）；响应缺失但 ctx 有更新帧的 sid 保留（新建会话帧先到） |
| ④ 重连校正 | `onResumed` 回调重跑 hydrate（退订句柄 onDestroy 回收，严于 use-squad-meta 先例，防 singleton 残留回调） |

- **无组件 UI 变化**（纯 hook 数据层；消费方 seats-panel/seat-card/seat-row/sidebar 零改动）。
- `session-api.ts` 新增 `listSessionsByBiz(biz)`：**纯前端封装**，`listSessions` 原签名零改动（3 现有调用方不动）。
- **API spec 零变化**：`GET /session?biz=` 是 server 既有路由参数（**biz 参数 v0.0.56 既有契约**，`specs/api/overall/04-agent-session.md §2.2` 已记载）；server 代码零改动。
