# v0.0.316 — 配置面板统一保存按钮

> 2026-08-10 | PRD
> 调研：`outputs/team-panel-save-behavior-report.md`

## 1. 背景与目标

### 1.1 问题

当前配置面板存在保存行为不一致：同一 tab 内混合即时生效（toggle 即 PATCH）与手动保存（攒入 draft 点保存）两种模式，且部分 tab 有多个独立保存按钮。用户无法预期「改了之后要不要点保存」。

**根因**（调研确认）：保存模式由「后端数据源」决定而非「UI 体验」决定。同一 API group → 统一保存；不同 API 端点 → 各自独立 save。用户看到的是同一个 tab，但底层多个独立数据源各自为政。

### 1.2 用户偏好（一句话）

**一个 tab 一个保存按钮，任何配置改动都触发 dirty 状态亮起保存按钮，点保存统一提交。**

### 1.3 范围

4 个需治理的面板（按优先级）：

| 优先级 | 面板 | 当前保存按钮数 | 目标 |
|--------|------|--------------|------|
| P0 | 管理 tab（ManageTab） | 1 + 即时 toggle | 1（toggle 改为攒入 dirty） |
| P1 | 自动工作 tab（AutoworkTab） | 2 + 即时 toggle | 1（3→1） |
| P2 | 工具 tab（App Config） | 4 | 1（4→1） |
| P3 | 可观测性 tab（App Config） | 2 | 1（2→1） |

**不受影响（保持现状）**：解散团队、deploy/bench、新增成员（操作类确认即执行）；通用 tab 语言切换（即时）；记忆 tab CRUD（即时）；会话/模型/整理/插件 tab（已一致）；Member 编辑面板（已统一保存）。

## 3. 功能设计

### 3.1 P0: 管理 tab（ManageTab）[v0.0.316]

**当前**：名称/描述/模型/effort 已有统一保存（✅）；群聊开关即时 PATCH（❌）；解散团队即时 DELETE（✅ 操作类保留）。

**改动**：`GroupChatToggle` 从即时 PATCH 改为攒入 ManageTab 级 dirty。

#### 3.1.1 GroupChatToggle 改造

| 字段 | 当前 | 目标 |
|------|------|------|
| toggle 行为 | 点击即 `onPatch({ enableGroupChat })` → PATCH | 点击改本地态 → 上报 onChange → ManageTab dirty |
| error 处理 | 自管 error banner | 去掉（保存失败由 tab 级统一处理） |
| pending 状态 | 自管 pending（防双击） | 去掉（tab 级 saving 统一管控） |

**新增 props**：
```ts
interface GroupChatToggleProps {
  enableGroupChat: boolean;        // 当前值（来自 draft，非 server 回灌）
  onChange: (value: boolean) => void;  // 上报变更 → 父级 dirty
}
```

去掉 `squadId` / `onPatch`（不再自管 PATCH）。

#### 3.1.2 ManageTab dirty 扩展

ManageTab 已有 5 字段 dirty 判定（name/description/modelDefault/modelDefaultProviderId/effortDefault）。新增 `enableGroupChat`：

```ts
const dirty =
  name !== detail.name ||
  description !== detail.description ||
  (modelDefaultSel?.modelId ?? '') !== detail.modelDefault ||
  (modelDefaultSel?.providerId ?? '') !== (detail.modelDefaultProviderId ?? '') ||
  effortDefault !== detail.effortDefault ||
  enableGroupChat !== detail.enableGroupChat;  // ← 新增
```

#### 3.1.3 ManageTab save 扩展

save() 合并 PATCH 增加 `enableGroupChat`：
```ts
await onSaveMeta({
  name, description, effortDefault,
  ...(modelDefaultSel ? { modelDefault, modelDefaultProviderId } : { modelDefault: '' }),
  enableGroupChat,  // ← 新增
});
```

#### 3.1.4 保存按钮位置

保持当前位置（群聊开关上方，`flex justify-end`），dirty 时高亮。**不引入 TabSaveBar**（ManageTab 已有自己的保存按钮风格，只需扩 dirty 字段，保持视觉一致）。

> **裁决**：团队管理面板复用 ManageTab 现有保存按钮风格（`BTN_PRIMARY`），不强制换成 TabSaveBar。理由：ManageTab 已有成熟的保存交互，改动最小。AutoworkTab 则需要引入新的统一保存按钮。

### 3.2 P1: 自动工作 tab（AutoworkTab）[v0.0.316]

**当前**：SquadAutonomyToggle 即时 PATCH（❌）；HeartbeatConfigSection 独立 save（❌）；BudgetMeter 独立 save（❌）；AutoWorkHistory 只读（✅）。

**改动**：AutoworkTab 从「纯容器」提升为「dirty 管理者」，底部统一保存按钮。

#### 3.2.1 AutoworkTab dirty 聚合

AutoworkTab 维护 tab 级 draft state，聚合 3 个子组件的 dirty：

| 字段块 | 当前 draft owner | 目标 draft owner |
|--------|-----------------|-----------------|
| enableHeartBeat（总开关） | 无（即时 PATCH） | AutoworkTab |
| heartbeatConfig（间隔/时间段/范围） | HeartbeatConfigSection | AutoworkTab |
| budget（开关+上限） | BudgetMeter | AutoworkTab |

AutoworkTab 持有完整 draft：
```ts
// AutoworkTab 内部
const [enableHeartBeat, setEnableHeartBeat] = useState(detail.enableHeartBeat);
const [heartbeatConfig, setHeartbeatConfig] = useState(detail.heartbeatConfig ?? null);
const [budget, setBudget] = useState(detail.budget ?? null);

const dirty =
  enableHeartBeat !== detail.enableHeartBeat ||
  JSON.stringify(heartbeatConfig) !== JSON.stringify(detail.heartbeatConfig ?? null) ||
  JSON.stringify(budget) !== JSON.stringify(detail.budget ?? null);
```

#### 3.2.2 子组件改造（controlled 模式）

子组件从「自管 draft + 自管 save」改为「受控 + 上报 onChange」：

**SquadAutonomyToggle**：
- 去掉 `squadId` / `onPatch`
- 新增 `enableHeartBeat: boolean` + `onChange: (v: boolean) => void`
- 去掉自管 pending / error

**HeartbeatConfigSection**：
- 去掉 `squadId` / `onSave`
- 新增 `heartbeatConfig` + `onChange: (v) => void`
- 去掉自管 save 按钮 / reset 按钮（reset 改为 tab 级 cancel）
- 保留 enableHeartBeat prop（UI 展示用——heartbeatConfig 在总开关关闭时可能 disabled）

**BudgetMeter**：
- 去掉 `squadId` / `onSaveBudget`
- 新增 `budget` + `onChange: (v) => void`
- 去掉自管 save 按钮 + budgetOn 本地态（改为受控）

#### 3.2.3 统一保存

AutoworkTab 底部新增保存按钮（风格对齐 ManageTab `BTN_PRIMARY`）：
```ts
const save = async () => {
  if (!dirty) return;
  setSaving(true);
  try {
    await onSaveMeta({
      enableHeartBeat,
      heartbeatConfig,
      budget,
    });  // 一次 PATCH 合并提交
  } finally {
    setSaving(false);
  }
};
```

**重置（cancel）**：点「取消」→ draft 回 detail 原值（同 TabSaveBar cancel 语义）。

#### 3.2.4 预算开关假即时问题（同步解决）

BudgetMeter 的 `budgetOn` toggle 当前是 `useState` 本地态，切了不会立即调 API，但视觉上和即时 toggle 一样。改造后 budget toggle 变为受控（上报 onChange → AutoworkTab dirty），与其他配置统一行为。

### 3.3 P2: 工具 tab（App Config）[v0.0.316]

**当前**：4 个 section（web_search / web_fetch / see_image / bash）各自独立 GET + 自管 draft + 独立 save 按钮。

**改动**：去掉 4 个独立 save/reset 按钮，引入 tab 级 dirty 聚合 + 底部 TabSaveBar。

#### 3.3.1 dirty 聚合策略

4 个 section 各管不同 API group（`web_search` / `web` / `see_image` / `runtime`），无法原子提交。采用 **dirty 注册 + 逐个 save** 策略：

```
工具 tab 级维护 dirtyRegistry: Map<sectionId, { isDirty: () => boolean, save: () => Promise<void> }>
```

- 每个 section 注册自己的 dirty 判定 + save 方法
- TabSaveBar dirty = `dirtyRegistry.values().some(s => s.isDirty())`
- TabSaveBar save = 遍历 dirty section 逐个 `await save()`（Promise.all 并行）

#### 3.3.2 section 改造

每个 section（如 `SectionWebSearchConfig`）：
- **保留**：GET 挂载 + draft 管理 + dirty 判定 + save 逻辑（内部不变）
- **去掉**：自身的 save/reset 按钮区域（底部 toolbar）
- **新增**：注册到 tab 级 `dirtyRegistry`（暴露 isDirty + save 方法）

section 对外暴露 ref/callback：
```ts
interface SectionConfigHandle {
  isDirty: () => boolean;
  save: () => Promise<void>;
  reset: () => void;  // draft 回 baseline
}
```

#### 3.3.3 统一保存条

复用 `TabSaveBar`（App Config 已有组件）。tab 级：
- dirty = 任一 section dirty
- saving = 统一保存进行中
- save = 逐个 section save（Promise.all）
- cancel = 逐个 section reset

#### 3.3.4 部分失败处理

4 个 section 并行 save，可能部分成功部分失败。策略：
- 任一 section save 失败 → tab 级显示 error（「部分保存失败，请重试」）
- 成功的 section baseline 已更新（不会丢）
- 失败的 section draft 保留（用户可修正后重新保存）
- tab 级 dirty 仍为 true（因为失败 section 仍 dirty）

---

### 3.4 P3: 可观测性 tab（App Config）[v0.0.316]

**当前**：observability 配置独立 save（自渲染 section）+ logs 开关 ×7 走 page-tab 级保存。

**改动**：observability section 注册到 tab 级 dirtyRegistry，与 logs 统一。

#### 3.4.1 改造方式

同工具 tab §3.3 策略：
- observability section 去掉自身 save 按钮，注册到 tab 级 dirtyRegistry
- logs KV group 仍走 `useAppSettingsConfig`（已有 page-tab 级 dirty 机制）
- tab 级 dirty = logs dirty OR observability dirty
- tab 级 save = logs save + observability save（并行）

#### 3.4.2 复杂度说明

observability 是列表 + 详情编辑（类似 providers），天然适合独立 save。但用户要求统一，所以将其注册进 tab 级聚合器。改动量中等。

## 4. 交互细节定义

### 4.1 dirty 判定标准

**什么算「改了」**：

| 控件类型 | dirty 判定 |
|---------|-----------|
| 文本输入（name/description） | draft !== baseline（字符串比较） |
| 选择器（model/effort） | draft !== baseline |
| toggle（群聊/总开关/预算） | draft !== baseline（布尔比较） |
| 心跳配置（复合对象） | JSON.stringify(draft) !== JSON.stringify(baseline) |
| 预算（复合对象） | 同上 |
| SecretInput（apiKey） | draft.credentials !== baseline.credentials |

**不算 dirty 的情况**：改了又改回原值（=== baseline → dirty = false，保存按钮熄灭）。

### 4.2 切 tab 时的未保存变更处理

**策略：静默丢弃 + 不阻断**（暂不实现 unsaved warning）。

理由（PRD 倾向，架构阶段可推翻）：
1. dirty draft 是本地态，切 tab 后组件卸载 → draft 自然丢弃（React 默认行为）
2. 用户切 tab 意味着「我想去做别的」，强制弹窗阻断体验差
3. 当前已有保存按钮的 tab（如 ManageTab、App Config 会话 tab）都是静默丢弃，保持一致
4. unsaved warning 是独立功能（v0.0.316 不含），未来可全局加

> **架构阶段待定**：如果 leader 要求必须有 unsaved warning，需在 tab 切换层（`component-seats-panel.tsx` / `page-app-settings-merged.tsx`）加 dirty 门控 + 确认弹窗。PRD 默认不加。

### 4.3 保存失败的部分成功场景

| 面板 | API 结构 | 部分失败可能？ | 处理 |
|------|---------|--------------|------|
| 管理 tab | 单次 PATCH /squad（原子） | 否（整体成功/失败） | 失败 → 显示 error，draft 保留 |
| 自动工作 tab | 单次 PATCH /squad（原子） | 否 | 同上 |
| 工具 tab | 4 次并行 PUT（不同 group） | **是** | §3.3.4 部分 |
| 可观测性 tab | logs + observability（不同 group） | **是** | 同 §3.3.4 |

**统一错误展示**：
- 保存按钮下方 / tab 底部显示 error 文字（`text-danger text-xs`）
- error 文案：完全失败 → 显示后端 error message；部分失败 → 「部分配置保存失败，请重试」
- error 不阻塞用户继续编辑 + 重试保存

### 4.4 保存按钮位置

| 面板 | 位置 | 组件 |
|------|------|------|
| 管理 tab | 群聊开关上方（现有位置，`flex justify-end`） | ManageTab 现有按钮（`BTN_PRIMARY`） |
| 自动工作 tab | 底部（history 下方） | 新增统一保存按钮（风格对齐 ManageTab） |
| 工具 tab | 底部 sticky（`TabSaveBar`） | `TabSaveBar`（复用现有） |
| 可观测性 tab | 底部 sticky（`TabSaveBar`） | `TabSaveBar`（复用现有） |

**位置差异说明**：团队管理面板用 tab 内按钮（随内容流），App Config 用 sticky bar（固定底部）。理由：两个面板已有各自的设计风格，统一保存按钮的「位置」保持各面板内部一致即可，不强求跨面板一致。

### 4.5 保存中状态

- 按钮 loading 文案：「保存中...」（`saving ? t('common:status.saving') : ...`）
- 按钮禁用（`disabled={saving}`），防重复点击
- toggle / 输入控件不禁用（用户可继续编辑，保存完成后新 draft 进入下一轮 dirty）

## 8. 约束

1. **后端零改动**：所有 API 已支持部分字段提交（PATCH /squad）+ per-group 提交（PUT /config/app）
