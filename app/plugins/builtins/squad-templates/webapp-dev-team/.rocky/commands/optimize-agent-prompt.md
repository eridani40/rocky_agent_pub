# Optimize Agent Prompt

用户想优化某个 agent 的 prompt。从 `$ARGUMENTS` 获取 agent 名称（如未提供则询问）。

## 准备工作

在做任何判断之前，先充分阅读上下文：

1. `.rocky/agents/` — 整个 agent 团队的所有成员，了解这个角色在团队中的位置和协作关系
2. `.rocky/AGENTS.md` — 整体工作流和双轨状态管理机制
3. `states/` — 已完成的版本记录，agent 在现实中的表现、遇到的问题、走过的弯路都藏在这里

## 分析

带着一个问题去读这份 prompt：**这个 agent 够聪明吗？**

聪明不是指执行正确，而是：
- 它知道什么是重要的，还是只知道自己被分配了什么？
- 它会主动探索，还是等着被告知每一步该做什么？
- 它有没有足够的背景，在面对没有预料到的情况时仍能做出好的判断？
- 它有没有被某些表述框住，觉得世界只有 prompt 里描述的那几种情况？

states/ 里的记录是很好的参照——当时发生了什么，哪里出了问题，是 agent 能力不足还是 prompt 给的信息和空间不够？

## 改写原则

给方法论和目标，不给具体实现。告诉 agent 做什么、为什么，而不是怎么做。不要把当前对话中的分析和推理写进 prompt。

## 输出

以对话方式分享观察，给出改写思路和前后对比。不要修改文件。
等用户确认后再执行修改。
