# playground-stream-scroll-stick — 流式生成长内容自动贴底跟随

> 纯自然语言 case（v0.0.188 范式）；PRD `specs/prd/version_logs/v0.0.287.stream_scroll/prd.md` UC-1/3/4 的 E2E 主链路冒烟。
> executor 读 case.md + `specs/ui/overall/00-app-guide.md` §3.1，按 snapshot 文案/位置自选定位方式。

## Use Case

作为用户，我想在 Playground 发一条需要 LLM 生成长内容的消息，验证流式生成过程中视图始终贴底跟随最新内容（不被甩到中间），同时验证上翻时不会把我拉回、手动回底后恢复吸底——核心修复场景的端到端验收。

## 前置条件

- env.sh 已起好环境（headless 或 electron 模式）。
- LLM provider 可用（minimax 优先；executor 看 app 内可用 provider 选）。
- Playground 已建/选一个会话。

## 操作目标（编号步骤）

1. **进入 Playground 会话**：照 `00-app-guide.md` §3.1——从 nav-rail 点 Playground → 选/建会话 → 落到 chat 区。
   - 确认对话区当前在底部（空会话或已有几条消息均可，关键是滚动位置在最底）。

2. **UC-1 核心：发长内容消息 → 验证贴底跟随**：在输入区发一条会触发长内容生成的消息，如：
   - 「写一篇 800 字以上的科幻短篇小说」
   - 或「详细解释量子纠缠的原理、历史和应用，越详细越好，至少 500 字」
   
   发送后进入流式生成，**持续观察对话区滚动行为**：
   - **心证重点**：生成过程中视图应**始终贴底**——最新文字不断从底部出现，用户能看到内容持续增长。如果生成到中段时视图突然停在中间、最新内容滚出可视区下方看不到，即为 bug。
   - **若模型回复太短**（如只回了 100 字，不足以撑出滚动条）→ 换更长的 prompt 重试（如「写一篇 1500 字的文章」），**必须触发滚动**才能验证贴底。回复太短不足以触发滚动条时，记 small 并换 prompt 重试，非 blocking。
   - 生成期间可多观察几秒（长内容生成通常 10-30s），竞态 bug 是间歇性的——持续贴底无甩尾才算 pass。

3. **UC-3：生成中上翻 → 验证不拉回**：**发第二条长内容消息**，在其流式生成过程中：
   - 用鼠标滚轮**主动向上翻**几屏（离开底部）。
   - **心证重点**：上翻后视图应**停留在上翻位置**，不被强制拉回底部。新内容仍在生成但用户能看到的是上翻区域的历史内容。
   - 上翻后应出现引导气泡（「新消息」文案，浮动在输入框上方居中）。
   - **注意**：上翻操作必须是鼠标滚轮（wheel）/触摸滑动，不是键盘——确保是「用户交互」触发。

4. **UC-4：手动回到底部 → 验证恢复吸底**：在 UC-3 上翻状态下（生成仍在继续或已结束）：
   - 手动**滚回底部**（鼠标滚轮向下滚到底），或点击引导气泡（显示「回到底部」或「新消息」）。
   - **心证重点**：回到底部后，若生成仍在继续则后续内容应恢复贴底跟随；若已结束则停在底部。
   - 引导气泡在回到底部后应消失。

5. **（可选）UC-4 补充：点击气泡回底 + 新一轮生成**：上翻后点击气泡「回到底部」→ 平滑滚底 → 气泡消失 → 发第三条消息 → 新一轮生成应贴底跟随（验证恢复吸底后持续有效）。

## 验收口径（executor 自由心证）

- **pass**：
  - UC-1 长内容流式生成过程中视图**始终贴底跟随**（核心修复验证通过——间歇性甩尾 bug 未复现）
  - UC-3 生成中用户上翻后视图**不被拉回**，停留在上翻位置，引导气泡出现
  - UC-4 手动滚回底部或点气泡后**恢复吸底**，后续生成继续贴底
- **small**：主路径走通但偶发轻微抖动/视觉小瑕疵（不影响贴底跟随核心行为）；或某轮回复太短需换 prompt 重试后通过
- **blocking**：
  - UC-1 长内容生成时视图被**甩到中间**不贴底（核心 bug 未修复）
  - UC-3 用户上翻后**被强制拉回**底部（回归破坏——用户意图被覆盖）
  - UC-4 回到底部后**不恢复吸底**（后续生成不跟随）
  - 引导气泡不出现 / 关键元素找不到 / 发不出消息

## 注意事项

- **长内容依赖模型实际输出**：minimax 等模型回复长度不确定。executor 需确保回复足够长以触发滚动条（回复未撑出滚动条 = 无法验证贴底）。prompt 越长越容易触发（「1500 字」「详细展开」等指令）。
- **间歇性 bug**：竞态甩尾是间歇性的（与生成速度/一次性长度相关）。一轮通过不算充分——建议至少 2 轮长内容生成观察，均贴底才算 pass。
- **上翻操作方式**：UC-3 的上翻必须用鼠标滚轮（wheel）或触摸滑动（touchmove）——这是「用户交互」的定义。如果用键盘 PageUp 也算用户交互但 playwright 模拟方式不同，executor 按实际情况选。
- **引导气泡**：上翻后浮动气泡文案可能是「新消息」（生成中）或「回到底部」（空闲），两者均正常——存在即说明 nearBottom=false 正确检测到。
